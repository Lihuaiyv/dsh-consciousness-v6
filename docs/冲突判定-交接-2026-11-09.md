# 冲突判定与「记忆时态」的接缝 · 交接（2026-11-09）

> 起因：11-08 23:06，主人先说「我好像没有get到哎」，三分钟后说「哦，我我好像能get到了」。
> 写入时被判成「前后矛盾」，开了张冲突卡；问句没排上，于是每轮开头被塞一句
> 「（你注意到一处对不上：…）」——第一人称，连着两个会话都在念，看上去像我嘴碎。
>
> 查下来是四处叠在一起，不是一处 bug。本文记：链路、已修、留着等模型的三处。

---

## 一、链路（现状）

### 写入

```
一轮对话
  │
  ▼
raw_turns（原文落盘）
  │ 抽取
  ▼
候选记忆 cand（fact / appraisal …）
  │
  ▼
gate.decideWrite ── 池：最近 200 条在册事实
  │                ① 字面相似度（字符集 Jaccard，同实体 +0.08）
  │                ② 共享 ≥4 字 + 否定词位置一有一无 → 判「矛盾」
  │                   （整句像不像、什么时候说的，都不参与）
  │                ③ 热/冰 这类互斥值 → 也判「矛盾」
  │
  ├── new / merge ──► 正常写入
  └── conflict
        │
        ▼
     gate.applyWrite
        │  ④ addMemory 里又判一次 → 同一对可能出两张卡
        │      · 低风险 → 记一张「已自动结案」的卡（不排问句）
        │      · 高风险 → 开 open 卡
        │  ⑤ 开卡的同一步就：作废旧那条 · 挂告警 · 排问句
        ▼
     conflicts: open
        │
        ▼
     maybeJudge（时态 M1）—— 事后的
        ⑥ 模型指认「哪条旧的是被取代的」；shadow 只记不判；on 也只收旧条，不结卡
```

### 开口

```
每轮开口前（index.js 拼提示词）
  ├─ 人格 / 情绪 / 驱力 / 关系 / 召回 / 日记 / 挂着的事
  ▼
查最新一条 open 冲突 → 开卡 < 2 天 · 问句没排上 → ⑦ 塞一句（旧版第一人称）
  ▼
拼成提示词 → 开口
```

### 问句 / 结案

```
开卡 ──► askAboutConflict ──去重──► proactive 排队 ──► 投递 ──► 问一句
                                       │ ⑧ 旧去重把「自动结案」的卡当成问过
结案 ──► ⑨ 唯一出口是面板拍板；问过也只压 24 小时；2 天后卡还在，只是不念了
```

## 三、留着没动的（等模型那一步）

| # | 位置 | 为什么留着 |
|---|---|---|
| ① | `gate.decideWrite` | **判矛盾该不该由字面规则定**，这是整件事的大头。规则只该负责召回候选 + 机械确定的那几类（同 key 值变了、热/冰互斥、做完/没做），「这两句到底能不能同时成立」交给模型。改这个要连带改调用时机与失败退回，不能顺手改 |
| ② | 同上 | 相似度在判矛盾时不参与（0.33 也开 high）。和①一起改，单改数字会变成拍脑袋 |
| ③ | `gate.js` 开卡分支 | 开卡即作废旧条 + 挂告警——这是「先动手后判」的另一半，要等①定下来再一起翻 |
| ⑥ | `maybeJudge` / `pair_judge` / `supersede_pick` | 时态判官的位置（在开卡之后）、开关（`memory.judge.gate=shadow`）、以及「判成取代也不结卡」。要和①合成一条线：**先问算不算数，再谈矛盾** |

### 建议的下一步（未做）

1. **先回放，不改代码**：拿库里现有的 40 条真冲突（含 11-08 两条误报）喂现在的判官，看它能不能把「没 get 到 → 能 get 到了」判成改口、把真冲突挑出来。
2. 回放过了再动①：`decideWrite` 判出 conflict 时**不开卡**，只进待判队列；模型三选一（真矛盾 / 改口 / 无关）；只有「真矛盾」才开卡排问句。
3. 模型失败或超时 → 静默挂面板，不开卡、不开口（失败即退回）。
4. 判成「改口」时顺手结案（`resolveConflict` 或直接标 resolved），别留一张开着没人管的卡。

对应文档：`docs/记忆时态-v3-总计划-2026-11-07.md`（M1「谁让谁不成立」）、`docs/记忆时态-模型窄门-修改计划-2026-11-04.md`。

### 还留着的

1. **addMemory 自己那条路**（抽取时判出的 `via: polarity` 冲突）还是老样子：开卡 + 排问句。

2. **pending 没地方看**：面板只筛 `state='open'`，pending 的行在数据里但界面上看不见。

## 五、2026-11-10 夜：两步补完 + 活库验证

### 1. 抽取路径也先判后动
`addMemory` 判出高风险冲突时：不再作废旧条 / 开卡 / 排问句，先落 `pending`，
再排一个后台判官（`queueConflictJudge`）。判完按结论结案（`settleConflictByVerdict`）。
开关仍是 `memory.conflict.judge`；关掉就走老路。

### 2. pending 的出口
- 夜里 `⑪f`：超过 1 小时的 pending 重判一次（`rejudgePendingConflicts`，每次最多 10 条）。
- 超 7 天或两侧记忆都不在了 → `resolved/unknown` 退场，别越积越多。
- 面板「它拿不准的事」里多了一块「待判 N 条」，可以直接拍板（`resolveConflict` 现在也认 pending）。

### 5. 顺手修：重复判定不再吃掉最像的矛盾（11-10 晚）
**高相似度的对立句会被当「重复」吞掉。** `addMemory` 先判 `sim ≥ 0.9 → duplicate`，
再看否定差异；所以「生日是十月三日」和「生日不是十月三日吧」只有相似度掉到 0.9 以下才会进冲突流程。
实测：0.846 能进；把两句写得再像一点（只差一个「不」）就直接合并，连冲突都不记。
这是独立的一条，要改得动 `memory.js` 那句 duplicate 判定；记在这里，下一轮再说。
**已修（11-10 晚）**：`memory.js` 先找「极性相反」的那条，再判重复；只有「重复的那条不是同一对矛盾」时才合并。
新测试 `test/memory-duplicate-order.test.mjs`（5 条）：0.9 相似度的「是 / 不是」现在判矛盾，同一句和同极性近义句照旧合并。
