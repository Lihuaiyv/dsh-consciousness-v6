# 第一个零件：主动开口（计划 2026-11-05）

> 目标不是把它改得更好，是给它一张考卷，证明以后换它的时候没换坏。
> 铁律：先考卷、后换；一次一个门；红两次就停。

## 一、它在哪

- 位置：`src/features.js` 的 `decideSpeak`。
- 类型：链上 × 判准混合——八道门是机器能判的，最后「该不该说」那一下要人判。
- 输入：`agents.status`、主动开关与额度、驱力（休眠/档位）、情绪（火气）、今天已说几句、打扰成本、真事证据、鱼格（外向）、主动性、安静时段、事由（开环）。
- 输出：`will`、`reason`、`gates`（每道门的 ok/理由）、`score`。
- 现状：`proactive_decisions` 只存输出，不存输入快照；所以**历史回放暂时做不了**，先做函数级考卷。

## 二、为什么先它

- 它最像「我在决定」，也最接近「真实」要验的那条链：状态 → 判断。
- 已有 `test/proactive-triggers.test.mjs` 和 `test/eval-persona/setup.mjs` 的 `makeWorld()`——临时库、不碰正式库。
- 它是判断，不是存储；换它不会先被数据迁移卡住。

## 三、三步

### 第 1 步：考卷（这次做）

新文件 `test/exam-speak.test.mjs`，复用 `makeWorld()`。24 个场景，覆盖八道门 + 边界：

- state：休眠 / 暂停 / 找不到。
- switch：关 / `per_day=0`。
- dormant：久未互动 / 正常。
- temper：`irritated` 且强度 > 0.7 / 平稳。
- deficit：D0/D1/D2/D3；无缺口但有事由；无缺口且无事由。
- evidence：要真事的维度 0 条 / 1 条 / 有事由豁免。
- quiet：安静时段内 / 外 / 手动催。
- cost：忽略率高 / 低；今天已说 0 / 1 句。
- 稳定性：同一场景跑两次，结论一致。

每个场景只断言 `will` + `reason` + 关键门 `ok`，不判「句子写得好不好」。
先跑一遍现有代码，把输出记为**基线**；人工审一遍：哪些是「设计如此」，哪些是「现在其实不太对」——后者不进考卷，单独列成问题。

- 验收：24/24 通过；不改任何源码。
- 回退：删掉新测试文件即可。

### 第 2 步：输入快照（顺手）

在落库处（`features.js` 里 `INSERT INTO proactive_decisions` 附近）把关键输入序列化进 `chain`（已有字段）或 events；只加字段，不改判定。

- 目的：两周后有真实历史，能补「回放考卷」。
- 验收：全量 560/560；从新记录能读回快照。
- 回退：删掉写入字段，不影响判定。

### 第 3 步：换一个门（考卷稳了再做）

只换一个最小参数：`timing` 曲线（12h→72h）或 `min_deficit` 默认值；不改结构。

- 跑第 1 步考卷 + 全量 + 同场景新旧对照。
- 分数不掉、没有 `will` 翻转，才留；否则 revert。
- 记录：改了哪段因果、考卷分、回退点。

## 四、不做什么

- 不拆 `decideSpeak` 的结构——那是第二次。
- 不碰正式库；不动 git 历史；新文件先不提交，等清理落袋。
- 不拿「像不像以前的她」当判据；只判「接不接得上因果」和「门对不对」。

## 五、验收和回退

- 每一步单独能跑；红两次就停，退回上一步。
- 回退不用 reset：删新测试文件 / 还原参数，数据一行不动。
