## 0. 一句话结论

这次没有再加「像人」的新维度，而是把已有的内心内容接成了会认账的闭环：

1. **取 / 说分离**：主动消息、开环、潜台词、自发浮现，只有真的进了注入文本才落账；被预算丢掉的不再被记成「说过了」。

## 1. 三条各改了什么

### 1.1 取 / 说分离

**旧行为（`commit_after_pack=off` 可复现）**：四类内心内容在「取出来」时就写状态，可它们随后可能被 `clampInjection` 丢掉。紧预算下一轮里，她「本来想说的」根本没进提示，账上却记成 delivered / fired / shown / surfaced。

**新行为（默认 on）**：

- `clampInjection` 支持带 key 的行，返回 `kept` / `removed`；整行被丢、被削断、被硬截断都不算「说过」。
- `proactive` 读出来不更新，拼装后按 `kept` 标 delivered。
- 开环拆成 `loopCandidate` / `commitLoop`；同轮重复拼装只记一次。
- 潜台词拆成 `subtextCandidate` / `commitSubtext`；收尾命中不出、不消耗 24h 冷却。
- 自发浮现改用 `pendingSurface` + `consumeSurface`；被丢掉时队列仍是 pending，下一轮还能再出现。
- 四类都写 `inject.mind_committed` / `inject.mind_dropped` 事件，预算到底多紧有数可查。

**改前 / 改后（紧预算 40 token，同一套代码 A/B）**：

| 指标 | 旧路 off | 新路 on |
|---|---|---|
| 主动消息 | delivered | **pending** |
| 开环 fire_count | 1 | **0** |
| 潜台词事件 | 1 | **0** |
| 自发浮现 | delivered | **pending** |
| 浮现记账 | 1 | **0** |

也就是说，旧路在「一句话都没进提示」的情况下，记了 4 笔「已经发生」。

### 1.2 来源徽章

**旧行为**：只有 `source='life'` 带「我自己看到的」。模型抽的、自己推的、主人亲口说的，在提示里长得一样，于是「我猜的」会被说成「你之前说过」。

**新行为**：

- 来源分三类：`我自己看到的`（life / browse / tool）、`从聊天里记下的`（extract / episode / summary）、`我自己想的`（consolidate / reflect / subtext）。
- 默认来源（manual / chat / ui / remember）不贴，避免每条都挂「你告诉我的」。
- `confidence < 0.55` 且来源是推断 / 转述时，末尾加 `不一定对`。
- 顺序：来源 → 年龄 → 清晰度 → 不一定对。
- 兜底记忆块（`consciousnessBlock` 的 `mem`）也贴；不只是 `packMemoryBlock`。
- 检索链路 `retrieve.js` 补了 `source` / `confidence` 两列，动态召回也带得出来。
- 时间标签开关和来源开关独立：`memory.inject.age=off` 时来源徽章仍然保留。

**改前 / 改后（同一组 4 条记忆，宽预算 800）**：

| 指标 | 关 | 开 |
|---|---|---|
| 注入 tokens | 445 | **456（+11）** |
| 我自己看到的 | 2 | 2 |
| 从聊天里记下的 | 0 | **1** |
| 我自己想的 | 0 | **1** |
| 不一定对 | 0 | **1** |

代价是 4 条记忆多 11 token（约 +2.5%）；换来的是「这条是我猜的」不再冒充原话。

### 1.3 关系余量

**旧行为**：关系账本只吃用户那句话（`R.ingest` / `learnFromTurn` 都只传 `u`）。她自己的回话只走 `applySelfRead`，只碰快情绪、单轮 ≤0.02，慢情绪和三轴都不动。所以她冷一句、敷衍一次，账本上没有痕迹。

**新行为**：

- `commitTurn` 里用 `readReplyTone(aText)` 对当轮表达基准 `expr.warmth`，偏离 ≥0.45 才记 `rel.self_residue`（cold / warm）。
- 下一轮 `residueCandidate` 最多给一句「上一句你说得有点硬 / 比平时软」；真的进注入才写 `rel.self_residue.shown`。
- 6 小时过期；紧预算可丢、不消耗。
- 夜巡 `settleSelfResidue`：同方向 ≥3 条、冷的方向累计 ≤ -1.2，才 `bumpRelation` 一次；默认 `relation.selfresidue.settle=off`，先 shadow。
- 只记主人；QQ 群 / 陌生人跳过。
- 三轴幅度：单次 `v=-0.08`、来源权重 0.35、`stepCap=0.05` 兜底。

**模拟结果（3 条冷余量）**：

- 注入里出「上一句你说得有点硬」= true；提示落账 1 条。
- 结算默认关：`settle-off`，信任变化 0。
- 打开结算：cold / 3 条，信任 **-0.002**、亲近 **-0.0008**；同日只结算一次。
- 紧预算 40：余量不进注入，提示落账 0 条（不会「没说却记成说了」）。

## 4. 已知限制 / 真机注意

1. **QQ 侧来源徽章**：`consciousnessBlock` 的 `recallOverride` 是外部通道预拼好的文本，本版没有在 QQ 路径重贴来源。先把 DSH 路径做对，QQ 等真机验过再接。
2. **老记忆的置信度**：老行 `confidence` 多为 0.8，低置信徽章只对**新写入**生效；来源徽章不受影响。
3. **关系余量结算只对主人**：QQ 群 / 陌生人跳过，避免把关系记到错的人头上。
4. **结算默认关**：`relation.selfresidue.settle=off`，先看一周 `rel.self_residue` / `.shown` 的分布，再决定是否打开。
5. **必须重载插件**：`index.js` / `features.js` / `nightly.js` 是宿主侧，当前进程跑旧代码；设置 → 插件 → 关掉再打开，刷新页面。

## 7. 追加：Shadow 观测 + QQ 接入（当日下午）

### 7.1 为什么现在做

前三条闭环都在「写」：写余量、写徽章、写落账。写完却只能靠翻 SQLite 看有没有生效——她自己是看不见的，主人也看不见。Shadow 观测把已有的只读数据接成三个入口（CLI / API / 页面），**只读、不写状态**；同时 QQ 通道补上「她的回话也留余量」，否则主人只在 QQ 上说话时，这条闭环等于不存在。

### 7.2 做了什么

**Shadow 观测**

- `self_residue.js` 新增 `shadowReport(db, aid, { days })`：余量（记录 / 提示 / 结算 / 冷热分布 / 最近一条 / 最近结算）、内心行（落账 / 丢弃 / 丢弃率 / 按 key）、记忆（总数 / 低置信 / 按来源）、当前参数。
- `GET /v1/agents/:id/shadow?days=7`：复用同一个聚合，页面和 CLI 读同一份数。
- `scripts/shadow-report.mjs`：`npm run shadow:report`，不带参数打最近 7 天。
- 页面「验收看板」下新增 **Shadow 观测** 区块：余量、开关、内心行、记忆四行；读不到时显示「没有观测数据」，不编数。

**QQ 接入**

- `writeTurn` 在落 `agent` 行之前，主人私聊会调 `recordReplyResidue`：用她在这个会话里自己的回话中位数当基准，不拿 `expressionState` 的当轮值硬套；先判余量再写当前行，避免把刚说的话当自己的常态。
- 群聊 / 陌生人照旧不记。
- 顺带确认 QQ 落库的 `mood` 现在真有值（之前这条路径写 null）。

### 7.7 这一轮修掉的 bug

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `UPDATE ... ORDER BY ... LIMIT` 语法错 | SQLite 不支持带 ORDER BY/LIMIT 的 UPDATE | 先选出最老一条 id，再按 id 更新 |
| 2 | 页面加了 Shadow 区块后 `完整清单与代码同步` 红了 | `src/catalog.json` 是生成文件，没重跑 | `node scripts/build-catalog.mjs`（96 项） |
| 3 | 模拟里 QQ 回话 `mood` 是 null | 模拟库没建 `affect_state`，不是产品路径问题 | 用 `openDb` 建全表并写一条 calm |
| 4 | 模拟里结算 `bump-failed` | 最小库缺 `agents/persons/relations` | 同上，换临时真库 |
| 5 | 模拟里 `memory_items.confidence` NOT NULL 失败 | 真 schema 是 `NOT NULL DEFAULT 0.8`，没有「null 置信度」这回事 | 用例改成正常 0.8，低置信只测 0.3 |
