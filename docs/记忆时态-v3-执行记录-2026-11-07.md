## 3. 关键设计落地

### M1 有界指认（替代自由四档）

- 输入：新事实 + 最多 3 条候选旧条；
- 输出：`{"invalidate":[1,2]}` 或 `{"invalidate":[]}`；
- 规则先行：短文本（<12 字）跳过、专名闸过滤、无候选不调模型；
- 失败（超时 / 非法 JSON / 没模型）一律不指认；
- shadow 只写事件 `memory.judge.pick`；`gate=on` 才对指认的旧条 `invalidateMemory`。

### M2 夜间状态核对

- 对 `pending` 且 ≥3 天的 claim，找之后的相关记录（同 key / 同主题 / 同 turn）；
- 模型只回 `done / stale / still` + 证据序号；
- shadow 只改 claim；`claim.enable=on` 才作废 done/stale。

### S4 loop 联动

- `closeLoops` 关闭时，若 loop 有 `memory_id`：写 claim（user_done→done，expired→stale），事件 `loop.closed_memory`；
- `loop_link=on` 才同时 `invalidateMemory`。

### S5 注入弱提示

- `claim.inject=off`（默认）：与改造前逐字一致；
- `on`：pending loop 的「还没做完」换成「当时还没做，之后没再确认」；到期的仍说「已经到期了」。
