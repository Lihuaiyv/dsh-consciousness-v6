## 3. 这张表说了什么

**第一，当前系统对「旧」的明确表达覆盖率是 1.2%（81 条里 1 条）。**

剩下 85.2% 全靠年龄徽章「（5 天前）」。年龄徽章有没有用？我不知道——它只说了「多久以前」，
没说「这条可能已经不对了」。这是**弱信号**，不是时态判断。

**第二，陈述时态（这轮新加的）对这批候选基本无效。**

原因很具体：`statementNote` 只对非槽位（反思/情景/评价）生效，而且要求超过 3 天。
134 条 weak 候选里，85 条是槽位（fact/appraisal）——不在它的管辖内；剩下 49 条非槽位里，
进注入的只有 6 条，且都还在 3 天内。所以它在这批数据上贡献 0。

它到底有没有用？**要另外测这批之外的数据**（非槽位的旧反思）。这次回放的候选集没覆盖到。

**第三，唯一能明显提升「提示」率的开关是 `memory.passport.weak`（默认 off）。**

D 组把它打开：提示从 5 → 13（+8 条），明确率不变（还是 1 条）。
代价是每轮可能多几句「同主题后面还有一条更晚的说法」，平均 token 没变（292）。

## 4. 那到底有没有进步？

**有，但不在「旧当现在」这条线上。**

| 维度 | 改前 | 改后 | 判断 |
|---|---|---|---|
| **误标（假阳性）** | 127 条挂「有更新」 | 0 | ✅ **实打实的进步** |
| 误挤（正常条被踢出正桌） | 5 条 | 0 | ✅ 进步 |
| 明确时态覆盖率 | 1 / 81（本来也差不多） | 1 / 81 | ❌ **没动** |
| 仅年龄覆盖率 | 69 / 81 | 69 / 81 | ❌ 没动 |
| T2 纪要带 created_at | 无 | 有 | ✅ 有（但这次回放没测到它的效果） |
| T3 日记带日期 | 无 | 有 | ✅ 有（同上） |
| 可见性（面板 / 文件口径） | 无 | 有 | ✅ 有 |

一句话：**这轮把「说错话」修掉了，没把「说不出话」补上。**

之前 127 条会主动告诉模型「有新说法」，那是**主动误导**；现在它不说了，这是净收益。
但剩下 81 条「可能过时」的说法，系统仍然只会说「5 天前」——它到底是不是过时，我们**没有能力判断，也没有表达**。

## 5. 所以下一步该做什么

按数据，优先级应该是：

1. **先把 `memory.passport.weak` 的默认值重新考虑。** 打开它：提示 5 → 13，明确率不变，token 不涨。
   这几乎是白捡的「别处还有说法」。之前默认关是因为怕吵——回放显示它不涨 token，因为只是加在已有行上。
2. **别急着做语义级评测。** 现在连「明确时态」都只有 1 条，模型级评测测不出差异——
   样本里根本没有足够的强信号让它表现不同。先把这个覆盖率做上去，再测。
3. **真要做语义评测，得先造样本。** 拿 invalid 的 193 条（它们 100% 有「旧」提示）做正样本，
   拿 weak 的 134 条做负样本，问「现在怎样」，看模型分别怎么答。这才是还没测过的那块。

## 6. 这份测评的局限

1. 分级靠关键词正则，不看语义。「（3 天前）」算 1 级，但它对模型的实际作用可能比正则估计的强或弱。
2. 只测了「这条说法自己那一行」，没测「整段上下文里其他条目的提示会不会被错挂到它身上」——后者是之前 22.7pp 错的来源。
3. 没调模型，所以测的是「提示在不在」，不是「模型会不会因此说对」。
4. 候选集只来自 `stampRow` 判出的 139 条，不包含已作废的 193 条（那些走 S2/S3，另一条路径）。
