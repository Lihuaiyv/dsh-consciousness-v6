# 计划 · 零件落地 v1（2026-11-05）

> 这份只记决定和步骤。**表本身不在这里**：待立的看 [零件-待立-2026-11-05.md](给人看的/零件-待立-2026-11-05.md)（只是待办）；已经立的以 `src/modules/parts.js` 为准（界桩查着它）。
> 一句话：图纸是待办，落地 = 有一件零件，登记了、考过、能切回来。

## 一、今天谈定了什么

1. **切法**：一行一个「能单独拎出来、说得出输入输出、能单独喂数据」的实现。不按目录、不按域；域是表归谁管，零件是能单独考的一小段。
2. **数量**：约 35 行（链上 28 + 链外 7），照术语表 5.1；**不分组、不合并**——分组和合并留给以后「老一起改 / 共用一张考卷」自己浮出来（术语表 5.2、第七节）。
3. **「自己拉」可以**：零件调对方的公开函数不算粘连。三条底线：不直接 SQL 别人的表、不 import 别人的内部文件、不靠别人顺手写下的副作用（事件、记账）过日子。
4. **现状（2026-11-05 晚）**：登记在册 5 件——主动开口 21/21、开环 63/63、召回 76/76、情绪评价 59/59、记忆衰减与分层 69/69；其余按[待立](给人看的/零件-待立-2026-11-05.md)，不叫「可换零件」。

## 三、四笔技术账

1. **界桩漏扫（最安全，先做）**：`scripts/dep-graph.mjs` 只扫 `src/modules/*.js` 顶层，子目录、`parts/`、`algo/`、`host/` 都不看；`scripts/check-ownership.mjs` 只查 ownership 名单里的文件，`parts/speak/` 不在。扩到全 src。
2. **flags 抄了四份**：`parts/speak/judge.js`、`trigger.js`、`budget.js`、`prefs.js` 各自写了一套 `SELECT/INSERT flags`；`kernel.js` 已有 `flagGet/flagSet`，收回去，只留一把锁。
3. **开口直读记忆表**：`parts/speak/judge.js` 第 144、148 行直接数 `memory_items`；改成调记忆域的公开函数（或加一个 `memoryCount(db, aid, since)`）。
4. **sangguan 一个真环**：`fast.js → inject.js`（`noteAskSpoken`），环是 `inject → liveness → fast → inject`。改法：`noteAskSpoken` 挪出去或走事件；这个会碰行为，放最后，先跑 `sangguan` 考卷。

## 四、风险（写下来防自己忘）

- **表 ≠ 落地**：35 行铺完，一行行为都没变；别把「写完了」当成「做好了」。
- **表会漂**：判准一改，切法就得改；改的时候回来改这一页，不悄悄改。
- **别当巡检单**：35 行不是「每天过一遍」，是「要动谁，先看它归谁、有没有考卷」。
- **零件盒先立住**：先让零件盒里那一行「看得见、点得开、有状态」（开口已经在），再往里加行。做一个能跑的局部，比铺满 35 行有用。

## 五、不做

- 不建 world snapshot / 输入信封（等真要整件替换或离线回放再上）。
- 不给 35 行都写说明页；先写考卷。
- 不为了凑数改切法。
