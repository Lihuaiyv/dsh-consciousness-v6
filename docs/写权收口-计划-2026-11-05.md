# 写权收口计划（2026-11-05）

> 背景：[表-谁在写-2026-11-05.md](表-谁在写-2026-11-05.md) 扫出来 80 张写表、20 张多人写。
> 目标：写权单点。一张表只有一个零件写；别人只读，或走那个零件的公开函数。
> 两类例外要写清理由：`ops`（清库级联删）、`host`（导入 / 导出整包）。它们不是业务写，是搬库。

## 一、最重的三张

| 表 | 写的人 | 收口方向 |
|---|---|---|
| `memory_items` | memory / selfhood / layers / timeline / writegate（+ host、ops） | 业务写全部走 memory 的公开函数；先盘每一处在写什么 |
| `changes` | kernel / persona / selfhood / selfmod（+ host） | 谁改的谁记；kernel 只留 setParam 那条 |
| `flags` | kernel / layers / sangguan / timeline（+ host） | 要么升成 SHARED（本来就是便签），要么按域分前缀、各写各的 |

## 二、顺序（一次一张表，一个 commit）

1. **memory_items**：五处业务写先分类——
   - 新增记忆：走 `addMemory`
   - 改状态 / 作废：走 memory 的 patch（timeline 的「作废 / 复活」就是这类）
   - 改计数（强化 / 热度）：走 writegate 或 memory 的计数函数
   - 收口后，`memory_items` 的 `writes` 只留 `memory`；wp / ops / host 写进例外清单。
2. **memory_fts**：它是 `memory_items` 的影子，跟着一起收。
3. **changes**、**flags**：按上表。
4. 其余 15 张：照 audit 报告一张一张来。

## 三、每张表的考卷

- 写前读到的和写后读到的一致（同一行、同一字段）。
- 不崩：写入失败返回错误，不半写。
- 不丢：迁移旧数据能读、能回退。
- 界桩：收口后 `check-ownership` 的 `multi_writer` 必须过。

## 四、先不做

- 不一次全动；不顺手改行为。
- 不为了「好看」把表合并或改名；先把写权收口，再谈结构。
