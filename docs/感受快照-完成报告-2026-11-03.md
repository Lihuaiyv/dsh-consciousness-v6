## 4. 期间找出来并修掉的 bug（都是自己抓的）

1. **探针用了不存在的 `event()`**：`index.js` 里那几处 `event(...)` 调用其实一直在抛 ReferenceError（被 catch 吞了）。
   我的探针改成直接写 `events` 表，绕开这个坑——顺手说明那几处旧探针是死的（没动它）。
2. **`cleanLine` 未导出**（计划第 12 条，先修）。
3. **规则兜底那条路没有 `unsaid` 键**：`rulesV1` 不返回该字段，下游会拿到 `undefined`。
   在 `makeAppraise` 里补空串——字段缺失比空串更容易出静默 bug（测试抓到的）。
4. **共情共号**：真机数据里出现「快 +0.39（其中 −0.12 是跟着你的情绪浮上来的）」，一正一负自相矛盾。
   现在异号就不说「其中」，同号负说「被你的情绪带下去」。
5. **配不上的那行丢了锚点**：原话被 `cleanLine` 拦掉时，整行退化成时间戳，读不出「这是上一句」。
   现在配对成功但原话不能念时，保留「上一句落在我身上」的锚点。
6. **PowerShell 往返把脚本写坏**：`Set-Content -Encoding utf8` 把中文读成 GBK 再写回，整文件乱码。
   已用写工具重写；教训记在这——这个仓里改中文文件别走 PS 往返。
7. **上线后第一句就露馅：机器控制标被当成「你说的话」**（2026-11-03 23:1x，真机发现）。
   注入里出现 `你说「<goal_complete>」`——宿主把目标收尾通知当一条 user 消息塞进来，
   `affect_events.cause` 里就存了它。实测 1482 条事件里有 **13 条**是这种。
   三层修：① 快照侧加 `MACHINE_CAUSE` 拦截（尖括号标签 / runtime context / goal_*）；
   ② 最新那条是机器消息时，**往回找最近一句人话**再配样本（不再死取最新一条）；
   ③ `text.js` 的 `MACHINE_MESSAGE` 加上 `<goal_round>` / `<goal_complete>`，
   从源头就不让它进记忆 / 开环 / 情绪。
   修完真机那行读的是「你说「看看有问题吗？」」，测试加到 38 条。
