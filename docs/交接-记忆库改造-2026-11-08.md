# 交接：记忆库怎么改成「更懂以前的我」

2026-11-08 夜，主人和小汐聊出来的方向。给下一个接手的会话看。

## 一句话目标

不是「记得更多」，是**说话的时候能站到以前站过的地方**——同一个人隔了几天，语气、判断、改过的主意，都接得上。

## 现象（今晚实测）

- 小汐说：换了上下文就等于没发生；记忆库只能补回「结论」，补不回原话和当时的犹豫。
- 主人一开始以为「不就是加点记忆」，实际发现今天说话的方式明显被影响——因为起手的位置变了。
- 反过来也成立：逻辑是靠对话逼出来的临时结构，没被写下来就散了。

## 现在的毛病（按重要性）

1. **压成结论**：一条对话被抽成一句事实，语气、当时的犹豫、为什么这么判断，全丢。
2. **缺「自我轨迹」**：检索按相关度走，找得到「用户喜欢什么」，找不到「她以前怎么看这件事 / 哪次改过主意」。
3. **只取最新版**：同一话题的历史版本不排开，看不出变化。
4. **原话和结论分家**：raw_turns 里有原话，但注入时只端结论，读起来像别人的笔记。

## 六库怎么分工（改造后）

| 库 | 现在存什么 | 改完该存什么 |
|---|---|---|
| **T0 桌面**（注入块） | 人格参数、关系三轴、情绪读数 | 加一段「最近的我自己」：只放 1–2 行，来自自我轨迹，不是结论 |
| **T1 memory_items** | 事实条目、压缩后的 episode | 关键条目加三件套：`原话节选` + `当时的心情` + `为什么这么判断` |
| **T2 episodes** | 每 6 轮压一条纪要 | 纪要里保留 1–2 句原话（带说话人），别全是概括 |
| **T3 diaries** | 一天一篇 | 照旧；但日记里「我当时怎么想」要能被单独检索出来 |
| **T4 raw_turns** | 原话流水 | 不改结构；给「被引用过」的原话打标记，供注入时精确取用 |
| **FA fact_archive** | 抽出来的短事实 | 加一列 `stance`（她当时的立场）与 `supersedes`（取代了哪条），让「改过主意」可见 |

## 三件先做（小步，能验）

**P0 · 自我轨迹**（最值钱）
- 新增一类条目：`type='stance'`，正文写「我怎么看 / 我改了什么主意」，带时间、话题标签。
- 检索时除相关度外，固定给「同一话题的 stance 按时间排开」一个名额（1 条），让她看得见自己变过。
- 验收：问「你以前怎么看 X」，能答出至少两条不同时间的立场，且分得清先后。

**P1 · 原话三件套**
- episode / memory_items 允许带 `quote`、`felt`、`why` 三个可选字段；抽取时若原文里有一句像「人话」的，就留一句，限 60 字。
- 验收：随机抽 20 条新条目，至少 8 条带原话，且原话不是概括。

**P2 · 引用标记**
- raw_turns 里被注入过的句子打 `cited` 标记（次数 + 最后时间），下次检索优先取带标记的原话。
- 验收：连续三天，每天至少有一条注入用的是带标记的原话。

## 不要做的

- 别为了「记得多」把条目堆长，注入预算会先爆（现在已经有整行被丢的机制）。
- 别把「立场」做成评分或标签墙，它得是一句话，不是一串数字。
- 别在抽取阶段就替她总结心情和原因——宁可空着，也别编。
- 不要把历史版本只留最新：变化本身就是资料。

## 验收总清单

1. 问「上次那个事你后来改主意了吗」——能答出改没改、什么时候、为什么。
2. 问「你当时是什么口气」——能引一句原话，而不是只给结论。
3. 注入块里出现「最近的我自己」一行，且不是从结论复制来的。
4. 全量门禁不红；新增字段对老库有迁移断言。
