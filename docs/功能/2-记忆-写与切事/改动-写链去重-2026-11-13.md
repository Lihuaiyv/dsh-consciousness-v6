# 改动 · 写链去重（第 1 步：chat_turns）· 2026-11-13

> 今天第 3 件的第一刀。目标：`commitTurn`（网页 / QQ 桥）与 `chatReply`（/chat、微信、QQ）不再各写一份 chat_turns。
> 一次只动一条链：这次只收「两行账的形状」，召回、记忆、抽取全不碰。

## 动了什么

| 文件 | 改动 |
|---|---|
| `src/modules/turn_write.js`（新） | `writeChatTurns(db, aid, {user, agent, at, conversationId, mood, packUser, packAgent})`：一轮两行，同一处 INSERT |
| `index.js` commitTurn | 两处 `writeChatTurn(...)` → 一次 `writeChatTurns(...)`（mood 用 `moodLabelOf`，user 包 `[]`） |
| `src/features.js` chatReply | 两处内联 INSERT → 一次 `writeChatTurns(...)`（user 包 = pack.items，agent 包 `[]`） |

`writeChatTurn`（单行版）保留导出，外部/旧调用不受影响。

## 行为差异（只有一处，很小）

- commitTurn 原来 user / agent 两行各算一次 `moodLabelOf`；现在算一次、两行共用。同一轮里情绪标签本来就不会变，行为等价。

## 怎么验

1. `node scratch/test-turn-write.mjs`（临时库）：
   - 两行、role 正确；user 的 pack/mood/conversation_id 都带对；agent 的 pack 是 `[]`。→ **OK**
2. 门禁：`node test/run-tests.mjs` → **560 / 560，exit=0**。

## 怎么退

- 把 `commitTurn` / `chatReply` 里的 `writeChatTurns` 调用改回原来的两条 INSERT 即可；`turn_write.js` 可留可删。
- 没有表结构变化、没有数据迁移。
