# 改动 · 回填入口（P1b）· 2026-11-13

> 今天六件之外的第一件 P1b。目标：把「切→导→热」从「手跑一天」变成「能补历史」。
> 回填必须在**插件进程**里跑——独立 node 进程拿不到宿主注入的 llm（model.complete 恒为 false）。

## 动了什么

| 文件 | 改动 |
|---|---|
| `src/modules/event_write.js` | 新增 `backfillDays(db, aid, {days, dry, complete})`：从昨天往回 N 天，逐天 `cutAndIngest`；已切过的天按 `events.cut.<day>.<aid>=done` 跳过；单天失败不拖垮整批 |

## 怎么验

- `node scratch/test-backfill.mjs`（临时库 + 假模型）：
  - 昨天/前天各 3 条碎片 → 回填 2 天：`days=2, events=2, added=2, hotAdded=2`；
  - 第二次跑：两天都 `marked`，不再写；
  - 冷库 2 行、热库 2 行。
- 门禁：`node test/run-tests.mjs` → **560 / 560，exit=0**。

## 边界与代价

- 7 天 ≈ 7 × 每天若干次模型调用；建议夜里跑，别在聊天高峰。
- 回填的热事件想头起点 0.2~0.35（与旧导入器一致），**当天基本不会浮**，要等 2.5~5 小时涨到 0.5——这是设计选择，别偷偷改公式（问题登记 D9）。
- 回填质量要看：抽 10 天，人工看「事像不像」「抓手撞不撞得上」；可命中率 <80% 就停下来改抓手规则。

## 怎么退

- 删 API 路由即可停用；已回填的冷/热事件保留（只追加）。
- 想重切某天：删掉对应 `flags` 的 `events.cut.<day>.<aid>` 再跑；写入器按稳定 id 幂等，不会写两遍。
