# 改动：切事模型改走 CPU（不占显存）· 8B 方案否决

日期：2026-11-16 00:47
前一份：`改动-本地摘要模型换8B-2026-11-16.md`（换 8B 的尝试，结论否决，过程留在那）

## 结论先说
1. **8B 不接切事**。实测同一批真实数据，8B 和 14B 的 digest 有明显分歧，不能换。
2. **14B 保留，但默认全放 CPU/内存跑**（`num_gpu: 0`），不占显存。
3. `keep_alive` 设 120 秒，跑完自己散，不再常驻。

## 8B vs 14B 实测（2026-11-15 真实 work 段，同参数）
取 11-15 的 869 行 work 段，按 `chunkByChars(8000)` 切成 37 块，抽最长/中间/最短三块：

| 块 | qwen3:8b | qwen3:14b |
| --- | --- | --- |
| 23（14 行 7767 字） | 讨论事实库分类与系统优化，涉及事件与事实区分及记忆管理 | 讨论事实库设计，涉及事件与事实区分、记忆分类及**提示词调整** |
| 20（32 行 7325 字） | 完成「留一句」功能开发…… | **在优化判官的提示词**…… |
| 36（9 行 2787 字） | 讨论如何分区域记录……确定分生活区和工作区的方案 | ……并**确认使用 8B 模型处理切事、重载插件生效** |

第 20 块两条指的是**不同的事**——同一块里两件事都有，digest 只写一件，8B 和 14B 选的重点不一样。切事写错重点，后面汇流、检索、「关于这句话」全跟着歪。这是否决 8B 的硬理由，不是感觉。
速度：8B 3.7~4.3s / 14B 5.1~5.6s；显存 7.5GB / 11.7GB。

一天 37 块 ≈ 52 分钟，夜里跑。

## 改了哪
`src/modules/local_llm.js` 的 `localComplete`：

- 请求体加 `keep_alive: '120s'`
- `options.num_gpu`：读 flags `memory.cut.local.num_gpu`，**默认 0**（全 CPU/内存）；设 `-1` 交回 ollama 自己分（等于回 GPU）
- `db` 为 null 时（`fact_distill.js` 那几个调用）走默认 0，不会意外占显存

代码一行没动别的；重载插件后生效，改 flag 可即时切换（不用再改代码）。

## 怎么验
重启后跑一次切事，看 `nvidia-smi` 全程不动、`ollama ps` 里 `PROCESSOR` 显示 CPU、processed 在 80s/块上下。

## 怎么退
`UPDATE flags SET value='-1' WHERE key='memory.cut.local.num_gpu';`（回 GPU 分摊）
或把 `local_llm.js` 里那段 `numGpu` 删掉、`num_gpu` 那行去掉。
