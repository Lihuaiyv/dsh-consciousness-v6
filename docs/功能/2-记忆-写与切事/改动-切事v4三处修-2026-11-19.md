# 改动 · 切事 v4 三处修（指标口径 / 判缝上下文 / 输出排序）2026-11-19

> 起因：11-18 旧数据 103 件里 84 件单段（82%）、十几件「改代码并跑脚本·DONE」1 句货。
> 核对后不是判缝刀口坏，是三处外围：验收指标选错、判缝看得太少、件输出乱序。
> 主人 2026-11-19：「登记，然后修」。问题登记：D86 / D87 / D88。

## 动了哪

1. **D86 指标口径**（`src/modules/event_cut_v4.js` 返回的 `stats`）
   - 新增 `tiny`（成员 ≤3 句的件数）、`oneSeg`（单段件数）；`events` 仍保留。
   - 不改判缝逻辑。单段比例从此只作参考，不再当「碎件」判据——单段里 6~22 句是正常一件事。
   - 门禁锁：`check-event-cut-v2.mjs` 新增「stats 带 tiny / oneSeg」「假模型全 next：没有 ≤3 句的碎件」。

2. **D87 判缝上下文加宽**（`cutDayV4` 的判缝 prompt）
   - 前段取末尾、后段取开头，句数从 2 → 4（`wideCtx`，默认 `true`）；关掉回退 2 句。
   - 缓存键加 `wideCtx` 位，换开关必须换缓存文件（沿用坑 5 的教训）。
   - worker 开关 `events.cut.v2.wide_ctx`（默认 on），`src/host/workers.js` 读它传给 `cutDayV4`。
   - 门禁锁：wide 开时 prompt 含「最近4句原话」、关时含「最近2句原话」。

3. **D88 件输出按会话分组**（`cutDayV4` 返回前）
   - 每件带 `sessionId`（不写库，只给排序/验收用）；
   - 排序：会话分组、组内按时间、组间按各组首件时间；`_at`/`_sess` 临时字段在输出前剥掉。
   - 门禁锁：测试数据加第二个会话（s2 薄荷段，时间交错在 s1 里），断言「两个会话都出件」「同一会话的件不被打断」。

## 为什么这样修

- 判缝刀口（粗切 + 〇条）本身没看到明显切错：新判据 11-18 39 件内部连贯，1 句件只剩 1 个。
- 加宽上下文只动输入，不改 「same/next/new」标签集，回退成本低。
- 排序是纯显示顺序，写库 id 与成员都不变，读口按 `start_at` 查也不受影响。
