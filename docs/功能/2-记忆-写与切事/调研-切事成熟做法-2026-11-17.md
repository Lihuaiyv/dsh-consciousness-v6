# 调研 · 「把一整天的话切成事件」有没有成熟做法 · 2026-11-17

> 触发：D79（切事颗粒混）。主人说「别自己瞎做，先上网查查」。
> 只读调研，不改代码、不碰真库。

## 0 一句话结论

学界把这件事叫 **event segmentation（事件分割）**，既不叫「切」也不叫「合并」——成熟做法是**两段式**：
先用便宜的信号找**候选边界**，再让模型在候选上判「这里换没换事」，最后把边界之间归并成一件。

- 只合并不找边界 → 退化成摘要（我们工作段现在的毛病：整块压成一条 digest）。
- 只切不归并 → 切碎（我们日常段的毛病：8000 字一刀，一件事劈两半）。
- 最接近我们需求的是 2026-01 的 **ES-Mem**（事件分割 + 三层记忆 + 边界当检索锚），可以直接抄结构。

## 1 先把问题说准

我们要的是「一天 1000+ 条碎句 → 若干件事，每件以后能被想头带出来」。文献里对应的三个子问题：

1. **单位**：一条记忆存多大？（turn / session / event）
2. **边界**：在哪里断开？（语义一致性 vs 意图转向）
3. **锚**：断开了以后，读的时候怎么找回整段？

我们一直在纠结 1 和 2，**3 从来没做过**——而文献里 3 才是检索能用的关键。

## 2 三条路线（按成熟度排）

### A 不分割：每条观察单独存，靠打分检索

Generative Agents [S1]：把「观察到的一切」按自然语言原样存进 memory stream，每条带重要性分，
检索时按 recency / importance / relevance 加权；再定期把零散观察合成更高层的 reflection。
消融实验里 observation / planning / reflection 三块各自都关键。

- 优点：永不切错。
- 缺点：一天几千条，成本全压在读口的打分和注入预算上。我们要的是「一件能单独被带出来」，不是「几千条里捞」。
- 结论：**当兜底方向可以，当主路太重。**

### B 监督式分割（研究界主战场）

SuperDialSeg [S2]：9,478 条对话、18 个模型五个类别做基准，监督学习在域内很有效。
但论文自己承认：**「分割点的精确定义」本身仍是难题**——所以他们是拿「有文档支撑的对话」来反推边界定义的。

- 这条线告诉我们：**边界定义不能靠自由发挥，得有一个可操作的判据集**。
- 但我们没有标注数据，也不是英文学术对话，抄不到模型。

### C 两段式：候选边界 + LLM 判定 + 边界锚（推荐）

**ES-Mem** [S3]（2026-01，重庆大学等）是目前最贴的一篇，动机和我们一模一样：

> 现有方法两条毛病：(1) 记忆颗粒固定，切断语义完整性，碎；(2) 扁平检索只比相似度，没有话语结构。

它的做法：

- **Stage 1 Topic Coherence Detection**：让 LLM 给每轮抽一个简短话题表示（带上上一轮的输出，防漂移），
  嵌入成向量；用相邻向量的互信息 `I_t = -½·log(1-ρ_t²)` 当语义耦合度，
  **耦合度掉到全局下分位（如 35%）以下的位置 = 候选边界**。便宜、只看统计。
- **Stage 2 Intent-Aware Boundary Refinement**：只对候选边界，取前后 L 轮做窗口，让 LLM 在**固定标签集**里选：
  边界正类（Topic_Shift / Topic_Intro）vs 边界负类（Detail_Elaborate / Direct_Resp），给置信度；
  两个方向平均后过阈值 τ，才是真边界。
- **三层记忆**：① 精炼边界（一句话写「A 结束了，转到 B，上下文是…」，**当检索锚**）② 事件摘要 ③ 原文。
- **粗到细检索**：query 先跟「边界描述」比 → 命中锚点后向两侧扩窗 → 窗口内用摘要精排 → 取原文。
- 评测：LoCoMo、LongMemEval-S；分割模块另在 DialSeg711 / TIAGE / SuperDialSeg 上验；骨干是 Qwen2.5-3B、Llama3.2-3B、GPT-4o-mini（**小模型跑得动，这条对我们很重要**）。

同一批思路里还有（均为 ES-Mem 综述提及 [S3]，二手引用，我没逐篇读原文）：

- **Nemori**：LLM 检测器 + 边界/表示对齐，直接切连续对话流。
- **EM-LLM**：先用 Bayesian surprise 定初始边界，再用图论指标精修。
- **RMM**：前向反思，按语义主题动态拆分与整合历史。
- **SeCom**：结构化提示直接生成「话题连贯的块」。

### D 干脆不切：抽事实 / 时间图

- **Mem0** [S4]：从对话里抽显著信息，做增删改合并；LOCOMO 上 LLM-as-judge 比 OpenAI 记忆高 26%，
  p95 延迟降 91%、token 省 90%+。**它存的是事实，不是事**。
- **Zep** [S5]：Graphiti 时间知识图，边带时间有效性；DMR 94.8% vs MemGPT 93.4%，LongMemEval 最高 +18.5%、延迟 -90%。
  **我们的 `event_edges` 只追加 + `valid_to` 封口，跟它是同一个套路**——这块我们已经在路上了，不用改。

## 3 可以直接抄的四件事

1. **边界要写成一句话，并且当检索锚**。
   ES-Mem 的 Level 1 是「Topic A ended. Transitioned to Topic B. Context: …」。
   我们现在的 `title` 只写「这件事是什么」，没写「它从哪来、转到哪去」——所以 `continue` 边判出来也说不清顺着哪条线。
   这是我们最该抄的一条，**而且跟大因果体判边的需求直接对上**：边界描述本身就是主干上的一段。
2. **边界判定用标签集，不许自由发挥**。
   `Topic_Shift / Topic_Intro / Detail_Elaborate / Direct_Resp` 四类，模型只许选一个 + 给置信度。
   比「换了目的/换了话题/告一段落」这种散文判据稳定得多，也可统计。
3. **两段式，别一次读 8000 字让它自由切**。
   第一段廉价（时间间隔、换人、字数、换 mode），第二段只对候选点花模型调用。
   **调用次数反而可能比现在少**：现在是每块一次全量切，候选点通常比块数少。
4. **三层：边界 / 摘要 / 原文**。我们现在只有摘要 + 原文。

## 3.5 embedding 通道（2026-11-17 实测，事件库的前置）

卡片：宿主模型只有聊天能力（`src/model.js:428` 原话「宿主 llm 有 complete、没有 embed」），本机 Ollama 原先一个 embedding 模型都没有；`memory_vec` 698 条、最后写入 **11-01 12:17Z**，覆盖 7928 个在用记忆的 8.8%——事实库那条向量是停的，不是通的。

已拉：**`qwen3-embedding:0.6b`**（639 MB，**1024 维**）。冒烟 `scratch/ro/embed-test.mjs`（真句子）：

- 冷启 14.2 s（载模型进内存），**热 61 ms / 4 条**
- cos(排查显存, 14B 吃掉显存) = **0.6617**；跨话题 0.4437 / 0.4512
- 查询「显存不够，模型占太多」→ 显存那件 **0.772**，同组的 **0.694**，切事 0.444，feel 0.432 ✅

接法：`model.js` 的 `embed()` 走 OpenAI 格式 `${url}/embeddings`；Ollama 自带 OpenAI 兼容口 `http://127.0.0.1:11434/v1`，所以只要一条 embedOnly 适配器（baseURL + `embedModel=qwen3-embedding:0.6b`），不用另写协议。

`bge-m3`（1.2 GB，1024 维）同时在拉，落地后跑同一个脚本对比，两个选一个，别都留着。

## 4 抄不了、别抄的

- **评测口径**：他们考的是「读完历史能不能答对 QA」。我们要的是「这件事以后会不会被想起来」。
  照抄 LoCoMo 分数没有意义，验收得自己写（见 §5）。
- **嵌入**：ES-Mem 的 Stage 1 依赖 embedding，我们向量线已经停了（`memory_vec` 不写、`vector_index` 归档）。
  要么改用「换人 / 时间 / 字数 / 换 mode」的廉价候选点，要么单独给切事开一条小嵌入通道——**二选一，别顺手把向量线翻回来**。
- **工作段只做摘要**：没有任何一篇这么做。这是我们自己发明的省调用办法，也是混合体的主因。

## 5 落到我们代码上的最小改动（先写验收，别现在就动）

| 位置 | 现在 | 改法 |

**验收（动代码之前先定死）**：

- 同一件事不重复：现在 12 对里 6 对重复，目标 ≤2/12。
- 一格里不装两件：人工标 30 件，混的比例现在估计 >30%，目标 <10%。
- 边界那句能单独看懂：抽 10 条 boundary，不看原文能不能说清「从什么转到什么」。
- 调用量不涨：切事一天的模型调用次数记下来，改完不许超过现在的 1.2 倍。
- 门禁 `node test/run-tests.mjs` 全绿、`check-event-causal` 43/43 不掉。
