## 一、流水线定成三段

```
粗切（纯算法，宁多切） → 每段写记叙（模型） → 判缝（模型） → 合并 → 出件
```

- **粗切不打模型**：会话内向量滑窗取深谷，窗口 `w≈len/40`（2–6），只收 `i>4 && i<len-4` 的谷，相邻切点至少隔 4 句。有数据：583 条碎片 → 50 段。
- **为什么宁多切**：多切了后面的判缝能合回来；少切了就是把两件事焊死，再也分不开。这是单向门。
- **每段写记叙**：线索、起因、经过、结果、地点、人物、归属，一次调用出全。
- **判缝**：只把前段的〔线索＋起因＋结果〕和后段的〔线索＋起因〕给模型，答 `same / next / new`。
- 实测：50 段 → 37 件，91 次模型调用，约两分半；对照上一版（一步到位切）是 33 件。

## 二、判缝的判据（这一夜最重要的修正）

判缝不问「话题像不像」，问两件事：

1. **前段结果有没有落地**。没落地（“继续讨论提示词”“等主人确认”）就不是断，后段自然是 next。
2. **后段是不是接着它**。换的是**要解决的那个问题**才算 new；只是提到同一个东西（都提到“模型”、都提到“提示词”）不算。

被这一条纠正过的例子：`整理提示词关系` 那处，我一开始判“合错了”，主人指出前段结果是“别硬加，继续讨论提示词”，根本没结束——该合。我错在把“换了说法”当成“换了事”。

抽检 13 处合并，按这条标准全部成立。

## 三、具名：名词进线索，不进标题

- 标题作为**检索抓手**有用，但独木难支：它短、会丢细节。
- **线索**里带 1–3 个主要名词，且必须能核对：
  - 只许抄原文里出现过的词，不许造；
  - 每个名词在**这一段原文里至少出现 2 次**，代码去原文 grep，核不到就丢。
  - 反复出现的才是“主要”，出现一次的多半是路过的。
- 线索的形式改成：`名词、名词——这件事的下场`，例如「情绪链提示词、调用点——整理成一张表」。
- 标题不塞名词，只把线索讲成人话：带一个具体对象、带一个结果。反面样本：「整理提示词关系」（平齿，什么锁都对一点，打不开）。
- 检索分两层：标题＝第一层抓手（专名＋结果），另挂一栏关键词＝第二层。只留一层迟早滑回抽象话。

## 四、命运（成／卡／破／变）

- 不要让模型直接判，它会全判“成”（实测 33/33、28/33 都出现过）。
- 改由**规则推**，判据只取一个来源：它自己写的「结果」那句。
  - 结果里写“放弃／作废／不做了” → 破
  - 结果里写“完成／定了／通过／跑通／成了”且不含“没、待、回头” → 成
  - 还写着等什么（waiting 非空） → 卡
  - 都不沾 → 变
- 已试过“做完但没验 → 卡”的变体，结果是变被当成垃圾桶（23 件落进去）；词表法整体不稳，**暂时不写库**，等有人标的金标再学。
- 生活场景的措辞：不用「验收」，用「着落」——跑通了、吃完了、说定了、没着落。工作和日子同一套说法。

## 五、生活与工作同写

- 提示词里明写：过日子和干活一样写，吃饭、散步、拌嘴、改代码都用同一套写法，别把日子写成任务汇报。
- 另加一栏 `归属`：生活 / 工作 / 两边都有，为的是统计能分开看。
- 一整天全是工作件时，这一栏会全落“工作”或“两边都有”，属于素材问题，不是标签问题。

## 六、两法对比（否掉了“标题法更准”的猜想）

同一批 22 个断点，两路都是模型判，不掺余弦：

- A 路（标题法）：左右各起一个标题，模型自判是不是同一件；
- B 路（ES-Mem 意图标签）：Topic_Shift / Topic_Intro / Detail_Elaborate / Direct_Resp。

结果：一致 8、分歧 14。分歧几乎都是“A 说断、B 说并”——B 的四类里三类算延续，这段语料大半是接着说，所以 B 只认 4/22 个断点，等于几乎不切。

结论：两法不是谁更准，是粒度取向不同；A 偏细，B 偏粗。要细就用标题法，要粗用标签法。

## 七、数据层的问题（要单独修）

碎片表里存在**同一条消息被切成两条**的情况：`@23` 那处前后两段都是同一条长消息（“事实和事件并列当主……”），切事时凭空造出一个边界。

这会污染任何边界判断，得在碎片写入侧查（不在切事侧）。
