## 1 输入：碎片表

`fragments`（`src/db.js:265`）一行 = 一段原话。切事件只用到下面这几列：

| 列 | 切事件怎么用 |
|---|---|
| `text` | 唯一的语义来源。切事件只读这一列 |
| `role` | `user` = 主人，`assistant` = 我。用来判「换人说话」 |
| `created_at` | UTC ISO。**日界按本地 +08:00 读**，不按 `day` 列（那是 UTC 日期，差 8 小时） |
| `turn_id` | 一轮的身份证；事件的 `turn_ids` 只能从这里取。同一 `turn_id` 可能有两行（主人一句、我一句） |
| `id` | `turn_id` 缺失时的兜底标识 |
| `session_id` | 只用来查时间线，不参与切 |
| `tool` / `meta` / `form` / `snapshot` / `antecedents` | 不进判断 |

**读法**：取本地日 `[00:00, 24:00)` 内的 `user`/`assistant` 行，按 `created_at` 升序排成一条流。

**什么不算「人的话」**：正文为空、`You are the Team Lead named` 开头的委派指令、工具回显（``` 、`{|[`、`## `、`Repeated tool call detected`）、`[SCHEDULE` 开头的定时消息。这些先剔掉，它们不是任何一件「事」。

**去重**：同一天里「同 `role` + 同正文」只留第一条。重复的话不产生新信息。

## 2 参考：论文做了什么

ES-Mem（arXiv:2601.07582，2026-01）的出发点和我们要解决的是同一个：颗粒固定会切断语义，扁平检索只看相似度、没有话语结构。它给的三样东西如下。

### 2.1 事件的定义

> 一段以「稳定的主题或意图」为中心的时间段，内部语义高度同质，边界由**话题切换、任务阶段变化、互动形态变化**标记。

判据是三条，不是一条：话题、任务阶段、互动形态。这一条比「换了目的」好判——它给了三个可分开看的维度。

### 2.2 Stage 1：话题耦合度 → 候选边界

1. 对每一轮 `uₜ` 抽一个**简短话题表示**。抽取时把上一轮的输出也拼进去，防止语义漂移。
2. 把这些话题表示嵌入成归一化向量 `hₜ`。
3. 假设相邻两个向量 `hₜ`、`hₜ₊₁` 的各维服从联合高斯，算它们的 Pearson 相关 `ρₜ`。
4. 耦合度用互信息：`Iₜ = -½·log(1 - ρₜ²)`。
5. 取 `Iₜ` 落在全局**低分位**（论文用 35%）的位置当**候选边界**。

要点：这一步只花统计，不花模型；候选是「可能有边界」，不是「边界」。

### 2.3 Stage 2：意图边界精炼

只对候选点做，而且只看**局部**：

1. 对每个候选点 `t`，取前后各 `L` 轮做窗口（`ℒₜ`、`ℛₜ`）。
2. 让模型判断「从 `ℒₜ` 到 `ℛₜ` 这次过渡」属于哪一类。标签是**固定集合**：
   - 边界正类：`Topic_Shift`（换话题）、`Topic_Intro`（引入新话题）
   - 边界负类：`Detail_Elaborate`（补充细节）、`Direct_Resp`（直接回应）
3. 模型同时给置信度 `cₜ`。正类取 `cₜ`，负类取 `1 - cₜ`，得到 `p(yₜ)`。
4. 取置信最高与最低两次判断平均：`p_eb(t) = ½·(p(y_high) + p(y_low))`。
5. `p_eb(t) ≥ τ` 才是真边界。

要点：**标签集固定**是这一步的全部价值。自由发挥的模型每次给的标准都不同；固定标签把判断变成可重复的分类。

### 2.4 三层记忆

- **Level 1 精炼边界**：用 LLM 把「从上一件到这一件」写成一句状态转移描述，形如「Topic A ended. Transitioned to Topic B. Context: …」。**这一层是检索锚**。
- **Level 2 事件摘要**：这件里各轮的核心内容与关键词，做细粒度匹配。
- **Level 3 原文**：逐字对话，保证事实准确。

### 2.5 检索

由粗到细：query 先跟 Level 1 边界描述比 → 命中锚点后向两侧扩窗 → 窗口内用 Level 2 摘要精排 → 取 Level 3 原文。

### 2.6 论文没做的、留给我们的

- 它按「一轮/一次会话」连续处理，没有「一天里有 4 小时没人说话」这种自然断裂。
- 它只有一种对话形态，没有「工作」和「日常」两种口径。
- 它没有「这件事以后能不能被想起来」这个目标，它考的是读历史能不能答对 QA。

## 3.3 归属与回链：两条硬保证怎么做到

要的是两句：**每个碎片都属于某件**、**每件都能回链到自己的碎片**。

办法不是让模型挑成员，而是**成员由代码算**：

1. 段是连续区间。切只产出边界位置（`[i, j)` 这种下标），**不产出成员名单**。
2. 段内的行 = 从边界处依次取，代码自己填。这样天然全覆盖、无重叠——模型只回答「这里是不是换事」，不回答「这句归谁」。
3. 权威索引单独一张表，不塞 JSON：

```sql
CREATE TABLE IF NOT EXISTS event_members(
  event_id TEXT NOT NULL, fragment_id TEXT NOT NULL,
  agent_id TEXT NOT NULL, day TEXT NOT NULL,
  PRIMARY KEY (event_id, fragment_id));
CREATE INDEX IF NOT EXISTS idx_evm_frag ON event_members(fragment_id);
CREATE INDEX IF NOT EXISTS idx_evm_ev ON event_members(event_id);
```

`events_v2.turn_ids` 只是副本，方便查；对账以 `event_members` 为准。

**能保证到什么程度**（写清楚，别含糊）：

| 说法 | 能不能保证 | 前提 |
|---|---|---|
| 参与切事的碎片，100% 落在某一件里 | 能 | 段是连续区间切的，代码填成员 |
| 每件都能按 `event_members` 回链到具体碎片 | 能 | 同一事务里写事件和成员 |
| 每一行 `fragments` 都有归属 | **不能** | 机器话、去重掉的重复句、那天没切完的行，本来就不该硬塞 |
| 同一碎片只属于一件 | 能 | 同一版（同一个 `cut_rev`）成立；补切会出新版，旧版仍挂着旧行，用版本区分 |

**三条例外怎么处理**（不装作有归属）：
- 机器话（工具回显 / 委派指令 / 定时消息）：不进切事，也不标归属。
- 去重掉的重复句：同一句已在别处有归属，不重复进 `event_members`。
- 没切完的天 / 模型空回：那天就是有碎片没事件——不许补假事件，覆盖率脚本会把这个洞报出来。

**校验**（写进 `scratch/` 的验收脚本，动手前先写好）：
```
1. 某一天：SUM(每件成员数) == 参与行数（无重复、无遗漏）
2. 每一行参与碎片都能 JOIN 到且只 JOIN 到一条 event_members
3. 每一件在 event_members 里非空
4. 反向：随机抽 5 件，turn_ids 里的每一轮都能在成员表里找到
```

## 3.4 一件事怎么记：线索 · 边界 · 命运

**一件 = 一条线索，落在一个边界上，落到四种命运之一。** 缺一样都记不完整：没有线索，不知道在说什么；没有边界，看不出变化；没有命运，它只是个话题。

| 列 | 是什么 | 例子 |
|---|---|---|
| `thread`（线索） | 这段里一直没变的那个东西：一个目标、一个主题、一个待办。≤14 字，具体 | 把切事件改成按会话切 |
| `kind`（命运） | 变 / 成 / 卡 / 破，按下面的顺序判 | 变 |
| `edge`（边界） | 它为什么和前后分开：`time`（时间断）或 `causal`（因果断） | causal |
| `edge_why` | 为什么断，一句话；`time` 时留空 | 发现会话其实是并行的 |

**判定顺序（模型不许自由选，判到就停）**：

1. 有目标、但没闭合 → **卡**
2. 闭合了、结果和预期不一样 → **破**
3. 闭合了、结果对得上 → **成**
4. 没有明确目标，只是某样东西换了样子 → **变**

这么定的用意：挡住模型一贯的「什么都想判成」——先卡住未闭合的，再处理落差，最后才轮到普通的「变了」。

**四类的出处**（写明，免得以后拿它当铁律）：

- **变**：事件本体论那一路，事件是「状态发生了改变的个体」，靠因果分辨（Davidson）。
- **成 / 卡**：事件分割理论以「目标」当骨架，目标达成即闭合；没达成会悬着——悬着的反而记得更牢，这是蔡格尼克效应（1927，凭记忆引，未核原文）。
- **破**：同一理论里的预测误差，预期被打破处最容易成为边界。
- 曾想过第五类「圆」，没有依据，撤掉了。

**边界只有两型**：时间断（没人说话、换会话、收工）和因果断（因为 A 推出 B，或「以为 A 结果 B」）。时间边界能切出段，但只有因果边界能读出「破」；「卡」几乎总是被时间切断的——事没完，天亮了。

**标题不是另写一句，是这三样拼出来给人读的**：

- 卡：`<线索>，卡在<什么>`
- 破：`原以为<预期>，其实<实际>`
- 成：`<线索>，成了`
- 变：`<线索>，换成了<什么>`

**为什么是这三样**：搜的时候人搜的是 `thread`（「那件事」）；看那天过得好不好看的是 `kind`（几件卡着就是那天的气味）；连边看的是 `edge` + `thread`——**线索是事件之间天然的接缝**，大因果体缺的主轴就是这条线。

**不存什么**：变化前是什么、卡在等什么，都写进 `summary`，不单开列。

## 4 算法（把论文落到我们的数据上）

### 4.0 先分组：会话是并行的，不是一条时间线

**2026-11-17 查出来的，推翻了本文早先那句「一天排成一条流」**：`fragments.session_id` 记的是**并行**的会话，不是先后顺序。11-16 有 9 个会话、583 条，最大的两个分别覆盖 11:12–15:34 和 12:15–15:59，时间交叠；11-15 更明显，962 条散在 17 个会话里。

所以：

- **按会话分组，各组自己切**。窗口绝不跨会话——拿 A 渠道的话去跟 B 渠道的话比，是纯噪声。
- 组内只按 ≥4 小时断开（人睡了一觉）。
- 「工作/日常」先不分：分组之后每组形态已经比较单一，等验收再决定要不要按 mode 再切一刀。
- 跨会话的「同一段时间」留到**读**的时候再并，不在切的时候混。

段内再按「工作 / 日常」分成两段不同的口径（`chat_turns.mode`；老数据没有标签就是日常，不猜）。这一步只是把材料分堆，不决定一件事的边界。

### 4.1 话题表示

论文让模型给每一轮抽话题。我们第一版**直接用正文前 160 字当话题表示**，理由是实测过：1024 维嵌入对中文短句够用（排查显存 vs. 14B 吃显存 = 0.66，跨话题 0.44）。

留一个开关：如果验收时发现候选边界明显偏，再加回「让模型抽一句话题」这一步（每段一次批量调用，不是每轮一次）。

### 4.2 候选边界

对一个段内的向量序列按 §2.2 算 `Iₜ`，取低分位当候选。

**分位不能用论文的 35%**。那是短对话校准的——我们一天 540 条碎片按 35% 出 189 个候选，等于每三条话换一次事。我们的目标是**一天 8~15 件**，按这个反推：候选数取 `件数 × 2.5` 左右，也就是 20~40 个，分位在 **4%~8%**。这是起点，用 §6 的金标调。

### 4.3 精炼

对每个候选点取前后各 `L = 6` 轮窗口，让模型在四个标签里选一个 + 给置信度，按 §2.3 算 `p_eb`，`τ = 0.6` 起。

提示词只做一件事：读 `ℒ` 和 `ℛ`，回答「这次过渡是换事还是没换」，四个标签、一个置信度，不给别的自由度。

### 4.4 成事

真边界之间的区间 = 一件。区间里给模型一次调用，产出 `title`、`summary`、`quotes`、`cues`。

硬约束（这三条是验收的一部分，不是建议）：
- `quotes` 必须是原文子串，对不上的整条丢。
- `turn_ids` 必须是这一段里出现过的。
- `start_at`/`end_at` 用区间首末碎片的真实时间，不信模型写的时间。

### 4.5 边界描述

事件写成之后，**单独一次调用**为每件生成 Level 1 那句：用前一件和后一件的摘要 + 边界附近原文，写「A 结束了，转到 B，因为…」。这就是以后检索的锚，也是大因果体主轴上一段现成的文字。

### 4.6 幂等与断点

- 一天切完写 `flags.events2.cut.<day>.done`；没切完写断点 `pos`（最后一件的末轮）。
- 重跑同一天：同一天已有的件按 `day` 先清空再写（影子表，允许重来）；正式表以后靠 `cut_rev` 追加。
- 一条事件写失败不影响其它件。

## 5 参数怎么定（不许从旧库反推）

| 参数 | 取值 | 怎么定 |
|---|---|---|
| 一天件数 | 8~15 | 由「一天里人真正做了几件事」这个外部标准估，不由历史平均倒推 |
| 候选密度 | 每 30 句 1 个，夹 2~12 | 2026-11-17 扫过 20/30 两档，件数只差 10%，不敏感 |
| 滑窗宽度 | `round(会话条数/30)`，夹 3~8 | 实测：200+ 条的长流用 8 最好（深 0.32~0.44），几十条的短流用 3（0.17~0.21） |
| 单件上限 | 40 句 | 超了在内部递归再切，切点取内部最深的谷；没信号就停 |
| 嵌入模型 | `qwen3-embedding:0.6b` | 1024 维，热调用 61 ms/4 条 |

## 6 验收（动手之前就定死）

**金标**：挑一天的碎片，**在没看过任何旧切点的情况下**人工标 10 件（写清每件从哪句到哪句）。顺序反了就白标。

通过标准：
1. 金标 10 件，机器切出的边界落在人工边界 ±2 轮内的 ≥ 7 件。
2. 同一件事不被切成两件：抽查 12 对，重复 ≤ 2 对。
3. 一件里不装两件：抽查 30 件，混装 < 10%。
4. `boundary` 那一句单独看能说清「从什么转到什么」，抽 10 条人工判，≥ 8 条通过。
5. 一天切完的模型调用次数记下来，作为以后不许膨胀的基线。

## 7 开关与红线

- 开关：`flags.events2.write`（默认 off）。开着也只写 `events_v2`，不碰 `cold_events`。
- 只加不改：`events_v2` 只追加；重切用 `cut_rev` 标新的，不 UPDATE 旧的。
- 不删：`fragments` 只读，一个字节都不写。
- 不动：`cold_events` / `hot_events` / `event_edges` 在影子期一律不碰。

## 8 与论文的差异（照抄之外多做的部分）

| 差异 | 为什么 |
|---|---|
| 先按 4 小时 / 会话断成段 | 论文假设对话连续，我们的一天不是 |
| 段内再按工作/日常分口径 | 我们的数据两种说话方式混着，一套判据判不了 |
| 话题表示先用正文原文，不调模型 | 先省调用；嵌入实测够用，不行再加 |
| 分位从 35% 降到 4%~8% | 35% 是按短对话校准的，套到一天 540 条上过密 |
| 多一层「一天切完写 done + 断点续」 | 论文是离线批处理，我们是夜里跑、会被打断 |
