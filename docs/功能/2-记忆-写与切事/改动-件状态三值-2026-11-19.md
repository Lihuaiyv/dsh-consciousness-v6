# 改动 · 件带「了结状态」（2026-11-19）

> 问题：D93。`events_v2.status` 一直空着——读口答不了「那件事后来完了吗」，因果线也没法接在「还没完的事」上。
> 早先想判「阶段性结束 vs 完全结束」，但那个二分站不住：世上没有真正的完全结束，事情做完还有余波。
> 主人 2026-11-19 定：**只判还要不要管。**

## 三值

- **挂着**：等回话、等重启、等验收、还悬着。这就是开放环——同一件事的两种叫法。
- **收起**：没人再管、也没有新件接上。沉底不删，哪天线再被提起还能翻出来。
- **空**：拿不准就不写，别硬判。

## 动了哪

`src/modules/event_cut_v4.js`

- 新增 `statusOf(text)`：从整件收尾的「结果」（`tail.result | head.result`）读。
  挂起词优先（`还等 / 待验 / 等重启 / 还没 / 没跑通 / 没生效 / 没加载 / 悬着 / 明天再 / 后续再 / 先这样 / 暂不 / 要继续`）→ 挂着；
  完成词（`完成 / 完了 / 做完 / 修好 / 绿了 / 通过 / 归档 / 定了 / 收工 / 已修 / 已验 / 跑通 / 落地 / 搞定 / 换好 / 落了 / 上线`）→ 收起；都没有 → 空。
- 出件时带上 `status`；`writeEventsV2` 本来就会写 `status` 列（`e.status ?? null`），不用改库。

`scripts/check-event-cut-v2.mjs`：假模型两件的「结果」一个写成「盆换好了，还等旧土回填」（挂着）、一个写成「标注跑完了，可用」（收起）；
新增断言「件带状态：挂着和收起都能判出来」。

## 为什么挂起词优先

写着「修好了，但还等重启验证」的件，前面有完成词，但事情还没到头——先认「还等」，判挂着。不然会把还在等的事收掉。
