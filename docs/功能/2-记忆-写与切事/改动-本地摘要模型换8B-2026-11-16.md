# 改动：本机摘要模型 14B → 8B（2026-11-16）

> **已否决。** 8B 在切事上会写偏重点，最终方案是「14B 保留、改走 CPU」，见
> `改动-切事模型走CPU-2026-11-16.md`。本文只留当时的换模型过程和第一次的性能数字。

## 动了哪
真库 `runtime/consciousness/app.db` 的 flags 表，一条：

```
memory.cut.local.model = qwen3:8b
```

`memory.cut.work.local`、`memory.cut.daily.local_fallback` 都保持 `1` 不动。

代码一行没改。`src/modules/local_llm.js` 里 `num_ctx` 仍是 16384（注释记录了 8192 装不下 8000 字工作块的实测）。

## 为什么
2026-11-15 深夜查「发送对话卡住」：不是模型排队，也不是内存，是**显存**。

- `qwen3:14b`（14.8B，Q4_K_M）单独占显存 **11.7GB**，16GB 的 RTX 5080 只剩 1.4GB 给桌面。
- Electron 渲染层分不到显存，合成退回软件，渲染进程 CPU 从 ~0 飙到 20%+，界面一按发送就转圈。
- `ollama ps` 里保留 keep_alive 5 分钟，每轮对话（`presence.last_sentence` 那条「上一句摘要」）都调它，所以基本常驻。
- 手动 `ollama stop` 后它又自己回来，证明不是赖着不走，是每轮都在叫。

## 怎么验（2026-11-16 00:12 实测）
同一段六轮工作对话，走和 `localComplete` 一样的参数（`format:json`、`think:false`、`num_ctx:16384`、`temperature:0.1`）：

| 项 | qwen3:14b（改前） | qwen3:8b（改后） |
| --- | --- | --- |
| 显存占用 | 11.7 GB | **7.5 GB** |
| 空余显存 | ~1.4 GB | **~5.3 GB** |
| 冷启动首答 | — | 15.3s（含加载） |
| 热态 | 2.6~3.3s（11-15 记录） | **0.9s** |
| 输出质量 | — | digest 准确，4 个抓手，合法 JSON |

`nvidia-smi` 实测：模型加载后 used 10600 MiB / free 5378 MiB。

## 怎么退
```
UPDATE flags SET value='qwen3:14b' WHERE key='memory.cut.local.model';
```
或直接删掉这一行回到代码默认（`DEF_MODEL = 'qwen3:14b'`）。

本改动前的库备份：`scratch/backup/app-20261116-0013.db`（217.5 MB）。

## 还没做
- 没有把 `num_ctx` 从 16384 降下来。降 8192 还能再省约 1.5GB，但 `local_llm.js` 注释说 8192 装不下 8000 字工作块会截断不吐 JSON，要动得先按工作块实际长度量一遍。
- `qwen3:14b` / `qwen2.5:14b-instruct` 两个旧模型还留在盘上（共 18.3GB），没删。
