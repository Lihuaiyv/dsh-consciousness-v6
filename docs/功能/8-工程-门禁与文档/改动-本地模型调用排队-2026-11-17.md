# 改动 · 本地模型调用排队（2026-11-17）

> 主人原话：「现在本地模型的调用经常给我卡住。我想看看现在所有的调用。给他们整理一下做好排队。」
> 结论：所有本地调用收进一条队列（单并发 + 优先级插队 + 排队超时提前失败），并加一个只读工具能看队列。

## 二、为什么

改之前：所有本地调用各自直连 Ollama，**没有并发上限**。
Ollama 一次只真正服务一个生成，多出来的请求都在 Ollama 里面排队；
调用方自己的 120s / 180s / 240s 超时从「发出」就开始算，所以后到的请求
常常在 Ollama 队列里干等到超时——表现出来就是「卡住」。

队列改完后：

- 同一时刻默认只跑 1 个本地调用（`memory.cut.local.concurrency` 可改 1~4）。
- 按优先级插队：聊天（1）> 切事摘要（3）> daily 兜底（4）> 判边/蒸馏（7）。
- 排队等待算进调用方自己的 `timeoutMs`：等超了提前失败，调用方走主模型/词法兜底，
  不占着队列空转。
- 每条调用有名字（`split:work` / `causal:main` / `affect:frame` …），出问题能对上是哪条。

这次只加队列，没动显存策略。

验收基线（2026-11-17）：

- 单并发：三任务同时入队，`maxNow=1`，顺序 `a,b,c`。
- 优先级：先排 batch(7)、后入 chat(1)，跑出 `high,low`。
- 排队超时：预算 1000ms 的第二个请求在 ~1s 被拒、**没执行**，计数回 0。
- 门禁：见 `test/run-tests.mjs` 输出的总数（原来 566，本条 +1）。

## 五、怎么退

1. 只想恢复旧行为（不做队列）：把 `localComplete` 的函数体改回
   `localCompleteInner(db, req)`（队列代码留着不用），或把 `queueConcurrency` 的默认值从 1 改回 Infinity。
2. 只想去掉优先级：删掉各调用点的 `priority` / `label` 字段即可（不改也能跑，默认 5）。
3. 只想放宽：`memory.cut.local.concurrency` 设 2~4（默认 1）。
4. 代码回退：
   - `src/modules/local_llm.js` 是 git 跟踪文件，`git checkout -- src/modules/local_llm.js` 即可；
   - `src/modules/affect_v4_shadow.js`、`src/modules/event_causal.js` 在本仓库里是**未跟踪新文件**，
     不要整体 checkout/删除，只删本文档第二节列出的那几行（priority/label）；
   - `index.js`、`src/modules/actions/index.js`、`src/modules/event_split.js`、`test/run-tests.mjs`
     也是跟踪文件，按行回退（或 `git diff` 对照删掉新增段）。
5. 不影响：数据库、flags 结构都没动；`localBusy()` 语义仍是「本地正忙」，
   切事让路逻辑不变。
