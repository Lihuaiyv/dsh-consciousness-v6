# 改动 · 本地模型唯一通道与排队（2026-11-22）

> 主人原话：「调用模型总是卡住。再做一下优先级整理和排队。实验使用的小模型也要做排队。
> 不允许一次启动两个小模型进程。防止卡住。给一个实验用的调用接口，以后实验只能用那个接口排队不能开新的进程。
> 默认只有一个不能修改参数的唯一模型使用通道。默认 2.5 的 14B 和语义的常驻，各自只有一个稳定通道，一次只能进一个任务。」
>
> 结论：Ollama 现在**只有一个口子**。聊天、切事、向量、判官实验全部从这一条通道进；
> **14B 和语义模型各一个槽、各自一次只跑一个**（不同模型不互相等，向量永不被 14B 堵）；
> 参数（模型 / ctx / gpu / keep_alive / url）写死，flag 和 `req.model` 改不动它；
> 实验只能 POST `/local/exp`，换模型由通道负责「先卸、再加载、跑完卸、把 14B 热回来」。

## 二、为什么（现场证据，不是感觉）

1. **14B 被挤下来过**：11-22 11:38 有一个新的 `llama-server` 进程起来（14B 那份），
   而 ollama 本体是 10:39 起的——说明中间有东西把常驻 14B 卸了又载。
   `model.json` 里判官配的是 `gemma4:12b`，本机 `ollama list` 里**没有这个模型**；
   `MAX_LOADED_MODELS=2` 下，任何不在常驻名单里的模型一调用就会挤掉一份。
2. **向量是绕过去的**：`model.json` 的 embedding 指向 `127.0.0.1:11434/v1`，
   走的是 `OpenAIAdapter` 直连，没排进队列。14B 一生成，它就在 ollama 后面干等，
   上层只等 800ms 就放弃 → 向量通道静默全关。
3. **预热和拉起也是绕过去的**：`warmLocalModels` / `ensureLocalServer` 直接 fetch / spawn，
   启动时可以跟真实调用同时撞上去；失败重连还会再 spawn 一个 `ollama serve`。
4. **老队列的并发能用 flag 改**（`memory.cut.local.concurrency`），且没有「任务里再调通道」的保护：
   一个占着唯一槽的任务如果内部再 `localComplete`，就是**一个槽等自己**——永久卡死。
   这跟日志里「在排越堆越多、聊天没反应」的症状一致。
5. **实验脚本直连**：`exp-llm-judge.mjs`、两个 `judge-frame-continuity` 都自己连 11434，
   队列挡不住它们。

## 三、现在的规矩

### 写死的参数（不读 flag、不接受 req 覆盖）

| 项 | 值 |
|---|---|
| 地址 | `http://127.0.0.1:11434` |
| 聊天/切事模型 | `qwen2.5:14b-instruct`，常驻（keep_alive=-1） |
| 语义模型 | `qwen3-embedding:0.6b`，常驻（keep_alive=-1） |
| num_ctx / num_gpu | 8000 / 99（整块上显卡） |
| 并发 | **两个槽，各自写死 1**：14B 一个槽（聊天/切事/判边/实验），语义模型一个槽（只跑向量） |
| 实验模型 | 跑完 `keep_alive=0` 立刻卸，再把 14B 热回来 |

要改任何一项：先跟主人申请，改 `local_gateway.js` 的 `GATEWAY`，并在文件头写日期和原因。

### 优先级（数字小的先跑）

**顺序（主人 2026-11-22 定）：对话 > 实验 > 事后整理。**

| 优先级 | 谁 | 说明 |
|---|---|---|
| 1 `chat` | 聊天 / 情绪精修 | 人在等，最高 |
| 2 `embed` | 向量 | 聊天要用的前置，轻快 |
| 3 `exp` | 实验（判官、对照） | 人叫的，排在事后整理前面 |
| 5 `split` | 切事摘要 | 事后整理 |
| 6 `normal` | 普通本地调用 | 事后整理 |
| 7 `batch` | 判边/蒸馏兜底、预热 | 最不急，空闲时再跑 |

注意：优先级只决定「下一个谁先跑」，**不打断正在跑的**。14B 槽里，实验正在跑时对话要等它结束；
所以实验的 `maxTokens` 封了 4096、每个任务都有硬超时，不会让一次实验把聊天堵很久。

向量有自己的槽，**永远不等 14B**。之前一度把两个模型排进同一个槽，那会让向量吃亏：
它上层只等 800ms，前面排着一个 60 秒的切事，它就静默超时、向量检索整条失效。

### 实验怎么调（唯一入口）

**默认就是热的**：不传 `model` 就用常驻的 `qwen2.5:14b-instruct`，不卸、不载、不换，跟聊天同一个模型。
只有你**明确点名**另一个模型时，才走「先卸 14B → 加载它 → 跑完卸掉 → 热回 14B」那条路。
为什么留这条路：独立判官不能跟被判的是同一个模型（`model.json` 的 judge 段就是为此单独配的），
强制全部走 14B 会变成自己给自己判卷。

换模型前会先查 `/api/tags`：模型没装就直接失败（实测 22ms），**不会先卸 14B 再白跑一趟**。

```powershell
# 不换模型（最稳，用常驻 14B）
node scripts/lib/exp-call.mjs --text "只回一个字：在" --max 24

# 换实验小模型（通道会先卸 14B、跑完卸实验模型、再把 14B 热回来）
node scripts/lib/exp-call.mjs --text "只回一个字：在" --model qwen3:14b --max 24

# 看队列
node scripts/lib/exp-call.mjs --status
```

脚本里：

```js
import { expCall } from './lib/exp-call.mjs'
const { text, ms, model, swapped } = await expCall({ system: SYS, text, maxTokens: 60, format: '' })
```

底层就是一个 POST（插件在跑才通）：

```json
{ "token": "user", "method": "POST", "path": "/local/exp",
  "body": { "system": "", "text": "...", "maxTokens": 200, "model": "", "format": "", "label": "bench-x" } }
```

**端口不用手写**：DSH 重启会换 Web 口（50200 → 64932 …）。插件每次处理 API 请求都会把端口写进
`runtime/consciousness/gateway-api.json`，`exp-call.mjs` 读它自己找口子；
要指到别的地址再用 `DSH_CONSCIOUSNESS_API` / `DSH_WEB_PORT` 覆盖。

**不许**再：自己 `fetch('http://127.0.0.1:11434/...')`、自己 `spawn` ollama、在实验脚本里起 python 模型服务。

## 五、怎么退

- 代码：`git revert` 本次提交即可；新代码全部收在 `local_gateway.js` + 三处接线（`local_llm.js` / `model.js` / `api.js`），旧函数名都还在。
- 不想让向量走通道：把 `model.json` 的 `embedding.url` 改成非本机 ollama 的地址，`createModel` 会自动回到 `OpenAIAdapter`。
- 不想让判官走实验通道：把 `judge.url` 改成非本机地址。
- 队列本身没有开关（主人要求「默认只有一个通道」）；要停本地模型，用 `memory.cut.work.local=0` 关调用侧。

## 六、还没做 / 留意

- **换模型期间聊天会慢一次**：卸 14B → 载实验模型 → 跑 → 卸 → 热 14B，实测 8.7 秒一次。实验尽量走在没人说话的时候。
- `gemma4:12b` 本机没有，`model.json` 里的判官配置现在会走实验通道并以「模型不存在」失败；
  要么拉下来，要么把 judge 改成 `qwen3:14b`（或删掉 judge 段，让判官退到宿主模型）。
- 进程锁只防「本插件进程自己拉第二个 ollama」；别的软件（比如手动开的 ollama）不在锁里，
  体检 `--live` 只能看常驻模型数 ≤ 2。
- 旧的 `memory.cut.local.*` 参数（model / num_ctx / num_gpu / concurrency）现在**不再生效**，
  flag 里还留着值只是历史记录，别照着它改。
