# 设计 · 链与块（2026-11-23，v2 重写）

> **本文件覆盖同日 v1。** v1 的核心（块分三、链=有序步骤+ctx、模型步骤进队列、纯代码不进队列）保留；
> v1 缺的**数据流账**补进来：链上每一步的输入和输出都要落盘，能回看、能单步重放。
> 一句话：**块管「跟谁抢」，链管「按什么顺序」，账管「带着什么走、走到哪一步变成什么样」。**

## 一、v1 为什么不算数

v1 的 `runChain` 是这样：

```js
for (const step of steps) {
  const res = await step.run(ctx)        // 数据写在内存的 ctx 上
  onStep({ id, kind, ms, ok })           // 只记「哪步、多久、成没成」
}
```

三处断：

1. **数据看不见**。`ctx` 出了函数就散；同一句话在哪一步被改写成啥，事后只能翻 flags 和表，再对着代码猜。
2. **不能重放**。想把「事层」单独拿旧输入重跑一遍看是不是判错了——没地方拿那个输入。
3. **情绪链根本没上链**。v1 只把「找核写链」上了链；情绪链（摘要 → 事层 → 判断 → 位置 → 挑词 → 落表）还是三个文件里的 `await` 接力。

## 二、三个概念

### 块（Block）—— 不变

块回答「这个模型调用排在谁前面」。三块（聊天 1 / 实验 2 / 夜间整理 3），块内 FIFO，块间小的插大的。
纯代码/IO 步骤**不进队列**，只带块标签归账。

### 链（Chain）—— 保留，补契约

链 = 一串有序步骤 + 一份上下文（ctx）。步骤按声明顺序执行，后一步能拿到前一步写的 ctx。
链内模型步骤的块号必须**单调不减**（加载时校验，违反直接拒）。

### 账（Run）—— 新增，这次的重点

账 = 一条链的**一次执行记录**：哪条链、哪个会话、哪一轮、从哪开始、到哪停、每一步的 in/out。

- 每一步跑之前，先把 **in** 落盘；跑完把 **out** 落盘。
- in/out 是**可以喂回去重跑**的最小数据，不是给人看的日志。
- 账落表（见 §四），一步一行；整条链一行。
- 账写失败**不许影响链**：账是旁路，链不能因为记账挂了而停。

## 三、数据流契约（每步必须遵守）

```js
{
  id: 'topic',                   // 步骤名，链内唯一
  kind: 'local',                 // code / io / local / host
  block: 'chat',                 // 模型步必填（或继承链）
  label: 'affect:topic',         // 模型步必填：进队列/看板用
  input: (ctx) => ({ ... }),     // 【必填】这一步吃的东西，纯数据、可 JSON 化
  request: (ctx) => ({...}),     // 模型步：由 ctx 拼请求；返回 null = 跳过这步
  run: (ctx, raw) => ({ ... }),  // 【必填】这一步吐的东西，纯数据、可 JSON 化
}
```

四条硬规矩：

1. **in / out 必须是纯数据**（能 JSON.stringify），不许塞函数、db 句柄、Promise。
2. **in 要在调模型之前算完**——这样模型没回来，账上也留下了「这步吃了什么」。
3. **out 只写这一步的产出**，不写「顺手改了全局」。全局副作用（落表、写 flag）留到最后的 `write` 步。
4. **单步 in/out 上限 8KB**，超了截断并标 `truncated: true`。账是给回看用的，不是数据仓库。

## 四、账的表

两张，只追加（跟碎片/事件一致：只追加，不改）。

```sql
-- 一次链执行
CREATE TABLE IF NOT EXISTS chain_runs (
  id          TEXT PRIMARY KEY,   -- run_<ts>_<rand>
  chain_id    TEXT NOT NULL,      -- 'affect.turn'
  agent_id    TEXT,
  conversation_id TEXT,
  turn_id     TEXT,
  key         TEXT,               -- 防重入键（链 id + 会话 + 轮）
  started_at  TEXT NOT NULL,
  ended_at    TEXT,
  ok          INTEGER,            -- 1 / 0 / null(未完成)
  failed_step TEXT,
  ms          INTEGER
);

-- 每一步
CREATE TABLE IF NOT EXISTS chain_steps (
  id        TEXT PRIMARY KEY,     -- step_<run>_<seq>
  run_id    TEXT NOT NULL,
  seq       INTEGER NOT NULL,     -- 0 起
  step_id   TEXT NOT NULL,
  kind      TEXT NOT NULL,        -- code/io/local/host
  block     INTEGER,
  label     TEXT,
  in_json   TEXT,                 -- 【可喂回去重跑】
  out_json  TEXT,                 -- 【可回看这一步变成了什么】
  truncated INTEGER DEFAULT 0,
  ms        INTEGER,
  status    TEXT NOT NULL,        -- ok / skipped / stop / err / no_result
  err       TEXT
);
CREATE INDEX IF NOT EXISTS idx_chain_steps_run ON chain_steps(run_id, seq);
```

## 五、情绪链：第一个上链的（`affect.turn`）

```js
const CHAIN_AFFECT_TURN = {
  id: 'affect.turn',
  block: 'chat',
  onError: 'abort',
  steps: [
    { id: 'read_prev',  kind: 'code',  input: ctx => ({ conversationId: ctx.conversationId }),
      run: ctx => ({ affairs: readAffairs(ctx.db, ctx.conversationId), prev: lastModelRow(...) }) },

    { id: 'topic',      kind: 'local', block: 'chat', label: 'affect:topic',
      input:  ctx => ctx.read_prev,
      request: ctx => topicRequest(ctx.read_prev, ctx.text),
      run:    (ctx, raw) => ({ what, target, ok }) },

    { id: 'judge',      kind: 'host',  block: 'chat', label: 'affect:judge',
      input:  ctx => ({ affairs: ctx.read_prev.affairs, topic: ctx.topic, text: ctx.text, ctx: ctx.frameCtx }),
      request: ctx => judgeRequest(ctx),
      run:    (ctx, raw) => ({ judgment, missing }) },

    { id: 'position',   kind: 'code',
      input:  ctx => ({ prev: ctx.read_prev.prev, judgment: ctx.judge.judgment }),
      run:    ctx => ({ position, dyn }) },

    { id: 'pick',       kind: 'code',
      input:  ctx => ({ position: ctx.position.position, frame: ctx.frame }),
      run:    ctx => ({ label, primary, confidence }) },

    { id: 'write',      kind: 'code',
      input:  ctx => ({ turnId, position, label }),
      run:    ctx => ({ rowsWritten: 2 }) },
  ],
}
```

跟现在的代码一一对应，只是**把隐式的 `await` 变成显式的节，把每节的 in/out 落盘**：

| 链上节 | 现在在哪 |
|---|---|
| read_prev | `appraiseTurnNow` 开头的 `readAffairs` / `lastModelRow` |
| topic | `localComplete`（label `affect:topic`） |
| judge | `hostComplete`（label `affect:judge`） |
| position | `nextPosition` + `advanceState` + 参照点 |
| pick | `infer` / `gridDistribution` |
| write | `insertShadowRow` × 2 + `writeState` + `setFlag(valence)` |

**摘要和总结不在这一条链上**：它们在回复之后异步跑，是另一条链（`affect.summary`），逻辑是「压句 → 总结 → 写 affairs」。两条链通过数据库里的 affairs 接头——这正是主人说的「上一轮总结喂这一轮」。

## 六、引擎语义（`src/modules/chain.js`，在 v1 基础上加账和重放）

```
runChain(chain, ctx, { runId, onStep, record = true })
  1. validateChain(chain)                 // 同 v1：id/steps/kind/label/块单调不减
  2. 防重入：key = chain.id + ':' + ctx.key；正在跑 → { ok:false, skipped:'running' }
  3. 建 run 行（record=true 时）
  4. for step of steps:
       when 不满足            → 记 skipped
       in = step.input(ctx)   → 先落 in（调模型前）
       模型步：req = step.request(ctx)；req=null → 记 skipped
              raw = await ctx.runner[kind](req, { block, label, lane })
       代码步：raw = undefined
       out = await step.run(ctx, raw)
       ctx[step.id] = out     → 后一步能拿到
       落 out + ms + status
       out?.stop → 记 stop，正常收尾
       抛错 → 记 err；onError=abort 停 / continue 下一步
  5. 收 run（ok/failed_step/ms）；finally 清防重入
  6. 返回 { ok, runId, steps, failedStep, stopped, skipped }

replayStep(runId, stepId, { runner })
  1. 从 chain_steps 取那条的 in_json
  2. 用同一条链的定义重建 ctx（只到这一步需要的字段）
  3. 重跑这一步，结果另起一行账（同 run_id，新 seq，标 `replay_of`）
  4. 不改任何业务表——重放只出账，不落库
```

- 引擎不 import 模型、不碰 db：`ctx.runner` 由调用方注入，记账走 `onRecord` 回调。
- **账写失败不影响链**：所有落账都包在 `try/catch` 里，失败只打一行日志。
- `lane` 一路传下去（会话号），保证同一会话内的排队顺序（已落地，见改动-宿主链按会话拆开）。

## 七、缺料与失败

- 模型步没回来（超时/缺字段）：记 `status: 'no_result'`，`onError: 'abort'` 停在那一节；**不推进状态、不落表**（现有规矩不变：缺料不硬判）。
- 代码步抛错：记 `err`；abort。
- 整链失败：回复照常，情绪停在这一轮之前的位；账上有 `failed_step`，一眼知道断在哪。

## 八、与块 / 并发 / 队列的边界

- 链不占队列；链里的模型步各自进它声明的块。
- 纯代码步不进队列，但**在链上**（这是这次的关键区别：代码步也要记账，因为它可能改数据）。
- 两条链可以同时跑（不同会话）；同一条链同一个 key 不许重入。
- 宿主并发 2（已落地）；本地单槽。

## 九、落地顺序（一步一验，随时能停）

1. **建表 + 引擎加账**（`chain.js`：`record` 开关、`chain_runs`/`chain_steps` 写入、in/out 截断）。验收：mock 链跑一遍，两张表各得应有的行；关掉 `record` 行为与 v1 一致。
2. **情绪链上链**（新文件 `src/modules/affect_chain.js`，6 节；`appraiseTurnNow` 内部改成 `runChain`，出口签名不变）。
   验收：门禁 608 全过 + 真库一轮跑出 1 条 run、6 条 step，in/out 都在。
3. **摘要链上链**（`affect.summary`：压句 → 总结 → 写 affairs）。验收：回复后 3 秒内两张表各多一条。
4. **单步重放**（`replayStep`）。验收：拿一条历史 run 的 judge 输入重跑，输出与当时对得上。

第 1、2 步之间可以停：停下时现有行为不变，只是多了一张表。

## 十、验收（数字）

- 引擎单测：顺序 / when / stop / err abort / err continue / 防重入 / 块递减拒绝 / 缺 label 拒绝 / **每步 in 先于模型调用落盘** / **out 截断** / **账写失败不影响链**。
- 情绪链单测（临时库 + mock runner）：6 节全 ok 时两张表行数对；judge 缺字段时 `no_result` 且不落表；topic 超时不落表。
- 门禁：`node test/run-tests.mjs` 全过。
- 真库：重载后 10 轮，`chain_runs` 10 条、`chain_steps` 60 条左右；随机抽一条 run，能按 seq 讲出这一轮数据怎么变的。

## 十一、怎么退

- 账先关：`affect.chain.record=off`（引擎退回 v1 行为，不落表）。
- 链退回函数：`appraiseTurnNow` 里改回原来的 `await` 顺序（git 有完整旧版）；账表留着不影响。
- 整条停：删 `affect_chain.js`，`appraiseTurnNow` 恢复直调。

## 十二、已知不做（这次）

- 链不做断点续跑（中断就重来，账上有半截 run）。
- 链不做自动重试（要重试显式加 `retry` 字段）。
- 不做「跨链事务」：`affect.turn` 和 `affect.summary` 是两条链，靠 affairs 接头，不做分布式事务。
- 不做 in/out 的压缩与归档（8KB 上限 + 只追加，先够用；量大了再谈）。
