# 改动：把 DSH 的两类口子收成一条通道（2026-11-19）

> 一句话：以前只有「接口」收在一处，「读 DSH 私有文件」散在四个地方、断了一律静默；现在两类各只有一个口，而且「昨天读得到、今天读不到」会被说出来，下一轮我能自己开口提。

## 一、怎么发现的

主人问「DSH 以后破坏性更新对咱们有没有影响」，顺着盘了一遍：

- **接口**已经收好了：7 个接缝（`systemPrompt` / `agent/pre-step` / `session/event` / `webServer` / `services` / `tools` / `commands`）全在 `src/host/dsh.js` 一个文件里，各有 `level + reason + hits`。
- **读私有文件**没收：`api.js` 和 `binding.js` 各读一遍 `workspace.json`；`api.js` 读 `session_projcache` 拿会话标题；`qq_watch.js` 找 `qq-sessions.json`；三处各解析一遍 `DSH_HOME`。
- 这些读全部包在 `catch {}` 里，断了只有「功能悄悄变差」：标题空、归档认不出、QQ 映射找不到。没有一个地方说「我接不上了」，ping 的 `host` 段也看不到。

## 二、动了哪

1. **新增 `src/host/fs.js`**：DSH 私有文件的唯一读口。
   - 三个读点：`workspace`（侧边栏分支 / 归档名单）、`session.title`（projcache 的标题）、`qq.sessions`（桥接映射表）。
   - `read()` 永不抛，拿不到给 fallback；每次读更新 `{ level, reason, file, lastOkAt, hits, fails }`。
   - 断链判定：**冷启动没这个文件 = `absent`，不算断**；曾经读到过、后来读不到 = `missing`（删了）或 `degraded`（结构变了）/ `error`（读不动）。
   - 第一次坏时记一条待回报（`takeBreaks()` 取走即清），同一读点同一级别 6 小时冷却；级别升级（degraded → missing）会重报。
   - `dshHome()` 统一口径，别的文件不再各算一遍。
2. **`src/api.js`**：`readWorkspaceIndex` / `sidebarTitle` / QQ 映射表改走通道；删掉本地 `dshHome()` 和 `os` import。标题缓存从「按 mtime」改成 20 秒 TTL（页面本来就是 20 秒轮一次）。
3. **`src/modules/binding.js`**：`archivedSessionIds` 改走通道，删 `fs` / `os` import。
4. **`src/modules/qq_watch.js`**：`findQQSessionsFile` 改成问通道要路径（候选路径也搬进通道），`dshHome` 转出。
5. **`index.js`**：
   - ping 多一段 `files: defaultFileSeam().report()`（给能开页面的人看；主人不看这个，主通路是下面那条）；
   - 系统提示里加 `seamBlock`：有断链就拼一句「宿主接不上：<id> — <原因>；可能是 DSH 更新改了接口或存储格式，跟主人说一句，我去查」。拼装本身抽成纯函数 `breakLineOf()`（在 `fs.js`），**上测试锁住**，不靠口头保证。
   - 同时记 `event('host.break.<id>')`。
6. **新增 `test/host-files.test.mjs`**（23 项，含「有断链时提示词那行带 id + 原因」「没断链一个字不加」），挂进 `test/run-tests.mjs` 门禁。

## 三、怎么验

```powershell
cd D:\deepseek_local\plugins\dsh-consciousness-v6
node test/host-files.test.mjs    # 23/23
node scripts/check-host.mjs      # 23/23（接口那半没被碰坏）
node test/run-tests.mjs          # 门禁 598/598（原 597 + 新增 1 条）
```

断链进提示词那一步有测试锁（`breakLineOf`）：没断链一个字不加、有断链带上 id 和原因。**主通路是这条**——下次开口时我自己说，主人不需要开任何页面。`ping` 里的 `files` 段只给想深看的人。

## 四、怎么退

- **只关提示、留通道**：删掉 `index.js` 里 `seamBlock` 那一段，读口照旧工作，只是断链不再进提示词。
- **整刀回滚**：删 `src/host/fs.js` + `test/host-files.test.mjs`，把 `api.js` / `binding.js` / `qq_watch.js` 四处读改回直接 `readFileSync`（改动集中在 4 个文件，逐处可对照本文件第二节）。行为上回到「静默吞错」，其余功能不变。

## 五、注意

- **`session.title` 可能误报 degraded**：刚建的会话 `record.rows` 还没写全时会被判「缺 record.rows」。只影响这一项、且只是显示原因，不影响功能；真嫌吵可以把它从 `absent` 之外放宽。
- **`qq.sessions` 不是 DSH 的文件**：是 `dsh-qq-onebot-bridge` 写的。放在同一个通道里是因为它也在 `~/.dsh` 下、也属于「外部私有格式」，断了同样没人说。
- **这个通道只负责「读」，不负责「写」**：插件从不写 DSH 家目录，所以没有写侧通道。
- 断链提示和情绪罢工块一样，是**进提示词让我自己说**，不是自动给主人发消息——主动开口要不要说，还是走原来的主动链路。
- 主人 2026-11-19 明确：他不看 ping/HTTP，只要我开口报。所以主通路是提示词那句；`files` 段不算验收项。
