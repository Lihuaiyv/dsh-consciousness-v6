# 改动：宿主闸门加优先级（2026-11-17）

> 一句话：后台宿主调用以前纯先来后到，上一轮的总结会挡住这一轮的判断；判断排队超时（5 秒）就回退规则、情绪罢工。现在判断带「急事」优先级，不排在大件后面。

## 一、怎么发现的

整体检查情绪链时序时发现：`host_llm.js` 的闸门对**同一个 agent 严格保序**（chain 串行），且**没有优先级**，所有任务按入队顺序执行。

但情绪链里两件事的快慢要求不一样：

| 调用 | 何时 | 预算 | 失败后果 |
|---|---|---|---|
| `affect:judge`（判断层） | 回复前 | 5 秒（排队+执行合计） | 超时回退规则 → 情绪罢工 |
| `affect:summary`（总结） | 回复后异步 | 8 秒 | 缺一轮「事」，无碍 |

上一轮回复后总结在跑（最多 8 秒），这一轮判断一来就排在它后面；5 秒排队超时 → 回退规则，用户看到的就是「情绪模块罢工」。

## 二、动了哪

- `src/modules/host_llm.js`
  - `scheduleHostTask(db, { ..., priority = 5 })`；`hostComplete` 透传 `priority`。
  - 高优先级（`priority < 3`）**不挂同 agent 链**，直接进闸门抢全局槽；普通任务仍按链保序。
  - 全局等待队列从 FIFO 改成按 `priority` 升序插队（同优先级按入队顺序）。
  - `exec` 的全局槽获取 `acquire(db, it.priority)`。
- `src/modules/affect_v4_shadow.js`：判断层 `affect:judge` 两处调用加 `priority: 1`；总结不传，默认 5。

## 三、怎么验

```powershell
cd D:\deepseek_local\plugins\dsh-consciousness-v6
node scripts/check-host-queue.mjs    # 12 项（并发/同 agent 保序/排队超时/快照）
node scripts/check-appraise-turn.mjs # 16 项
node test/run-tests.mjs              # 全量门禁 588/588
```

## 四、怎么退

- 只关优先级：把判断那两处 `priority: 1` 删掉，就回到纯保序；`host_llm.js` 的改动可以保留（默认 5 不生效）。
- 回滚文件：`git checkout -- src/modules/host_llm.js src/modules/affect_v4_shadow.js`（未跟踪的先备份）。

## 五、注意

- 同 agent「严格保序」被高优先级插队打破：旧精修那条 `topic -> judge` 的顺序不再受保护。旧精修业务已经不跑，暂不影响。
- 判断现在最多占一个全局槽（并发 2），总结占另一个；两个总结占满时判断仍会等槽，但只等一个任务的时间，不会等整条链。
