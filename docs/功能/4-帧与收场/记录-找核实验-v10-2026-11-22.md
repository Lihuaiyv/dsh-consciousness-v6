> 原来的《判据清单-2026-11-22》已并进本文第四节，那份单独文件删了。

这一段是**离线实验**，脚本都在 `scratch/frame-core/`，没接进主链。目的只有一个：验证「核 + 卫星」能不能自动判出来、判出来的东西像不像话。

## 一、这轮定下的两条

1. **问答一致性只是入口，不是终点。**
   文档《记录-疑问清单-2026-11-21》第 24 行原话：「它是入口，不是终点。」
   入口用来圈出候选核；逐句那一步是「这句**服务谁**」，不是「这句在回答什么」。
   我中途把入口当成了逐句的尺子，结果卫星全被逼成「答案」——那是错的，已改回。

2. **核的个数不预设。**
   一段里有几件事，由数据自己定；不再固定「一两个候选」「三个候选」。

## 二·五、v18：把七步串成一条链，整段跑了一遍（2026-11-22 中午）

题目顺序照第五节：题 → 件 → 主判 → 字面加挂 → 回指合并 → 接续 → 塌（入度）。

S20 四轮 + S15 两轮 + S19 三轮，共 10 轮，每轮 **2～10 秒**：

- 题：8 轮出了稳定题（2～3 票）；S15 轮2、S19 轮3 没有稳定题——都是三四句的短文，本来就没题。
- 核数：1～4 个。S20 轮3 判 2 核、S15 轮6 判 2 核、S19 轮7 判 4 核。
- 回指合并真的动了：乙→甲、丙→丁、丁→甲，都是「两句指同一物却分给两件」。
- 缝：每轮都找出来了。

**两处明显过宽（还没修）：**

1. **起点例外太宽。** S19 轮3 只有 4 句、缝是 ②③④，四个件全被判「起点核」——等于没筛。
   应该只给「含第一句」的件开这个口子，缝不算。
2. **缝太常见，不能直接当帧边界。** 接续答「没有」很普遍，S15 轮6 一轮四条缝；缝只能当候选，要与其他信号一致才切。

另外一处观察：S20 轮1 里回指把乙并进甲后只剩一个件，单件谈不上结构——件数为 1 时应该直接输出「这一轮只有一个核」，不再走后面几步。

## 三、一个可读的例子（S20 第 3 轮，13 句）

四个核：①「电脑麦克风状态检查」、④「无线麦电量低表现」、⑤「描述与现象匹配」、⑨「重新配对话筒和接收器」。
②③⑥⑦⑩ 挂 ④，⑧⑪⑫ 挂 ⑨，⑬ 挂 ⑤。

判对：②③ 确实替「电量低」做解释；⑧⑪⑫ 确实归「重新配对」。
判错：⑤「这和你描述的顺序完全对得上」只是给 ④ 点头，被提拔成独立的核。

## 四、判据清单（提示词原文 + 实测）

### 判据 1｜题（问答一致性）

多问几遍、看交集；出现多次的才算这一段稳定的「题」。三种问法轮着用：

```
只输出一个 JSON 数组：[{"what":"这件事是什么，不超过12个字"}]。这一段在说哪几件事？一到四件。不要解释。
```
```
只输出一个 JSON 数组：[{"what":"这件事是什么，不超过12个字"}]。这一段在回答哪些问题？一到四件。不要解释。
```
```
只输出一个 JSON 数组：[{"what":"这件事是什么，不超过12个字"}]。如果别人问「你刚才在说几件事」，你会列出哪几件？一到四件。不要解释。
```

实测：交集稳定但颗粒度塌到最粗（S20 轮3 三遍都是「电脑麦克风问题」）；S15 轮2、轮8 三组完全不重合，交集为空。

### 判据 2｜件（这句主要为哪件事说话）

系统：`只回答一个字母：甲、乙、丙 或 丁。不要解释。`

```
这几件事：
甲：……
乙：……

问：④ <这一句的原文>
这一句**主要**在为哪一件事说话？只挑一个字母。
```

三遍（正序／逆序／绕一位）取多数，两票以上才算。

### 判据 3｜接续（这句接着上面哪一句说的）

系统：`只回答一个符号（①②③…）或者「没有」。不要解释。`

```
前文：
① ……
② ……

问：⑥ <这一句的原文>
这一句是接着上面哪一句说的？只答那个符号；如果是另起一句、不接任何一句，就答「没有」。
```

实测（S20 轮3）：12 句里 8 句接上（④→③、⑤→④、⑥→④、⑦→⑥、⑩→⑥、⑫→⑪、⑬→⑪），②③⑨⑪ 答「没有」。

### 判据 4｜回指（「它、这个、那个」指的是哪一个）

代词由代码找出，指向由模型指认：

系统：`只回答一个符号（①②③…）或者「没有」。不要解释。`

```
前文：
① ……

问：⑨ <这一句的原文>
这句里的「它们」指的是上面哪一句说到的东西？只答那个符号；指的不是某一句而是别的东西，就答「没有」。
```

实测（S20 轮3）：5 句带代词，2 句指认到具体句子（⑥的「它」→④、⑨的「它们」→⑧）；②⑪⑫ 答「没有」——那三处确实指外部实体（麦克风本体、浏览接口、说明书）。

### 判据 5｜塌（抽掉一件，剩下的缺什么）

不是二选一「成段／散句」，而是让它做一件具体事：

系统：`先判断，再动手。只输出 JSON：{"ok":true或false,"missing":"缺什么（没缺就留空，15字内）"}。不要解释。`

```
下面是某一段里剩下的句子（有些句子被拿掉了）：
· ……

如果你只能用这些句子改写成一段完整、说得通的话：写得成吗？写不成的话，缺的是什么（主语？结论？因果？）。
```

实测（S20 轮3）：四件各抽一遍，四次都 ok=false，但缺的东西不同——抽「电脑状态」缺开头与问题核心；抽「黄灯原因」缺结论；抽「充电测试」缺开头与问题描述；抽「重新配对」**缺连接上下文的主语和对象**。

**2026-11-22 中午：这条问法试了三次都失败，最后改用「入度」，不再问模型。**

- 按「缺什么」挑承重（缺主语/对象才算）→ S20 一件不承重、S15 三件全可疑。模型答「缺什么」时默认写「缺结论/总结」，没分辨力。
- 改成「只要说改不成就算承重」→ 两段全承重（3/3、3/3），也没分辨力。
- 改成对比「A 原文 / B 抽掉后，哪版更像完整的一段」→ **七个件全答 B**。诊断脚本原样打出回答，两种系统提示都是 `"B"`：它只是偏好更短更干净的那版。

**定论：塌不是「读起来通不通」，是「有没有人接它」。**
删掉任何一句，剩下照样通顺，所以问「还成段吗」永远答成段；塌的真实形态是**指称悬空**——抽走这件，别处还有句子原本指着它。
于是塌不用再问模型，直接数接续图上的入度：外面有多少句接它。被接的 = 承重核；一句没人接 = 孤岛。
例外一条：一段话的开口本来没人接它，不能因此判孤岛——含第一句或落在缝上的件算「起点核」。

### 判据 6｜字面证据（代码，不是提示词）

一句话要不要算给第二件事，看词面：事件名里抽出两个以上的两字词、且都在句中命中。
实测：S20 轮3 加挂 0 次，S15 轮6 只有 1 次——「一句同时服务两件」本来就少见。

### 判据 7｜加粗（只作对账）

我自己加粗的句子和模型判的核，16 轮里只有 1 轮对上。作废，只留作报警。

### 废 1｜旧「抽走塌不塌」（立得住／立不住）

问「删掉这句剩下的还连得上吗」，全答连得上，饱和。

### 废 2｜词法数回指

直接数句子里的「它、这个、那个」，16 轮里最多次数都是 1，等于没信号——因为那不是回指，只是在数词。

## 五、判据的位置：三遍思考

### 第一遍：每个判据到底能说出什么

| 判据 | 说出什么 | 形态 |
|---|---|---|
| 题 | 这段在谈什么 | 粗、方向 |
| 件 | 这段有哪几件事 | 意见（候选） |
| 主判 | 这句归哪一件 | 一票、单一 |
| 字面证据 | 这句的字面指向哪件 | 证据，不产观点 |
| 接续 | 这句跟在哪句后面 | 顺序 |
| 回指 | 这个词指向哪句／哪个东西 | 同指，稀疏 |
| 塌 | 抽掉它，剩下缺什么 | 结构承重 |

### 第二遍：每个判据会怎么坏

- 题会塌到最粗，只能可靠回答「这段有没有第二个不相干的题」。
- 件会漏（「重新配对」被并进步骤）、也会凑。它只会想，不会判。
- 主判稳，但天生只认一个；两句撑两件时它压掉一个。
- 字面证据在同义改写时会漏，在泛词上会误命中。它不会提新东西，只会确认或否决。
- 接续有时偷懒指最近一句，密度不匀。它给顺序，不给归属。
- 回指稀疏（2/5），指外部实体时答「没有」。它只在两句指同一物时才有信号。
- 塌只能评「件」的必要性，评不了句；它的答案还要看缺的是什么——缺主语/对象是承重，缺开头/总结多半是拼出来的假件。
- 加粗是我的写作习惯，不是内容证据。

### 第三遍：谁决定什么、按什么顺序、冲突怎么裁

三层三刀，各裁一层，不重叠：

- **题裁帧**：交集里出现两个以上互不相干的题 → 这段不是一个帧，先切，再往下走。
- **回指裁件**：两句同指，却被提出成两件 → 合并成一件。它改的是「件」，不改句子归属。
- **塌裁核**：缺主语/对象 → 这件承重，是核；缺开头/总结 → 可疑件，降为句群或并回别的件。

顺序与权限：

1. 题先跑，定这次处理的范围。
2. 件在帧内提候选（一到四件，宁可多提，后面靠回指和塌裁）。
3. 主判分配，三遍取多数。**全程只有它改句子归属。**
4. 字面证据跑在主判之后：只许加挂第二件，不许否掉主判给的主件。
5. 回指跑在分配之后：只许合并件，不许改句归属。
6. 接续跑在分配之后：给每件内部排序；接不上的地方是缝，缝是帧边界的候选。
7. 塌最后跑：裁核，给收尾。

冲突裁决：

- 归属打架 → 主判说了算；字面证据只能加挂。
- 件数打架（回指发现两件同指）→ 合并，件只能减不能增。
- 帧边界打架（题多题 vs 接续无缝）→ 两者一致才切；只题多而接续无缝，说明是同题的两种说法，不切。

一句话：**题管切帧、件管候选、主判管归属、证据管加挂、回指管合并、接续管顺序与缝、塌管收尾。**
v12/v13 失败的根子，就是让几个判据都去动「归属」，谁也说不清谁说了算。

## 六、现在的不足（v15 + 整合之后）

1. **核被钉死在句子上。** 文档说核的形式自由，我却是先分句再挑。v11 改成「一件事」好一些，但藏在「步骤」里的动作仍提不出来。
2. **附和句会被当成核**（⑤ 那种点头句）。
3. **跨轮没接。** 现在给的是单轮切片，不是树。
4. **一句挂两件只能靠字面证据**，同义改写就漏。
5. **塌的形态已定**：它不是「读起来通不通」，而是「有没有人接它」（接续图入度）；已接进 v18。旧的三种问法（成段/散句、缺什么、A/B 对比）全部作废。
6. **问答一致性只给「题」**，给不出题下几件。

## 八、顺带修的本地模型问题
