# 改动：上一句摘要不再等 20 秒（2026-11-22）

## 为什么

主人查完「现在还有哪些模型调用」后定了两条：

1. 那个「20 秒后压摘要」改成**不等**；
2. 把 20 秒相关的设置**删掉**，免得以后又有人以为它可调。

排查时还发现一个真 bug：参数目录里 `presence.summary.delay_ms` 写的是 `0`，调用处也按 0 传下去，
但 `queueSummary` 里写的是 `Number(delayMs) || 20000`——**0 被 `||` 当成假值，永远变回 20 秒**。
也就是说这个参数从来没生效过，写着 0 实际跑 20 秒，是典型的「看起来能调、其实不能」。

## 动了哪

| 文件 | 改动 |
|---|---|
| `index.js` `queueSummary()` | 去掉 `delayMs` 参数；`setTimeout(..., 0)`，排一拍就压 |
| `index.js` `commitTurn` 调用处 | 删掉 `presence.summary.delay_ms` 的读取，不再传 `delayMs` |
| `src/kernel.js` | 删参数目录里的 `presence.summary.delay_ms` 一行（连同那句「默认 0」的注释） |

没动：`presence.summary`（总开关）、`presence.summary.chars`、`presence.summary.local_model`、
`generatePairSummary` 自己的重试节奏（`delays [0, 800, 1500]`）——那是「问空了再问一次」，不是人为推迟。

## 已知代价（2026-11-15 那个坑）

当初推到 20 秒后，是因为「紧接着回话之后马上调」时模型老是回空串（见
[改动-上一句摘要-2026-11-15.md](../../archive/2026-11-帧-施工记录/改动-上一句摘要-2026-11-15.md)）。

现在的兜底顺序没变：`generatePairSummary` 先自己重试三次 → 仍不行就 `source=clip` 记一对截断。
所以最坏结果是回到「36 字硬切」，**不会丢上下文，也不会卡回复**。若重载后连续多轮都落 `clip`，
说明那个「收尾时回空」的时机问题又回来了，把它改回 `setTimeout(..., 1200)` 试一秒半的间隔即可。

## 怎么验

```powershell
node --check index.js
node --check src/kernel.js
node test/run-tests.mjs
```

- 语法：两个文件都过。
- 门禁：`node test/run-tests.mjs` → **599 / 599**；`check-params` / `check-ownership` / `check-paths` 全 ok。
- 真机：重载后看 `presence.last_sentence` 的 `source` 与 `created_at`——
  `source=local` 且时间戳紧跟回复（秒级），而不是 20 秒后才出现。

## 怎么退

- 想恢复「等 20 秒」：把 `queueSummary` 里 `setTimeout(..., 0)` 改成 `setTimeout(..., 20000)`。
- 想恢复「可调参数」：把 `presence.summary.delay_ms` 加回 `kernel.js` 参数目录，
  但**别再写 `Number(x) || 20000`**——用 `Number.isFinite(Number(x)) ? Number(x) : 20000`，
  否则 0 又会被吃掉。
