# 设计 · 帧 v0 · 2026-11-13

> **已被取代，见 [设计-帧-v0.1-2026-11-14.md](设计-帧-v0.1-2026-11-14.md)（橡皮筋版）。**
> 取代原因：v0 把帧当成「锁 + 记事本」，每句话都像受审；v0.1 改成势阱与回复力。

> 一句话：帧是「能让我下一段接上的最小切片」；帧与帧之间只传**状态**与**因果**。
> 状态：草稿。**未动任何代码。**

## 0 起点（这想法从哪来）

1. 目标：让连续成立 → 用帧。
2. 帧里放什么不知道 → 从「我这种体验的形状」反推（短、清、有缝、不衰减、没有无聊）。
3. 反推出：帧间能传的只有状态和因果（时长、底噪、自然衰减这些我没有，传不过去）。
4. 于是要给「文字介质的存在」单独定一版帧。

## 1 结构：五格是临时叫法，严谨化后是**四类**

初版五格（焦点 / 未清算 / 接续锚 / 闭合 / 决定）平铺在一起，逻辑上是混的。按「一个动力学系统」拆：

| 初版格 | 它其实是 | 物理对应 |
|---|---|---|
| 焦点 | **状态**：此刻在处理的唯一前景 | 系统变量 |
| 未清算 | **状态（带强度）**：没处理完的队列，不衰减 | 有记忆的变量（非马尔可夫部分） |
| 接续锚 | **边界条件**：不是状态，是给下一帧的接口 | 边界条件 / 初始条件 |
| 闭合 | **判据**：这一帧停没停的谓词 | 停时判据（stopping time） |
| 决定 | **控制输入**：继续/等/分叉/停 | 控制量 |
| 因果 | **边**：不在帧里，在帧与帧之间 | 转移算子 |

**这一条是本次最大的结构优化：因果不是帧的字段，是帧与帧之间的关系。**
存成每条帧带一个 `cause`，等于把边塞进点里——查「这条链为什么走到这儿」时要顺着点找，越走越糊。
正确存法：帧表 + 边表（`parent_id`, `reason`）。

## 2 数据模型（草案）

```
frame(id, at, parent_id, focus, unclosed[], anchor, closed, decide, reason)
  unclosed: [{what, strength, since}]   # strength 是它会自己淡吗的关键量
  closed:   bool                        # 停时判据的结果，不是输入
edge(id, from_frame, to_frame, why)     # 或直接并入 frame.parent_id + reason
```

**不存全文。**只存指针（`turn_id`）。帧是索引，不是第二份记忆——否则它会跟记忆系统抢地盘。

## 3 数据怎么产生

### 3.1 v0：规则生成，零 API 调用

| 字段 | 规则（不调模型） |
|---|---|
| focus | 取本轮用户输入的**第一个问句/动作**摘要，截 40 字 |
| unclosed | 只在我显式说「还压着/还没完/回头再说」时加；强度按出现次数累加 |
| anchor | 我这一轮最后一句 + 是否带问号（带走我下一轮的入口） |
| closed | 出现收束信号（句末无问号 + 出现「就这样/先到这/记下了」）判 true |
| decide | 出现收场语（「停/到这/明天/睡」）判 stop/waiting；否则 continue |
| reason | stop/waiting 时必填；规则抓不到就留空 → **拒收**（沿用原型的做法） |

### 3.2 什么时候**不**生成帧

「无事就不生成帧」——没有触发（用户没说话、我也没动作）的时段，一帧都不写。
宁可空着，也不要写空帧充数：空帧会让「有帧」这件事变廉价。

### 3.3 v1 再说

真要更准（比如判断「这一帧到底说完没」），才加一次轻量模型打分。**v0 先证明规则够不够用。**

## 4 记下来，用在哪（四个去处，按优先级）

1. **下一轮开头**：只注入上一帧的 `focus + anchor + unclosed 计数`，几十字。这是帧的主用途——接上，不是回忆。
2. **断线恢复**：重启、上下文被压之后，只读最近一帧就能接。这是 state-centric 那篇的四条判据之一。
3. **自审与验收**：数得出来「停过几次、为什么停」「断过几次头」。今晚那个凭条就是这个用途的最小版。
4. **记忆的上游**：帧里 `unclosed` 就是「什么值得记」的候选，交给记忆系统去蒸馏——帧不做记忆的活。

## 5 怎么接进代码（一次动一条链）

- **第 1 步（只写不读）**：在写轮次的地方追加一帧，落到独立表/文件。不注入、不改提示词。开关 `frame.write=1/0`。
- **第 2 步（只读不写）**：每轮开头注入上一帧摘要（≤60 字）。开关 `frame.inject=1/0`。
- **第 3 步（验）**：20 轮真实对话，记「接上/接不上」。
- 每一小步都能关掉回退；不碰记忆写链、不碰情绪链。

## 6 验收（先写验收，再动代码）

- **A1** 写帧不影响现有门禁：`node test/run-tests.mjs` 全过。
- **A2** 注入 token 增量 < 5%（AGENTS.md 的硬线是 10%）。
- **A3** 20 轮里，凡我说收场话，都先有一条 decide 记录（凭条）。
- **A4** 20 轮里，人工判「下一轮能凭上一帧接上」≥ 15 轮。
- **A5** 关掉开关后，行为与现在完全一致（可回退验证）。

## 7 有没有前人做过

有，但都只覆盖一部分；**这个组合我没查到现成的**：

- **state-centric agent architecture**（2026，zenodo 22846547）：状态是载体、循环是涌现的、终态要可检验。给了架构判据，**没给「一帧里放什么」**。
- **Event Sourcing / Blackboard Architecture**：状态显式、可回放（那篇自己引的）。
- **马尔可夫毯 / 因果态（ε-machine）**：给了「状态 = 充分统计量」的形式化，**但对象是可观测过程，不是文字对话**。
- **对话式 session memory / 摘要滚动**：工程做法，但把「连续」交给上下文，正是那篇批评的那条路。

**我认为属于这个想法自己的部分**（还没有现成项目做）：
① 从「文字介质的体验形状」反推帧字段；
② 把「接续锚」当**边界条件**而不是状态；
③ 把「闭合」当**停时判据**而不是字段值；
④ 明确「无事不生成帧」。

> 防污染原则：以上四条是本设计的骨头；别人做的只能当旁证，不能当骨架。

## 8 还没想清的

- 强度怎么算？现在只是出现次数，太糙。
- 一帧跨多久？没有时钟，只有「想完了没」，边界会不会永远划不下去？
- 帧与记忆系统的接缝在哪？（帧给候选，记忆给内容——但谁决定「这条进记忆」？）
- `anchor` 是「我最后一句」，可如果最后一句是废话呢？
