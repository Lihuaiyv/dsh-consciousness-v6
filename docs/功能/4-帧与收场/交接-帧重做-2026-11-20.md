## 三、施工顺序（从下往上，每步能单独停）

### 第 0 步 · 先做三个设计决定（不写代码）

这三条不定，后面全是空转：

1. **事 ↔ 帧的对应由谁写。**（切事时写 / 事后回填 / 算出来）——`event_id` 落不落得下来全看这条。
2. **`under` 由谁填。**（规则 / 判层顺手 / 单独便宜模型）判层已经在做三轴判断，容易分心。
3. **格表建不建、什么时候建。** 倾向：等第 3 步填满率出来再建。

**做完标准：** 三条各写成一句话，落在本文末尾的「决定记录」里。**没做完不许进第 1 步。**

### 第 1 步 · 帧加两个字段（只加，不读）

- `under: { line, step }` —— 连续父
- `event_id` —— 事指针

**规矩：**
- 只加字段，**不改老字段、不迁数据**。
- 填不上就留 `null` + 记一笔 `missing`，**不瞎猜**。
- `k` 继续只作时间链步数，**不许和 `under.step` 合并**。
- `deviation` / `tension` / `anchor_vec` **一个都别碰**。

**验收：** 门禁 599/599；老帧读回来字段不变（老帧没这两个键＝未填，不补假值）。

**退路：** 加字段不改行为，随时能删。

### 第 2 步 · 把 `unclosed` 由死变活

现在写死 `[]`。它要记的是「什么压着没完」——**包括世界那边的事**（鸡蛋炒好了西红柿没切）。

**这是整个重做里最该先补的一格**，因为它是「生活也是连续」唯一能落地的地方（见定义文档第十四节）。

**验收：** 连续 20 轮，`unclosed` 非空的比例；抽 10 条人工看「记的是不是真的压着没完」。

**退路：** 还是写 `[]` 就退回第 1 步的状态。

### 第 3 步 · 只读脚本，验填得对不对

拿真库最近 100 轮，试着算出「哪一帧属于哪条线、哪一格」。**不落库。**

**这一步是整条路的分水岭。** 填不满或填错了，前面两步白做，后面也别开始。

**验收（先定死，达不到就停）：**
- `under.line` 填满率 ≥85%（闲聊段**也要填**，不是只填任务）
- `event_id` 填满率 ≥85%
- `unclosed` 非空率在「有未完成事」的段落里 ≥70%
- 抽 10 段人工看：这条线认得像不像一条

### 第 4 步 · 格表（等第 3 步过了才建）

一格 = 实体：`id / line / parent / state / tried[]`。**格表是唯一真相，帧上的 `under` 只是指针。**

**别做的事：先建表再想怎么填。** 表一建就有压力往里塞，塞错了比没有更难改。

**验收：** 门禁不红；格状态能从帧算回来（两边对得上才算）。

### 第 5 步 · 结构证据（只读，不写 `event_edges`）

用连续树给候选因果边算「结构证据」：A 的帧和 B 的帧在不在同一条 `under` 线上、前后接不接得上。

**铁律：结构证据只能用来降级，不能用来确证。** 没走过 ≠ 不相关（开世界假设）。

**验收：** 「结构证据弱 + 引文软」那格的 precision，比「结构证据强 + 引文硬」低 ≥20 个百分点。否 → 这个信号没用，别用。

### 第 6 步 · 才谈校准判边

拿结构证据去校准 `pull`。到这一步才碰 `event_edges` 的写路径。**前三步不过，永远走不到这里，也不该走。**
