## 一、已经定下来的

### 1. 帧是什么

> **一帧 = 一个核 + 它的一片范围。**

不是「最小时间片」，是「**再切就没有核了**」。

### 2. 核怎么认

**核的形式是自由的**——可能是一个词、一个短语、半句话、整段逻辑。**不能拿形式去认它**（我先判成词、又判成分句，都不对）。

**主判据：抽走它，剩下的塌不塌。** 塌，它就是核。

这是个**充分条件，不是充要条件**——「是核 → 抽走一定塌」不成立（同一个核别处还说过，抽掉一处不明显）。但**充分就够用**：那种抽掉不塌的核，别处本来就在重复说它，不判它是核也不亏。

**配一个入口**：先问「这句话在回答什么问题」（问答一致性，Büring 2016）。它好答——是复述一个已经在问的东西，不像「核是什么」那样凭空判。**它是入口，不是终点。**

**还能数一个东西：回指。** 核只出现一次，但被「它、这个、那个」指回去好几次。**数词频数出来的是卫星，数回指才是核。** 这条路有人做过——指代消解是成熟任务，中文在 ACE 2005 上 F 值 63~70。

### 3. 三种关系，三个工具

| 关系 | 用什么 | 为什么 |
|---|---|---|
| **核 ↔ 核** | 图 | 两边都是点。并列是双向边，对立是带「否」的边 |
| **核 ↔ 卫星** | 拓扑 | **卫星是一片范围，不是另一个点**。范围到哪为止、怎么叠，是拓扑的活 |
| **边 ↔ 边**（复合） | 范畴论 | 只问一件事：箭头能不能接起来 |

**「一个卫星服务好几个核」不是一条边连两头，是两个范围重叠**——拓扑里叫交。第一版先不做交叉。

### 4. 范围怎么定：反过来做

**不是从核往外划，是从话往里归。** 每一句自己站队：

- 只服务 A → 归 A
- 同时服务 A 和 B → 交集
- 谁都不服务 → **游离**

**游离不是垃圾，是缝**——闲聊里大量接话、语气词，它们不承载内容，但把两块粘在一起。

「分割还是覆盖」不是前提，是**标完之后的测量结果**。

### 5. 同一个名字反复出现，不是父子

**名字重复 → 图上的边**（后一个修正前一个）。两个平级的点，一根边，不是爷孙。

**父子只在拆解时出现**——一件事拆成几步（做西红柿炒蛋 → 处理鸡蛋、处理西红柿），小的**属于**大的。

这两件混在一起才是灾难。

### 6. 树必须当场在

**这条是把前面「树事后连」推翻之后定的。**

人不能一边打鸡蛋一边不知道自己在做西红柿炒蛋——不知道，就会打多了、先干别的、白打了。**树是当场的方向盘，不是事后的总结图。**

### 7. 但当场的东西不回是一条路径

真实里是**几条路交替走**：洗完西红柿回去打鸡蛋，打完回来切西红柿，切完再去炒。

不是「这条走完回父节点」，是「**现在有几条路，各自停在哪**」。回退不靠完成驱动，靠**条件驱动**——哪条现在能往下走。

### 8. 节点怎么算「完成」

**不问「做完了没」，问「还有没有下一步」。**

洗完西红柿，还有剥皮 → 没完成；剥完还有切 → 没完成；切完，下一步清单空了 → 完成。

下一步是**边走边补**的，不用一开始就知道全部。

### 9. 结束：当场不判

**阶段性结束还是完全结束，当场判不了，也不需要判。**

人干到一半停下来，也不知道是真完了还是明天接着。是过了一阵没人提，才慢慢算停。这正是 v0.2 那句：**「停」不是宣布结束，是「没动静了」。**

当场只要能判「还在不在动」就够。

### 10. 几百条树不放进脑子

**不是要全知道，是要能查回来。**

脑子（上下文）里只放**最近在动的几条**，其余在库里，碰上相关的词再查回来。记不住不丢人，**查不回来才丢人**。

## 二、参考：别人具体怎么做的（2026-11-21 读到原文）

这一节是为「树怎么喂进去」找的。**只记具体机制，不记综述。**

### 2.1 Spine（arxiv 2610.37224，Codex 上实测）

**它的单位叫 work scope**：一个有入口、有父任务、完成时要交一句话结果的最小单位。

**四个命令：**

| 命令 | 干什么 |
|---|---|
| `Open(任务)` | 进一个子任务，**同一个 agent 原地做**，不派子 agent |
| `Close(结果)` | 做完，交一句话结果给父任务 |
| `Next` | 关掉当前，打开兄弟 |
| `Spawn` | 只有真能并行的独立活才派出去 |

**核心不是树，是这一条裁剪规则：**

> 未完成的子任务，**保留交互细节**；
> 已完成的子任务，**用它的结果替换掉全部细节**。

**为什么这条值钱：它实测省 32% 总成本、SWE-Milestone 涨 11.8%。** 论文里给了失败例子：把九个文件的检查记录压成摘要，模型又去重读了其中七个——**重复探索正是被"完成了却被压掉"逼出来的。**

**它的树有个精确定义**：`Open` 未闭合的序列 = 从根到当前的**活跃路径**。完成的分支留着，但不在活跃路径上。

### 2.2 s07 任务图（learn-claude-code）

每个任务一个 JSON 文件：

```
{"id": 2, "subject": "...", "status": "pending", "blockedBy": [1], "owner": ""}
```

**状态只有三个**：`pending → in_progress → completed`。

**一条自动解锁**：任务完成时，把它的 id 从所有任务的 `blockedBy` 里删掉。那一刻所有等它的任务同时变「ready」。

**随时能答三个问题**：什么 ready（`pending` 且 `blockedBy` 空）、什么 blocked、什么 done。

**画出来是 DAG**（有向无环图）：箭头不许绕回来。绕回来就说明几件事互相等，永远动不了——所以这不是设计讲究，是能开工的前提。

### 2.3 能借什么，不能借什么

**借：**

- **「未完成留细节、已完成换结果」** → 这是上下文裁剪的判据，而且它按**完成与否**分，不按重要度打分。比"留最近 N 轮"硬。
- **`blockedBy`** → 一个字段同时记「卡在哪」和「什么可以动了」。
- **状态就三个** → `pending / in_progress / completed`，不多设。

**不能借：**

**Spine 是栈式的。** 它的 `Open/Close` 严格是栈——一次只有一条活跃路径，最深那个 scope 是当前。**它表达不了"洗完西红柿去打仗鸡蛋、再回来切西红柿"这种交替。** 那种在它那儿要么得 `Spawn`（派 agent），要么根本写不出来。

**而我们撞的正是这个。** 我们不是一条栈，也不是 s07 那种纯 DAG——我们是**几个 open scope 同时开着**。

**结构得自己定：多个开着的域并存。** 借它的机制，不借它的形状。

## 三、还悬着的

1. **树当场怎么喂进去。** 现在定的是「几条并行、各自停在哪」，但具体喂什么形式没定——给整棵树太重，给一条路径又不够。这是最要紧的一条。
2. **「条件驱动」具体怎么判。** 说「哪条能走」，但凭什么判能走？灶热没热在对话里对应什么？没定。
3. **范围的实际算法。** 按归属标这条逻辑上通了，但没在真数据上跑过。
4. **核的判定没验过。** 抽测、问答一致性、回指，三条都是纸上的，一段真对话都没跑。
5. **核之间相撞怎么裁。** 图能画两条相反的边，谁赢、怎么标，没定。

| **顺着最后一个人倒** | 谁刚说了话就往谁那边倒，三次翻都是这样 |
