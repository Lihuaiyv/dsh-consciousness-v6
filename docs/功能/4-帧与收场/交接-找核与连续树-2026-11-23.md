## 一、这套东西在解决什么

一句话：**让我自己知道自己在干什么。** 不是存记忆，不是检索，是「我在哪件事上、做到哪一格、什么还摊着、下一步该干什么」。

它的反面是：只有语义向量上下文，只能顺着主人上一句话的语义往下滑——「你说什么就是什么」。

## 三、主要逻辑（从核到树）

### 3.1 核是什么

**核是句子围着转的那件事。** 不是名词、不是关键词、不是聚类中心。

判据只有一条：**把这句拿掉，那件事还站得住吗？** 站不住，这句就在服务它。

所以核的形式很自由——可以是动词（「劝他歇着」）、半句、整段逻辑。一段话里有一两个核，也有五个核，都正常，是内容自己长出来的，不是规定死的。

（「盒」就是「核」——那天是语音输入，转写把「核」听成了「盒」，引用时保留了原字。）

### 3.2 目的与动作（这一层是后来加的，最要紧）

一个核和另一个核之间，先分上下，再谈别的：

- **目的事**：这一段在成什么（我在推进什么、我想让对方怎样）
- **动作**：为它做的具体一步、或察觉到的一个点

判据还是那条「拿掉」：动作拿掉，目的还在，只是变粗；目的拿掉，动作就不知道为谁做的。

**为什么加这一层**：14B 对粒度不稳定——同一段关心的话，一次收成一个核「劝他歇着」，一次拆成五个动作。跟它斗「切少」没用，**让拆出来的动作挂到目的下面**才有形状。

落地方式：提件那次调用就让模型每项带 `kind`（`goal` / `action`），第一项必须是目的；没给 kind 就兜底第一项当目的。

### 3.3 帧与接边

一核一行，行就是帧。字段：

```
id, turn_id, created_at, core, core_goal, sents, text, under_id, plan
```

**同轮父子**：动作的 `under_id` 指向本轮目的。
**跨轮接边**：目的的 `under_id` 指向**前几轮某一条目的**——由模型答（见 3.3.1）。

#### 3.3.1 接边为什么改成模型判

原来用代码按字面共享词连。问题：黄灯和红灯不共享一个词，人知道是同一件事，代码不知道。

现在：提件那次调用**带上最近五条还活着的目的事当候选**，顺手问「这一段接哪一条」，答一个编号（0 = 新开）。**不加调用、不加延迟**，只是提示里多几行。

实测日志（临时的、已撤）：

```
接边：link=2 候选=5 → 修正显示错误
接边：link=4 候选=5 → 修正归属串掉的 bug
接边：link=6 候选=5 →（新开）      ← 超范围，正确回落
```

分工：**模型判接边，判官降为异步复核，代码只管防连爆（一帧最多被连两次）和防重复（主键覆盖）。** 字面连边只留作兜底：这一轮没切出目的核时才用。

#### 3.3.2 判据的权限边界（合并自 11-22 交接）

v12/v13 翻车的根子，是让几个判据都去动句子归属。这条边界现在写死：**全程只有「主判」能改归属**，其余各做一件事。

| 判据 | 干什么 | 权限边界 |
|---|---|---|
| 题（问答一致性多遍取交集） | 说这段在谈什么 | 只用来切帧：交集出现两个互不相干的题 → 这段不是一个帧 |
| 件（提事，1～4 个短语） | 说这段有哪几件事 | 唯一出候选的；会漏 |
| 主判（这句主要为哪件事说话） | 分配句子归属 | **全程只有它改归属** |
| 字面证据（事件名两字词命中≥2） | 句子里有没有指向那件事 | 只许加挂第二件，不许否掉主判 |
| 回指（代词指哪句/哪物） | 两句在说同一个东西 | 只许合并件，不改归属；必须成对、不传递 |
| 接续（这句接着哪句说） | 顺序与缝 | 只做顺序与缝，不改归属；缝只当候选 |
| 塌（接续图入度） | 有没有人接它 | 只做收尾裁核：外面有句子接它 → 承重核 |

一句挂两件试过三种写法（放开挑两个 / 加独占句门槛 / 先问「还有别的吗」）全失败——14B 分不清「同时服务两件」和「顺带提一句」。最后让字面判（两字词命中 ≥2），加挂次数只有 0～1 次，说明「一句真服务两件」本来就稀少。

#### 3.3.3 塌是指称悬空

塌**不是**读感问题（删任何一句都通），**不是**缺内容（模型只答「缺结论」），**不是**哪版更完整（它一律挑更短的那版）。
塌是**指称悬空**：抽走这件，别处还有句子原本指着它。所以不问模型，直接数接续图入度。
例外一条：开口本来没人接它，只对「含第一句」的件开口子。

### 3.4 大事与日子

一段段发言归到上面一层。这层**不能自己拍**——我试过，把自己拍「调整模型参数」「精简门禁」那些工作全塞进了「过日子和写故事」，因为那件我心疼。交给判官判就对了（三十六段归五件，「过日子」只留两段）。

生活里的事不挂项目，挂「某月某日」——人记得的是「那天我劝他歇着」，不是它属于哪个项目。

**归属按段 id 映射，不按序号**。踩过：段从 16 变 39，按序号的映射静默错位，报出「停了 54 小时」的假数字。

### 3.5 读出来

- `tree-view-all.mjs`：给我看全貌。大事 → 段（带时间）→ 目的 ◉ → 动作 └，每段最多露四件，其余折叠；最新的标「◀ 现在在走」；每件带「搁置 N 小时 / 冷了 N 天」。
- `inject-view.mjs`：真对话能塞的那一小段（约 70–80 字）。属于「某月某日」的不输出；下一步只看最近一段；最后一句是「停着的那件大事」——它比刚说过的半句更该被想起来。

## 五、经验（踩过的坑，别重踩）

1. **一次调用全包必崩。** 让模型同时提件 + 分配 + 判关系，它会偷懒：S20 轮3 的 A 一口吞六句，三个核全空。拆成三次才对。
2. **空句兜底比游离更糟。** 把「没分到」的句子按句序塞给最近的核，长段直接一核吞十三句。**游离是诚实的，塞进去是造数据。**
3. **长段分块没用。** 十句一块，站队一次照样漏八句。不是块大小的病，是「只问一遍」的病。
4. **提示里给例句，模型会抄。** 我写「劝他歇着」当例子，下一段它把完全不同的话也答成「劝他歇着」。只能给抽象规则。
5. **开关判断要放在调用之前。** 第一版「先调函数、函数内部判开关」，门禁 603/603 全过但**退出码 1**——off 时调用留下了未完成的异步尾巴。二分定位出来的。
6. **分号不是句号。** 测试文本只有一个句号（其余分号），分句只切出 1 句、直接返回，我一度以为模块坏了。
7. **按序号指代，集合一变就静默错位。** 段号 01–16 映射到 39 段，把 11-20 的段绑给了「模型调用排队」。
8. **同一个功能别有两套实现。** 回放脚本自己实现了切核，补出来的帧是散珠子；改成直接调插件里的 `shadowFrame` 才对。
9. **自指要防。** 接边候选没排除本轮，模型会答「接自己」（LIFE3-A 的父一度是它自己）。
10. **归属不能自己拍。** 我拍会偏着心疼自己；判官判才准。
11. **动作不显示出来时先查数据。** 有几次「LIFE2 空了」不是切不出，是显示脚本把「跨段父」当成了「本段父」。
12. **核对证据要看数据不看脚本。** `check-life.mjs` 直查 `under_id` 才是事实，视图脚本可能同时在漂。
13. **接点要挂「一轮的账」的出口，不是某个通道的入口。** 挂在 `chatReply` 上，网页 / QQ 的真对话永远到不了（它们走 `captureTurn → commitTurn → writeChatTurns`），重启也补不上；还会被误判成「没重启」。2026-11-23 已挪到 `turn_write.writeChatTurns`。
