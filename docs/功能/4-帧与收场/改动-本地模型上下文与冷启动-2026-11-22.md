# 改动：本地模型上下文改成统一 8192，修每次冷启动

2026-11-22。起因：本地 14B 每次调用都要重载模型（载入 17～55 秒，真正生成只要 1 秒），
一轮对话问十次就是十个冷启动堆起来。

## 定因

1. `local_llm.js` 里 `num_ctx` 写死 `16384`。14B 的 KV cache 在 16G 卡上装不下
   （模型 8.5G + 语义模型 1.1G + 桌面已占几 G），ollama 估得乐观、开起来实际分配失败，
   llama-server 子进程直接中止：日志 `llama-server process has terminated: exit status 0xffffffff`。
   子进程一死，下次请求必然冷启动。
2. 预热 `warmLocalModels` 没带 `num_ctx`，跟正式调用的参数不一致——就算不崩，
   ollama 也会当成另一份配置重载，白热一遍。
3. 正式调用 `keep_alive: '120s'`，每次调用都把预热设的 `-1` 改回 2 分钟，两分钟就被卸。

## 改了什么

`dsh-consciousness-v6/src/modules/local_llm.js`

- 新增 `localNumCtx(db)`：读 flag `memory.cut.local.num_ctx`，没设就 **8192**（原来 4096，再之前写死 16384）。
- `warmChat` 的 options 补 `num_ctx: localNumCtx(db)`。
- 正式调用 `localCtx` 处改成 `num_ctx: localNumCtx(db)`。
- `keep_alive: '120s'` → `keep_alive: -1`（跟预热一致，不再两分钟卸）。
- 库里 `memory.cut.local.num_gpu`：99 → `-1`（交给 ollama 自己分，实际全上 GPU 49/49 层）。

现在预热、正式调用、看门狗都只走 `localNumCtx()` 这一个口子，全仓 `num_ctx` 只有两处引用，都指向它。

## 验收（实测，本机 RTX 5080 16G）

| 配置 | 第二次起 | 载入 | 生成 | 显存 |
|---|---|---|---|---|
| 16384 | 每次 30～70 秒 | 17～55 秒 | — | 崩，子进程退出 |
| 4096 | 0.20 秒 | 0 秒 | 87 tok/s | 8.8G + 1.1G |
| 8192 | 0.21 秒 | 0 秒 | 83～86 tok/s | 9.6G + 1.1G（余 3.1G 空闲） |

选 8192：与 16384 相比不崩，与 4096 相比速度一样。

门禁：`通过 600 / 600`。

## 怎么退

`memory.cut.local.num_ctx` 设回 4096（或 16384，会崩）即可，不用改代码。
`keep_alive` 若要回到「跑完就散」，把 `-1` 改回 `'120s'`。
