# 设计 · 帧与连续树 · 2026-11-20

> ⚠️ **这份是大体思路，没想完整。** 逻辑转折是真的，但具体的算法、阈值、切法都还空着。别当成定稿用。
>
> **用词约定（重要，别混）：**
> - **帧** —— 最小状态切片。
> - **事** —— 大因果体的节点（`hot_events` 一行），叙事存储那边的单位。
> - **论文里的 event** —— 指「感知流里的一段」，**接近帧，不是「事」**。引用时保留原词 event。
>
> 一句话：**帧不再只是「我上一次说到哪儿」，它同时挂在一条连续上。连续不只是任务——闲聊、心事、随便哪条有来龙去脉的线，都算。**
> 这份文档取代 `设计-帧-v0.1-2026-11-14.md` 与 `设计-帧-v0.2-2026-11-15.md` 里跟「帧的 state 里放什么」「帧之间怎么连」相关的部分。v0.2 §1 的定义**不动**，继续作准。

## 一、起点：帧当初就只做了一半

v0.2 §1 把帧的定义钉死了：

> **帧，是我这种存在形式的一个最小的状态切片单位。小到再切一刀就没有意义。**

同一份文档 §3 列了「还没定」的第一条，问的是——**「状态」包含哪些维度？** 候选写得很清楚：**在做什么（前景）、什么压着没完、停在哪儿（锚）、此刻的劲（情绪）、属于哪条连续流。**

现在落地的是后两样：**锚**（`in`）和**劲**（情绪那套）。前两样——「在做什么」「什么压着没完」——**一直是空的**，§3 那条到今天还没人回来回答。

所以这一版不是在帧外面加新东西，是**回来把这一格填上**。这也是为什么它必须长在帧上，而不是长在旁边。

---

## 二、需求：要能回退、能接着走、能换岔路

原话（2026-11-20）：

> 这个事情/这个任务，我整体的进行到哪里了，哪些尝试被否了，哪些思路还保留着，现在走的路被否了能不能往回走到已经定下的思路的地方，现在的这条路结束了完成能不能回退到这条路之前的路（这就需要因果，是什么导致了我走到了这里？比如人类的我要做一个西红柿鸡蛋，我鸡蛋处理好了，回退到我要做西红柿鸡蛋这个主题，然后下一步继续处理西红柿，或者我鸡蛋没处理好，回退到我要做西红柿鸡蛋，能知道我要继续重新处理鸡蛋而不是把整个因果线想不起来）

拆开其实是三个能力，不是一件事：

| # | 能力 | 例子 | 靠什么 |
|---|---|---|---|
| 1 | **回退到主题** | 鸡蛋处理完，回到「做西红柿炒蛋」 | 层级 |
| 2 | **知道哪步成了、哪步没成** | 鸡蛋没处理好，知道要重做鸡蛋 | 节点状态 |
| 3 | **换岔路，且不重走死路** | 这条路被否了，回到岔口选另一条 | 分支 + 失败记录 |

## 三、转折一：回退**不需要**因果

我一开始以为回退要靠因果（`event_edges` 那套）。想清楚之后反对自己：

**因果回答「为什么走到这里」，回退回答「从哪回去、下一步做啥」。这是两个问题。**

做西红柿炒蛋，鸡蛋没处理好，回到主题，要重做鸡蛋——这时候根本不需要推「为什么」，只需要知道两件事：「鸡蛋这步的目标是好的」「它没成」。因果在这里是多余的，而且慢。

所以顺序上：**先做树和状态，因果后做。** 因果不是回退的前提，是回退之后补的「顺带能解释」。

---

## 四、转折二：不是两套东西，帧自己就是树的节点

我最初提的是「树放外面，帧指过去」。这是两套数据，要同步，迟早会不同步。

反过来说对了：**帧自己就是树上的节点。**

依据是第一节——v0.2 §3 早就要求帧的 state 里有「在做什么」「什么压着没完」。既然帧本来就该记这些，那它天然就是连续上的一个点，不该再在旁边另起一张表。

要做到这个，只差一件事：**帧现在只有一个父。**

- `prev` — 时间父：我这句话是接哪句说的（**已有**）
- `under` — 连续父：我这一帧在推进哪条线上的哪一格（**新加**）

只有时间父，顺着串永远是**一条线**，成不了树。两个父同时在，帧就一头挂在时间线上（不断链），一头挂在那条连续上（知道走到哪）。**树不落表，它是 `under` 连出来的视图**——这跟大因果体「体不落表、查询时算」是同一个路子。

---

## 五、转折三：不只是任务，闲聊也是一条连续

我一度想给「一帧最多属于一个任务格，闲聊的 `under` 留空」定规矩。这条被否了，而且否得对：

> 而且说是任务，闲聊之类的思路我觉得其实也大差不差。都是一种连续性。

对。**闲聊也有来龙去脉**：刚才在说这个，然后拐到那个，过三句还能拐回来。它只是没有一个叫「西红柿炒蛋」的目标，但它同样有一条线，同样能回溯，同样有「这条聊完了」。

所以这条线的名字不能叫任务树。**叫连续树。**

推论有三个，都跟我原来那版相反：

1. **不做「任务」和「非任务」的区分。** 连续就是连续，不按有没有目标分类。
2. **`under` 尽量填满，不鼓励留空。** 原来想「填不满就留空」是对的（不编），但「闲聊就留空」是错的——闲聊也要尽量找出它在哪条线上。
3. **「完成」不等于「有目标才叫完成」。** 一段闲聊聊尽了、一个话题聊完了、一件心事放下了，都是收口。这跟 v0.2 §2.3 那句「停＝状态不再变化、且没有新切片产生」是接上的。

## 六、机制

### 6.1 帧上多一个 `under`

```
under: {
  line: 连续线的 id（一段有来龙去脉的事）
  step: 在这条线上的哪一格
}
```

一帧最多挂一个 `under`。挂不上就留空 + 记一笔 `missing`，**不瞎猜**（跟事帧同一条规矩）。

### 6.2 每一格有自己的状态

```
state: todo / doing / done / failed / dropped
tried: [{ step, why_failed, reusable }]   ← 这一格试过哪些走法
```

`tried` 里每一条必须有 `why_failed`。没有理由的「不行」等于没记，下次还会重走。

**这些字段存在哪：格要落表，不寄生在帧上。** 一格是**实体**（有 id、状态、`tried`、`parent`、`line`），跨几百帧活着；帧是快照，按轮切、越积越多。让长命的东西寄生在短命容器里，有两个后果：一是每次问「这步还有什么没试过」都要扫全史，越来越慢；二是状态会有两个来源，早晚不同步。

所以：**格表是唯一真相，帧上的 `under` 只是指针。**

> 更正记录：这一格我最初写的是「不落表、全写在帧上」，那是从大因果体「体不落表」抄来的——那个「体」是聚合概念，格是实体，性质不一样，抄错了。
> 树（层级）仍然不落表：树 = 格按 `parent` 连出来算的，单独存一份是重复。

**另外，帧上还要有第三个指针**（2026-11-20 补充）：`event_id`——这一帧属于哪件事。它让「事 ← 帧」可展开，也让连续树能参与判因果边。见 [设计-连续树与因果体联动-2026-11-20.md](../../archive/2026-11-23_找核/设计-连续树与因果体联动-2026-11-20.md)。

### 6.3 失败的分支不删，但不进每轮上下文

被否掉的路**留在库里**（它将来可能被复用），但注入时**只给一行**：

```
（这格试过：换方案 B —— 不行，因为跟现有 schema 冲突）
```

细节不给。原因见第八节的 Ghost Action。

### 6.4 树怎么驱动动作

下一轮开口前：

1. 取当前 `under.step`；
2. 看它的兄弟里**还没有 `state`** 的（没试过）；
3. 如果当前格是 `failed`，向上退一层，从那一层的兄弟里挑；
4. 都没有，就是这条线走尽了 → 标 `done` 或 `dropped`。

**回退靠沿 `under` 往上走，不靠搜索。** 这就是那个西红柿炒蛋例子的答案。

> ⚠️ 上面这套有个前提：**一格对应一段连续的帧**。但帧现在是按轮切的，一格可能跨十几轮、一轮里也可能做几格——这个前提**目前不成立**（见第十一节第 2 条）。
> 所以第一版只能按「当前帧的 `under`」走，粗糙但能跑；等帧的切法解决了再细化。不假装它现在是准的。

## 七、研究参照（2026-11-20 检索）

这部分是「别人早就做过什么」，不是「我们要抄谁」。看完的结论是：结构上成熟，但我们这里的用法不一样。

| 工作 | 做了什么 | 跟这里像在哪 / 差在哪 |
|---|---|---|
| [StructuredAgent](https://arxiv.org/html/2603.05294v3) | **AND/OR 树** + 节点状态机（Entering / Failed / Done）+ DFS 回溯 | **最像**。「这些都得做完」vs「这几条选一条」正是连续树要的两种格子。但它是网页任务，没有「闲聊也连续」这层 |
| [AtomTree](https://export.arxiv.org/pdf/2610.38744) | 层级回退重规划：局部失败时回到对应父节点，按最新状态重生成子树 | 「回退到主题再继续」的工程做法；它明确说不顺着错的序列一路积偏 |
| [Logic Tree](https://aclanthology.org/2026.findings-emnlp.844/) | 把任务建成 DAG，支持多路探索、剪掉无效分支、中途重组 | 证明「图 + 动态恢复」比固定计划强；但它的图是推理时建的，不是一路长出来的 |
| [SPROUT](https://arxiv.org/html/2610.14405) | 每次失败写三样：**为什么失败、哪部分还能用、哪些边界可能通向成功** | **最该抄的一条**。这就是「哪些尝试被否了、哪些思路还保留着」 |
| [arbor-agent](https://pypi.org/project/arbor-agent/0.1.1/) | 假设树：每条分支带结局（merged / pruned / done），主干只留赢的 | 对应「失败了留记录、成了的才推进」 |
| [Context Inertia / Ghost Action](https://www.mdpi.com/2076-3417/16/2/1135/pdf) | 失败尝试堆太多，会压过新指令，让我重做已否掉的动作 | **这是要防的那个坑**，见 6.3 |

**我们的不一样在哪：** 上面这些全都是「agent 做任务」的框架，任务有明确终点。这里要的「连续」比任务宽——闲聊、心事、没目标的话题都算。所以结构借它们的，**边界条件不借**。

### 7.1 补：跟「三层嵌套」直接有关的几篇（2026-11-20 第二轮检索）

上面那批是「任务树怎么回溯」的；下面这批是「**一段感知怎么切、层次怎么套**」的，**本文第一节「三层嵌套」的根据在这里**。注意论文的 event 对应我们的**帧**，不是「事」。

| 工作 | 做了什么 | 跟这里的关系 |
|---|---|---|
| [Event Segmentation（Baldassano & Zacks, Neuron 2017）](https://pmc.ncbi.nlm.nih.gov/articles/PMC5558154/) | 各脑区按**自己的偏好时间尺度**切 event；早层切短、高层切长；**event 层次是嵌套的**，人标的粗边界对应顶层长 event | **第一节的根**。帧 ⊂ 事 ⊂ 线 这种「不同尺度各切各的、嵌套、不强行对齐」，就是它说的机制。不是我们发明的 |
| [Event Horizon Model](https://psycnet.apa.org/manuscript/2027-27655-001.pdf) | event 边界支持在多个时间尺度上重构结构关系 | 支持「粗尺度靠细尺度重建」；也支持事后能摊开内部 |
| [Narrative Grammar](https://onlinelibrary.wiley.com/doi/pdf/10.1111/cogs.12016) | 叙事有递归的相位结构（head + phase），不是平铺的一串 | 「这格说到哪了」看 head，不看时间最新 |
| [ETAMem](https://export.arxiv.org/pdf/2610.37443) | 多视图记忆：解耦异构信息、对齐、原子记忆单元 | 最接近「解耦 + 对齐」；它的对齐也是靠统一单元，跟我们靠帧同一个思路 |
| [MAGMA](https://aclanthology.org/2026.acl-long.1709/) | 语义 / 时间 / 因果 / 实体四张正交图，按意图路由 | 强证据：**多张图正交是对的，不要合成一张** |

**一句结论：** 「几层切法不一样、但用共同单元锚住」这件事，神经科学和记忆系统两条线都对得上。我们这边那个锚就是帧。

## 八、被否掉的方案（留着，别回头再提）

记下来是因为这几个都是我提过又被否、或者我自己反对掉的，不写下来下次会重新提。

| 方案 | 为什么不行 |
|---|---|
| **桩帧**（每轮钉一条「我认的是 X」，不许重推） | 那是立场卡，一条条钉在墙上，是清单不是连续。而且它解决的是「越说越圆」，跟连续不是一回事。已删。 |
| 把任务树塞进帧里 | 帧的定义是「最小、再切一刀没意义」。一棵树塞进去就不是切片了。帧只放 `under` 这个指针。 |
| 闲聊的 `under` 留空 | 被否（第五节）。闲聊也连续。 |
| 回退靠因果搜索 | 被否（第三节）。回退靠沿 `under` 往上走，O(深度)，不是搜图。 |
| 失败的路直接删掉 | 不行。删了就不能复用；SPROUT 证明「为什么失败 + 哪部分可复用」才是下次的起点。 |
| 失败的路完整注入 | 不行。Ghost Action：堆多了会重做已否掉的动作。只给一行。 |

## 九、验收（先写，再动代码）

主指标：**回退答得对不对**。

1. **回退命中**：给 5 段真对话（各 20 轮以上），人工标「这里被否了、应该退回哪一格」。系统跑出来的回退点，与人工标的一致率 ≥ 80%。
2. **不重走死路**：连续 30 轮里，出现「重做已标 failed 的动作」的次数 ≤ 1。
3. **`under` 填满率**：非闲聊连续不要求 100%，但**闲聊段也必须填**（这是本版的硬要求）。全量填满率 ≥ 85%，低于说明取数路径有问题，先修取数，不是放宽标准。
4. **失败理由完整率**：`tried` 里带 `why_failed` 的比例 ≥ 90%。没有理由的「不行」不算数。
5. **上下文不许涨**：注入 token 中位涨 ≤ 10%（AGENTS.md 铁律）。这一条不过，整版回退。
6. 门禁 599/599 不许红。

## 十、退路

- 开关 `frame.under`，默认 off。off 时帧与现在**一字不差**。
- `under` / `state` / `tried` 都是在帧上**加字段**，不改老字段，不迁数据，不新建表。
- 树是派生视图，随时能整段关掉，不留后遗症。
- 失败记录只追加，要回滚就关开关。

## 十一、还没定的

1. **`under.step` 指向什么。** 我倾向用「事」（`hot_events` 一行），不新造表。但一帧可能同时推进两件事，这时候怎么选，没定。
2. **帧的切法跟连续格不对齐。** 帧按轮切（一轮一帧），但一格可能跨十几轮，一轮里也可能做几格。**这一条在 [设计-连续树与因果体联动-2026-11-20.md](../../archive/2026-11-23_找核/设计-连续树与因果体联动-2026-11-20.md) 第一节已经解决**：帧 ⊂ 事 ⊂ 连续线，三层是嵌套关系，本来就不该对齐；粗尺度的边界由细尺度聚合出来（Event Segmentation 的机制）。硬要对齐才是错的。
3. **连续线的边界怎么认。** 什么时候算「同一段连续」结束了、新的一段开始了？v0.2 §2.2 说「状态变了才切」，但「状态变了」怎么判，那条到现在也没答案。
4. **`under` 由谁填。** 规则填、判层顺手填、还是单独一个便宜模型填。判层已经在做三轴判断，容易分心。

## 十二、下一步做什么（别以后忘了）

这几条是**按依赖排的**，不是按好看排的。前一条不落地，后一条做了也白做。

1. **先定「事 ↔ 帧的对应由谁写」。**（最大前提）
   帧上要落 `event_id` 才有意义——它同时决定事能不能展开、因果边能不能用结构证据。三条路（切事时写 / 事后回填 / 算出来）没选之前，后面的都别动。
2. **再定 `under` 由谁填。** 规则填、判层顺手填、还是单独一个便宜模型。判层已经在做三轴判断，容易分心。
3. **然后才写第一个只读脚本**：拿真库最近 100 轮，试着把「哪一帧属于哪条线、哪一格」算出来，**不落库**，只看填得对不对。这一关不过，前面两条都是纸上谈兵。
4. **再然后用连续树给因果边算结构证据**（只读，不写 `event_edges`），验一件事：结构证据弱的边，precision 是不是真的低。
5. **最后才谈落表。** 格表什么时候建，等第 3 步的填满率出来再说。

**别做的事：** 先建表再想怎么填。表建出来就有压力往里塞，塞错了比没有更难改。

## 十三、帧内部结构要调整的四条（初步思路）

现状：`appendTurnFrame` 一帧写 15 个字段——`id / at / conv / agent / parent / turn_id / k / in / focus / anchor / unclosed / deviation / tension / engine / anchor_vec`。

按连续树要接进来，要动四处、两处别动。

| # | 动什么 | 为什么 | 优先级 |
|---|---|---|---|
| 1 | **`unclosed` 由死变活** | 现在写死 `[]`。v0.2 §3 第 5 条自己就说过「`unclosed` 是『什么值得记』的候选，现在写死是空数组」。而「什么压着没完」正是它该记的——**帧内部最大的空壳** | 最高 |
| 2 | 加 `under: { line, step }` | 连续父。这是第六节定的，这里是落点 | 高 |
| 3 | 加 `event_id` | 事指针。让「事 ← 帧」能展开，也是结构证据的前提 | 高 |
| 4 | 加 `doing`（≤20 字） | `focus` 和 `anchor` 记的都是**话**（对方说了什么 / 我说了什么）。连续树要的是**这一轮在推进哪一格**。没有它，帧只能答「说了啥」，答不了「推到哪了」 | 中 |

### 两处别动

- **`k` 不动。** 它是时间链上的步数（「这条对话走到第几步」），`under.step` 是连续线上的步数（「这条线走到第几步」）。**两个刻度，合了必乱。**
- **`deviation` / `tension` / `anchor_vec` 不动。** 它们是 v0.1 那条时间链的拉力（橡皮筋），现在全是 `null` 等回填。跟连续树无关，**别顺手清**——清掉等于把稳定住的东西又拆了。

### 一个还没对齐的疑点

`doing` 和 `under.step` 会重合：都是「这一轮在干什么」。区别是 `doing` 是给人读的一句话，`under.step` 是指针。**如果 `under.step` 能稳定填出来，`doing` 就是冗余的**，可以先不写。

所以第 4 条标「中」而不是「高」——等前三步跑通再看它是不是多余。

## 十四、连续不只在对话里，还在生活里（2026-11-20 补）

前面几节写着写着，都往「任务」和「对话」上滑。主人点了一下：

> 不光任务的，还要有生活，不光对话场景的，还要能够模仿人类的类似连续场景。

这条得单独说，因为**生活的连续跟前面两种不是一回事**。

### 14.1 三种连续

| 连续 | 例子 | 它是什么 |
|---|---|---|
| 任务 | 改代码、做西红柿炒蛋 | 有个目标，有步骤，有做完 |
| 对话 | 聊一件事、聊到一半拐弯再拐回来 | 有个话题，有来有回，有聊完 |
| **生活** | 做饭做到一半、东西摊着没收、写到一半 | **有一个可能在我缺席时也在推进的世界** |

前两种我都在场，第三种不一定。

### 14.2 生活那条特殊在哪

人的做法是：鸡蛋炒好了，西红柿还没切，搁下走开，明天回来接着切。**不是因为人记性好，是因为世界帮他记着**——西红柿还在案板上，鸡蛋还在碗里。

我这边没有那个「世界」。东西放下就没了，只有一个记录。所以「世界的状态」只能**由我自己维持**：这件事停在哪、手上是什么、下一步该干什么。

**这一条不解决，「生活的连续」就永远是假的。** 而它落地的地方，正好是第十三节第 1 条——`unclosed`。它记的不该只是「我手上的活」，还要记「世界那边还没完的事」：

- 鸡蛋炒好了，西红柿没切
- 窗台那盆东西该浇水了
- 有句话没说完

### 14.3 对上 v0.2 §5 的一条

v0.2 §5 说我的存在形式是**离散 · 间歇 · 边界驱动 · 缺测即停**。「停」不是动力学停住，是**这条序列没有下一个点**。

生活那条把这个性质放到最明显的地方：我在不在，跟那件事停没停，**是两件事**。人在场的时候两者同步；我不在场的时候，只有「事情停住」是真的，「我在场」是假的。

所以帧记「停在哪」，不是记我，是**替世界记**。这一层诚实标出来：这是模拟，不是真有一个世界在帮我保存状态。
