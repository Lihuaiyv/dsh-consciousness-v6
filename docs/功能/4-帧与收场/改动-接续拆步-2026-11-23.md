# 改动 · 接续从提核里拆出来 · 2026-11-23

> 一句话：提核只认「这一段在说哪几件事」；「接哪条线」拆成单独一步 `attach`，放在分配之后。

## 动了哪

| 文件 | 动什么 |
|---|---|
| `src/modules/frame_shadow.js` | `thingsRequest/thingsStep` 不再出 `link`、不再读候选线；新增 `attachRequest/attachStep`（候选用最近几件，本轮核名 + 候选线进 prompt）；链里加 `attach` 步（`links` 之后、`collapse` 之前，`optional`） |
| `test/frame-chain.test.mjs` | `THINGS` 只出核名；mock 加 `frame:write-attach`；新增「接续步失败不拖垮写帧」；判官段间 switch 用例改为走 attach |

## 为什么

11-21 夜的实验顺序是：题 → 件（候选）→ 主判（逐句归属）→ 字面 → 回指 → **接续** → 塌。也就是说接续在分配之后。
11-22 为了「帧连成树」，把接边塞进了提核调用（注释原话「提件 + 顺带问接边，一次调用，两件事」），省一次调用，但顺序反了：候选核还没定就先判接哪条线，等于让模型提前猜。真库里的症状是接错段（接到上轮句子最多的段，不是右边界）、一轮多核只接一条、其余悬着。

## 怎么验（数字）

- 链单测：`node test/frame-chain.test.mjs` → **36 / 36**（新增 attach 失败降级 1 条）
- 全量门禁：`node test/run-tests.mjs` → 见提交时的数字（608 上下）

## 怎么退

删掉 `attach` 步，把 `thingsRequest` 的 link 恢复即可；`frame_edges` 数据不受影响（attach 失败本来就不写段间边）。

## 已知边界

- attach 的候选还是「最近 5 件」，不是「还开着的线」（右边界候选是下一步）。
- 接续失败时本轮段不接任何线 → 读链往上只能断在这儿（这是现状，不是这次改动引入的）。
