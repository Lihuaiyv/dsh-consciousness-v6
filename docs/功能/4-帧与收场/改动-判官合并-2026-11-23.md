# 改动 · 判官（合并 + 补漏/删非事）· 2026-11-23

> 一句话：本地三问只出候选（用整段原文问），最终核名交给宿主判官——合并同义、删非事、补漏。

## 动了哪

| 文件 | 动什么 |
|---|---|
| `src/modules/frame_shadow.js` | `topicReq` 改用整段原文（`ctx.text`）；删掉 `things` 提核步；新增 `judge` 步（`kind: host`，宿主任 `frame:write-judge`）：读整段原文 + 三份候选 + 本地合并参考，输出最终 `things`；判官空/失败回退本地合并题名（不拖垮写帧）；`runner.host` 接上 `hostComplete` + `kernelModel.complete`；`assignStep/fixStep` 过滤候选里不存在的字母（防凭空多核） |
| `test/frame-chain.test.mjs` | mockRunner 加 `host`（judge 默认回两核）；「判官空」改为回退本地题名；并发 runner 补 host；label 全部换 `frame:write-judge` |

## 为什么

1. **问模型要用整段**：切句后的「换这个？」会被当成一件；整段输入后，样本 2/4 的「样本太少」「meaning 系统改进」都回来了，也没有「问要不要换」这种对话动作。
2. **三问只出候选**：三次问法各答一次，互相隔离；它们的产出是候选，不是最终名单。
3. **判官定名单**：合并同义 + 删非事（问句/反问/征求同意）+ 补漏（三份都没提、但原文确实在说的）。实验里本地合并会为了压数量丢件（样本 1「数据被抬高」、样本 3「纠正前提」），宿主判官能保住。

## 成本

- 每轮多 **一次宿主调用**（`frame:write-judge`，聊天块优先级）；本地三问照旧。
- 判官失败/空 → 回退本地字面合并的题名，写帧不受影响（optional + fallback）。

## 怎么验（数字）

- 链单测：`node test/frame-chain.test.mjs` → **36 / 36**（新增「判官空回退」「并发 host」）
- 全量门禁：`node test/run-tests.mjs` → 见提交时数字

## 怎么退

删掉 `judge` 步，恢复 `things` 本地提核步（旧 prompt 在归档实验记录里）；`runner.host` 可留着。

## 已知边界

- 判官是宿主调用，比本地慢（几秒）；它按「最多 6 件」限，超过时取最实的 6 件。
- **事件补字段（2026-11-23）**：`frame.write` 事件现在记 `things`（判官给的核）、`assign`（每句归谁）、`missing`（漏句）。0 行时能一眼看出是判官没给、还是分配没分上。
- 判官补漏依赖整段原文；超长回复（>2000 字）可能截断（目前 prompt 没截，靠模型上下文）。
- **零句子核不再无声丢（已修）**：分配 prompt 要求「每件至少一句；分不上写 empty」；`assignStep` 兜底算出零句子字母，记进 `ctx.emptyCores`，写进 `frame.write` 事件的 `emptyCores`。落表仍只落有句子的核（结构如此），但事件里能看到哪件被丢了。
- 分配归属质量：模型可能把相邻主题的句子凑进一件（长段实测「句7」被归给「判官降级」）；靠 prompt 的「一句只归最贴的」约束，暂未做二次校验。
