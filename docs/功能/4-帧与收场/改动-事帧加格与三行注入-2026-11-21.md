## 二、为什么这么加

1. **四格只能答「我在做什么」**，答不了「还差什么、下一步」。所以要 `open`（手上没完的事）。
2. **`next` 不给模型写**：实测两次，让它直接写「下一步」，它写的是自己刚在做的事（「解释当前差距」）。改成从 `open` 第一条推——有卡点先解卡点，没卡点直接做。这是「模型不擅长选，擅长描述」那条教训的直接应用。
3. **`kind` 要双轨**：模型一律填「任务」，连麦克风充电那种生活场景也填任务。`kind` 先由模型写，`plusLine` 不校正（校正实测放在提示词侧，见下）。

2. `shadowFrameLine` 在有加格时输出 3 行（标题 + 正文 + 加格三行）
3. **把加格删掉后输出 2 行**——与改动前逐字一致，说明老路没被动

## 四、怎么退

- **字段级**：`agent_params` 里把 `affect.v4.affairs.plus` 设成 `off`。下一轮 `writeAffairs` 就不写那三格，`plusTail` 读到空自动不出那行，注入与以前一字不差。
- **代码级**：这两个改动各自独立，回退等于删掉 `plus` 相关几段；`motive/step/events` 一路没动。

## 七、格表：连续树真正接上了（21:00）

之前每轮只重写一份现状快照，所以会出现「它还写着『卡在插件还在跑旧代码』、可早就在跑了」这种事——没有树来更新它。

现在加了**格表**（flag `affect.v4.grid|<conv>`）：

- 用 `open` 里的**线名当 id**，每轮把 open 合进来；
- 还在 open 里 → `state=open`，更新 `done / todo / blocked`；
- 上一轮在、这一轮没了 → 自动 `state=done` 并记 `closedAt`；
- 注入层**先读格表**（开着的几条线 + 各自停在哪），没格表才退回 affairs 快照。

`verify-grid.mjs` 用内存库跑了两轮，走的就是西红柿炒鸡蛋：

```
第 1 轮：做西红柿炒鸡蛋（已做=鸡蛋炒好了，下一步=切西红柿）；改帧代码（卡在=门禁还没跑）
第 2 轮：做西红柿炒鸡蛋（已做=西红柿切好了，下一步=下锅炒）；改帧代码 → done
开着的线 1 条、已完成的线 1 条
```

**同一根线跨轮更新、做完的线自动封掉——这就是「接到前面的树上」。** 门禁仍是 599/599。

还没做：格表的 `parent`（父子）还没填，所以「回退到上一层」暂时走不通；注入只显示前两条线。

## 八、还没做的

1. **`under.line` 目前只记一条**（`open[0]`）：多条线并存已经进了 `openLines`，但连续树还只用得上第一条。真要「几条路各停在哪」，得让注入和树读取都改成多条。
2. **要重载插件才生效**，重载后下一轮才带出三格。
3. **`todo` 偏软**（14B 写「继续完善代码」这种）；宿主模型写会具体得多。
4. **闲聊场景只验了一段**（QQ 孤独那段），样本太少。
