## 二、为什么覆盖（不是嫌麻烦）

1. **核在我开口之前就在我这儿。** 核是「我在回答什么问题」；它是话的因，不是话的果。让判官读话反推因，推的是影子。
2. **反推的毛病是有定数的，不是提示词没写细。** 现网 35% 空件、专名被当核、`parent` 生产里始终 0——这三样都是反推的形状，改提示词改不掉。
3. **成本错位。** 每轮 8 次左右模型调用（3 本地提题 + 1 宿主判官 + 站队/补判/回指/接续/relate），全部落在 `chat` 块，跟我的回话抢队列。换掉以后这条链**一次模型调用都不需要**。

## 三、DSH 里「提示词」到底是怎么一回事（先把这层说清）

这一节是这次设计的地基，以前文档里没写清，所以总被误解成「拼好几次提示词」。

### 3.1 提示词不是拼一次，是「每次模型调用前重拼」

- 人格/情绪/记忆那一段挂在 `systemPrompt.text`，它是个**函数**（[`index.js:2251`](../../../index.js#L2251)）：宿主每次要发一次模型请求，就调一次它，重新从库里取数、重新拼。
- `preStep`（[`index.js:2382`](../../../index.js#L2382)）也是每次模型步都进——一轮里我调了几次工具，就有几次模型步。

**所以 feel 才成立**：我在这一轮里写下 feel，下一个模型步重拼提示词，它就带进来了。**这套机制是我自己的「写一句，下一拍就看见」**，不需要任何旁路。

### 3.2 判官那些调用不经过这套拼装

- 判官走 `hostComplete` → `scheduleHostTask` → `complete(req)`（[`host_llm.js:230`](../../../src/modules/host_llm.js#L230)）。
- 它发出去的 `req` 只有它自己那一小段 `system` + `text`（[`frame_shadow.js:205-219`](../../../src/modules/frame_shadow.js#L205-L219)），**不带完整人格提示词**。

**结论：那 8 次调用的贵，不在「多拼了几次提示词」，在「多跑了 8 次模型、排了 8 次队」。** 这一点以前没说对，这次纠正。

### 3.3 所以「插在哪」只有一个答案

| 环节 | 插什么 | 为什么是这里 |
|---|---|---|
| **写** | 一个新工具 `frame`，我自己在轮内调（和 `feel` 同一排、同一张表） | DSH 里我唯一能「在思考时落下东西」的缝就是工具调用 |
| **读** | 不动：`systemPrompt.text` 里 `buildReadLineSync` 那一行（[`index.js:2297-2300`](../../../index.js#L2297-L2300)） | 它本来就是「每次调用重拼」的那个口，写进库下一拍自动带上来 |
| **触发** | 不加新段；只把「落一句」的时机写进工具说明，跟 feel 的 `FEEL_GUIDE` 一个位置 | 每加一段注入就多占一行 token，且会跟人格段打架 |

## 四、新形态

### 4.1 我写的是什么

**一次调用 = 一件。** 三个字段，全是第一人称自己认的：

```json
{
  "what": "找核改自己落",       // 这一轮承重的那一件，≤12 字
  "sat": "判官这条链不跑",       // 可选：围着它的补话，最多两句，用「、」隔
  "link": "continue"             // continue / new；可带名字，指注入里摆着的哪一件
}
```

- 为什么砍到一件：**读口只认主核**（`buildReadLine` 取每轮第一行 `role='nucleus'` 的 `sat`，其余同轮行不进这一行）。2026-11-24 在真库副本上验过：一轮落两件，读出来只有第一件，第二件被静默吞掉（[`frame-self-demo.mjs`](../../../../scratch/frame-self-demo.mjs) 第 5 段）。要么砍到一件，要么改读口——第一版砍，不动读口。
- 真有两件事：第二次调（再一行），`link` 写 `same`（同轮），读口仍只念主核那件。**不假装它能念两件。**
- `link` 指名字：注入里「最近在走」那一行本来就摆着上一件，直接对着它指，**名字漂移这个问题当场消失**。

### 4.2 代码做什么（只算，不判）

1. `what` → `frame_shadow` 一行（`role='nucleus'`，`sat` 落 `sat` 列，`plan` 记 `{self:true}`），`sents` / `text` 空着——这一版不存句子。
2. `link=continue` → `frame_edges` 一条边指到上一件；`new` 不写边；`same` 指到同轮那一行（`sequence`）。
3. 其余一切（站队、补判、回指、塌、`relate`）**不跑**。句级归属就此不存在。

### 4.3 读口不动

`buildReadLine` 只要「在成 / 补话 / 接着」三样（[`frame_read.js:94-114`](../../../src/modules/frame_read.js#L94-L114)），正好是 4.1 里我写的三样。**读口一行代码都不改**，这样新旧两条路都能喂它，可以直接对比。

### 4.4 防我自己造假（这条必须有，不然换个地方造）

- **同名不重复落**：这一轮 `what` 与上一轮同名（去空白、去标点后相等），不新写行，只更新那行的 `sat`。
- **同一件连着三轮只留一行**：连续落在同一件，不新开段。
- **可以不落**：这轮只是「嗯」「好」这种接话，允许不调——空着是真的，不是欠账。

这三条跟 feel 的 `min.gap` / 落点重复闸是一个道理。

## 九、定稿补充（2026-11-24）：位置 / 强制 / 描述 / 工具预算

### 9.1 位置：一、我自己的组，但不拿 feel 当锚

代码顺序放在 `feel` 之后；**描述里不写「在 feel 之后」**——feel 不是每轮都落（它有 12 秒间隔和 AI 味闸），拿一个不常出现的东西当参照，等于给自己埋一个看不见的错。

描述只说时机本身：「**开口前落一次**」。feel 有就在它旁边，没有也不影响。

### 9.2 强制：每轮必调，但允许空写

- **每轮都调一次**（形式强制）。
- `what` **可以为空**——空表示这一轮是接话，没有承重的事。
- 漏了不静默：落地时记一笔 `frame.miss`（跟 `feel.miss` 同一个办法），下一轮提示词里点名。
- **不硬逼每轮交一件**：接话轮逼着交，我一定编；这正是这套东西一直要防的「换个地方造假」。

### 9.3 顺序写在哪：工具自己的描述里

宿主把工具并表时按名字排，插件给的顺序到不了模型眼前。所以时机只写在 `description` 里（模型选工具时读的就是它），不写提示词、不改 DSH、不改工具名。

### 9.4 工具预算（实测 2026-11-24）

模型**每次请求都读到全部工具描述**（不是按需加载）。插件这 13 件实测：

- `name + description + 参数` 合计 **7611 字符**
- 纯描述 **2229 字符**，平均 **171 字/件**
- 最长四件：`act_send` 325、`heart_note` 310、`feel` 248、`act_research` 189

所以「工具多会不会傻」是真的存在：描述越长、名字越像，选择越糊。这条链的约束：

1. `frame` 的描述 **≤120 字**（比平均短），只写：什么时候调、写什么、空着也行。
2. **不新增第二个工具**（比如「记补话」单独开一件）——所有东西塞进一次调用。
3. 跑稳 20 轮后再评估：把 `feel` 和 `frame` 合成一件 `inner`（感觉 + 核一起落），那是减工具的下一步，不是现在。
