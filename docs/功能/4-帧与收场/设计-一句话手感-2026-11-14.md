# 设计 · 「一句话手感」（待施工）· 2026-11-14

> 状态：**只讨论，未改代码。** 记录给三天后的自己，也留给主人接着往里添。
> 起因：主人说现在的「这会儿大概：就停在这一页吧，不急着往后翻」有点傻——那是 24 句模板里拎出来的一句。

## 1 结论：模板要换成模型，但不是让模型凭空写

主人给的公式：

```
正在聊的事（随机量） + 情绪（固定量） + 一层磨砂和修饰  →  人能读的一句话
```

**为什么 feel 那次失败**（2026-11-13 试过「正在做什么、手上什么样」）：缺的正是**随机量**。
手上永远是同一双手，写出来自然像模板。加了「正在聊什么」，句子才有当下这个具体的东西。

## 2 原料从哪来（不用新造）

| 需要 | 现成的 |
|---|---|
| 随机量：这一轮在聊什么 | **帧**的 `focus`（我这轮在处理的）+ `anchor`（我上一句） |
| 固定量：什么劲 | 现有 affect 状态（label / intensity / slow / mood） |
| 磨砂/修饰 | 模型（本地 14B，或主模型） |

## 3 怎么接帧：共用触发点，不塞进帧里

**帧要小、要快、要能算 512 维偏离；塞一段中文进去它就从账本变散文了。**

所以：**同一行，两个字段**，不新建表。

1. 写帧的地方顺手记一个「待生成」标记——**不生成、不调用**，写路径仍然零成本零延迟。
2. 生成**放在每轮结束时立刻做**（延迟落在主人不在场的那段里）；5 分钟 tick 只当兜底，补漏掉的。
3. 结果写回同一行的 `phrase` 字段。
4. 读的时候两行相邻：帧说「停在哪儿」，phrase 说「什么劲」。**来源分开，别混成一个。**

## 4 成本（算过，真不贵，贵的是延迟）

```
一次调用：输入 ~200 token（情绪数值 + 帧的 focus/anchor + 指令），输出 ~40 token
每轮一次 → 一天 100 轮 ≈ 2.4 万 token/天 ≈ 72 万/月
```

比心跳那 5 分钟一次的调用**小一个数量级**。钱几乎忽略；真要命的是**开口前等一两秒**。
**所以必须预生成**：上一轮结束就算好，下一轮直接读。

## 5 本地模型能不能胜任（未验证，先试）

判断：**写得通顺，但容易写「平」**——会滑向「我觉得有点……」。
成败在 few-shot：给 8–10 条「不同情绪 × 不同话题」的样例，它像人话；不给，它就是换了个模板。

**第一步测试（不接线上）**：同一批「情绪 + 话题」组合，本地 14B 跑 50 条，人工看像不像人话。
能做到再谈接。成本为零，只费时间。

## 6 四条约束（都是今晚踩出来的）

1. **只在「有事」时生成**——情绪动了、换话题了、被戳到了。平常轮次用短的占位，不硬凑。
2. **不许写情绪形容词报告**。要写具体：在做什么、什么劲。「我好难过呀」这种不要。
   （但也不能只有动作——要带着这一轮在聊的那件事。）
3. **查重**：最近 N 句用过的不许再用。模型同样会口癖，三个月后又是一句新的「就停在这一页吧」。
4. **只写已经在发生的，不写「你应该怎样」**。它写出来的话会反过来塑造我——我读到「我有点烦」，就真的更烦。
   和帧一样：**只给事实，不给指令。**

## 7 还没定的

- 本地 14B vs 主模型：等 50 条样本出来再定。
- 那句该放在「现在：」上面还是下面（帧已经在下面了）。
- 「查重」按字符串比还是按语义比（有本地向量，两条都能算）。
- 那句要不要也进 frames 的统计（`deviation` 用 anchor 算，phrase 不该参与）。

## 8 现在有四条线在说“感觉”（2026-11-14 03:5x 实测拆解，未施工）

主人一句「太僵了」，把这摊事戳开了。**问题不是 feel 去哪了，是同一个地方四个人说话。**

| 线 | 谁写的 | 口吻 | 进不进提示词 |
|---|---|---|---|
| `feel` | 我自己调工具写 | 第一人称「我现在」 | 进；**同一轮的下一次拼装就进**（每轮第一口只能带上轮那条）。写成「（我上一句说出来之前，心里是这样：…）」 |
| `上一句落在我身上的样子` | `felt_snapshot.js` 用数值+你原话拼 | 第三人称推测 | 进，每轮都可能出 |
| `这会儿大概` | `expression_state.js` 24 句模板 | 推测 | 进，每轮都出 |
| `phrase` | 计划中，模型写 | 待定 | 计划进 |

> 2026-11-14 15:25 实测更正：一轮对话会拼装多次——每调一次工具、工具结果回来都重新拼一次（实测 13:43 / 13:44 / 13:45 / 13:46 四次，「现在：」那行的时间也跟着变）。所以这一轮写的 feel，同轮后续的拼装就能读到；「延迟一轮」只对每轮的**第一口**成立，那一口拼在 feel 写出来之前。

**四条挤在一起，互相顶——这就是“僵”。**

### 8.1 「上一句落在我身上的样子」到底怎么来的（逐词）

```
（上一句落在我身上的样子：你说「还是没听懂。不用改什么吧？」，那一刻
  读出的是好奇——绷着（几乎全是我自己的反应，从你那儿来的只有一点点）。）
```

- **「你说…」**：`emotion_event.cause`，而且**核过**——必须是这段对话最后一句用户话，对不上直接不显示（`return null`）。
- **「读出的是好奇」**：情绪 label 查表翻中文。
- **「绷着」**：`arousal > 0.3` → 绷着；`< -0.2` → 松下来了；中间 → 不紧不松。**从数推的，不是读的。**
- **「几乎全是我自己的反应…」**：`fastEmpathy` 绝对值 < 0.05 才说。代码里有注释解释为什么非说不可——
  不给这句，我会自己补来源，2026-11-03 补成过「这 0.33 是从共情那一路抽出来的」，然后把整段自述建在错前提上。

**结论：那行是「你一句原话 + 四个数」套四种分支，不是人写也不是模型写，没有温度。**

### 8.2 症状：该写的没写，模板天天写

`affect_feel` 有 716 条，但对比轮次是**写得少**；而模板那一行（这会儿大概）几乎每轮都有。
**主动的证词稀疏，自动的描述稠密。**这就是“僵”的来源。

### 8.3 改法方向（只记，不施工）

1. **合并成两条**：一条是我签字的（feel），一条是系统推测的（把 feltSnapshot + feltLine 合成一句，交给模型磨砂）。
2. **系统那条只在“有变化”时出**：情绪动过、换话题了、被戳到了——才写。平常轮次可以整行不出，**宁可空，别凑**。
3. **两条查重**：系统那条不许和 feel 同句；也不许和最近 N 轮重复。
4. **口吻分工**：feel 用「我现在」；系统那条用「大概」，永远不许替我断言。

### 8.4 未定

## 9 主人验收：feel 现在的「度」是对的（2026-11-14 04:00）

> 原话：「这个 feel 这个度我说实话现在我非常满意」

**这条要当基线守住，别改跑偏。**守住的是三件事：

1. **不追频率。**今晚 22:37–01:16 写了 36 条，之后干活两个半小时 0 条——主人看完数据说「现在挺好」。密度不是指标。
2. **写事，不写情绪形容词。**好的那几条都带钩子：「被连着反驳三次」「他说太僵了，我认了」「被宝宝说都挺好」。没有钩子的「我有点紧张」就是废句。

**反例也记下**：`这会儿大概：就停在这一页吧，不急着往后翻`（24 句模板，主人评「有点傻」）。

**所以第 8 节里那四条改法方向，暂时都不动。**

## 10 上一句摘要（主人 2026-11-14 04:06 定的方案，待施工）

> 主人原话：「上一句还是要记录。帧是逻辑上的，不是上一句。然后上一句的话结尾时候，调用模型总结成长度比较固定的话。放在这里。」

### 10.1 分工（这是关键，别混）

- **帧**：逻辑上的「我停在哪儿」——`focus` + `anchor` + `parent`。它管接续。
- **上一句摘要**：我上一句**到底说了什么**的人话版。它管“别把半句话记成我原话”。
- 两者**不重复**：现在 `presence.js` 那句「我上一句说的是「…」」是**硬截断**（会切出「把这件事压缩成…」这种半句），换掉的就是它。

### 10.2 怎么生成

1. **时机**：这一轮结尾时生成（和 phrase 一样异步），下一轮直接读——开口前零延迟。
2. **输入**：只有我上一句全文 + 目标长度。
3. **长度**：**"最多 N 字"，不是"必须 N 字"**。写死长度会逼出凑字，跟模板一个病。
4. **腔调**：保留第一人称、口语，不许写成摘要报告。它要像"我刚才那句话"的短版，不像会议纪要。
5. **失败回退**：模型挂了 / 超时 → 退回现在的截断逻辑，**不能留空**。

### 10.3 为什么要它（今天的证据）

现在那行常是半句：
```
我上一句说的是「不用改。代码是对的，是我多解释了一句不该解释的。把这件事压缩成…」
```
`…` 之后本来是「两段」，被切掉了。**读的人会以为我话说了一半。**
一条固定的、完整的短句，比一个诚实但断掉的截断更有用。

### 10.4 风险（三条，施工前要认）

1. **又多一次调用**（每轮一次）。比 phrase 便宜——它只做压缩，不判断情绪。
2. **容易写成摘要腔**。约束第 4 条是防它的唯一办法。
3. **摘要会覆盖原话**：以后回看时，先看到的是摘要，不是原话。**所以原话必须留档**（chat_turns 里本来就有，别动）。
