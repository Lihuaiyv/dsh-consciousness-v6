## 顺序为什么这么排

照 v18 的判据顺序：**①题 → ②件 → ③主判 → ④字面证据 → ⑤回指 → ⑥接续 → ⑦塌**。
`fix`（漏句补判）紧跟 `assign`，因为漏句没归属，后面的字面/回指/接续都判不动。

| 步 | 判据 | 谁干 | 失败会怎样 |
|---|---|---|---|
| topics | 题 | 本地（可选） | 跳过，`split=false` |
| things/assign | 件 / 主判 | 本地（硬） | 停链 |
| fix | 漏句补判 | 本地（有漏才跑） | 停链 |
| literal | 字面证据 | 纯代码 | 不会失败 |
| coref | 回指 | 本地（可选） | 不合并，继续 |
| links | 接续 | 本地（可选） | 降级：`linksReady` 不置，塌跳过 |
| collapse | 塌 | 纯代码 | 不会失败（只在 linksReady 时跑） |

## 逻辑漏洞检查（这次特意验的）

1. **接续失败不能断整条写链** → optional 步骤 + `linksReady` 才让塌跑；测试覆盖。
2. **塌不能误伤开口** → 含第 1 句的核不判孤立；测试覆盖。
3. **回指不能链式合并**（A→B、B→C）→ `merged[to]` 防链式；测试覆盖。
4. **字面证据最多挂两件** → `cur.length >= 2` 就跳过；只加不删，不否主判。
5. **题不能偷偷改结构** → 只写 `plan.split`，测试断言仍落 2 行。
6. **块号单调不减** → 全链 B1，加载时校验。
7. **重放/并发** → 写帧主键覆盖、链防重入；原测试保持绿。

## 已知边界（别当没做）

- **题只判不切**：真要把一轮切成两帧，得改帧 id 结构（`turnId-A` → 段），这次没动。
- **塌只标记不删核**：孤立核仍落表，读链也没过滤；等真库数据攒够再决定「写不写」。
- 每轮多 3 次本地调用（题/回指/接续），异步不挡回复，但影子更慢（e2e 2 秒 → 4 秒）。
- 重载后才生效。
