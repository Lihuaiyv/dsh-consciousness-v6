## 2. 现在是怎么补的（接手的先看这里，别重复踩）

## 5. 怎么验才算完（建议顺序）

1. 先在真库副本上跑只读那批脚本，数字对得上再动下一块。
2. 切事按「同一批碎片、同一天、固定种子」跑新旧两版，比件数、覆盖率、碎片率（<5 分钟件应为 0）与单件最大跨度（≤90 分钟）。脚本现成：`scratch/shadow-run.mjs <day> <quantile> <minGap>`。
3. 编排类（自己想起/日记/导入导出）用真实会话回放，比「注入里出现了什么」而不是比代码。
4. 每改一处跑一次门禁；门禁红就停。

## 6. 红线（别再犯）

- 不要再对未提交的工作区用 `git checkout -- <文件>`。要回滚先 `git stash push -- <文件>` 或整目录复制到 `scratch/backup/`。
- 动真库前先备份：`Copy-Item runtime/consciousness/app.db scratch/backup/app-<日期>.db`；在线库要连 `-wal`、`-shm` 一起复制，否则副本会报 `database disk image is malformed`。
- 模型参数（`num_gpu` / `num_ctx` / `keep_alive`）改动前先申请，见 `src/modules/local_llm.js` 顶部警告。
