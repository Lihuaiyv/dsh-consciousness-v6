# 设计 · 事实怎么形成（C2 口径）· 2026-11-15

> 主人 20:2x 定稿的原则：**抽象切稳定**——事实不是从单次事件里「总结」出来的，而是跨事件重复后抽象出来的。
> 这份是设计口径；实现目前只在影子（`scripts/c2-shadow.mjs`），不写库、不进注入。

## 一、分层不变

| 层 | 存什么 | 规则 |
|---|---|---|
| 碎片 | 原话 | 只追加，不改 |
| 事（episode） | 一件事：时间、经过、原话引文、想头 | 只追加，带出处 |
| 事实库 | **跨事件成立的认识** | 新增，按下面的流程进来 |
| 叙事 | 日记/纪要 | 不变 |

事件层照旧存原话；**事实库不从事件层搬内容，只从「重复抽象」里长出来。**

## 二、流程

```
事件 → 蒸馏候选 gist → 跨事件聚类 → 同一 gist 在 ≥2 件独立事件出现 → 升为事实
                                   └─ 只出现 1 次 → 留在影子（weak），不升格
```

1. **蒸馏只出候选**：候选 = `kind`（world / preference / inference）+ 一句 gist（≤40 字）+ `why`（原文逐字片段）。
2. **候选不进事实库**：先落影子，按事件挂着。
3. **聚类**：同义/同一规律的候选并成一组。一组只许对应**一条**具体规律；需要「、」串多个偏好的，是合错了。
4. **升格**：组的支持事件数 ≥2（且事件不同）才升；`support` 一起写进事实。
5. **来源链**：每条事实保留 `events[]`（支持它的事件 id），随时可回到原文。

## 三、升格门槛（按类不同，2026-11-15 21:0x 定）

| 类 | 门槛 |
|---|---|
| world | ≥2 件独立事件 |
| preference | ≥2 件独立事件（「明确自述」单次升的例外还没接） |
| inference | **≥3 件**独立事件，且至少**跨 2 天**（防一场对话里连着说两次） |

所有类共同要求：
- 组内成员 ≤5 条（超过=并错了，标 `oversized` 不升）；
- gist 不含模糊词（某些/部分/有时/可能/相关/影响/通常/一般/往往/各种/各类）；
- falsifier 必须像一个场景（含「当/如果/假如/一旦/在……时」，或 ≥10 字）；写不出反例 = 空话。

## 三、两个例外（单次也能升）

- **挂得上已有图式**：同一类事已有事实（比如已有「他不想要主动推送」），新事件再强化 → 可以只凭一次强化该事实（相当于 Tse 2007 的「有图式时快速固化」）。
- **明确自述**：用户直接说了规则句（「以后别主动弹」「我不吃辣」）→ 一次即可升，但 `why` 必须逐字引用原句，并在 `support_reason` 标 `explicit`。

## 四、推断单独标

- `inference` 不是事实，是**当前最佳猜测**：带 `confidence`、`basis_events`，随新证据更新；
- 被反例推翻时不出库，走「改写/作废」记一笔，保留历史。

## 五、事实字段（草案）

```
kind: world | preference | inference
text: 一句话（≤40 字，删掉时间仍成立）
why: 原文逐字片段
events: [支持它的事件 id，≥2；例外见 §3]
support: 支持事件数
valid_from / valid_until: 有效期（可空）
confidence: 0~1（inference 必填）
source: 'distill'
```

## 六、验收（先定，后接线）

- 同一批事件跑两遍，升格的事实集合稳定（不抖）；
- 抽样 20 条升格事实，**没有一条**是「某次决定/某次行为/空话」；
- 每条都能点回 ≥2 件不同事件；
- 单次事件即使很精彩，也只能留影子——除非命中 §3 的例外，且例外要能在影子里标出来。

## 八、最新结论（2026-11-15 21:1x）

- 生成加 cue（下次遇到什么情境会想起它）+ effect（想起后做法有什么不同）；升格要求 cue 像情境、effect 非空；
- 同一批 60 件：候选 84 → 组 23 → **升格 0**；
- weak 原因：**no-use 8**、oversized 4、single-event 4、need-3-events 4、same-day 3；
- 两种可能：①这批对话确实没长出「以后用得上」的认识；②生成侧 cue/effect 填得太空（18 件空结果）。**还没分开验证**；
- 决定：**事实库先不建、不接线**；C2 停在「未证实有用」。若继续，先做检索验证（真实问题里事实能不能被召回、召回后做法变不变），不再纯调提示词。


## 九、口径更正（2026-11-15 21:2x，主人纠正）

**问题出在我们把「提示词要抽象」误读成「事实要抽象」。**

- **提示词**：要抽象、要写规则（防僵化），不能靠例子堆；
- **事实**：必须是客观、具体、可核对的——谁、什么、数字、时间、决定、原话；**不许抽象化**；
- 之前 60 件升格 0，不是没有有用信息，是「把事实当认识去概括」把具体性洗掉了。

## 十、按此改（待做）

1. 生成：抽具体事实；标签沿用现有，参考别家细分（profile / preference / boundary / behavior / project），不大改；
2. 判官：只问「客观吗、具体吗、有原文依据吗、以后检索得到吗」；空泛道理一律不收；
3. 聚类：只合并「同一件具体事实」的不同说法，合并后**取最具体、信息最全的那条**，不概括；
4. 升格：一次明确陈述即可收（project / preference / boundary / profile）；behavior 类要 ≥2 次；
5. 验收：同一批 60 件应出现具体条目（带名字/数字/决定），而不是 0。


### 十·补充（21:2x）：world 这一格允许抽象

- 默认：事实要**具体**（人名、数字、时间、决定、原话）——profile / preference / boundary / project 都按这个。
- **world 例外**：这一格就是留给「可复用的规律/道理」的（例：「格式服从和智力是两回事」「关掉思考的模型吐 JSON 更稳」）；
- world 的硬要求：有原文依据、能说出一个反例、能改变判断；否则就是空话，不收。
- behavior：倾向类，要 ≥2 次。


## 十一、可重复性验收（2026-11-15 23:0x）

- 已加：Ollama temperature=0、固定 seed=42；同一批 60 件连跑三次。
- 三次升格数：**10 / 12 / 12**；并集 29 条，**三次交集 = 0**；两两重合 1~2 条。
- 结论：14B 蒸馏 + 聚类这条流水线**不可重复**——同样的数据，每次留下的「事实」几乎不同。
- 处置：C2 停在影子，**事实库不建、不接线**；要再试只有两条路：换主模型（有成本）或改成「只作候选、不叫事实库」。门禁 580/580。
