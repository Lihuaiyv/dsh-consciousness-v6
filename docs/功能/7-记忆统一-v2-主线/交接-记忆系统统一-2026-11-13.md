## 2 核心问题：碎片 → 事/事实 的开销

已知数字（2026-11-13）：
- `memory_items` 约 5,4xx 条；每轮 `episode/manual` 约 500 条/天；
- 事件：冷/热各 48；10-27 一天清洗后 896 行 → **41 块**（8000 字/块）；11-12 同规模；
- 一次 daily 块 ≈ 8~11k tokens（输入 5~6k + 输出 1.5~4k）；41 块 ≈ **33~45 万 tokens/天**；
- work 轻模型一块 ≈ 6.5~7.5k，只省 20%~30%；
- 规则切 0 次，但边界粗。

**这就是当前的总问题**：一天的量需要几十次调用，切事/沉淀一次就是几十万 token。
其余问题（work 段标准、锁、断点、批量、限额、本地模型）都是围绕它的子问题。

## 3 已做的降本（都已过门禁 566/566）

1. 抽取：`qqBatchExtract` 3 句 → 12 句；worker 合并读 5 合 1（`memory.extract.batch` / `memory.extract.merge`）。
2. 切事：`splitDayBatch` 按 mode 分段、按字数（8000 字）切块；空回自动砍半重试；
   `cutDayBatch` 每块落库 + 断点续 + 同一天并发锁（`events.cut.<day>.lock`）；
   **不设次数上限**（冷库要完整；护栏只剩锁与断点）。
3. 自动 worker：只切「前一天 + 近 30 天有碎片但没落 done 的欠账天」；切不完下一跳续。
4. 10-27 真机对照：12 次调用 → 8 件切出、7 件入库、1 件拒收（抓手不够专名）。

## 4 未决的关键取舍（新脑子请先想这个）

1. **work 段**：轻模型（约 6.5~7.5k/块）vs 规则切（0 次、边界粗）vs 混合（规则兜底 + 长段/关键信号升级轻模型，省 80%+）。
2. **本地模型**：能否把「切事/摘要」接到本机（Ollama 等），回复仍走 DSH 模型；
   初步调研：Qwen2.5-7B/14B 强在 JSON/结构化输出；GLM4-9B 强在中文长文（128K）；Gemma 4B 轻量；
   比模型更关键的是**约束解码**（Ollama `format:json` / JSON Schema、vLLM guided_json、llama.cpp GBNF）。
   需要：实测同一块 prompt 的件数、证据合格率、速度；未知：本机显卡/显存。
3. **事实两条来路**（D20）：`extract` 与「事件→事实」蒸馏并存；当前事件库还薄，先不拔旧路。
4. **读侧**：已定「不分区、不加权、不过滤」——靠抓手撞；不要再为模式动读口。
