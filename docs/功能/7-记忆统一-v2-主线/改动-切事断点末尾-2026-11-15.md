## 为什么

`splitDayBatch` 原来的结束条件是「最后一块处理过、且不是空回/写错」。
但断点 `pos` 记录的是「最后切完那一块的最后一轮」；当它落在最后一块之后（比如尾巴块已经切过、后来又有新碎片让 chunks 变长又变回来），这一轮 `for` 循环一次都不进，`results` 是空数组 → `lastOk=false` → `finished=false`。
于是 `cutDayBatch` 每次都写 `state=pending`，worker 每 30 分钟调一次、每次 0 调用 0 写入——**看起来在跑，实际原地空转**，而且永远好不了。

## 怎么验（数字）

- 副本复现：修前 `cutDayBatch` 0 秒返回 `chunks=92 calls=0 finished=false`，冷事件 0 新增；修后同样输入返回 `finished=true state=done`，`dayCutGate` 变 `up-to-date`，`doneAt` 自动补到 17:25:02.708Z。
- 验收：`node scripts/check-event-batch.mjs` → **8/8 PASS**（新增「断点已在末尾」）。
- 真库补数据（先备份 `scratch/backup/app-2026-11-15-1342.db`）：4 段粗切写库，**added 4 / rejected 0 / hotAdded 4**；事件库 **2025 → 2029**（11-14：65 → 69）；盖章 `doneAt=2026-11-14T17:25:02.708Z`，gate=up-to-date。
