# 改动 · 事层去掉 act（2026-11-22）

> 主人：「把 act 从事层拿掉。」
> 只动事层（`TOPIC_SYS` 那一层），不碰判断层、三递质、选词。

## 一、动了哪

| 位置 | 改动 |
|---|---|
| `TOPIC_SYS` | 输出的 JSON 从四键收成**三键**（summary / what / target）；删掉「act：这一句算什么动作——威胁、骂、夸、求、问、收话、闲聊，七选一」那行 |
| `appraiseTurnNow` | ① `slot` 不再带 `act`；② frame 不再写 `act`；③ 解析事层输出时删掉 act 分支；④ `missing` 不再记 `act`；⑤ 规则垫底行改成 `rulesJudgment(null)`（给的是中性数，不是对这句的判定） |
| `missing` 的语义 | 事层**没跑成**时记 `missing.topic`（原来靠「act 空」当信号——可 act 常常空着，分不清是没跑还是模型没给） |
| 判断输入 | 「事层没回来」的提示条件从 `missing.act` 改成 `missing.topic`，措辞改成「这句没有摘要和冲谁」 |

**没动**：summary / what / target 的取法、判断层十个字段、三递质、选词、任何数值。

## 二、为什么

`act` 在整条链上没有读者：判断层输入里没有它（只有「正在发生 / 我上一句 / 这一句 / 冲谁 / …」），
选词的 `slotOf` 不读它，三递质的增量不读它。它唯一喂的是那张**不算结论**的规则垫底行
（状态只由最终那行写回）。而它还是事层最不稳的一键：真库 11-21 起 381 条 model 行里填满率 **79.5%**
——每五轮就有一轮空着，还天天往 `missing` 里报。

收窄之后：本地 14B 少判一件事、输出短一截（超时/漏写概率跟着降）、`missing` 少一个常年误报的键。

## 三、怎么验

```powershell
node ..\scratch\frame-core\verify-frame-ctx.mjs      # 23 项
node ..\scratch\frame-core\verify-frame-fallback.mjs # 16 项
node scripts/check-appraise-turn.mjs                 # 19 项
node scripts/check-affect-chain-e2e.mjs              # 19 项
node test/run-tests.mjs                              # 门禁
```

`verify-frame-ctx` 里「事层没回来」那条改成**源码断言**：传了 `complete` 的测试根本不跑事层，
造不出「事层失败」的场景；现在断言源码里真有「记 `missing.topic` + 判断输入说明事层没回来」两段，
真链路行为靠观察 `missing.topic` 的出现率。

实测：`verify-frame-ctx` **23/23**、`verify-frame-fallback` **16/16**、`check-appraise-turn` **19/19**、
`check-affect-chain-e2e` **19/19**、门禁 **602/602**（exit 0）。
