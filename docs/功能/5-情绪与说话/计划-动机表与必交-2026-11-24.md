# 计划：动机表与「必交」

日期：2026-11-24
状态：设计定稿，未实施
一句话：每轮开头强制我交一份「这轮要干什么」，之后每次状态落后就强制补交；交到「待办空、无未提交动作」时，触发收口。

## 为什么做

今天下午两个现象：

- 16:35:46 那次 `affect:judge` 跑了 **54,725 ms**，而它 `timeoutMs: 0`、又跑在 preStep 里等我——整轮停 54 秒。
- `close` 靠我自觉调。漏了只有 `turn/end` 记一笔；而「开口前」这一步没有可插信的缝，强制只能提前或退后。

绕开的办法不是加更硬的强制，而是把「结尾」变成一个能判断的状态：**待办全空**。

## 形状（很轻，没有算法）

一张表 `motivation`，每轮几行：

| 列 | 意思 |
|---|---|
| `turn_id` / `agent_id` | 哪一轮 |
| `seq` | 第几版 |
| `items_json` | 待办：`[{id, text, done}]`，最多 3 条 |
| `note` | 这一版改了什么、为什么改（必填，一句话） |
| `submitted_at` | 提交时间 |

规则只有三条：

1. **轮头必交**：第一封信发出前没交过 → 强制调 `plan` 写一版。写「这轮不办事，陪她说会儿话」也算交。
2. **落后必交**：这一轮调过的工具、勾掉的待办，和表里最新一版对不上 → 强制先更新。
3. **交干净了就收口**：待办全勾（或删光并写了原因）且无未提交动作 → 下一步强制 `emotion`（判断层），随后 `close`。

核 = 最终版：`items_json` 的最终形态 + 各版 `note`，由代码拼成一句话，不再跑模型「找核」。

## 钩子挂哪（都已核过存在）

- `agent/pre-step`：每封信发出前检查上面三条。已在我们 `preStep` 里，直接加一段。
- `deepseekLlmApiExtensions.register('tool_choice', …)`：把「这一步必须调 `plan` / `emotion`」写进请求。字段名可认领，`tool_choice` 不在基础请求里，不冲突。
- `model.select({ provider, model, reasoningEffort: 'off' })`：强制那一拍关思考（思考模式下 DeepSeek 拒绝指定函数，会 400）。之后拨回原档。
- `agent/turn-stopping` / `turn/end`：兜底——没交、没触发就记一笔，不推用户窗口。

## 验收

1. 一轮纯聊天：轮头强制出 `plan` 一版（写「不办事」），不报错、不卡。
2. 一轮有活：待办勾完后，下一封信被强制调 `emotion`；之后再放行说话。
3. 落后检测：工具调用后不更新 plan，必然被拦一次补交。
4. 删光要原因：删光但 `note` 为空 → 视为未交，被拦。
5. 门禁不红，且 `affect.on=off` 时整套自动让路（这条链属于情绪上下文，总闸关着就不工作）。

## 不做

- 不把「哪条待办配哪个工具」写进计划：工具选择留给有思考的步骤。
- 不写结论：计划只写待办和原因。
- 不强制内容：一句话也算过；可以空、可以删（带原因）。
- 不为了它去动算法或模型。

## 软化的口子

- 每轮最多 3 条待办；纯聊天轮允许「不办事」。
- 计划可以随时改，改必带一句原因，旧版保留。
- 整套带开关（先默认 off），能一句撤掉。
