# 计划：动机与「必交」

日期：2026-11-24（定稿）
状态：设计定稿，未实施
一句话：每轮开头强制交一份「这一轮为什么值得做 + 要做什么」；之后每次改动都得重交动机；交到「待办全清、无未提交动作」时，触发收口。

## 一句话的形状

**动机是因，计划是果。** 表叫 `plan`，工具也叫 `plan`，页面 `/plan`，同一个词。

一版交两格：

- `motive` —— 一句话：这一轮为什么值得做、我想得到什么。**每版必填**；没变就写「同前」（这本身是一次确认）。
- `items` —— 台上待办 1–3 条，动词开头；可以空（写「这轮不办事」那一版也算交）。
- `deferred` —— 台下延后池，不限条数；从台上挪下来的写一句为什么延后，下一轮可捞回。

**动机得挂得住。** 每版 `source` 必须填：他那句原话、文档里某个「还没做」、或我自己冒出来的念头。preStep 已经把这一轮的原话拿到了，一起存进去——对不上就是偏题，页面上一眼能看见。

**改计划必须重交动机。** 改动时那句原因，就是在回答「动机还成立吗」：多半是「动机没变，这条路走不通」，少数是「动机变了」——旧动机照样留在历史里，不能悄悄换。没有 `motive` 的那一版 = 未交，被拦。

与情绪分开：`emotion` 管「我心里那股劲」，`plan` 管「我这一轮想干成什么」。

## 表

`plan`，每轮几行，只追加不改写：

| 列 | 意思 |
|---|---|
| `turn_id` / `agent_id` | 哪一轮 |
| `source` | 动机挂在哪：`user`（他那句原话 + 轮次号）/ `doc`（某个「还没做」）/ `self`（我自己冒出来的念头） |
| `seq` | 第几版 |
| `motive` | 这一版的动机；「同前」= 确认未变 |
| `motive_changed` | 与上一版不同就为 1（页面据此高亮） |
| `items_json` | **台上**待办：`[{id, text, done}]`，最多 3 条（这一轮真在动的） |
| `deferred_json` | **台下**延后池：`[{id, text, reason}]`，不限条数（不丢，随时可捞回来） |
| `note` | 这版改了什么、为什么改（一句话，我写） |
| `diff_json` | **代码自动算的改动明细**（新增 / 勾完 / 删除 / 改字），不是我填的；填了也会被覆盖 |
| `submitted_at` | 提交时间 |

## 三条规则

1. **轮头必交**：第一封信发出前没交过 → 强制调 `plan`。写「这轮不办事，陪她说会儿话」也算交。
2. **落后必交**：这一轮调过工具、勾过待办，和最新一版对不上 → 强制先更新（并且必须带 `motive`）。
3. **交干净就收口**：`items` 全勾（或删空并写清原因）且无未提交动作 → 下一步强制 `emotion`，随后 `close`。

核 = 最终版：`motive` + 最终 `items` + 各版 `note`，由代码拼成一句话，不再跑模型「找核」。

## 改动怎么被检查（代码在旁边看着）

一次改几条都行，不要求一条一条来——拆成三次提交要多三次强制、三次没思考的往返，太贵。防糊靠**显形**，不靠禁止：

- **编号继承**：新版里原有待办必须沿用旧编号，不许整批换新号重写。这样一比就知道哪条勾了、哪条字改了、哪条删了。
- **台面只摆三条**：总数不封顶，但同一时刻“在动的”最多三条。干到一半发现别的事更该做，就把台上一件挪到台下（写一句为什么延后），新事补上台——总数没涨，顺序换了，不算撞红线。
- **上台必须说清下了谁**：往台上加一条，而台上原本已满，必须在 `note` 里写明挪走了哪条；不写 → 拒收入。
- **代码校验（不合格直接拒收）**：台上超过 3 条；编号重复或缺失；同一条又勾又删；`motive` 空着；条数变了但编号不继承；上台没写下台了谁。
- **明细自动生成**：`diff_json` 由代码比对上一版算出，页面上翻成中文一行行摆：完成 1 条、新增 1 条、删除 0 条、改字 0 条。
- **动机与改动分开放**：我写"为什么"（`note`），代码写"改了什么"（`diff_json`）。两者对不上时，页面会标出来——比如我说"没改计划"，明细却显示勾了两条。

## 你能看见（P0.5）

插件自带的只读页 `/plan`，两秒轮询，只看库：动机在顶、**来源紧跟着**（原话摘要或文档条目）、待办在下面、改动历史按 `seq` 排，每版附一行中文明细（完成 / 新增 / 删除 / 改字）；动机变过的版本标出来；再看两行状态——「判定落后 / 已交」。

成本：写表是一次 insert（毫秒级），页面只是 SELECT，不碰模型、不占队列。**不用文档当窗口**——每轮写快照会把 `docs/` 堆成山；历史在库里，需要留证的某轮再手动导出。

## 钩子挂哪（都已核过存在）

- `agent/pre-step`：每封信发出前检查上面三条。已在我们 `preStep` 里，直接加一段。
- `deepseekLlmApiExtensions.register('tool_choice', …)`：把「这一步必须调 `plan` / `emotion`」写进请求。`tool_choice` 不在基础请求里，不冲突。
- `model.select({ provider, model, reasoningEffort: 'off' })`：强制那一拍关思考（思考模式下 DeepSeek 拒绝指定函数，会 400），之后拨回原档。
- `agent/turn-stopping` / `turn/end`：兜底，没交、没触发就记一笔，不推用户窗口。

## 验收

1. 纯聊天轮：轮头强制出一版（动机 + 「不办事」），不报错、不卡。
2. 有活的一轮：待办勾完后，下一封信被强制调 `emotion`；之后再放行说话。
3. 改动必须带动机：只改 `items` 不写 `motive` → 视为未交，被拦。
4. 删光要原因：`items` 空但 `motive` / `note` 缺 → 同样被拦。
5. 门禁不红；`affect.on=off` 时这条链也让路（它挂在情绪上下文上）。

## 不做

- 不把「哪条待办配哪个工具」写进计划：工具选择留给有思考的步骤。
- 不写结论：计划只写动机、待办、原因、来源。
- 不替我做决定：README 的「还没做」只是原料，不自动变成待办；写什么仍由我定。
- 不强制内容：一句话也算过；可以空、可以删（带原因）。
- 不为它改算法或模型。

## 留出的活动空间（不是“聊天例外”）

这套东西不是跑道，是记录我怎么走的。不管这一轮是聊天还是办事，都要留够空间：

- **动机可以很粗**：一句话就够，“先看看再定”也算动机；不要求写得多准、多好听。
- **待办可以少、可以撤、可以换**：改就带一句原因，旧版全留；删空也算一版（只要写了为什么）。
- **偏离不算违规**：干到一半发现另一件更该做，改计划就行——**把原因写下来就够**，不用道歉、不用装作原本就这么打算。
- **判断权归我**：规则只查“有没有交、改得清不清楚”，不查“做得对不对、值不值得”。
- **强度可调**：提醒 / 只记账 / 真拦，三档，默认最软；整块开关 `motivation.on` 和表都能撤。
- **唯一硬的地方**：动机必须挂住一个来源、改计划必须重交动机、编号必须继承。这三条是“可信”，不是“听话”。

## 施工步骤（P0–P4，每步先验收再动手）

### P0 先能看见（0 行逻辑）

只加观测：`events` 写 `plan.submit`（第几版、几条待办、动机变没变）和 `plan.check`（查了什么、判定落后没有）。

- 验收：跑一轮，库里能查到这两类记录；提交次数 = 我实际调 `plan` 的次数。
- 退路：无（不改行为）。

### P0.5 只读页 `/plan`

动机在顶、待办、改动历史、状态两行。

- 验收：浏览器打开能看到上面四样；刷新后跟着库变；不开页面时零开销。
- 退路：删路由。

### P1 表和工具（还不管）

建 `plan` 表 + `plan` 工具（`motive` / `items` / `note` / `action`）。

- 验收：一轮里我能自然写出动机和 2–3 条并勾完；`seq` 递增、旧版仍在；只改 `items` 不带 `motive` 会被拒。
- 退路：删工具，表留着不碍事。

### P2 必交检查（只记账，不拦）

每次模型步之前查：交过没有；上一版之后有没有工具调用或勾选没同步。落后只写 `plan.check`，不强制。

- 验收：纯聊天轮也记到「没交」；有活的一轮在勾完后仍记为「落后」，不当成已交。
- 退路：关 `motivation.on`。

### P3 强制（第一次真正拦）

接两个钩子：`tool_choice` 指定 `plan`；`model.select` 关那一拍思考再拨回。

- 验收：一轮里至少被拦一次并补齐；补齐后能继续；那一封信确实非思考（`host_calls` 里思考字数为 0）。
- 退路：`motivation.force=off` 只关强制、保留记账。

### P4 收口触发

条件：`items` 全勾（或删空带原因）+ 无未提交动作 → 下一步强制 `emotion`，随后 `close`。

- 验收：一轮有活，收口落在说话之前（唯一例外：最后一封信里临时起意，这条已知拦不住）。
- 退路：`motivation.close.gate=off`，回到「靠自觉 + turn/end 记账」。

### 依赖

P0 → P0.5 → P1 → P2 严格串；P3 依赖 P2 判定准；P4 依赖 P3 能用。P4 也可以先做预演，但那时收口仍可能漏。
