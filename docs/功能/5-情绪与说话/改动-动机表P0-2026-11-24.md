# 改动 · 动机表 P0（只加观测）

日期：2026-11-24
范围：P0 一步，只搭记账，不改任何行为。

## 动了哪

- 新增 `src/modules/motivation.js`：建 `plan` 表（幂等）；`logSubmit` / `logCheck` 两个函数只往 `events` 写 `plan.submit` / `plan.check`；`latestPlan` 读最新一版。**没有任何检查、没有强制、没有工具。**
- `src/db.js`：开库时顺带调 `ensureMotivationSchema(db)`（和 `ensureSangguanSchema` 同一个位置、同一个 try 兜底）。
- `src/kernel.js`：登记三个参数，全部默认关——`motivation.on`（总闸）、`motivation.force`（强制）、`motivation.close.gate`（收口触发）。

## 为什么

计划的 P0 是「先能看见」。但当前还没有 `plan` 工具，所以「提交」不可能自然发生——P0 的真实产出是**把记账的位置先占好**：表和两个事件类型都在，后面接工具/判定时不需要再补观测。

## 怎么验

`node scratch/p0-plan-check.mjs`（临时库，不碰真库）：

- `plan` 表已建；
- 调两次 `logSubmit` → `plan.submit` 两笔，`seq` 1/2，`items` 条数对得上，第二笔 `motiveChanged=false`；
- 调一次 `logCheck` → `plan.check` 一笔，`stale=true`；
- `latestPlan` 仍为 `null`——证明 P0 只记账、不写表、不参与判断。

门禁：`node test/run-tests.mjs` → 610 / 610。

## 踩到的坑

第一版 `motivation.js` 里 `import { nid } from '../kernel.js'`，而 `db.js` 引 `motivation.js`，`kernel.js` 又经 `algo/index.js` 引回 `db.js`——成环，门禁两条红（`Cannot access 'bootstrapped' before initialization`）。改成模块内自带 `now` / `nid`，不引 kernel，环断开。

## 怎么退

删掉 `src/modules/motivation.js`、`db.js` 里那两行 import+调用、`kernel.js` 里三个参数。表留着不碍事（`affect.on` 那套也是这么退的）。
