# 设计 · 事帧 v2（2026-11-19）

> 一句话：事帧只写「**发生了什么**」。感觉、好坏、要不要紧，**一个字都不进事帧**，全部交给判断层。
> 这一版的目标不是加字段，是**把「我上一句」和「这事第几轮」放进来**——因为我现在对自己刚说的话没有记忆。

## 一、三条原则

1. **事帧只写事实**。谁、做了什么、冲谁、什么时候、第几次。写「难过」「威胁」进事帧就废了。
2. **判断层只写幅度**。goal_delta / expect_delta / future_delta 是「这一下推了多少」，不是标签。
3. **进事帧的每个字段都要能被代码填满**。填不满就留空 + 记一笔 `missing`，不瞎猜。

## 二、字段表（四组）

### A 时空（代码填，零模型）

| 字段 | 类型 | 说明 |
|---|---|---|
| `conv` | string | 会话 id。会话隔离用，跨会话不串。 |
| `turn` | int | 这一轮在本会话里的序号（chat_turns 行号）。 |
| `at` | ISO | 这一轮发生的时间。 |
| `gapMs` | int | 距上一轮隔了多久。**隔 3 秒和隔 8 小时，同一句话的重量不一样**。 |
| `open` / `startedAt` / `lastAt` | | 保留现有：这一帧还开着吗、什么时候开的、最后一次更新。 |

### B 事本身（规则 + 模型填，模型只填摘要类）

| 字段 | 取值 | 谁填 | 说明 |
|---|---|---|---|
| `who` | owner / self / other / world | 规则 | 这件事是谁做的。现有 `who` 恒为 owner，v2 明确成「谁发起」。 |
| `act` | threat / criticize / praise / request / ask / withdraw / chat | 规则先出，模型可改 | 做了什么。 |
| `target` | me / other / none | 规则先出，模型可改 | 冲谁。 |
| `agency` | self / other / world | 规则 | 谁造成的。 |
| `what` | ≤60 字 | 模型 | 这一句说了什么（原话摘要，不改写）。 |
| `summary` | ≤20 字 | 模型 | 这件事在干什么（「主人在催我改代码」）。 |
| `material` | {quotes[], summaries[]} | 代码 | 近 6 句原话 + 近 10 轮摘要。**v2 要给每条标角色**（user / assistant）。 |

### C 上下文（v2 新增，代码填）

| 字段 | 类型 | 来源 | 为什么要有 |
|---|---|---|---|
| `prev` | ≤60 字 | 上一轮 assistant 的回复 | **我这轮的情绪有一半是对自己刚说的那句话的反应**。说了句硬的，下一轮心里就悬；现在事帧完全看不到它。 |
| `prevLabel` | 情绪标签 | 上一轮的 v4 label（或旧 label） | 让判断层知道「我上一句说的时候是什么状态」，能判「越说越急」还是「说完就松了」。 |
| `turnIndex` | int | 这一帧内第几轮（1 = 新事） | 同一件事的第 1 轮和第 5 轮判断不该一样；现在累积在 `advanceState`，事帧里看不出来。 |
| `scene` | ≤12 字 | 模型给 `summary` 时一起给 | 这件事属于哪一类（改代码 / 闲聊 / 被夸 / 被骂）。**只用来分组统计和门控，不参与算数**。 |
| `with` | owner / self / none / group | 规则（渠道） | 这段对话对面是谁。单聊主人 / 群里 / 自言自语，反应不同。 |

### D 判断层（**不进事帧**，单独一行）

| 字段 | 取值 | 说明 |
|---|---|---|
| `goal_delta` | -1~1 | 这一下让「现状」变好/变差多少 |
| `expect_delta` | 0~1 | 这一下有多脱离预期（0 预料内 / 1 震惊） |
| `future_delta` | -1~1 | 这一下让「奔头」变好/变差多少 |
| `severity` | none / strong / existence | 极端事件标记（触发 applyShock 用） |
| `why` | ≤30 字 | 为什么这么判 |
| `from` | 字符串 | 依据哪条材料 |

> 判断层是**唯一调模型的地方**。事帧给它的输入 = B 组 + C 组 + D 组的上一帧位置。

```json
  "who": "owner",
  "act": "request",
  "target": "me",
  "agency": "other",

```

（判断层那六个字段**不在这一行里**，落另一张表/另一列。混在一起就又是老问题。）

## 四、跟现在比，差在哪

| 项 | 现在 | v2 |
|---|---|---|
| `prev` / `prevLabel` | **没有** | 有 |
| `turnIndex` | 没有（累积在 advanceState 里，事帧看不见） | 有 |
| `gapMs` | 没有 | 有 |
| `scene` | 没有（summary 里糊着） | 单独一格 |
| `with` | 没有 | 有 |
| `material.quotes` | 纯字符串数组，不分角色 | 带 role |
| `who` | 恒 `owner` | 真填 |

## 五、验收（先写，再动代码）

1. 拿真库最近 200 轮重放，五个新字段（`prev` / `prevLabel` / `turnIndex` / `gapMs` / `scene`）**填满率**各是多少？低于 80% 的说明取数路径有问题，先修取数。
2. `gapMs` 分布：中位多少、有没有异常（负值 / 超一天）。
3. `prev` 抽 10 条人工看：是不是真的「我上一句」，有没有串到别人的话。
4. 同一个 `scene` 下，第二轮之后 `expect_delta` 是否普遍下降（论持久战该麻木，不该每次 0.5）。这一条是**加 prev 到底有没有用**的判据。
5. 门禁 596/596 不许红；影子表只追加，不动旧行。

## 六、这次不做

- 不重写 `act` 的分类体系（只是把 `who`/`with` 填对）。
- 不动判断层的提示词（`prev` 先只进材料，喂法单独一步）。
- 不加任何「情绪词」进事帧。
- 全字段默认值 = 空，不编。
