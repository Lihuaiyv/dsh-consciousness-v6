# 改动 · 判断层 by / to 判据与增量 0（2026-11-22）

> 25 条真库样本：by 错 3 条（主人的话判成我做的）、to 错 3 条（派活/问句该冲我判成 other）、
> 三个增量 72 个数里 0 个 0（每句都在推）。
> 主人确认：「by 和 to 的判断者都是小汐，但材料里的人称不等于判断者。」——按这条改提示词。

## 一、动了哪

`src/modules/affect_v4_shadow.js` 的 `JUDGE_SYS`，三处：

1. **by 加一条边界**：「材料里的人称不是判断者。『我』是说话人（主人）在说他那边的事，不等于这件事是我造成的；他说『我刚才设置了』『我没看见』——造成的是他，不是我。只有材料里写明了是我做的，才给 me。按『谁造成了这件事』判，不按句子里出现了哪个字判。」
2. **to 加一条**：「他让我做事、问我、把事递到我手上——劲是冲我的，给 me。哪怕句子里提到第三方（『你查查他』『他会好吗』『咱们关掉那个会怎样』），冲的是被使唤、被问到的我，不是那个第三方。」
3. **增量 0 放宽**：原来「别习惯性给 0……只有这一句跟上一句完全一样才给 0」——实测 72 个数没一个 0，等于每句都在推。
   改成「真的没变就给 0：0 是『没变』，是合法的数，不是『不知道』。别为了凑『每句都有变化』硬给 0.05，也别把一根 0.05 拆成三个 0.02。」

**没动**：选项定义（me/other/world 的含义）、三个增量的刻度表、severity、严格模式的十键检查。

## 二、为什么

错例的共同点不是「不懂 me/other 的含义」，是**把材料里的人称词当成了判断者**：
- 「我刚才 360 已经设置信任了」→ 它看见「我」，当成了小汐，判 by=me。
- 「那你查查现在他正常一点了」→ 它看见宾语「他」，判 to=other；实际是派活给「你」。

所以补的是「人称 ≠ 判断者、宾语 ≠ 劲的落点」，不是重写定义——按主人规矩，不叠例子、不动设计。

## 三、怎么验

提示词进不了单测，门禁只保证没碰坏别的：

```powershell
node --check src/modules/affect_v4_shadow.js
node test/run-tests.mjs
```

重载后真验收：抽「带『我』但他的事」和「派活/问句带第三方」两类句子，看 by / to 是否落对；
再看三个增量里有没有真 0 出现（日常轮次该有）。

## 四、怎么退

`git` 取回 `JUDGE_SYS` 里 by / to 那两段和「别习惯性给 0」那一行。
