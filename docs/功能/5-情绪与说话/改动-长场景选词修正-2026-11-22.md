# 改动 · 长场景选词修正（2026-11-22）

> 主人：「自己研究情绪功能……反复挑选真实场景和长时间各种场景模拟……汇报之前要再挑新的长十轮左右长例子来判断。」
> 这一轮造了 A–D 四个长场景（10–12 句），全链路（`appraiseTurnNow`）从空库、平静基线起跑，
> 判断数据由子代理按 `JUDGE_SYS` 原文逐句产出，不是人手写档位。

## 一、方法

- 场景：`scratch/sim/scenes/{A,B,C,D}.json`（每句带分钟间隔）。
- 判断：`scratch/sim/judge-{A,B,C,D}.json`（子代理只看该句之前的上下文）。
- 全链路：`node scratch/sim/sim-scene.mjs <id>` → 规则帧 → 判断 → `advanceState` → `infer` → 落 `affect_v4_shadow`，读回 s/n/d 和词。
- 输出：`scratch/sim/out-<id>.json`。

## 二、发现并改的四处（`src/algo/grid_pick.js`）

1. **被当面指出弄坏东西，词挑成「回过味 / 不痛快」**（场景 A 第 4–5 句）。
   加「被指出」签名先验：`by=对方` + `goal_delta < -0.12` + `expect_delta > 0.10` →
   「心里一紧 / 心里发虚 / 被说中 / 闷了一下」进候选并加 0.15。改后 A4「闷了一下」、A5「心里发虚」、C5「心里发虚」。
2. **「被点破」出现在他回来求助的场合**（场景 C 第 7 句）。
   「被点破/被说中」原来只要求 `by=other`；补「我确实被揭了短」（`goal_delta < -0.05`）才算。改后 C7「缓过来」。
3. **问题解决那句挑出「挂牵」**（场景 C 第 8 句）。
   「松快」族原来只认位置帧 `peak.s`；长场景里 peak 没记到就不成立。补「解决感」：
   `goal>0.1` 且 `future>0.2`，且最近五轮出过慌/闷/虚/担忧类词 → 松快族 +0.12。
   改后 C8/C9「松快」，A8「挂心」没被带坏。
4. **「消了气」在没有气可消的时候出现**（场景 C 第 8 句）。
   原来「先有过气」的正则含单字「恼」，「懊恼」一次就让它通过。收紧成 `/恼火|生气|来气|气不过|憋气|怨|烦|火大/`。

**没动**：三递质动力学、判断层提示词、词表数据和坐标。

## 四、还不算干净

- C3「被派活」挑出「受用」、A11「被夸」挑出「惊奇」——偏词但在可接受范围内，没再为单句加规则。
- 判断数据是子代理模拟的，不是真实宿主模型；同一句两分钟内可能判出两种强度（已知，主人说不强求稳）。
- 词表深水区还在：`挂牵` 这类「牵挂人」的词在「事情解决」位置仍可能近；这次靠「解决感」把它挤开，没从根本上改词表。
