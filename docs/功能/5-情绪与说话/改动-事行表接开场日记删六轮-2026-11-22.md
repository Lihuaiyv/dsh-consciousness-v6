# 改动：事行表接开场与日记，删掉六轮一收的纪要生成（2026-11-22 01:0x）

## 为什么

六轮一收的纪要写的是 `episodes` 表，只覆盖最近一段，且读它的开场/日记在它不生成后就断了。改成：每轮收的「事」追加进新表 `affair_rows`（只增不改），开场和日记都改读它；六轮生成整条删掉。

## 动了哪

1. 写：`src/modules/affect_v4_shadow.js`
   - `summarizeAffairs` 落 flag 之后，再往 `affair_rows` 追加一行（id/会话/本地天/时间/一句事/四格/加格）。
   - `ensureAffairRows` 首次用时建表 + `(agent_id, day)` 索引；`day` 用本地日期，不用 UTC。
2. 读：开场（`src/modules/archive.js` 的 `sessionBridge`）
   - 先取 `affair_rows` 最新一条，按「今天早些时候 / 上次（日期）」+ 70 字返回；没有或表不存在才退回旧纪要。
3. 读：日记（`src/modules/diary.js` 的 `collectCandidates`）
   - 按天把 `affair_rows` 的行作为 `kind='affair'` 的候选塞进去；没有不影响原流程。
4. 删：六轮一收
   - `index.js`：删 `narrativeAfterTurn` 函数与调用，去掉 `buildEpisode` import。
   - `src/modules/nightly.js`：删「① 当天各会话补纪要」「①b 近一周补缝」两块及 `buildEpisode` import。
   - `src/kernel.js`：删 `memory.episode.auto` 参数。
   - 老纪要（episodes）留在库里，读不到事行时仍可退回。
5. 白名单：`src/ports/ownership.js`
   - `WRITES.layers` 与 `OWNERSHIP.layers.tables` 都加 `affair_rows`，否则 INV10 表白名单 CI 会红。

## 怎么验

- `node scripts/check-ownership.mjs`：ownership ok。
- `node test/run-tests.mjs`：**600 / 600**。
- 读口实测（`scratch/test-affair-readers.mjs`，临时插两行再删）：
  - 开场返回「今天早些时候（2026-11-21）测试事1：在接开场和日记」；
  - 日记候选里读出两条 affair；
  - 测完删掉，`affair_rows` 归零。

## 怎么退

- 恢复六轮纪要：从本次改动回滚 `index.js` / `nightly.js` / `kernel.js` 三处，并把 `memory.episode.auto` 加回。
- 不想要事行：`affair_rows` 可整表删（只追加、无其他表引用）；读口会退回旧纪要。
