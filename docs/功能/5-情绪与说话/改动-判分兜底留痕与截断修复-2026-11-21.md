## 为什么

**这是两个独立的问题，被同一批数据混在一起。**

1. **兜底不留痕。** `ModelPort._run` 的注释早就写着「落到规则兜底：记下来，别让调用方以为这句话是模型说的」，但它只把 `servedBy/lastError` 放在内存里，判分那条路从不读。于是 `judge.diag` 里只有一句 `sanitize-null`，看不出是没模型、熔断还是真报错。

2. **截断的判分被整条扔掉。** 2026-11-21 复查：11-20 23:08 之后 118 条 model 行，7 条落兜底（5.9%），其中 **6 条是 `unparsed`**。逐条看 `raw` 才发现——模型其实已经把 `fact / meaning / by / goal_delta / expect_delta / future_delta / severity` 全部写好，只在最后那个 `why` 写到半句就断了。整段里**一个闭合的 `}` 都没有**，而旧 `parseJsonLoose` 只有两条路（整段 parse / 截到最后一个 `}`），两条都走不通，只能退规则。**信息是全的，被解析器扔了。**

- 只想要留痕、不想要补全：把 `parseJsonLoose` 里那段 `if (i >= 0) { const cut = lastTopLevelComma(...) }` 整块删掉，回到两路解析。
