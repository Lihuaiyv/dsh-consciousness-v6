# 改动 · 删死参数与 with（2026-11-22）

> 主人：「看看情绪这条链上还有没有啥要删的……下游情绪那块还有没有需要的参数。如果确定不需要的话看看删。
> 『网页还是 QQ』的确定了就先删了吧。」
> 这一刀**只删**，不调数值、不改提示词。删的是「没人读」的东西。

## 一、盘点：判断层给了什么，下游谁在读（真库副本，11-21 起 381 条 model 行）

| 判断字段 | 填满率 | 下游读它吗 |
|---|---|---|
| `goal_delta` / `expect_delta` / `future_delta` | 99.7% / 99.7% / 99.5% | **读**：三递质累积（安的累积、觉的尖峰、欲的偏置） |
| `by` | 97.9% | **读**：选词落格（谁做的 × 冲谁）、想要那根的 by 调制、「被点破」类词的闸 |
| `to` | **74.8%** | **读**：选词落格（「心里那股劲冲谁」）。缺了才退回 frame.target |
| `severity` | 97.9%（none 253 / strong 120 / existence **0**） | **读**：一步通天（existence 才允许） |
| `fact` / `from` | 98.4% / 98.4% | **读**：一步通天的文字闸（防「他喜欢别人了」被砸到 0.02） |
| `why` | 98.7% | 只进账本（对账/复查看），不算数 |
| `meaning` | 98.2% | 只进账本（看 fact→meaning 有没有加戏） |
| `summary` | 7.9% | 只有旧精修路读；主链不读（事帧的 summary 来自上一轮「事」） |

**结论一：判断层没有「给了但下游不读」的大字段可删。** `why` / `meaning` 虽然不参与算数，
但它们是账本里唯一能复盘「为什么判成这样」的东西，删了等于瞎判——保留。
`summary` 收得很少，是旧路遗产，它不占提示词（`JUDGE_SYS` 不要求模型给），留着无害。

**结论二：真正的缺口是 `to`（25% 缺）。** 缺 `to` 时 top 词是「迷茫 / 暧昧 / 思念 / 不适 / 犹豫 / 无力 / 空落落」；
有 `to` 时是「蔫了 / 挂心 / 懊恼 / 赌气 / 担心 / 担忧」。**缺的那一方全是「说不清冲谁」的词**——
这就是「判断不准」的一条实锤：不是词表错，是「这股劲冲谁」没判出来，选词只能落进「无」格。
（补 `to` 的兜底 / 提示词强化是下一刀的事，这一刀只删，不动判分。）

## 二、删了什么

2026-11-22 上午加、当天删。全仓 grep：**没有任何读侧**（判断层不读、算数不读、面板也不读），

### 2. kernel 里的九个死参数

`affect.v4.s.base` / `s.k` / `n.base` / `n.k` / `d.base` / `d.k` / `angle.sigma` / `word.sigma` / `geo`。
全仓 grep（含 test / scripts）只有注册表自己提到它们：
- 六个 base/k：`transmitters` 只吃调用方传进来的 `opts`，没有任何地方从参数读；

- `geo`：查表几何那条路 11-20 就废了，`v4Opts` 不读它，代码注释也写着「没有 geo 这个开关了」。

保留的是**还在读**的：`label.tie`、`frame.ctx`、`dyn` 及其按轴的 ks/kn/kdu/kdd/hold/tau/edge/shock/cross。
