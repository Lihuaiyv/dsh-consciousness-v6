# 改动：Ollama 跟着 DSH 起、隐藏常驻、预热两个模型（2026-11-22）

## 为什么

本地模型老起不来，对句一路退截断。查出来两个真因：

1. `D:\deepseek_local\ollama\ollama.exe` 不是本体，是个 7.6KB 的发射器（OllamaShim）；
   它要找同目录的 `ollama-noconsole.exe`，那个文件不在了 → 每次启动报“系统找不到指定的文件”，
   常常就是那个黑框。
2. 直接跑本体时，Ollama 往 `C:\Users\l\.ollama\id_ed25519` 写私钥被拒 → 服务起来就退。
   必须把 HOME/USERPROFILE 指到便携目录 `D:\deepseek_local\ollama_home`。

## 动了哪

1. `D:\deepseek_local\ollama\ollama-noconsole.exe`
   - 从 `ollama.exe.cui-bak` 复制回来（本体，28MB）。发射器从此有目标可找。
2. `src/modules/local_llm.js`
   - `portableExe` 优先用 `ollama-noconsole.exe`，没有再退 `ollama.exe`。
   - spawn 环境加：`OLLAMA_KEEP_ALIVE=-1`、`OLLAMA_MAX_LOADED_MODELS=2`、`OLLAMA_NUM_PARALLEL=1`、`OLLAMA_FLASH_ATTENTION=1`。
     常驻不卸、最多两个模型、并行 1，防内存挤爆和互相卡。
   - 新增 `warmLocalModels(db)`：POST `/api/embed`（qwen3-embedding:0.6b）与 `/api/chat`（qwen2.5:14b-instruct），`keep_alive:-1`。
3. `index.js`
   - DB 初始化末尾由原来的「按开关懒启动」改成 `startLocalModels(db)`：DSH 一开就先 ping，没起就隐藏拉（detached + CREATE_NO_WINDOW，不出黑框）。
   - 每分钟看门狗：掉线就重拉；第一次起来后预热两个模型。

## 怎么验

- `node --check index.js` / `node --check src/modules/local_llm.js` 通过。
- `node test/run-tests.mjs`：599 / 599。
- 现场验：
  - `GET /api/tags` 返回两个模型；
  - `GET /api/ps` 两个都 keep 到 2319 年（= -1 常驻）；
  - 进程名 `ollama-noconsole`，无控制台窗口。

## 怎么退

- 不想自动起：把 flags 里 `memory.cut.local.autostart` 设 `0`（ensureLocalServer 会尊重它）。
- 想回旧路径：`portableExe` 改回 `ollama.exe`（但需要那个发射器目标存在）。
- 本次没有删任何模型、没有改数据。

## 补记（同日 00:4x）：回到 GPU、掐掉黑框来源

- 主人要求回 GPU（CPU 太慢）。`memory.cut.local.num_gpu` 原本就是 `32`，只是我预热时误传了 `num_gpu:0`。
  改成「预热跟随同一套 num_gpu 口径」后重载：
  - 14B 显存 6.4GB（32 层），语义模型 1.2GB，整卡 10.3/16.3GB，余 6GB；
  - 24 token 实测约 3.6 秒（模型已热）。
- 黑框来源：`ollama.exe` 只是个 7.6KB 的发射器（OllamaShim），它拉起控制台版本时容易闪一下。
  处理：DB flag `memory.cut.local.exe` 指到 `D:\deepseek_local\ollama\ollama-noconsole.exe`，
  代码里 `portableExe` 也优先 `ollama-noconsole.exe`；spawn 依旧带 `windowsHide + CREATE_NO_WINDOW`。
  另查过：启动文件夹、注册表 Run、计划任务里都没有 Ollama 的自启项。
- 备份：改 flag 前备份到 `scratch/backup/app-2026-11-22-preflag.db`。
