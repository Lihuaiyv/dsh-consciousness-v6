# 改动 · 空返回不再静默（2026-11-23）

> 一句话：宿主模型回空的时候，以前会原样返回空字符串，上层只能记「unparsed、raw 空」；现在带结束原因一起抛错。

## 动了哪

`src/model.js` 的 `HostLlmAdapter._chat` 结尾：`if (!out.trim())` 时抛错，错误里带 `finishKind`、`sawDelta`、`maxTokens`。

原来只有一种空会报错：`finishKind === 'length'`（额度用光）。其他原因的空一律 `return ''`。

## 为什么

真库测过：最近 300 条判定里 **32 条缺字段（11%）**，其中 26 条十个字段全缺、6 条只写了 fact。

往下查：

1. `host_calls` 里那几次 `affect:judge` 全是 ok、没有超时（6984ms / 7717ms）。
2. 判定行的诊断是 `why=unparsed`、`raw=""`——不是 JSON 截断，是宿主回了个空。
3. 那 30 个 turn 在 `chat_turns` 里 user 行和 agent 行都齐全——聊天是完整的，只有情绪判定那一环空响。
4. 空返回的原话平均 25 字，正常 41 字——短句略多，但不绝对（34 字那句也空了）。
5. 时间从 06:02 到 13:16 全天散开，不是集中在某个时段或重载之后。

结论：**额度没光、没超时、没被拒**，是「流正常结束、一个字没吐」的第三种情况。它到底是模型真空回还是流被掐断，缺结束原因，分不出来——所以先把它记下来。

## 怎么验

重载后看 `affect.v4.judge.diag` 或判定行的错误信息：

- 如果出现 `llm empty: finish=length` → 是额度/截断。
- `finish=(没收到)` → 流没正常结束，被掐了。
- `finish=stop` 且 `sawDelta=no` → 模型真空回。

三种对应三种修法，不再混着猜。

## 怎么退

`model.js` 里删掉 `if (!out.trim())` 那段即可，回到「空就返回空串」。

## 注意

- 行为变了：空返回从「静默成功」变成「失败」。所有宿主调用都会受影响——但空本来就该算失败，以前那样等于骗上层「有内容」。
- 要**重载**才生效。
