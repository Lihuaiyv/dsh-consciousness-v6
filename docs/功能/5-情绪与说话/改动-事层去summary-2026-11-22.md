# 改动 · 事层不再写 summary（2026-11-22）

> 主人定：「事层那个 summary 直接弄没」——summary 归事帧前置，事层不再读一份又写一份盖回去。
> 这一刀只动事层；前置那套（`summarizeAffairs` / `affair_rows`）不动。

## 一、动了哪

`src/modules/affect_v4_shadow.js`

| 位置 | 改动 |
|---|---|
| `TOPIC_SYS` | 输出从三键收成**两键**：`what`（这一句说了什么）/ `target`（指称落在谁身上）。删掉 `summary` 键和它的说明 |
| `appraiseTurnNow` 事层解析 | 删掉 `if (jt.summary) frame.summary = ...`——不再覆盖 |
| `frame.summary` | 保持构造时的原值：`readAffairs()` 拿到的**前置那一份**（没有就是「（新事）」） |
| 判断输入 / `turnIndex` | 不动——上一刀已改成读 `affairsLine`（前置原文） |
| `buildMaterial` / `frame_line` | 不动——上一刀已改成读 `affair_rows` / 前置 flag |

**没动**：前置的收拢逻辑、影子表结构、切事。

## 二、为什么

事层原来做的是：读前置的「正在发生」→ 自己再产一个 20 字的 summary → 覆盖回去。
两处来源重叠，而且事层那份更短、更粗，读侧还得靠「接前置」补回来。删掉它，职责就清了：

- **前置**：这件事在干什么（跨轮、慢）
- **事层**：这一句说了什么、指称落在谁身上（当轮、快）
- **影子表**：那一轮的情绪和判断（账本），`frame.summary` 就是前置那份，不再被覆盖
