# 改动 · 情绪链的账（2026-11-23）

> 一句话：**情绪链每一段的输入和输出都落盘了**，能按 seq 讲出「这一句进来 → 判了什么 → 落在哪个词」。

## 动了哪

- 新增 `src/modules/affect_chain.js`：`beginRun` / `step` / `endRun` / `readRun`。只写账，不碰情绪计算；全包 try/catch，账挂了不影响链；开关 `affect.chain.record`（默认 on）。
- `src/db.js`：加 `chain_runs`（一条链一行，结束时回填 ok / failed_step / ms）、`chain_steps`（一步一行，in/out 都存，超 8KB 截断标 truncated，只追加）。
- `src/modules/chain.js`：引擎加账——每步带 `runId` / `seq`；`input(ctx)` 在**调模型之前**打包；产出打包成 `outJson`；每步产出放 `ctx.steps[stepId]`（**不能**放 `ctx[stepId]`，见下）。引擎自己不碰 db，打包结果交给 `onStep` 回调。
- `src/modules/affect_v4_shadow.js`：`appraiseTurnNow` 里接五节——`read_prev`（读上一轮）、`judge`（判断层）、`position`（三根新坐标）、`pick`（挑词）、`write`（落表）；首尾 `beginRun` / `endRun`。

## 为什么

以前的「链」只管顺序：`ctx` 是内存对象，跑完就散，`onStep` 只记「哪步、多久、成没成」。于是：

- 不知道数据在哪一步变形，查问题只能翻 flags 和表再对着代码猜；
- 没法重放——同一节的输入没留下；
- 判断层缺料（`no_result`）时，缺哪个键只能靠事后推。

设计文档：`docs/功能/8-工程-门禁与文档/设计-链与块-2026-11-23.md`（v2，覆盖同日 v1）。

## 踩到的坑（记下来）

`ctx[step.id] = res` 会覆盖业务字段：链里有一步叫 `assign`，而 `ctx.assign` 本来是分组数据，被覆盖后补判那步拿不到分组，找核写链「三句」用例直接红。改成 `ctx.steps[step.id]` 后恢复。**以后加链：步骤 id 不许和 ctx 字段重名。**

## 怎么退

- 只关账：`affect.chain.record=off`（引擎行为与记账前完全一致，表留着不影响）。
- 整条退：`appraiseTurnNow` 里删掉五处 `step(...)` 与首尾两行（git 有完整旧版）。

## 补：摘要链与每步耗时（同日晚）

- **摘要链接上了**：`affect.summary` 三步——`read_pairs`（读料）→ `summarize`（压句/总结）→ `write_affairs`（写事）。
  模拟验证：1 条 run、3 步全 ok。它和 `affect.turn` 靠 affairs 接头：这条写下的事，下一轮判断层读。
- **每步耗时接上了**：用「距上一步的时间」做基准（打点紧跟在动作后面，所以包含真实工作时间）。
  模拟里 `judge` 4ms、`pick` 1ms；真库要重载后下一轮才看得到「判断层花 6 秒」这种数。
- **踩到的第二个坑**：`summarize` 打点一开始插在 `else` 分支里，走注入 `complete` 那条路会绕过去，账上少一步。
  挪到两条路汇合之后了。教训：打点要放在「所有分支都经过」的位置，不然账会骗人。

## 补二：单步重放（同日晚）

`replayStep(db, { runId, stepId, run })`：取那一步的原 `in_json`，交给调用方给的 `run` 重跑，
结果记成一行新账（`seq + 1000`，label 加 `:replay`）——**不碰业务表**。

实测：`judge` 那步重放后，账上多出 `[1001] judge ok label=affect:judge:replay`；
业务表 `affect_v4_shadow` 行数重放前后都是 2。总门禁 608 / 608。

设计取舍：引擎**不** import `JUDGE_SYS`，跑什么由调用方给——否则 `affect_chain` 和 `affect_v4_shadow`
会循环依赖。代价是调用方要多写几行；好处是引擎干净、能测。
