# 改动：关系评价（appraiseWithEdges）先停（2026-11-22 00:0x）

## 为什么

主人排查「回复之后到底还有几次模型调用」后决定：先把每轮一次的宿主调用停掉，观察情绪链本身。关系评价是旧的 v3 编排，v4 情绪链（appraiseTurnNow）不走它，停掉不影响 v4。

## 动了哪

1. `src/kernel.js`
   - 新增参数 `affect.appraise.edges`，默认 **off**（临时停）。改 on 即恢复。
2. `index.js`
   - 回复后那段异步链里，`appraiseWithEdges` 外面加了开关判断；off 时不调用，`res` 留 null。
   - `learnFromTurn(db, aid, u, res)` 照常跑（它容忍 null）。

## 副作用（必须知道）

- 近十轮收拢（`summarizeAffairs`）唯一的调用入口就在 `appraiseWithEdges` 收尾，所以停它之后：
  - 情绪 v4 链、TOPIC 事层照常；
  - 但「上一件事」（`affect.v4.affairs`）不再更新，事帧里的 summary 会停在旧值，材料里的历史摘要也不再增长。
- 关系观察（`relObserve`）、未说出口的话（`recordUnsaid`）也随之中断。

## 怎么验

- `node --check index.js` / `node --check src/kernel.js` 通过。
- `node test/run-tests.mjs`：599 / 599。
- 重载后，一轮回复结束不再出现 `affect.appraise` 一类调用；宿主只剩判断层（回复前）与感受行（低频）。

## 怎么退

- 把 `affect.appraise.edges` 改成 `on`（实例参数覆盖），或把 kernel.js 默认改回 `on`。
- 代码改动只有 index.js 那一处开关判断，删掉即恢复原状。
