# 改动 · 词门控先停用（2026-11-23）

> 一句话：`gateOf` 先返回 1，所有词平等。因为词条的 `gate` 语义没写清、实现里又拿两套字段混着判，很可能接反了。

## 动了哪

`src/algo/affect_v4.js` 的 `gateOf`：直接 `return 1`，旧实现留在函数里的块注释中（要恢复照着换回来）。

## 为什么

词库 276 个词里 38 个带 `gate`：`other`（委屈/怨恨/不满/心疼…）、`me`（喜欢/依恋/亲昵…）、`self`（愧疚/自豪/自卑…）。方向本身通顺，但：

- 实现里 `other` 和 `me` 用 `frame.target`（**这句话在说谁**）判，`self` 用 `by`（**谁造成的**）判——两套字段混着用。
- 「委屈」标 `other`，本意是「他造成的」，可代码看的是「这句在说谁」。真被骂的时候（「你太蠢了」）`target=me`，委屈就被压到三折——最该出的词反被压。
- `0.3` 这个折扣也没有依据。
- 生成它的原始数据 `scratch/lexicon/axes-v4.json` 已经不在，语义断了线，没法核。

11-22 那份 by/to 判据记录里写着「by 和 to 的判断者都是小汐，但材料里的人称不等于判断者」——现在的 `gateOf` 正好是按人称判，跟那条定的方向相反。

## 怎么验

重载后跑几天，看两件事：

1. 词分布有没有变差：暖族（暖/暖流/心里软/想靠近）占比有没有涨回去。
2. 负面词（委屈/懊恼/心里发虚/赌气）出现次数有没有掉。

没变差 → 这道门本来没帮上忙，继续拆着；变差 → 按 `by` 重新接（`other` → `by==='other'`，`self` → `by==='me'`，`me` 那一门要重新定义）。

## 怎么退

`affect_v4.js` 里 `gateOf` 的 `return 1` 换回块注释里那三行判断即可，一行不动别的。

## 注意

- 门禁只保证没碰坏别的（608/608 过），**门控本身的效果进不了单测**，只能靠真库对照。
- 这个改动不用改提示词，重载一次就生效。
