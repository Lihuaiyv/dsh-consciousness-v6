# 改动 · 事层 `what` 只认「这一句」（2026-11-22）

> 真库抓到一例：当前句「那都搞完了呗」，事层写的 `what` 却是「确认所有修改未影响功能」——
> 和那条帧里「正在发生」的第二条「确认功能无影响」几乎同句。它把背景抄成了这一句。

## 一、动了哪

`src/modules/affect_v4_shadow.js`

1. **事层输入换顺序**（`topicText`）：原来是「正在发生 → 我上一句 → 这一句」；现在是
   「这一句（what 和 target 都只判这一句）→ 正在发生（背景，别拿它当这一句）→ 我上一句（背景）」。
   短句时背景占的篇幅比主句大，把它压到后面、并标明「别拿它当这一句」。
2. **`TOPIC_SYS` 的 `what` 说明加边界**：
   「只从『这一句』提取，不许拿『正在发生』或『我上一句』里的句子顶。」
   再加一句：「这一句很短（『搞完了』『嗯』『好』『行』这种）时，照它本身写，别替它补上下文、别往上安事。」

**没动**：`target` 的判据、判断层的输入、前置、门禁逻辑。

## 二、为什么

错位那条的现场：当前句是「那都搞完了呗」（一句收尾，本身没什么可提炼），前置是三条
（判断部分已停用 / 确认功能无影响 / 确认读取位置未变）。模型拿「确认功能无影响」写了 `what`。
不是它不会写，是输入里主句太短、背景太多，它顺手借了最像的。

## 三、怎么验

```powershell
node --check src/modules/affect_v4_shadow.js
node test/run-tests.mjs
```

提示词和输入顺序不进单测；门禁只保证没碰坏别的。真验收看重载后的数据：
拿「当前句是短收尾句」的那些轮，看 `what` 是否还抄「正在发生」里的句子。修前抽到的就是「那都搞完了呗」那条。

## 四、怎么退

`git` 取回 `topicText` 的顺序和 `TOPIC_SYS` 那两行。
