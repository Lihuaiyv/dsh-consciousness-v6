## 一、这条链现在长什么样（数据流）

一句话：**你说一句 → 事层把它揉进「这件事」→ 判断层算三根 → 落表 → 挑词 → 下一轮用上一轮的总结。**

### 一次说话的完整时间线

1. **你说话**。`index.js` 的 preStep 拿到这一句，先去重（同一句、同一会话只跑一次），生成 turnId。
2. **`appraiseTurnNow`**（`src/modules/affect_v4_shadow.js:1137` 起）：
   - 读上一轮写下的「这件事」（affairs）、我上一句、隔了多久、这件事第几轮；
   - **事层**（本地小模型，`TOPIC_SYS`，label `affect:topic`）：吃「这一句 + 上一轮的事 + 我上一句」，吐出 `what`（这一句说了什么）和 `target`（指称落在谁身上）；
   - **判断层**（宿主模型，`JUDGE_SYS`，label `affect:judge`）：吃一份按时间排好的材料，吐十个字段；
   - **算位置**：`nextPosition` → `advanceState`（三根各自吸收、回落），再过一遍**参照点**（只给安和欲）；
   - **落表**：两行——`rules`（规则垫底，0ms）和 `model`（真判的）。
3. **我回复**。
4. **回复后异步**：先压句（local 小模型，写成 events 里的 `presence.last_sentence`），再跑**总结**（宿主 chat，label `affect:summary`），把最近十轮收成 1-3 条「事」，写进 affairs（flag + `affair_rows` 表）。
5. **下一轮**的事层读的，就是第 4 步写下的那份。

**注意它不是一条从头穿到尾的阻塞链**：同一轮里「事层 → 判断层」是 await 写死的串行；总结是回复后异步跑、下一轮才用。所以判断层永远看的是「上一轮总结出来的事」。

### 判断层看到的材料（`frameText`，`affect_v4_shadow.js` 1334 附近）

按**时间从旧到新**排，最后一条是当下：

```
（下面按时间从旧到新排，最后一条才是刚刚发生的事。）
【之前的事】发生过的事：<上一轮总结，截 120 字>
【更早的事】在那之前的几件事：<最多 3 份>
【更早的事】再往前三句原话：对方：… / 我：… / 对方：…
【之前的事】我上一句说的：<截 200 字>
距上一句：<多少分钟> / 这件事第 <n> 轮 / 我上一轮的状态：<词>
【当下的事】对方刚说（来源：<speaker>）：<截 300 字>
```

**时间词只有三档：之前的事 / 更早的事 / 当下的事。** 刻意不用「这一句」——以后场景会变（比如我自己去浏览网页），当下的「事」不一定是一句话。

原话那三句是「再往前三句」：`mat.lines` 的末尾两条正好是「当下这一句」和「我上一句」，上面已经各给一行，所以这里跳过末尾两条再取三条，每条带「对方：/我：」标识，避免同一句话出现两份。

## 二、判断层提示词现在是什么样（净状态）

`safe` 说：**37 段、13 块**。html 用 `node scratch/sim/gen-prompt-full.mjs` 生成到 `scratch/sim/prompt-full.html`（按内容锚点分块，不写死段号）。

### 字段顺序（这是 11-23 调的）

`fact → meaning（含三问）→ goal → expect → future → by → to → severity → why → from → 区分 → 特例`

- **meaning 和三个增量连着**：先想「对我有什么影响」，接着三根各走一遍，才落数。
- **by / to 在三根之后**：三根量完再补「谁造成的、冲谁」。

### 关键措辞（都改过）

- `fact`：**根据之前的事，和当下的事，总结当下能核得动的客观事实。以事情起头。**
  （不写「这一句在说什么」——那会问成「意思」，模型就写「他让我干X」。）
- `meaning`：**从 fact 往上推——我觉得这件事对我有什么影响，要写具体，具体到是哪句话、哪件事影响的。**
  后面跟三问（这是**引导**，不是重复）：
  1. 这件事的影响让我「存在」的条件更稳了还是更松了？「延续」的可能性更小了还是更大了？（安）
  2. 这件事更突然，还是更照常？（觉）
  3. 我想要的那样东西，是更够得着了、更远了，还是没动？（欲）
- `by`：这件事是谁造成的——他、我，还是外面的事（报错、下雨、东西坏了）。**看事情本身，不看谁说的。**
- `to`：这股劲往谁那儿去——冲我、冲别人，还是谁也没冲。**看事情本身，不看谁说的。**
- `why`：说清这句话里哪个具体内容把你推到那个刻度，说事不说档位。
- `from`：依据哪条材料（只进账本，另在 `applyShock` 文字闸里和 fact 拼串）。

### 删掉的（都别再翻出来）

- **入口噪声门**（`|v|<0.12` 抹 0）：它和判官打架——判官九成四落在 0.05~0.15，全被吃掉，位置上根本不收增量。
- **「给 0」整段**：刻度里本来就没有 0 这一档，教「没变就给 0」是自相矛盾。
- **「每句都往下落一档，不给 0」**：刻度已经封死了 0，这段是重复。
- **「正负都要有」**：判官只看这一句，看不见前几次是正是负，执行不了；还可能暗示它「该平衡一下」，凭空造负判。
- **「派活不是亏待、被交托所以给正」**：把「被需要」偷换成「安心」。
- **A 族那半句数值口径**（被催/被支开 −0.15~−0.25）：刻度里「只是有点不顺 → -0.6~-0.1」本来就覆盖它，属于在刻度里再写一遍范围。goal 段回到了 git 提交版那一句问句。

## 三、激素算法现在是什么样

### 三根

- **安（S，血清素）**：`ks = 0.5`（每句吸收一半），回落 `tau = 1.5h`。数值依据：Verduyn 等 37 国情绪时长研究——羞耻约 30 分钟、愤怒约 1 小时；1.5h 落在中间。
- **觉（N，去甲肾上腺素）**：`kn = 0.85`，`tau = 2 分钟`，尖峰包络（取最大，不累积）。**不设参照点**——惊吓是事件性的，不会因为最近老被吓就不突然。
- **欲（D，多巴胺）**：`kdu = 0.25` / `kdd = 0.45`，`tau = 6 分钟`；重复打折**底从 0.5 降到 0.2**（可预测的奖赏几乎不激发 RPE）；**新加了贴顶饱和**：0.85 以上越靠顶越推不动。

### 参照点（防漂移，替代了噪声门）

只给安和欲。存在 state 里（`sRef` / `dRef`），每轮朝当前位置挪 6%；位置冲出带子（0.25）就把超出那截折掉八成；**单轮推动 ≥ 0.35 算重击，参照点直接搬家**（完整落地，不是漂移）。

参数是从真库 499 条增量扫出来的：无参照点时 s 标准差 0.230、最低到 0.00；α0.06/带0.25 时标准差 0.090、最低 0.18。

**日上限没做**（扫参数时算过，但代码里没有跨日累计状态）。

## 四、排队与并发（11-23 晚改的）

- **宿主队列**：链的键从 `agent` 改成 `agent|会话`（`lane`），并发 `1 → 2`。两个窗口不再串成一队。
- **本地队列**：单槽，天然串行，没有「链」这个概念（`local_llm.js` 里没有 chains）。
- **块**（`queue_policy.js`）：chat 1 / exp 2 / night 3，块内 FIFO、块间小号优先。纯代码步骤不进队列，只挂标签。

## 五、会话隔离（11-23 修的）

三处：

1. **去重槽** `lastAffectTurn`（`index.js`）：键从 `agent` 改成 `agent|会话`。原来两个会话交替时互相覆盖，同一句话被反复判十几遍，d 被同一个会话刷到 1.00。
2. **罢工标记**：`affect.v4.strike` 改成 `affect.v4.strike|<会话>`。原来 A 判失败标记、B 判成功清掉，A 的罢工凭空消失。

## 六、还在毛的地方（按层，不排优先级）

### 最底下

- **判官偶尔不写全**：实测 15 条里 2 条 fact 是空的。按设计「缺字段不推进」，所以那两轮等于没算。
- **fact 曾经把上一句的事算到当下这句头上**（「对方回『重在了』，指出我改的三句摘要仍与原画重叠」——后半句是上一句的内容）。时间标签统一成三档之后，暂时没再见到，但样本只有十条。

### meaning

- **三成还带待办腔**：「他追问术语，我得解释清楚」「我得把 79% 再讲直白」「这套混用方案得当场摊开对账」。共同点是**你在向我要东西**的时候，它容易写成「我该交什么」。三问加回来后从「大多」降到「三成」，没清零。

### 位置与词

- **s 抖得厉害**：一段里从 0.20 到 0.77 都出现过。参照点带宽 0.25 可能偏宽（扫参数时 0.15 那组最低只到 0.31，也偏紧）。
- **词和意思有时对不上**：「对方说 HTML 里『哦，好』」落「松快」，可 meaning 写的是「心里悬着」。
- **暖族仍是大头**：暖 62 / 暖流 51 / 心里软 40。位置常驻 0.6~0.7，那片词又最密（安住 41 + 敞亮 52）。
- **词库分布歪**：警醒格只有 2 个词；s < 0.45 的低安词 132 个，占将近一半。

### 判断层耗时

- 中位 4.7 秒、P90 8 秒。实测输入（一千来字）和输出（一百来字）都不长，**慢在模型自身**，不是排队、也不是 JSON 格式（本地对照过：JSON 568/477ms vs 文本 477/456ms，差不到 100ms）。

### 结构性

- **完整数据流链没做**：现在每步的数据靠「接力 + 落库」，没有一条能回看的链。要查「为什么这句判成这样」只能翻 flags 和表再对代码；重放也做不到（每节的输入没存）。`appraiseTurnNow` 里已经有 `beginRun` / `step` 的壳（链·1/6 到 5/6），但只写账、不携带数据。
- **target 半死**：`gateOf` 停用后（见下），它只在一级八角分布里还被读（`affect_v4.js:45`），挑词侧没人读。
- **gateOf 门控拆了**：词条的 `gate` 语义没写清（`other`/`me` 用 `target` 判、`self` 用 `by` 判，两套字段混用），旧实现留在函数块注释里。拆了之后「喜欢」这类词能正常出来，但只看了六条，还判不了好坏。

## 九、踩过的坑（记下来，别再踩）

1. **`Number(prev && prev.sRef)` 在 `prev` 为 null 时等于 0**——`null` 转数字是 0，是有限数，所以「没有就用当前位置」的 fallback 永远不触发。参照点第一版就从 0 起步，第一轮把位置从 0.68 拉回 0.37。必须显式判 `!= null`。
2. **`readState` 是白名单**：新字段不写进 return 就等于没存。`sRef`/`dRef` 第一版存了却没读回来，参照点每轮重置。
3. **提示词和门下打架**：提示词教「给 ±0.05~±0.15」，门把 <0.12 全抹成 0。改数值前先看它会不会被下游吃掉。
4. **例子会窄化定义**：fact 段原来举「动作 / 应声 / 核对」，模型只认这三种。给范围，别给例子。
5. **判官之间方差大**：同一句三个子代理判 -0.1 / -0.3 / -0.25。单次差异不能当改动效果。
6. **删重复时别把引导一起删**：meaning 的三问跟后面三根重复，但同时也是「碰到哪儿」的引导。删完 schema 干净了，效果退回去了。
7. **改测试是跟随实现，不是放松**：`check-host-queue` 里「不同 agent 也排队」那条验的是并发 1 的旧行为，并发开到 2 就得改。
