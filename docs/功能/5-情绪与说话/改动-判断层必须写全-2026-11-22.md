# 改动 · 判断层必须写全，缺一个就报警（2026-11-22 下午）

> 主人原话：「不要兜底，兜底就是骗人。一定要写。没写就应该报警，所有有用的参数都是，没写就报警。
> 不要有任何代码，规则兜底。」
> 这一刀把上午加的「规则补 `by` / 规则顶上」整条撤掉，改成：**写不全就算没算成，报警，不推进。**

## 一、动了哪

| 文件 | 改动 |
|---|---|
| `src/modules/affect_v4_shadow.js` | ① `rulesJudgment(act)` 撤销第二参和 `by` 推导（不再有规则兜底）；② 新增 `REQUIRED_JUDGE`（十个字段）和 `judgeMissing()`；③ `appraiseTurnNow` 判断后先查缺：缺一个 → `judge='incomplete'` + 写 `affect.v4.judge.incomplete` + 写 `strike`；④ **缺参数时不调 `nextPosition`**（状态停住），情绪词用上一轮位置出、不拿默认 0 算假词；⑤ 删掉 `rules-fallback` 那段补判断；⑥ `JUDGE_SYS` 加一句硬要求「十个字段一个都不能省，少一个判定作废，没人替你补，也没有规则兜底」 |
| `scripts/check-appraise-turn.mjs` | 断言改成 incomplete + missing 非空 + 不补 by + 报警 flag；假判断数据补成十个字段 |
| `scripts/check-affect-chain-e2e.mjs` | 同上；假判断数据补成十个字段 |

**没动**：三个增量的含义、三递质参数、选词权重、表结构、调用次数。

## 二、为什么

上午那一版为了「缺 `by` 就落无·无格」，在规则判断里按 `target` 推了一个 `by`，还把规则判断顶上 model 行当结论。
主人否得很直接：**兜底就是骗人**。缺参数时补一个数字，等于让下游以为「判出来了」——
后面所有选词、状态推进都建立在一个编出来的值上，账面上还看不出。

改成：缺就是缺。报警，停住，不推进。宁可这一轮情绪没动，也不许它假装动了。

## 三、报警长什么样

1. `affect.v4.judge.incomplete`（flag，JSON）：`{ at, conv, text(前 60 字), missing:[缺的字段], why, raw(前 200 字) }`。
2. `affect.v4.strike`（flag）：已有机制，提示词最顶上会写「情绪模块罢工：上一轮没算成，这轮先按平常回；别硬猜情绪」。
3. model 行的 `judgment_json` 里：`judge:'incomplete'`、`missing:[...]`，**没有补的数值**。
4. 这一轮不写 `affect.v4.state`（位置停住）、不写 `affect.v4.valence`（总情绪的「当场」不动）。

## 六、后果（要知道）

- 模型少写一个字段（比如 `to`）时，**这一轮情绪不往前走**，词停在上次位置，面板/注入会看到罢工提示。
- 这是故意的：宁可停一拍，也不拿编出来的数往下推。
- `to` 的历史填满率 74.8%——重载后如果罢工频繁，先看 `affect.v4.judge.incomplete` 的 `missing` 分布，
  再决定是改提示词措辞还是拆判断调用；**不要回头加兜底**。
