# 改动 · 宿主链按会话拆开（2026-11-23）

> 一句话：**同一条链从「按 agent」改成「按 agent + 会话」**，两个窗口不再串成一队；全局并发 1 → 2。

## 动了哪

`src/modules/host_llm.js`：

1. `concurrency` 默认 **1 → 2**（`llm.host.concurrency` 仍可覆盖）。
2. `scheduleHostTask` 加 `lane` 参数，链的键 `key = agent + (lane ? '|' + lane : '')`。
3. `hostComplete` 签名加 `lane` 并透传给 `scheduleHostTask`。

`src/modules/affect_v4_shadow.js`（三个调用点补 `lane`）：

- 判断层 `affect:judge` → `lane: conversationId`
- 摘要 `affect:summary` / `affect:summary:retry` → `lane: cid`

## 为什么

判断层中位要 5.7 秒，90 分位 14.8 秒。拆开看（stage.txt）：

```
11:49:58.843 affect-topic     ← 事层开始
11:49:59.239 affect-judge     ← 事层结束，396ms
11:50:14.708 affect-write     ← 判断层结束，等了 14.5 秒
```

事层本地模型只花 **396 毫秒**，慢的全是判断层那一次宿主调用。而它慢不是生成慢，是等：`host_llm` 把同一个 agent 的所有宿主调用串成一条链，全局并发又是 1——两个会话（都是同一个 agent）被编进同一条链，一个等一个。

11-22 把并发压成 1、全部挂链，是为了防「下一轮判定插到上一轮摘要前面」（判定读到空的 summary）。但保序只需要管**同一会话内**：两个会话各干各的，互相不该等。

## 怎么验

- `node scripts/check-host-queue.mjs` → **14 项全过**。其中两条断言按新语义改：
  - 「不同 agent 也排队（并发 1 时 maxR=1）」→「不同 agent 可以并行（并发 2 时 maxR=2）」
  - 「快照：一个在跑」→「快照：并发 2 被占满」
  - 新增「同一 agent 不同会话互不等待」（`lane` 拆开的核心验证）
- `node test/run-tests.mjs` → **608 / 608**。

重载后真库看：判断层 `latency_ms` 的中位和 90 分位有没有掉。

## 怎么退

- 并发退回串行：`llm.host.concurrency=1`（不用改代码）。
- 链退回按 agent：`scheduleHostTask` 里 `key` 去掉 `lane` 那半截。

## 还没做的（已知）

1. **慢情绪回渗的竞态**：`settleWarmth` 是「读旧值 → 改 → 写回」，两个会话同时结算会丢一次（单次封顶 ±0.1，损失有上限）。这次没加序列化。
2. 全局 `affect.v4.valence`（无会话后缀那份）多会话下后写覆盖先写——设计如此，只影响页面「现在」显示哪个会话。
3. 「所有调用连同中间的纯代码步骤都进链」还没做——现在的链只覆盖宿主侧的模型调用。
