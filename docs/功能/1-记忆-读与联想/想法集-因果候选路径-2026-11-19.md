# 想法集 · 因果候选路径（2026-11-19，纯讨论，不承诺）

> 主人原话：「晚上总结的时候。挑出让你意外的事情，然后去到处索引找原因，索引路径可以有很多种。然后因果是慢慢建立的？
> 然后对的因果现实生活中用上了就是经验。事实从经验判断。然后有没放下的没找到原因的事情就一直放开环上让它索引？」
>
> 结论先说：这个闭环能拆成可验证的四步，但**先别建边表**——先只产「候选路径」和「两句话」，等重复出现再升边。

## 0 名字

暂叫「**因果候选路径**」（candidate causal path）：一条**可能**通向原因的路，还不是因果边。
每条候选带三样：从哪来（哪个索引命中）、指向哪个件、凭什么（用的什么信号）。

## 1 两类候选路径（这一版只做这两类）

### 1.1 专名线（thread path）

- 信号：同一个具体专名（项目名、文件名、编号、版本号、人名）出现在不同天的件里。
- 作用：把「同一件事的切片」串起来，作为找原因的**候选走廊**。
- 已知问题：泛词会串假线。2026-11-19 只读统计（真库 138 件、两天）：跨天专名只有 7 个，其中
  「词表、向量、判断、波形、验收」都是泛词，真正像同一件事的只有「因果库」「切事」。
- 所以：专名线**只作走廊，不作证据**；进之前先过专名闸（像 cues 的 `specific()` 那样挡泛词）。

### 1.2 叙事因果（narrative cue path）

- 信号：原话或记叙里出现因果词——因为、所以、导致、结果、修好之后、才会、要不是。
- 作用：直接从「人的说法」里取因果，不靠主题相似性猜。
- 已知问题：语言里的因果常是口头禅（「所以我说」不是因果），要靠问句形态过滤；
  还得允许「前后颠倒」（先说结果后说原因）。
- 优点：这条不依赖专名，也不依赖线；一句话里自带前因后果。

## 2 闭环的四步（每一步单独可验）

### 第一步：晚上挑「意外」

- 用什么：事帧里已有的预期 / 现实 / 以后（`cong` / `expectation` / `future`），落差大的就是意外。
- 不调模型，纯算；先挑 3 件人工看准不准。
- 验收：抽 3 天 × 每天 3 件，人工标「确实意外 / 不算」，≥2/3 对才算这一步成立。

### 第二步：给这几件找原因，只写两句话

- 「这事从哪来」和「这事之后什么变了」。
- 索引顺序（先便宜后贵）：同一件内的因果词 → 同日前后件 → 跨天同专名（专名线）→ 开放环里挂着的旧事。
- 找到就写一句自然语言（**不建边**）；找不到就挂开放环，等以后再撞。
- 验收：这 3 件找回来的原因，人工判「说得通 / 牵强 / 找不到」，记录比例。

### 第三步：候选边重复出现才升级

- 同一条「来处 → 去处」在不同日子出现 ≥3 次，才落成一条候选因果边（带出现次数、置信度）。
- 这一步之前，**任何东西都不进 `event_edges` 的 cause 类**。
- 验收：拿「改代码 → 门禁红」这种已知模式，看三天内能不能自动升上来。

### 第四步：「用上」才算经验

- 判据（近似、要认账）：这条因果被读口注入过（检索日志有记录），且之后 7 天内同类情况没再出错。
- 只被提起、之后没反应的，只算「提到」，不算经验。
- 三面同向（出现 3 次）+ 被用上 1 次 → 才送事实库候选；事实库那边现有的「未证实有用」卡点，
  正好用这两个数解开。

## 3 和事实库的接口

- 事实库现在缺「用过没用过」的数，这个闭环能给：候选边「被注入次数」「之后没再出错次数」。
- 规则：`出现≥3 次` 且 `被用上≥1 次` → 升格候选事实；否则继续躺开放环。
- 这不动事实库表结构，只在边上加两个计数。

## 4 没想清楚的

- 「意外」的落差阈值怎么定？情绪起伏大不等于意外，先把「数值落差」和「原话惊讶词」分开量。
- 因果词过滤：中文里「所以」太常见，建议只认「因为…所以」成对出现，或「导致 / 结果 / 修好之后」。
- 专名线跨天太少（两天只有 2 个真专名），要等历史回填后才有量，急不得。
- 开放环上挂着的「没找到原因的事」，多久重试一次？每次重试用哪条路径？现在没定。
- 「用上」的近似会不会把「只是被提醒了」算成经验——需要读口那边配合打标记。

## 5 顺序

1. 第一步（挑意外）先跑只读统计，不写库；
2. 第二步（两句话）先手工做 3 件，看值不值得自动化；
3. 第三步（升边）等历史回填后再说；
4. 第四步（经验→事实）等读口接上 `events_v2` 才有数。

## 6 边类型（2026-11-19 补，查完 ActMem 原文之后）

> 这一节是后来加的，不覆盖前面的话。总想法（含九类词表、我认下的、模式开关）在
> `D:\deepseek_local\docs\待实现想法\经验因果与存在-2026-11-19.md` 第九节，这里只记跟候选路径直接相关的结论。

- **九类是 ECI 原标签（Event Causality Identification），不改词**：cause / enable / prevent / revise / resolve / contradict / same / continue / none。
  分三组：**因果族（6）**、**语义族（2）**、**无关系（1）**。以后这块抄 ECI——标签、定义、判定口径以它为准，我们只加分组和用途。
- **因果族（6）**：cause / enable / prevent / revise / resolve / contradict，带方向，读时沿路走一两跳；只有它们进「三次 + 用上」的升格流程。
- **语义族（2）**：`same` 换个叫法 / 换个说法（串线、去重）、`continue` 接着往下走（接上下半截）。有关但不是因果，不进因果库。
- **无关系（1）**：`none` 判为无关，当负样本留档（防反复重判、量准确率）。
- **假因果过滤**：不抄 ActMem 的 PMI（要跑 GPT2 类模型算似然），用我们自己的「三次重复 + 用上」替代。
