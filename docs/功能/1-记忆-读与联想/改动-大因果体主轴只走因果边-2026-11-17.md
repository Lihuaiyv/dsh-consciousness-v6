# 改动 · 大因果体：主轴只走因果边，底图不再冒充 · 2026-11-17

## 为什么

文档 §7 写得很清楚：

> 第一版只用「主干边 + 桥」做体；**底图不参与体的边界**，否则全库会连成一个体。

我当时 `loadBody` 拿的是**所有** confirmed 边（含 `adjacent` 0.3、`continue` 0.5）去建最大生成树。结果主轴是底图串出来的：读「去看说明书」，尾巴跑到「调试 Muse 头环」，因为那几件只是同一天挨着。

这不是密度没调好，是**主轴的根本没在用因果**。

## 改了什么

1. `loadBody` 里建树只用主干边：`cause / enable / prevent / revise / resolve / contradict / sublate / same_as`。
2. 主干边连不成线（<2 个节点）才退回底图，并且返回 `weak: true`——**明确标「只是挨着」**。
3. `formatBodyLine` 分两种说法：
   - 有主干边：`（这条线：A → B。最新是「C」…）`
   - 只有底图：`（挨着：A → B。这几件只是连着，还没判出因果）`，且不再追加「并进/分叉」，避免尾巴拖成 `…还没判出因果）；这里并进了别的线）`。

## 怎么验

- `node scripts/check-event-causal.mjs` → **42/42**（新增两条：没主干边说「挨着」、有主干边说「这条线」）。
- `node test/run-tests.mjs` → **584/584**。

真库副本上读出来的现在是：

```
（挨着：确认Nacos配置 → 验证注入件效果 → 验证线上与测试环境差异 → 确认121:8848的作用 → 机器状态查询。这几件只是连着，还没判出因果）
```

**全部标成「挨着」是实话**：库里现在主干边只有 1 条 revise、0 条 cause。文档 §12.10 那句「图的错比没有图更糟」，现在系统不会假装自己有条因果线了。

## 代价与下一步

代价：开关打开时，读到的多了一条「挨着」而不是「这条线」，看起来"退步"了——其实是之前那条「这条线」本来就是底图拼的。

要让它真长出「这条线」，只有一条路：**攒主干边**。

1. 每晚 23:30 的增量任务继续跑（C 期），但现在判得太保守，一夜 5 条、0 条 cause。
2. 所以下一件该做的是 `pull` 标定（文档 B 期）：50 对人工排序，定 0.9 / 0.7 / 0.5 / 0.2 的锚点，再让模型按锚点判。没有锚点，模型判出来的 strength 没法比。
3. 标定之后可以批量回填最近 30~50 天，让主干边先长出来一批（文档 §5.4 说先在 30 件上试，不要全库回填）。
