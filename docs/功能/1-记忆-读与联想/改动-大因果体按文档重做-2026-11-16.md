# 改动 · 大因果体按设计文档重做（底图 + 一条关系）· 2026-11-16 晚

> 一句话：上午那版按 kind 分边（cue/turn/title/adjacent/day）是**错的**，推翻重做。
> 现在照 `docs/功能/1-记忆-读与联想/思路-大因果体检索-2026-11-14.md`：**存一条关系**（pull 带符号 + 方向 + 层级 + 证据 + 状态），kind 只当解释标签，不参与遍历。

## 一、为什么推翻

上午那版把边按 5 种 kind 分开建、按 kind 分开走，等于文档 §4.3 说的「判的时候细、存的时候乱」——
越分越碎，读的人最后分不清哪条才是「这条线」。主人原话：「照这个重新做，别被原来你自己想的污染了。」

## 三、表结构迁移（老库）

`openDb` 里补列（direction/pull/level/confidence/reason/status/judge/valid_from/valid_to/updated_at），
并把上午那批实验边**标 rejected 且封口**（`valid_to` 填上）。
封口这一步很关键：唯一索引只认 `valid_to IS NULL` 的活边，不封口会占着位置，新边全被 `INSERT OR IGNORE` 静默吞掉——
第一次实测就踩到了：覆盖只 47.6%，因为 2059 条 `adjacent` 全被旧边挡掉。

## 四、验出来的数（只读副本，真库 2122 件）

```
底图：2106 件 / 2948 条边 / 680ms
按 kind：adjacent=2059(pull≈0.3)  same_as=760(pull≈0.99)  continue=129(pull≈0.5)
覆盖：2106/2122 = 99.2%   （文档 §10 验收线 ≥95%）
红线：hot_events 2122 / cold_events 2122，一行没动
```

验收 `scripts/check-event-causal.mjs` **19/19**：四条判据、只加边不合并、覆盖 ≥95%、幂等、体带 head、线是一句话、四种意图分得开、旧实验边不参与检索。

## 五、还没做（按文档顺序）

1. **主干边**（cause/enable/prevent/revise/resolve/contradict）：要模型判 + 一字不差的引文证据，`status='confirmed'` 才算；默认 `none`。文档 §10 要求先人工标 50 对、precision ≥0.75 才进下一步。
2. **读路径接线**：现在只有 `formatBodyLine` 这个函数，`event_recall` 之后还没拼进去；文档 §9.3 要求开关 `event.causal.inject` 默认 off，只在 why/next/settled 意图下出，单开 `event.causal.budget` 200 字。
3. **夜里收边**：去重、查环、重算 head、底图覆盖率 ≥95% 自动补。
4. 向量那一路候选（§5.3 第三路）没接，向量现在是停的。

## 六、怎么退

- 边表留着不读：`event.causal.inject` 默认 off，现在读链完全没接因果行，等于回到今天早上。
- 建图那段心跳调用可以直接注释（`index.js` 里 `buildBaseGraph` 那一行）。
- 表可以整个 `DROP TABLE event_edges`，没有别的链路读它。

## 七、红线（照旧）

只加边、不合并事件；不 ALTER `hot_events`／`cold_events`；不塞 `memory_links`／`rel_edge`／`events`；
边只追加，作废用 `valid_to` 封口，不物理删。
