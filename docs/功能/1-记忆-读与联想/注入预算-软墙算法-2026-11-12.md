# 注入预算：软墙（压力式）—— 算法定稿，暂不实现

2026-11-12。定的是**算法**，不是实现。具体压哪些、留哪些，以后再说。

---

## 一、为什么要改

现在是硬墙：`clampInjection` 有一个 cap（默认 800），超了就按顺序整段丢。

问题有两个：

1. **800 是个死数字。** 超一点点和超一倍，处理方式一样。
2. **超出一点点就要丢一整段。** 为了几十个 token 赔掉一整段记忆，代价大于收益。

---

## 二、算法

只有一个参考点 `B = 800`。不设最终总量上限。

```
压力 p = max(1, 现在总量 / B)

不重要的段（日记、记忆……具体名单待定）：
    保留条数 = max(1, 原条数 / p)

重要的（情绪、feel、关系、他的原话……名单待定）：永远不压
```

**超得越多，压得越狠；超得少，压得少。**

## 三、几个点上的样子

| 现在总量 | 压力 p | 10 条时保留 |
|---|---|---|
| 850 | 1.06 | 9 |
| 1200 | 1.5 | 6 |
| 2000 | 2.5 | 4 |
| 4000 | 5 | 2 |

**下限是一条**，并附一句「（还有 N 条没带进来）」。

## 四、这条算法的性质

- **总量不固定。** 记忆密的一天可以超很多；安静的夜就在 800 附近。
- **超不会变成「砍」。** 它只会变成「压」——压到几条，就看超了多少。
- **永不归零。** 最少留一条，加一句交代。

## 五、还没定的

1. 哪些段算「不重要」（现在的候选：日记、记忆、例子）
2. 哪些算「重要」（候选：情绪、feel、关系、他的原话、糖罐）
3. 单行巨长的怎么办（一段一万字，压不动）
4. 上面那句「还有 N 条」本身占字，要不要算进 p

**这四条以后再说。**

## 附：本次已做、但**不是**这个算法的

- `clampInjection` 的 `reservedKeys`：带 key 的行不参与削减（feel 每轮那句用它）。**这个保留。**
- `trimBlock` 被压时留一句「（还有 N 条没带进来）」。**这个跟算法方向一致，保留。**
- `softRatio = 0.15` 固定软墙：**这是理解错时的产物，已撤。** 固定百分比就是阶梯，不是压力。
