## 结论：让额度这一刀**不需要**（2026-11-15 18:1x）

查了代码，前提是错的：

- chatReply：`contextBlock = 事件行 + clampContextBlock(上下文块, promptBudget)` —— 事件行在**钳外**，不占那 800；
- 网页主路径：`promptText = [base, eventLine, stateLine]`，base 里的 `clampInjection` 只钳上下文块，事件行**另加**。

所以「检索吃满 800、事件行被挤」并不存在；事件本来就单开 400。真实的总量是：

| 段 | 上限 |
|---|---|
| 上下文块（身份 + 情绪 + 记忆） | 800（`memory.inject.budget`） |
| 事件行（自己想起） | 400（`event.inject.budget`） |
| 状态行 / 场景行 | 另算 |
| **合计** | **≤1200 + 状态行** |

要再收紧，得动「总上限」——那是另一件事（会碰到身份段，得先定优先级），不在预算表这一刀里。**D54 到此关闭**。
