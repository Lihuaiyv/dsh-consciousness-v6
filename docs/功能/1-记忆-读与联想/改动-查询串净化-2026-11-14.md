## 二、底下的机制（从入口到提示词，这条链的哪几段）

1. **入口**：`cleanUserText`（`src/text.js`）把一条 user 消息里的「人话」取出来，机器样板按行丢掉。
2. **取句**：`preStep`（`index.js:2049`）从最近的消息里拿用户那句 → `cleanUserText` → 再拼上一句做指代消解。
3. **路由**：`retrieve`（`src/modules/retrieve.js:38`）按关键词分 S1 每轮 / S2 回看 / S3 深检索，门槛 0.35 / 0.30 / 0.20。
4. **召回**：打分、候选池、预算；`packMemoryBlock`（`index.js:562`）把结果压成一段。
5. **缓存**：`recentRecall`（60 秒有效）。
6. **拼装**：`buildPrompt` 的 `memLineOf`（`index.js:941`）给每条贴来源徽章（`memory_tag.js`）、
   判断时态（`passport.js:193`），再在 `index.js:1316` 贴成「关于这句话，你能想起的事」。

**问题就出在第 1 段**：入口没把「上一轮回放」切掉，后面 2~6 段全在脏输入上跑，越往后越像真的。

## 四、试的过程里踩的坑（施工时必须避开）

- **拿时间行当截断点会切掉真话**：`用量 965K tok / 17:42 / DeepSeek免费公皮.zip 下这个…` 被切得只剩
  「用量 965K tok」。所以纯时间行只能当噪音丢，不能当截断点。
- **只认半句的规则会连真话一起丢**：`ask the user for approval` 那半句和主人真话在同一行，整行丢 →
  query 变空（实测 0 字，退回「空查询」兜底）。要清得能只摘行内片段，不能整行丢。
- **库里已有的坏料不会被这次改动清掉**：`[SCHEDULE REMINDER BATCH]` + reminders_json 已经写进记忆条/纪要；
  清历史属于「忘」链，另外排。
