## 1 动了哪

`src/modules/event_causal.js` `completeBy()` 的本地分支（约 L484-497）：

改前：

```js
const out = await localComplete(db, { ... })
if (String(out || '').trim()) return { text: out, judge: 'local' }
```

改后：

```js
const out = await localComplete(db, { ... })
// 2026-11-23（D102）：localComplete → gatewayChat 返回的是 { text, ms, model }，不是字符串。
const txt = typeof out === 'string' ? out : String((out && out.text) || '')
if (txt.trim()) return { text: txt, judge: 'local' }
```

一处改完，`judgePair` / `judgeBatch` / `counterfactualCheck`（判边、反事实重排）全部恢复；
主模型分支（`via='main'`）本来就取的 `out`（hostComplete 返回字符串），不受影响。

## 2 为什么（D102）

`localComplete` → `gatewayChat` 返回对象 `{ text, ms, model, swapped }`。旧代码把它整个当字符串塞进 `text`，
下游 `JSON.parse(object)` 变成 `[object Object]`，解析失败 → `relation='none'`、`ok=false`。

后果不是「判得不太准」，而是**一条都判不出来**：`event.causal.write` 就算打开，也是 0 条成立边；
而 worker 判完照样盖 `event.causal.judged.<day>` 章，第二天不再重判——于是看起来「判过了、库是空的」。

11-17 记的 20 条 `local` 边是接口还返回 string 时期的历史遗留；接口改成返回对象之后，本地路径就一直静默空转。

### 5.1 这轮数字说明什么（D103）

模型给的理由几乎都是同一种句式：「A 和 B 的内容没有直接联系 / 话题不同」。问题不在模型保守，在**我们问的不是
那天真实发生的关系**：11-22 是一条排查线，轮流修一个个子问题（卡顿→排队→面板→胶囊→重启丢数据）。
每一件不是前一件的尾巴，是「同一批活的下一步」。

所以下一步不该调阈值，先定一件事：continue 到底指「同一件事的延续」还是「同一批活里的下一件」。
这个定了，再改问法和候选打分（相邻 0.55 保底，实测 13 对只出 1 条，保底分没有信息量）。
