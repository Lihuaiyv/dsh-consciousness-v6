## 0 一句话

**判边 = 先在「一组本来就有关系的事」里，判「是不是因果 / 同一件事 / 子事件」，判完过反事实和互斥，一条线只走因果；同一件事和子事件只当注释、不占强边；判不出关系的照旧写弱边，读的时候门槛自然滤掉。**

不推翻旧设计的任何一条：`pull` 仍是唯一的数、因果仍是唯一的方向、`kind` 仍是解释标签、主/体/肉仍不存、事件不合并。
**2026-11-23 主人定：删掉 `continue`（「接着做」）这一类**——它原先只做「保连通、标同一批活」两件事，这两件由「分组」和「related 弱边」承担，不用赌规则。

## 2 关系体系（九类 + 互斥）

> 词表：因果六类 + `same`（同一件事）+ `subevent`（子事件）+ `none`。
> **线只走因果**；`same` 和 `subevent` 不占强边、不进骨架，各有用途（防重复 / 做层级）。
> `continue` 已删（2026-11-23 主人定）。

### 2.1 十类

| 族 | 类 | 意思 | pull | 谁判 |
|---|---|---|---|---|
| 因果 | `cause` | A 导致 B | +1 | 模型 + 反事实 |
| 因果 | `enable` | A 让 B 成为可能 | +0.9 | 模型 + 反事实 |
| 因果 | `prevent` | A 阻止了 B | +0.8 | 模型 + 反事实 |
| 因果 | `revise` | B 改写/补充了 A 的结论 | +0.9 | 模型 + 反事实 |
| 因果 | `resolve` | B 把 A 收尾了 | +0.9 | 模型 + 反事实 |
| 因果 | `contradict` | 两件说法冲突（负边） | −0.7 | 模型 + 反事实 |
| 折叠 | `same` | 同一件事的两个说法（只折不合） | +1 | 规则优先，模型兜底 |
| 折叠 | `same` | 同一件事的两个说法（只折不合；用于防重复） | +1 | 模型 |
| 结构 | `subevent` | A 是 B 的一部分（小 → 大；用于层级，不占强边） | +0.6 | 模型 |
| 排除 | `none` | 没关系 | 0 | 模型；写弱边 |

- `same` 与旧 `same_as` 同义（写库时统一写 `same_as`，读时当作 `same`）。
- `subevent` 方向：**小件 → 大件**（A 是 B 的一部分，箭头指向 B）。
- 两类都不进因果线：`same` 只防重复，`subevent` 只做层级。

### 2.2 互斥规则（只约束「参与拓扑的强边」，弱边不受约束）

> 2026-11-23 主人定：**「要用密度算因果体，留多几个关系，不然密度会丢信息。」**
> 落实成「**都存，拓扑只认一条**」——存的时候不砍，选主干的时候才挑。

1. **同一对可以存多条关系**（每类一条）：`kind`、`pull`、`evidence` 都保留，**信息不丢**。
2. **参与拓扑的只有一条「主关系」**：选法 `因果族 > same > subevent`；其余的关系存成 `status='weak'`，读路径不进骨架。
   **准确地说，受影响的是三处**：①度数名额（每件因果 ≤6，同一对占两个名额会把真边挤掉，体反而变小）；②读出来的话会打架（同一对既说「因为」又说「接着」）；③若密度按权重和算，重复边会把分抬虚。
   **体的节点集合和边界本身不受影响**——同一对的两条边起点终点相同，收进来的件相同，最大生成树只挑权重大的那条。
3. `same` 仍是最强结论：一对判了 `same`，不再写因果/子事件。
4. 弱边有两种来源，别混：
   - `kind='related'`：判 `none` 的「同一张网底」，pull 极小；
   - 次要关系：`kind` 是真关系（如 `continue`）、`status='weak'`，pull 按关系给。
5. **不再有 `continue`**：它原先保连通、标同一批活，现在分别交给 `related` 弱边和分组。
6. **为什么这样不丢密度**：密度看的是「一件连了几件」（度数），同一对贴两个标签度数还是 1；真正撑起体的是「A 连到 B、C、D」。

**为什么这不破坏旧设计**：旧设计说 `kind` 不参与遍历——读路径仍然只看 `pull`/`direction`/`level`。互斥是**写之前**的一致性校验，不是读路径的一部分。两者管的是不同阶段。

## 3 判边流水线（四步）

```
① 分组（不判）          ② 组内细判（一组一次）        ③ 反事实（只对因果族）     ④ 互斥校验 + 写入
   同天/共享专名/挂着件      锚件 + 组员 + 会话上下文         没有 A，B 还会吗         一对一条主关系 + 弱边
```

### ① 分组（粗筛，不调模型）

信号（沿用候选 v2 的三源，只改「用途」）：

- **同天 + 共享专名**：同一天内，两个件至少共享 1 个「具体专名」→ 同组。具体专名的判法沿用 `concrete()`，但**放行 2 字词**（只按泛词黑名单挡），因为 11-22 实测「面板/排队/卡死」被长度闸挡掉，边数 9→20。
- **接续挂着**：前件 `status='挂着'` 且后件提到它的专名 → 单独一组（最高优先级）。
- **跨天**：只留共享 ≥1 具体专名、间隔 ≤7 天。

每组挑**一个锚件**：组内度数最高（与组内最多件共享专名）的那件；同分取开始时间最早。

**为什么是锚而不是两两判**：组内两两是全对全判（平方级），锚 + 组员是线性。代价是偏向锚，用 `judge='rule-anchor'` 记账，读时能回溯。

验收：11-22 的 38 件 → 组数 ≤ 8，待判对数 ≤ 20；与两两全判算出的「真相邻共享专名对」重合率 ≥ 80%（允许漏，不允许凭空造组）。

### ② 组内细判（一组一次调用，给上下文）

- 输入（2026-11-23 实验定）：每件给标题、摘要（220 字）、起因/经过/结果、专名、原话 3 条；**再加 A 收尾 1500 字原文、B 开头 1500 字原文**（接缝，从 `fragments` 按 `turn_ids` 取）。合计约 3000 字，本地 14B 的 8000 上下文放得下。
  - 实测：11-22 的 14 对，一致率 **11/14（79%）**；旧输入（只给摘要）是 1/21（5%）。剩下的 3 条不一致全在「U 的边界」。
- 另外给：同会话最近 2 件的摘要（文档级上下文）。
- 输出：每个组员一个关系，**四选一**：`cause` 因果 / `same` 同一件事 / `subevent` 子事件 / `none` 无关。因果族六类在这里只判到「是不是因果」，细分类在反问里定，或直接给六类之一（二选一，实现时定）。
- 证据：仍要一字不差抄一句（≥10 字整句）；抄不出 → `none`。
- **prompt 里删掉时间顺序**：不给「A 结束于/ B 开始于」，只给内容；顺序只用作分组信号，不喂给判官（[2410.23884](https://arxiv.org/abs/2410.23884) 的结论）。
- 置信度 <0.6 → 按 `none` 处理，写弱边。

验收：人工标 14 对（第 0 期）做金标；模型与人工一致率 ≥ 60%，否则不进步。

### ③ 反事实（只对因果族，沿用 `counterfactualCheck` / `demoteIfStill`）

- 判成因果族的，再问「没有 A，B 还会这样吗」；还会 → 降级为 `subevent` 或 `none`（只留弱边）。
- 降级理由写进 `reason`（`cfReason`），不丢。

验收：抽 10 条降级，逐条能说出理由；降级率报出来（不设线，先看数）。

### ④ 互斥校验 + 写入

- 写入前用 §2.2 规则校验：同一对可写多条，但只有一条主关系是强边；其余写弱边，不丢信息。
- 弱边照旧写（`related` 极弱 / 次要关系按类给 pull），读时门槛滤掉。
- 改判不覆盖：新边 + 旧边 `valid_to` 封口；`valid_to` 只标「记错/重复」，不标「因果被推翻」（旧设计 §2.1）。
- 度上限沿用：因果每件 ≤6，桥 ≤2。

## 5 自洽检查（怕有「逻辑上通不了」的地方，逐条查过）

| # | 潜在断点 | 处理 |
|---|---|---|
| 1 | 「`kind` 只是标签」vs「互斥要用 `kind`」 | 写读分离：互斥只在写入前校验，读路径不看 `kind` |
| 2 | 一对只留一条强边 vs 一个因引出多个果 | 分别指 `(from,to)` 不同，不冲突 |
| 3 | `same` 阻断其他 vs 需要「同一件事的两个版本」 | `same` 本来就是折叠关系，阻断是对的 |
| 4 | 删 `continue` vs「没有孤立事件」 | 连通交给 `related` 弱边（判 none 也写，读时门槛 0.25 滤掉）：图是连的，线只走因果 |
| 5 | 体从密度长 vs 密度不够 | 密度不够就不长，正确；体仍不存 |
| 6 | 存多条关系 vs 拓扑干净 | 都存；只有主关系进骨架，其余 `status='weak'`。体边界不变，要防的是度数名额、读出来的话、按权重和算的密度分 |
| 7 | 子事件方向 vs pull 正负 | 子事件 pull 正（+0.6），方向由 `from_id→to_id` 表示（小→大） |
| 8 | 反事实降级成 `continue` vs「continue 不进模型」 | 降级是「模型判的因果被否定」，落到叙事类；`continue` 仍不主动问模型 |
| 9 | v2 id 与旧边 id 混写 | 真库边表当前 0 行；只写 `ev2_*`。若将来回填旧边，按 id 前缀区分 |
| 10 | 扩词表会不会让旧边「不合规」 | 旧边一条都没有；旧文档的九类不动，只加一类 |
| 11 | 「不合并事件」vs `same` | `same` 只连边，不合并；跟旧红线一致 |
| 12 | 锚件偏向 vs 对称性 | 记账 `judge='rule-anchor'`；人工标时能看出偏差 |
