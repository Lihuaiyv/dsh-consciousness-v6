## 0 先说我自己的判断

这个想法不是空想。它正好戳在现有事件层的一个空处：

- 现在事件之间**没有边**。`event_recall.js` 只是拿这句话去撞每件事的抓手词，撞上就带一件出来，撞不上就什么都没有。
- `memory_links` 连的是「记忆条目」；`rel_edge` 连的是「人和人」。**「事和事」这一层是空的。**
- 所以「一件事被想起时，能不能带出它的前因后果」现在做不到，不是没做好，是根本没有这条数据。

但我先把三盆冷水泼在前面：

1. **「因果」在个人记忆里大多数不是严格因果，是叙事因果。** 「因为所以」只是其中一种；更多的是「接着上次」「同一件事的下一步」「把之前的结论改了」「这件事把那个开放环收掉了」。如果只认严格因果，会漏掉大半；如果什么都算因果，图会糊成一团。所以边要分类型，不能只有一个 `cause`。
2. **不能把事件合并成一个大事件。** 「大因果体」应该是「一张带类型的边图 + 查询时派生出来的簇」，不是把十件事压成一件。事件本身永远不合并，这跟现有「冷库只追加、热库可版本化」的规矩一致。
3. **因果不能取消时间。** 时间是事件的属性，因果是事件之间的关系；两条轴，不是替代。因果能减轻「翻时间线找当前结论」的压力，但「什么时候发生的」永远得留着。

## 3 名词先定死（不然写着写着就混）

| 名词 | 定义 |
|---|---|
| **节点** | `hot_events` 里 `active=1` 的一件事。`cold_events` 只做时间/证据来源，不直接进图（同一件事两个版本会打架）。 |
| **边** | `event_edges` 里的一条：`from` / `to` / `kind` / `confidence` / `evidence` / `created_at` / `status`。只追加，不覆盖。 |
| **底图** | `same_as` / `adjacent` / `continue` 这些「连接边」，保证每件事至少有一条边；不承担因果断言。 |
| **旁支** | 不在主干路径上的边，尤其 `adjacent`、`bridge`、非主路径的 `continue`；检索时只挂 1 跳。 |
| **因果体** | 由 `confirmed` 的主干边 + 旁支连起来的连通分量；底图边只负责连通，不单独扩体。**不落表**，查询时算；以后要缓存再说。 |
| **主干 spine** | 从一个头到尾、置信度最高的一条路径；检索时最多取 5 个节点。 |
| **头 head** | 没有被 `revise` / `resolve` 指向后继的节点里，事件时间最新的那个。有多个就标「未收口」。 |
| **跨体桥 bridge** | 两个因果体之间共享实体/目标/开放环，且确认过的一条弱边。 |
| **开放环** | `open_loops.state='open'`，或事件 `status='没过去'`。 |

## 4 边分三层（+ 冲突）：底图（连接）+ 主干（因果）+ 旁支

先回主人那句：**临步和重复切也是关系，但不是同一种「因果」。** 我把它们分开：

- **底图**：保证「没有孤立事件」。`same_as`（同一件事的重复切）、`adjacent`（时间/会话上紧挨着）、`continue`（同一话题的延伸）。便宜、宽、几乎每件都能连上。
- **主干**：主因果。`cause` / `enable` / `prevent` / `revise` / `resolve`。贵、少、必须有证据。
- **旁支**：`bridge`（跨体/跨线的弱关联），以及不在主干路径上的 `continue` / `adjacent`。
- **冲突**：`contradict`，不判谁对，两边都留。

| 层 | 类型 | 方向 | 意思 | 判据 | 初版权重 |
|---|---|---|---|---|---|
| 底图 | `same_as` | 双向 | 同一件事的重复切/版本 | turn / 引文 / 标题重叠 | 1.0（折叠用，不参与因果排序） |
| 底图 | `adjacent` | A→B | 时间/会话上紧挨着 | 同会话/同日、间隔小 | 0.3 |
| 底图/旁支 | `continue` | A→B | 同一话题/同一件事的延伸，**不是因果** | 规则优先（共享抓手/同实体/同开放环） | 0.5 |
| 主干 | `cause` | A→B | A 导致 B | LLM + 证据引文 | 1.0 |
| 主干 | `enable` | A→B | A 让 B 成为可能/铺路 | LLM + 证据 | 0.8 |
| 主干 | `prevent` | A→B | A 阻止/避免了 B | LLM + 证据 | 0.8 |
| 主干 | `revise` | A→B | B 改写/推翻了 A 的结论 | 规则 + LLM | 0.9 |
| 主干 | `resolve` | A→B | B 收口了 A 的开放环 | 规则 + LLM + `open_loops` | 0.9 |
| 冲突 | `contradict` | A↔B | 两件事说法冲突，未定谁对 | 双方证据 + LLM | 0.7（保留双方） |
| 旁支 | `bridge` | A↔B | 跨体/跨线的弱关联 | 共享实体/目标/情绪 | 0.3 |

### 4.1 主干怎么选，旁支怎么挂

1. **先把 `same_as` 折叠**：同一件事的多个版本当一个节点；原始多版本留在库里，只读，不删。
2. **在体里找主干**：从最早节点到 head，按 `confidence × 层权重` 找一条最大权路径。`cause/enable/prevent/revise/resolve` 是主料；`continue` 可以当连接料（0.5）；`adjacent` 只在没有更好的连接时用（0.3）。
3. **不在主干上的边 → 旁支**：只挂 1 跳，最多 3 条；`bridge` 单独限 2 条。
4. **一个体可以有多条主干**：多条故事线不要强行并成一条；检索时按当前意图挑最近的那条。
5. **主干不是「唯一正确」**：它只是「这次最该走的线」；换一个意图，主干可以换。

### 4.2 这样回答主人的四个点

- **「临步」**：它是底图里的 `adjacent`，是因果的**弱形式/候选**——同一张网上的近邻，但还没有证据说「谁导致谁」。模型判出 `cause` 后升级成主干边；没判出来，它就只是「时间上挨着」。
- **「重复切」**：它是底图里的 `same_as`，是**同一性**关系，不是因果。检索时折叠，不参与「谁导致谁」；不折叠就会把重影当因果。
- **「所有事都能链接」**：底图上可以做到——同会话/同日/同话题至少一条边。但**连得上 ≠ 这次用得上**。因果仍然稀疏，主干仍然只走强边。
- **「现实世界没有孤立事件」**：同意。但记忆检索不是重建整个世界，是「这次该走哪条线」。所以：**存储上求连通，检索上求稀疏。**

**为什么 `bridge` 第一版不劳模型判**：跨体桥直接用「共享实体/共享开放环」做弱边；等体内边准了再升级。

### 4.3 统一因果：一条关系 + 层级（2026-11-14 14:2x 补记）

主人说：「我想用一种因果整合这些各种各样的因果。越分越乱。越抽象且稳定才算成果。」

这句我认。上一版列了 10 种边，那是**判的时候用**，不是**存的时候用**。判完要收成一条关系，不然图会越分越碎。

**主结构只留两样真相 + 一个视图：**

| 结构 | 管什么 | 不混什么 |
|---|---|---|
| `event_alias` | 同一件事的重复切 → 折叠成一个 canonical 节点 | **不是因果**，是同一性 |
| `event_edges` | 一条统一关系：`pull`（−1~+1，带符号）+ 方向 + 层级 + 证据 + 状态；`\|pull\|` 是凝聚度，符号是方向 | 不再按 10 种类型分表 |
| `event_conflicts` | **从 `event_edges` 里 polarity<0 的边派生出来的视图/索引**，用来快速查冲突 | 不是独立真相；真相在 `event_edges` |

`kind`（cause/continue/revise…）只留作**解释标签**，不参与遍历；遍历只看 `pull`、`direction`、`level`。这样「越分越乱」就止住了：判的时候可以细，存的时候只有一条。

**层级（越往上越抽象、越稳）：**

| level | 节点 | 怎么来 |
|---|---|---|
| 0 | 事件 | 切事切出来的 |
| 1 | 线/体 | 事件按 `pull` 聚类；体有 head、开放环、一句摘要 |
| 2 | 项目/阶段 | 体再按 `pull` 聚合；摘要更短 |
| 3 | 人生/世界 | 最高一层；一段总叙事，不是全边表 |

聚合规则：父体的 `pull` = 子体之间跨边 `|pull|` 最大的那条（保留符号；或 top-k 加权均值）。不是 sum；sum 会让大体重得离谱。父体只留一条摘要 + 一个 head，不复制子边。

**检索方向：末梢 → 主干。**

1. 种子是叶子（具体一件事）。
2. 往上看：在当前层，选 `|pull|` 最大的父体/主干边走一步——**不分正负**。负边是转折，不是旁路。
3. 到主干 / head 就停；需要旁支时，再横向 1 跳，不继续泛滥。
4. 返回：叶子 → 它所在的线 → 这条线的主干 → head。**只向上，不横向铺开。**

这跟「从主干往下分」相反：从具体的事出发，往它所属的更大的因果结构里收。人想起一件事，也是先想起那件事，再想起「哦，那是那阵子那条线」。

**「稳定」怎么算成果：**

- **扰动稳定**：随机加/删 10% 叶子边，体重/主干变化 < 15% → 稳。
- **压缩比**：叶子边数 / 体级边数；越高说明抽象越有效。
- **预测**：体级主干对「下一件事 / head」的命中率，要高于叶子边直接猜。
- **主干凝聚**：主干边的平均 `|pull|` ≥ 0.6；正负边都能进主干（至少 20% 的主干边为负）。
- **净价**：Σpull 只作解释（这条线整体是建设还是消耗），不作强弱。
- 四条都过，才算「抽象且稳定」的成果；只过叶子精度不算。

### 4.4 否定之否定：冲突是负向因果，不是边角料（2026-11-14 14:3x 补记）

主人说：「这个我不认可。我认为是因果，但是是旁路。类似于人类的否定之否定。不过冲突的可能辩证统一了。也可能就永远作废或者暂时作废。所以也是相当重要的因果路径。」

这句我认，我上一版把冲突踢出因果，是错的。冲突不是「非因果」，是**负向因果**：A 否定 B，B 否定 A；它不产生「延续」，它产生**改变**。改变也是因果。

**冲突的三种结局（不是三种边，是三种状态）：**

| 状态 | 意思 | 图里怎么走 |
|---|---|---|
| `sublated` | 辩证统一了，出现第三件事 C（否定之否定） | A↔B 的负边 + A→C、B→C 的正边（`sublate`）；从 C 继续 |
| `invalidated` | 一方作废，另一方留下 | 负边标 `invalidated` + `winner_id`；从赢家继续 |
| `suspended` | 暂时悬置 / 永远悬置 | 负边保留，两边都留；head 标「未统一」，不硬选 |

**三角模式：**

```
A  ──oppose(−)──  B
 \               /
  \──sublate(+)─/──► C
```

C 是「否定之否定」。C 站住之后，可以变成新的正题，再被 D 否定——**这是螺旋，不是树**。所以主干不是一条直线，它会被冲突**掰弯**，甚至整条主干就是由几次强否定组成的；冲突不是旁支的装饰，是改道的力量。

**检索时：**

- 末梢→主干往上收，遇到 `polarity<0` 的**活跃**边，不能装看不见：必须带出对手和结局。
- `sublated` → 沿 `sublate` 边走到 C，C 是新主干。
- `invalidated` → 走到赢家，输家标「已作废」，但保留。
- `suspended` → head 标「未统一：A vs B」，两边都带，不偷偷判。
- 冲突边**也抢主干**：`|pull|` 大的负边就是主干的一部分。它不是旁路，是**转折**；旁路是 `|pull|` 小的那些。

**为什么不能把它塞回 `event_conflicts` 单表：** 单表会让它变成「另一个系统」，读的人又要问「这跟因果图什么关系」。它本来就该在 `event_edges` 里，只是极性为负、状态不同；`event_conflicts` 只是它的一个快查视图。

### 4.5 主干怎么算才不 NP-hard：最大生成树（2026-11-14 14:4x）

「主干 = `|pull|` 最大的路径」这句话，直接算会踩一个坑：在带环的图里，最长路径是 NP-hard。不能真去搜「最长」。

可算的做法：**最大生成树（MaxST）**。

1. 把每个体里的边按 `|pull|` 从大到小排；
2. 用 Kruskal / Prim 建一棵最大生成树（只保留能连通所有节点的最重边）；
3. 主干 = 这棵树上从最早节点到 head 的路径。

为什么这样好：

- 多项式时间，1893 件也能跑；
- 树天然破环，不会 A→B→A 绕死；
- 扰动稳定：加/删一条叶子边，树的主干大概率不变——正好对上「越抽象越稳」；
- 符号还在：边上的 +/− 不丢，主干读起来还是「正题 → 反题 → 合题」。

**互相否定（reciprocal）怎么处理**：A→B +0.8、B→A −0.8 时，MaxST 只会选更重的那条做骨架；另一条不删，作为「同时 B 也否定 A」的注脚。主干是一棵树，不是一张全图。

## 5 写路径：夜里切事之后，慢慢长

### 5.1 第 0 步：先认「同一件事」（必须先做）

候选：

- 同一天 + 共享 ≥2 个抓手；
- 标题/故事的字面相似（3-gram 覆盖 + 引文重叠）；
- `turn_ids` 有重叠；
- 向量余弦高（事件 story 的 embedding）。

判定：

- 规则先过：`turn_ids` 重叠 ≥1 或引文有同一句 → 高置信「同一件事」；
- 模型只判边界情况；
- 结果先写成 `same_as` 边（`status='candidate'`），**不自动合并**。人工看 30 对，确认后再决定是否走 `hot_events` 的 merge。

> 为什么先做这个：试跑里 8 对候选没有一对是清晰因果，大多是重复切。先连因果，等于先给重影发身份证。重复切不是噪声——它是底图的一条边；只是不能让它冒充因果。

### 5.2 第 1 步：先把底图连上（规则，不调模型）

在找因果候选之前，先保证每件新事至少有两条底图边：

- `adjacent`：同会话/同一天，时间相邻的前后各 1 件；
- `continue`：共享 ≥2 抓手，或同实体，或同一条开放环；
- `same_as`：5.1 的结果。

跨天先不硬连；跨天只走同话题/同实体。实在孤立的，连到时间上最近的同一天事件（权重 0.2），只用于「那阵子在干嘛」，不用于因果扩写。

这一步不调模型，先把「没有孤立事件」做到；连不上才进下面的模型候选。

### 5.3 第 2 步：给每件新事找 6 个因果候选

三路并集，去重后取 6 个：

1. **相邻**：同一会话/同一天里，事件时间紧挨着的前后各 2 件；
2. **抓手/实体**：共享 ≥1 个抓手或实体，按共享数排序取 4 件；
3. **向量**：事件 story 的 embedding 余弦 top 4。

再加一路：**共享开放环**（`open_loops` 里同一条 loop 关联的事件）。

### 5.4 第 3 步：一次判一批，不要一对一对判

每件新事一次调用，把 6 个候选一起给模型：

```
你是事件关系判断员。给 A（新事）和 B1..B6（候选），逐对判断：
- 关系类型：cause / enable / prevent / continue / revise / resolve / contradict / none（adjacent / same_as 已由规则处理，不要在这里判）
- 方向：A→B / B→A / 双向
- 置信度：0~1
- 证据：必须从两件事的 story 或 quotes 里一字不差抄一句；抄不出就 none
- 一句话理由
规矩：先后发生不等于因果；同一件事的重复切已经由 same_as 处理；说不清就 none。
只输出 JSON。
```

成本：100~190 件/天 × 1 次 = 100~190 次/天；夜里跑，不占开口延迟。先在 30 件上试，不要全库回填。

### 5.5 第 4 步：写边

- 底图边（`same_as` / `adjacent` / `continue`）规则直接写，`status='confirmed'`，不需要模型证据；
- 主干边（`cause/enable/prevent/revise/resolve`）只写 `status='confirmed'` 的（置信度 ≥0.7 且证据引文非空）；
- 其余写 `candidate`，不参与检索；
- 同一对 `(from,to,kind)` 只留一条，重复命中就抬 `confidence`；
- 边只追加，不改旧边；要推翻就写一条新的 `contradict` 或把旧边 `valid_to` 标掉（跟 `rel_edge` 一个路子）。

### 5.6 第 5 步：夜里收一次

- 去掉重复边；
- 查底图覆盖率：没有底图边的事件，补 `adjacent`；目标 ≥95%；
- 查环（A→B→A），环上的边降级成 `candidate`；
- 重算每个体的 head / 开放环 / 主干；
- 不每晚做全图社区划分；先用「主干边 + 桥」算连通分量，底图不参与，等主干边多了再说。

## 6 读路径：检索时怎么带出来

### 6.1 先认意图，不要每轮都带因果

借 MAGMA 的做法：查询先分意图。

| 意图 | 触发词（举例） | 走法 |
|---|---|---|
| `why` | 为什么 / 怎么变成 / 起因 / 怎么会 | 沿 `cause/enable/continue` **往回**走 |
| `next` | 后来 / 然后 / 结果 / 接下来 | 沿 `cause/continue/revise/resolve` **往前**走 |
| `settled` | 现在怎样 / 定了吗 / 还没完吗 | 取 head + 开放环 |
| `default` | 其他 | 只走 1 跳，双向，取置信度最高的 3 条 |

没有意图、也没有种子事件时，**不加因果行**。不加比乱加好。

### 6.2 检索步骤

1. **种子**：现有 `recallEvents` 照旧，取 top 1~2 件。这一步不改，保证不破坏现在的联想。
2. **向上收**：从种子叶子往上看，选 `|pull|` 最大的父体/主干边走一步——**不分正负**；负边是转折，不是旁路。到主干/head 就停。需要旁支时再横向 1 跳，不继续泛滥。
3. **取体的上下文**（每轮最多 1 个体）：
   - spine：最多 5 个节点，每个一行；
   - head：最新结论；
   - 开放环：最多 2 条；
   - 冲突：遇到活跃负边，带出对手 + 结局；`suspended` 时 head 标「未统一」；
   - 一个旁支：只在它和当前话题直接相关时带。
4. **排序**：种子分 + 边置信度 × 跳数衰减 + 新近；同一个 hub 节点最多出现 1 次。
5. **注入**：因果行单开一个小额度（建议 `event.causal.budget`，默认 200 字），不占事件那 400。

### 6.3 出来长什么样

不要倒整张图，只要一句「线」：

```
（这条线：花.md 重排错范围 → 回滚 → 改成按段重排。最新是「改成按段重排」；回滚那一步还没收口。）
```

或者：

```
（这件事的上一步是「先备份再改」，下一步是「抽宿主适配层」；这条线还没收口。）
```

或者，负边做主干的：

```
（这条线是：先做 24 句模板 → 被「太僵了」否定 → 改成模型磨砂。主干的重心在「否定」那一步，不在模板。）
```

**关键：给「线」，不给「节点列表」。** 人想起一件事时，带回来的是「那件事后来怎么样了」，不是六个孤立标题。

## 7 「大因果体」怎么长出来（涌现，不是一次性聚类）

- **先有主干边，后有体。** 不预先建「体」表；体是主干边 + 旁支组成的连通分量，底图边只负责把体接在地面上。
- **体与体之间用桥，不合并。** 两个体共享一个实体/目标/开放环，就连一条弱桥；它们仍然是两个体。这就是主人说的「主干和根须缠绕」——缠绕是边，不是把两棵树焊成一棵。
- **度上限**：主干边每件最多 6 条；`continue` 最多 4；桥最多 2。底图边可以多，但检索只走 1 跳，不拿它扩写。
- **社区划分**：第一版只用「主干边 + 桥」做体；底图不参与体的边界，否则全库会连成一个体。等主干边够多（>200 条）再上 Louvain/Leiden。
- **head 不是「时间最新」**：时间最新只说明它最后发生，不说明它是结论。head 必须是「没有 revise/resolve 指向后继」的节点；有多个就标「未收口」，别硬选一个。

### 7.1 整体因果与局部因果（2026-11-14 14:2x 补记）

主人说：「蝴蝶扇风和台风乍一看没有因果，但是就是个因果啊。整个世界不就是一个巨大的因果体吗？只是局部因果有限，整体因果无限。」

这句我认。上一版我把「因果」说窄了。准确说，要分三层：

| 层 | 是什么 | 能不能存 |
|---|---|---|
| **物理因果** | 世界是一个因果网；蝴蝶扇风、台风、你今天的情绪，都在同一张网里 | 存不下，也不该存：每个事件有无限多个原因 |
| **叙事因果** | 一件事的 story 里说得出来的「因为 / 所以 / 后来 / 结果」 | 能存，要求证据引文 |
| **检索因果** | 这次想起这件事时，值得走的那几条边 | 能存，稀疏、加权、按意图取 |

所以「世界是一个巨大的因果体」成立；但记忆不是把这张网抄下来，是**从网上剪一段能讲的故事**。局部因果有限，是因为剪得动；整体因果无限，是因为网本身没有边。

**设计上的三个后果：**

1. **开世界假设**：没有边 ≠ 没有因果，只代表「还没证据 / 还没连」。检索时不能说「这两件事无关」，只能说「我没找到直接证据」。
2. **全局因果是背景先验，不是边表**：每一对事件在物理上都可能有极弱的因果势；但 O(n²) 条边存不下、也没用。我们只把「有证据、够强、这次用得上」的边落到 `event_edges`；其余留在背景里。
3. **层级体**：局部体可以往上并成父体，父体再往上并成「世界体」。世界体是一句摘要 / 一个地平线，不是一张全边表。检索默认在局部体走；只有主人问「更大的图景」时，才升一层看父体。

**如果要把「整体因果」落成可查的**：不存全边（O(n²) 存不下），存三层——局部体（事件边）、父体（阶段/项目摘要）、世界体（一段总叙事）；再加一个「潜在因果」候选池，只在被问到时算，标 `speculative`，永不注入为事实。这样「世界体」是查得到的摘要，「潜在因果」是查得到的假设，但都不是假装的确定边。

一句话：**世界是一个因果体；记忆是它的一段可讲的局部。** 我们不否认整体，只是不假装能把它存完。

## 8 时态压力：因果能减多少，不能减多少

主人问的「争议的话用因果判断不就能极大减轻时态压力」——**能减一部分，不能全减。**

能减的：

- 「现在到底是什么结论」不用从头翻时间线，沿 `revise/resolve` 走到 head 就行；
- 「这件事后来怎么样了」不用按日期扫，沿 `continue/cause` 往前走；
- 两条冲突的说法，用 `contradict` 边挂在一起，而不是靠「谁的时间戳更晚」猜谁对。

不能减的：

- 事件什么时候发生，永远是属性；因果边不能替代时间戳；
- 因果不是传递的：A→B、B→C 不代表 A→C；不能做传递闭包；
- 「后发生」不等于「是结论」；「说得晚」不等于「推翻了前面」；
- 争议不该被图悄悄判掉：`contradict` 要保留双方，标「未收口」，检索时把两种说法都带出来。

所以准确说法是：**因果把「时态压力」从「每次都要翻时间线」降成「只在需要时看时间戳」。** 不是取消时态。

## 10 最小第一步（按 AGENTS.md：先写验收，再动代码）

### 第 0 步：只读，不碰运行库（建议先做这个）

1. 复制真库到 `scratch/`（已做：`scratch/causal-probe/app.db`）。
2. 取最近 30 件，跑「同一件事」候选，人工标 30 对（同一件 / 不是）。
3. 取最近 50 对，跑「因果」候选，人工标 50 对（none / continue / cause / enable / prevent / revise / resolve / contradict）。
4. 出三个数：底图覆盖率、同一件事 precision、因果边 precision；再出「none 率」看模型是不是过度连线。

**验收线（先定死，达不到就不进下一步）：**

- **底图覆盖**：≥95% 的事件至少有一条 `same_as`/`adjacent`/`continue` 边（规则就能做到）；
- **同一件事**：precision ≥ 0.9（重复切很显眼，应该做得到）；
- **因果边**：confirmed 的 precision ≥ 0.75（宁可少，不可错）；
- **因果覆盖**：30%~60% 的事件至少有一条主干边；不追求 100%——有些事就是日常，硬连因果会编；
- **主干像不像主干**：抽 20 个体，人工打 1~5 分，平均 ≥3.5；
- **扰动稳定**：随机加/删 10% 叶子边，体重/主干变化 <15%；
- **压缩比**：叶子边数 / 体级边数 ≥ 5:1（先测再定）；
- **主干凝聚**：主干边平均 `|pull|` ≥ 0.6；正负边都能进主干（至少 20% 的主干边为负）；
- **冲突处理**：抽 20 对冲突，检索必须带出双方和结局（sublated/invalidated/suspended），不能只留一方；
- `none` 率 ≥ 50%（如果模型对一半以上都说「有关系」，说明它在编）。

### 第 1 步：影子写

- 只写 `scratch/` 的 JSON，不写 `event_edges`；
- 用 20 条查询回放：有因果行 vs 没有因果行，人工打 1~5 分「有没有帮上忙」；
- 验收：平均 ≥3.5，且没有一条把话题带偏。

### 第 2 步：开关开写

- `event.causal.write=on`，只对新事件；
- `event.causal.inject=off`；
- 跑 3 天，人工抽 50 条边看。

### 第 3 步：开关开读

- `event.causal.inject=on`，只在 `why/next/settled` 意图下；
- 连续 20 轮验收：有没有带出「整条线」而不是「一堆节点」；有没有挤掉原来那件事。

### 退路

- 关开关就回到今天；边表留着不读，不影响任何现有链路；
- 不删 `hot_events` / `cold_events`；不删旧边，只标 `valid_to`。

## 12 风险 / 反例（必须先认）

1. **事后归因**：A 先发生、B 后发生，模型很容易说「A 导致 B」。必须要求证据引文，且默认 `none`。
2. **重复事件污染**：真库里 8 对候选没有一对是清晰因果，大多是重复切或邻步。不先做同一件事识别，因果图会先长出一堆假链。
3. **「最新」不等于「结论」**：最后发生的事可能是新话题。head 要用 `revise/resolve` 判，不是看时间戳。
4. **毛球化**：每件都连 6 条，三个月后就是一个大团。度上限、桥上限、`continue` 上限，一个都不能少。
5. **因果传递谬误**：A→B、B→C 不代表 A→C。检索最多 2 跳，不做闭包。
6. **时间被丢掉**：只沿因果走，会忘记「这是三个月前的结论」。时间永远是属性，检索要能回退到时间线。
7. **预算挤占**：因果行会抢占事件那 400 字。必须单开小额度，只在有意图时出。
8. **评估没有金标准**：人工标 50 对也会有分歧。先看 precision，不追求 recall；宁可少连。
9. **粒度不匹配**：一天 74~191 件，有的大事、有的一句话小事。因果边要允许「小事挂在大事下面」，别强行同级。
10. **图的错比没有图更糟**：没有图，最多是想不起来；图错了，会自信地带回一条错链。所以默认关、先影子、再开读。
11. **连通 ≠ 可检索**：底图会把 1893 件连成一个大分量；如果检索不加权，就会「想起一切」。所以底图只负责连通，检索只走主干 + 1 跳旁支。

## 13 我的建议（一句话）

**先做「底图 + 同一件事识别 + 50 对因果人工标注」，再谈大因果体。**
底图求「没有孤立事件」，主干求「因果准」，旁支求「周围有谁」。先证明「边判得准」，再证明「带回来有用」；不要先建全图。边不准，大因果体只是把噪声放大。

## 14 它能不能当检索工具：我的判断（2026-11-14 14:4x）

### 14.1 逻辑上成立吗

成立，但有三处要钉死：

1. **符号语义**：`+` / `−` 只说明「支持 / 反对」，说不清是「因果」「延续」「否定」「扬弃」。`pull` 管结构，`kind` 管解释，`state` 管结局；不要让 `kind` 参与遍历，但也不能把它删光——不然读线的人不知道这是「因为」还是「但是」。
2. **路径可算**：主干用 MaxST（§4.5），不用最长路径；否则带环就 NP-hard。
3. **pull 校准**：0.9 和 0.6 的差别不能拍脑袋。要有一张 rubric：明确连接词 / 证据 = 0.9，强蕴含 = 0.7，同话题 = 0.5，仅同日 = 0.2；否定词（不对 / 推翻 / 改回 / 算了）= 负。先标 50 对校准，再上线。

### 14.2 适合 / 不适合

| 查询 | 适不适合 | 为什么 |
|---|---|---|
| 「为什么现在是这样」 | **很适合** | 末梢→主干正好给出因果线 |
| 「这件事后来怎么了」 | **很适合** | 沿 `\|pull\|` 往前走到 head |
| 「现在到底哪个结论算数」 | **适合** | head + 开放环 + 冲突状态 |
| 「这条线里有什么没解决的矛盾」 | **适合** | 负边 + `suspended` |
| 「配置项是多少」 | **不适合** | 该走 T1 事实检索 |
| 「把所有相关的事都列出来」 | **不适合** | 图会泛滥；该走向量/关键词 + 上限 |

结论：它是**叙事检索**，不是通用检索。最好的用法是**路由**：先认意图，再决定走 T1 / 向量 / 事件因果。不是每轮都走图。

### 14.3 怎么验它是不是好工具

50 条查询，5 类（why / next / settled / conflict / fact 对照），每条人工标「期望的转折点 / head」。

对比基线：

- A：现在的抓手事件召回（单件）；
- B：向量 top-k 事件；
- C：扁平 top-k 事件列表（不给线）。

指标：

- **线召回**：返回的线里有没有那个转折点（正负都算）；
- **线精度**：线上的节点是不是真在这条线上；
- **head 命中**：当前结论对不对；
- **冲突召回**：未解决的冲突有没有带出来；
- **代价**：token / 延迟。

成功线：why / next / settled 三类上，因果线比扁平列表的人工评分高 ≥0.5（5 分制）；fact 类不下降（路由把它送去 T1）。

### 14.4 我的结论

- **逻辑**：成立。它是一张带符号的因果图 + 最大生成树主干 + 自底向上的层级检索；数学上站得住。
- **工具潜力**：有，但定位是**叙事 / 情境检索**，不是替代现在的 T1/T2/向量。它最值钱的地方是回答「为什么会变成现在这样」——这是扁平检索最弱的地方。
- **最大风险**：`pull` 是模型判的，不是物理量；不校准就会「看着很合理，其实在编」。所以先做 50 对校准 + 50 条查询，不要先建全图。
- **最大机会**：冲突 / 否定也能进主干。这一条如果成立，它比普通 GraphRAG 更接近「人的记忆」——人记住的往往不是「事实清单」，是「哪次转折改了我」。

### 14.5 多模式检索：我的看法

同意：人不是只有一种检索。线索、时间、情绪、关系、叙事、空间，各走各的。单一检索器是简化。

但「所有好的方式都做一下」要有三个前提，不然会摊成一堆不能比的玩具：

1. **统一接口**：每个模式都输出同一张卡——`id / text / source / score / why / cost`。没有统一输出，就没法融合、没法比较。
2. **统一评测**：同一套 50~100 条查询、同一套指标；每个模式只在自己擅长的类别上比，不拿自己的长处比别人的短处。
3. **路由 + 预算**：先认意图，再选 1~2 个模式；不是每轮全跑。路由错了，后面全错。

先做 **router + benchmark**，再按「现有系统最缺什么」排序：

```
因果叙事（why/next/settled） → 时间线（那阵子在干嘛） → 情绪/关系（我对这事什么感觉） → 空间/多模态（以后）
```

每个模式一个 flag，默认 off；赢了基线再进主路径。**探索可以全做，产品只能留赢的。**

### 14.6 漏洞与补全清单（2026-11-14，施工前必看）

| # | 漏洞 | 补全 |
|---|---|---|
| H1 | `pull` 把「因果强度 / 判断置信 / 事件重要」混成一个数 | 拆三列：`strength` / `confidence` / `importance`；主干只用 strength，confidence 做门，importance 做展示 |
| H2 | `+/-` 太粗：导致 / 延续 / 阻止 / 推翻都压成一个符号 | 加薄标签 `mode`（generate / block / revise / continue）；遍历只用 strength，读线用 mode |
| H3 | 后事改写前事，方向逆时间 | 边加 `retroactive` 标记；MaxST 按无向权重，方向只作解释 |
| H4 | `sublate` 判得太松，任何「后来改了」都像辩证统一 | 三证据门槛：A 的命题、B 的反命题、C 同时吸收两者；缺一降级成 `revise` 或 `suspended` |

### 14.7 深度审查：还能往哪深入（2026-11-14）

不是再加功能，是把三个东西从「说法」变成「可算的东西」：**层级、冲突、因果声明**。

**1. 体 / 主干 / 层级不一致 → 图过滤 + 持久性（persistent homology）**
- 问题：底图把所有事连成一个大分量；主干是 MaxST；「体」又按连通分量算。三个结构的阈值不同，会互相打架。
- 形式化：把边按 `|pull|` 从大到小加进去，记每个阈值下哪些点连成一片；MaxST 就是这棵「合并树」。一个体活得越久（跨的阈值范围越大），越稳定。**稳定体 = 长持久性的分量**，不是拍一个阈值。
- 最小动作：在 100 件样本上算合并树，取活得最久的前 3 个分量，和人工标的体比。

**2. 冲突检测只看单边不够 → 符号平衡（signed balance）**
- 问题：一条负边只说明 A 反对 B；但「矛盾」常常是三角：A 支持 B、B 反对 C、C 又反对 A。
- 形式化：Heider 平衡理论——三角里负边数为 0 或 2 = 平衡；1 或 3 = 不平衡。**不平衡三角 = 活着的矛盾**，优先送 `sublate` / `suspended`。
- 最小动作：抽 50 个三角，算平衡；看不平衡三角是否对得上人工标的冲突。

**3. 父体聚合会抹平冲突 → 守恒律**
- 问题：父体摘要容易写成「总的来说…」，把子体的未解决冲突抹掉。
- 形式化：父体必须守恒——`net = Σ 子体 net`；`cohesion = max 子体 abs(pull)`；`unresolved = Σ 子体 unresolved`。摘要必须能回指子事件。
- 最小动作：给体摘要加三个字段（net / cohesion / unresolved），抽 20 个体验守恒。

**4. 叙事因果 ≠ 因果效应 → 加 `claim_type`**
- 问题：我们的边是「故事里说因为」，不是「反事实检验过的因果」。两者混在一起，会过度声称。
- 形式化：`claim_type ∈ {narrative, counterfactual, physical}`，默认 `narrative`；`counterfactual_checked` 布尔；`asserted_by`（文本/主人/模型）。输出措辞要区分「故事里说因为」和「事实上导致」。
- 最小动作：边表加 `claim_type`；没有 `counterfactual_checked` 的边，注入时不许写成事实。

**5. 检索目标没定义 → 效用函数 + 学习排序**
- 问题：「最有用的一条线」现在是手调阈值，没有目标函数。
- 形式化：`U = relevance + λ1·turning_point + λ2·head_proximity − λ3·cost − λ4·redundancy`；λ 从人工偏好里学，不拍脑袋。
- 最小动作：50 条查询 × 4 条候选 = 200 对偏好，训一个小 reranker；和手调比。

**6. 度偏差 / 枢纽霸屏 → PPR + 度归一**
- 问题：叶子往上收，边多的节点更容易被走到；同一个 hub 会对所有查询都出现。
- 形式化：Personalized PageRank（从种子出发，`|pull|` 作权重，度归一）；或最大似然路径 + 度惩罚。
- 最小动作：20 条查询，比「贪心向上」和「PPR」的 hub 重复率。

**7. 反馈回路：冲突越检索越重要 → 边疲劳**
- 问题：冲突显眼 → 被检索 → 显得更重要 → 更容易被检索。图会自己放大戏剧性。
- 形式化：边级 exposure / fatigue，像事件的 `want` / `ceiling`：每被带出一次，下一次分数降一点；冷一段时间再回来。
- 最小动作：记录每条边被带出的次数；20 条查询后看同一个冲突是否霸屏。

**8. 单一树装不下多域生活 → 多视角 DAG（不是一棵树）**
- 问题：工作、关系、自我、世界各有主线；一棵树只能有一个根，会把别的域压成旁支。
- 形式化：`aspect`（work / relationship / self / world）各自一棵树，共享事件节点；检索按意图选 aspect；根是每个 aspect 的叙事根，不是唯一世界根。
- 最小动作：给 50 件标 aspect；建 2 棵 aspect 树，看重叠和主干差异。

**9. 评测只看相关性不够 → 反事实 / 消融 faithfulness**
- 问题：线召回高不代表线有用；可能只是把整张图都带回来了。
- 形式化：去掉主干上最重的一条边，看回答是否变差；变差 = 这条边是 load-bearing。再抽 20 对做「如果没有 A，B 还会发生吗」的反事实探针。
- 最小动作：20 条查询 × 3 次消融；记 answer change。

### 14.8 哪里难判断、哪里必须调模型（2026-11-14）

原则：**只在「语义不可归约」的地方调模型；能算的（MaxST / PPR / 持久性 / 疲劳 / 排序）一律不调。**

| 环节 | 难在哪 | 规则能做什么 | 模型做什么 | 频率 | 错了会怎样 |
|---|---|---|---|---|---|
| 同一件事（alias） | 换说法、补切、同标题不同事 | turn_ids 重叠、同引文、标题/抓手 | 边界情况判「是不是同一件」 | 新事件，少量 | 重影被当因果 |
| `continue` vs `cause` vs `none` | 先后发生 ≠ 因果；话题延续 ≠ 因果 | 相邻、共享抓手/实体 | 判关系类型 + 方向 | 每件新事 4~6 候选 | 图变糊 / 假因果 |
| `pull` 强度 | 0.9 和 0.6 没有客观标尺 | 只给档位（强/中/弱） | 给档位 + 证据；锚点校准 | 同上 | 阈值全失真 |
| `sublate`（否定之否定） | 三件事：A 命题、B 反命题、C 吸收两者 | 只能找候选三角 | 判 C 是否真的吸收 A+B | 少量高价值三角 | 把「换方案」当「辩证统一」 |
| 冲突状态（sublated / invalidated / suspended） | 要等后续；「暂时」vs「永远」 | 时间窗 + 后续事件 | 判状态、找赢家 / C | 事件更新时 | 提前判死 / 永远悬置 |
| head / 最新结论 | 最新发生 ≠ 结论 | 时间 + 无后继 revise/resolve | 判「这句是不是结论」 | 体更新时 | 把「停在这里」当结论 |
| 体 / 父体摘要 | 要压缩又不能抹掉冲突 | 守恒字段（net / cohesion / unresolved） | 写摘要、保留未解决冲突 | 每晚 / 每周 | 高层假和谐 |
| aspect 标注（work / relationship / self / world） | 一件事可能跨域 | 关键词 / 来源 | 边界情况判主域 | 新事件，少量 | 主干放错域 |
| 查询意图路由 | 一句话可能多意图 | 关键词表 | 轻量分类 / 小模型 | 每轮 | 走错检索模式 |
| 输出成句（composer） | 线要像人话，不能列节点 | 模板 | 把线写成一句 | 每轮 | 生硬 / 超预算 |
| 反事实检验 | 「如果没有 A，B 还会发生吗」 | 无 | 抽样判 | 少量高价值边 | 把叙事因果当事实 |

**最难的三件，按难度排：**

1. **`sublate`**：三体关系，不是两两；要判「C 同时吸收 A 和 B」。模型最容易把「后来换了个说法」当辩证统一。**必须人工抽检。**
2. **`pull` 强度**：不是判「有没有关系」，是判「多强」；没有锚点就不可比。**先标 50 对锚点，再让模型打分。**
3. **head / 最新结论**：要读整条线，不是看时间戳。**先用规则筛，再让模型确认。**

**不该调模型的：** MaxST、持久性 / 合并树、PPR、社区划分、边疲劳、候选去重、排序 / 预算、时间窗、alias 硬门。这些都能算，调模型只会更慢更贵更不稳。

**调用节奏：**

- **夜里**：切事（已有）+ alias + 因果边 + 冲突状态 + 体摘要。批量、离线。
- **查询时**：只做「意图路由 + 输出成句」；不判边、不遍历模型。图遍历是算法，不是模型。
- **人工**：锚点校准、sublate 抽检、评测标注。
