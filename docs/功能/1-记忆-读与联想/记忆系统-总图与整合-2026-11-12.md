## 0.5 重定（2026-11-12 下午）：原始碎片 + 事件（冷/热库）

> 这一段是主人和小汐从零谈的，**取代 §6 / §7 的旧五层方案**。旧方案保留在下面，只作参考。

**只有两样东西：原始碎片、事件。**

### 原始碎片

一条碎片 = **时间 + 源头 + 形式 + 内容 + 当时的状态快照 + 接自其他碎片（0 到多个）**。

- 只追加，不改不删；没有「属于哪件事」这种字段。
- 状态快照只写碎片出生那一刻；之后系统再出东西 → 另开一条碎片，接自指向它。
- 接自不是因果；只指向更早的碎片；0 到多个；空着也行。
- 图片、语音、文件只存指针，不塞进库。

### 事件

事件 = 从一段**连续碎片**里读出来的一件事：**名字 + 经过 + 证据**。

- **名字**：一句话，这件事是什么。
- **经过**：一段叙事，写起因、经过、结果，带上当时的语气、细节、转折。**不规定字数**——有的事长，有的事短。只写发生过的，不写「这说明什么」「我学到了什么」。
- **证据**：经过里那一两句原话，必须能在碎片里一字不差找到。
- **切事**：换目的、换主体、告一段落才换；同一件里情绪起伏不算换事；宁可少切，不可硬编。
- 允许留缝（有些碎片不进任何事件）；禁止孤儿事件（没有碎片支撑的名字不算）。

### 事件冷库 / 事件热库

- **冷库**：夜里第一刀切出来的事件。只追加、不改；每条指回连续的一段碎片；**补切允许**（追加新的冷事件，旧的一个字不动）。
- **热库**：当前用的那一版。可以合并、拆分、改名、压缩、沉底。
  - 每条必须有**来源**；来源直接记**冷库 id 的集合**，不记热库 id（避免链条越接越长）。
  - 合并时来源展平到冷库；拆分时来源 = 冷库事件 + 碎片子区间。
  - 变一次出**新版**；旧版 `active=0` 留档，另记一条**为什么变**。
- **追溯**：热库 → 冷库 → 碎片，两跳到底。
- **压缩 / 遗忘**：只动热库；冷库和碎片一步不动。遗忘 = 热库沉底（不再浮现）；复活 = 从冷库重新长一条热事件。

### 温度与额度

- 事件是**温库**：不是每轮都进，被带出来 / 被问起才进。
- 进的时候**名字 + 经过全文**一起进；**另开一个额度**，不占原来的 800 token。
- 额度先不设硬上限，只记 token；以后按实测再收。
- 一轮先按**最多一条**事件。
- 碎片是**冷库**：不进提示词，想深了沿事件翻。

## 4. 山在哪（七条病，带数）

1. **一句话最多记五遍**：原话（raw/chat）→ 每轮 episode 条目 → 纪要（episodes）→ 日记（diaries）→ 提示词留底（scene）。五份各自有开关、各自能改。
2. **四套时间边界**：纪要按「每 6 轮 / session·day」切；日记按「本地日」切；新设计按「清醒段（≥4 小时没人说话）」切；留底按「每轮 / 每 20 轮」截。同一段对话在四个地方被切成不同的事。
3. **两套 id，join 断**：raw_turns 是 `turn_*`，chat_turns 是 `cht_*`，没有列能对上；memory_items.source_turn_id 只指向 raw。于是「这条记忆是哪句话」只能靠时间猜。
4. **四条「自己想起」通道**：pulse（2h/条，12/天）、affect.surface（3/天）、quote_echo（3,843 条事件）、confluence self（默认关）。它们互不知道对方，抢同一个 800 token 预算。
5. **至少十套「重要度」**：w0、weight、stability、difficulty、importance、salience、hits、heat、band、temp_state（还有 valence）；episodes 另有 importance/hits。没有一个统一口径，调一个不会影响另一个。
6. **八套遗忘/失效**：HIDE（55 条）、fade（模糊）、temps（冷热）、tiers（band）、decay、passport（旧条）、claim（作废）、conflict（取代）。谁都能让一条记忆不再出现，但彼此不通知。
7. **观测比内容大**：events 68k、surfaced_items 30k，而 memory_items 5k、日记 20 篇。events 里大头是传感器（drive.sensor 7.4k、mind_dropped 6.5k、affect.appraised 6k），不是记忆。

外加三条：
- **能力覆盖率低**：向量只覆盖 14% 的条目；`memory_provenance` 只覆盖 21% 的条目（1,076/5,018，和 11-10 记的 4.5% 口径不同，先对齐）；revisit 0 行。说明「检索能做到的事」大多停在纸面。
- **空表当功能**：13 张 0 行表，页面上可能还显示着，实际没跑。
- **写口散**：一张 memory_items 30 处写点，出问题时很难知道是谁写的。

## 5. 整合原则（五条，先立规矩再动代码）

1. **一物一表**：每一层只有一个权威表；其余是投影、索引、观测，必须能重建。
2. **一个 id 到底**：`turn_id` 是血缘；`event_id`、`memory_id` 都挂 `turn_id`。chat_turns 补 `turn_id`。
3. **一个写口**：每层只有一个写函数（如 `addMemory`、`recordEvent`、`appendTurn`），别处只能调它，不许自己拼 INSERT。
4. **一个读口**：一个注入规划器统一取数、排序、裁预算；旁路只出「候选」，不直接往提示词里塞。
5. **一套重要度**：只保留两个口径——「事」的 `weight`、条目的 `importance`；heat/band/temp/hits 都从它们派生，不再各算一套。

```
L0 原话层   raw_turns（主人，turn_*）｜chat_turns（所有通道，补 turn_id）
              ↓ 只追加，不改写；这是唯一不可重算的真相

L1 事层     memory_events（每「事」一行）
              title / who / started_at / ended_at / quotes / turn_ids /
              status / cues / weight / r / ceiling / settled_at / segment_id
              ↑ 夜里切一次（清醒段），重跑覆盖
              ↓ 投影（不再重切原话）

L2 叙事层   episodes（段纪要）｜diaries（一天一篇）
              都从 L1 生成，带 event_ids；只负责「怎么讲」，不负责「记什么」

L3 条目层   memory_items（结论/事实/偏好/立场/自我）
              fact_archive（历史版本）｜memory_provenance（原话链）｜memory_timeline（变更）

L4 桌面层   一个 planner：检索 + 浮现 + 开环 + 感觉 + 引语 → 800 token
              每轮最多一条「自己想起」，来源只允许一个

索引（可重建）  raw_fts / memory_fts / fact_fts / memory_vec / entities
观测（可丢）    retrieval_log / surfaced_items / events（白名单，60 天）
档案（只读）    scene_archive / state_scene / confluence_log / revisit（照片永不删）
```

### 和「六库」的对应

| 六库叫法 | 落到哪一层 | 说明 |
|---|---|---|
| T0 桌面（注入块） | L4 | 只有规划器能写 |
| T1 memory_items | L3 | 只放结论/事实/自我，不再放每轮原话 |
| T2 episodes（纪要） | L2 | 从 L1 投影 |
| T3 diaries（日记） | L2 | 从 L1 投影 |
| T4 raw_turns | L0 | 权威原话 |
| FA fact_archive | L3 | 历史版本，不参与日常注入 |

### 归属落定（保留 / 改 / 停）

- **保留不动**：raw_turns、memory_fts/fact_fts/raw_fts、persona/relations/drive 等邻域、scene_archive/state_scene（照片）。
- **加列**：chat_turns.turn_id；episodes.event_ids；diaries.event_ids；memory_items 只加必要的（不要再加重要度列）。
- **改投影**：episodes、diaries 改为读 memory_events 生成。
- **停写**：memory_items 里「每轮用户原话」的 episode 行；pulse.surface_queue；两路旧浮现；events 非白名单。
- **降级**：memory_links 冻结；memory_vec 暂不扩；quote/subtext/loop/bridge/residue/closing 从「直塞」降为「候选」。
- **命名避雷**：观测表 `events` 和大事表 `memory_events` 别混；日志里必须能一眼分清。

## 7. 迁移顺序（旧方案，已被 0.5 取代）

> 旧的五步（统一 id → 停重复写 → 收读 → 收忘 → 收观测）作废；新顺序以 §0.5 末尾那条为准。

> 原则：先收「写」，再收「读」，最后收「忘」。一次只动一条链。

**第 0 步 · 立图（本文）**
产出：这份总图 + 全库清单 + 每条功能/每张表的「留/改/停」标记。
验收：主人点头；不再有人问「这张表是干嘛的」。

**第 1 步 · 统一 id**
- chat_turns 加 `turn_id`，新写入全部带；老行标 `turn_id=null`（明确「无链」，不猜）。
- 新增一列 `linked_at` 或复用 `pack` 标记，便于统计覆盖率。
- 验收：新一周内新行 `turn_id` 覆盖 100%；「这句话→原话」能一条 SQL 走通。

**第 2 步 · 停重复写**（带开关，先 shadow）
- 停「每轮用户原话」写进 memory_items（保留 self/life 的自我经历）。
- 停 pulse.surface_queue；新浮现接管。
- episodes 改为「从 memory_events 生成」：先 shadow 一周（生成但不入库），人工抽 10 天对比。
- 验收：同一句话在库里最多剩两份（原话 + 事）；`memory_items` 日增先测基线（现约 314 条/天），目标降到「真结论」级别（先定 30 条/天以下，看一周）。

**第 3 步 · 收读**
- 一个 planner：从 L1/L3/L4 取；所有旁路只出候选，由 planner 排序、统一裁 800 token。
- 每轮「自己想起」最多一条；来源唯一（要么新浮现，要么引语，要么开环）。
- 验收：注入来源数≤1；token 中位数不涨；一天浮现 4~5 次。

**第 4 步 · 收遗忘**
- `visibility`（HIDE）是唯一「能不能说」；`fade` 只管「说多清」；`temps/tier/heat` 只影响排序；`claim/conflict/passport` 只标状态，不删内容。
- 验收：造 3 个反例（已忘 / 模糊 / 被取代），三套规则互不打架。

**第 5 步 · 收观测**
- events 只留白名单（记忆写入、浮现、遗忘、注入决策）；drive.sensor / mind_dropped 之类 60 天清。
- surfaced_items 30 天、retrieval_log 60 天；affect_samples 采样降频。
- 验收：一周库增量下降 ≥50%；面板数字不受影响。

## 8. 先别做

- **不迁老数据、不删表、不合并库文件**。老数据是证据，先留着。
- 不新加「更像人」的评分/标签/算法。现在缺的是归位，不是新功能。
- 不动照片（11-10 定：scene_archive / state_scene 永不删）。
- 不在同一周同时改写链和读链。写链先收，读链后收。
- 不把「整合」做成一次大爆炸。每步一个开关，能回旧路。

## 9. 验收（七条，能测）

1. 同一句话在库里最多 **2 份**（原话 + 事），不再有每轮条目。
2. 新增行的 `turn_id` 覆盖 **100%**。
3. 每轮「自己想起」**≤1 条**，一天 **4~5 次**。
4. 注入 token 中位数 **不涨**（上限仍 800）。
5. 问「上次那事你后来改主意了吗」10 题，答对 **≥8**。
6. 一周库增量 **下降 ≥50%**（观测白名单 + 停重复写）。
7. 全量门禁 **不红**。
