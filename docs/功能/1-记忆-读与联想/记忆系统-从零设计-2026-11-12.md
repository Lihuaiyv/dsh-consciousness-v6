## 1. 两样东西

```
碎片 fragments          ← 档案，只追加，一点不动
 ├─ 冷库 cold_events    ← 夜里第一刀，只追加
 └─ 热库 hot_events     ← 当前用的版本，可以变

追溯：热 → 冷 → 碎片，两跳到底。
```

- 碎片是「发生过什么」的记录。
- 事件是「那是什么」的解释。
- 结论、事实、日记、纪要、检索、遗忘——这次都没进来，留作以后。

## 2. 原始碎片

### 2.1 它是什么

**最原始的档案。一点不动，只记录所有能读到的信息，包括时间。**

- 只追加，不改、不删、不打标签。
- 没有「属于哪件事」这种字段。
- 图片、语音、文件、工具结果、系统消息，都只是碎片的不同形式。

### 2.2 一条碎片长什么样

**12 列**，代码里用英文列名，中文是它装什么：

| 列 | 装什么 |
|---|---|
| `id` | 碎片编号 |
| `agent_id` | 哪只 |
| `session_id` | 哪段会话 |
| `turn_id` | 哪一轮 |
| `seq` | 第几句 |
| `role` | 谁：`user` / `assistant`（以后 `system` / `tool`） |
| `form` | 形式：`text` / `voice` / `image` / `file` / `system` / `tool` |
| `text` | 内容（图/语音/文件放外面，这里存指针） |
| `snapshot` | 当时的状态快照（JSON，先空） |
| `antecedents` | 接自哪些碎片（JSON 数组，先空） |
| `meta` | 附带：工具名、路径、参数（JSON） |
| `at` | 时间 |

### 2.3 三条铁律

1. **碎片一点不动**：只追加，不修改，不删除。
2. **状态快照只写出生那一刻。** 之后系统再出东西 → 另开一条碎片（`role='assistant'`），`antecedents` 指向它。
3. **接自不是因果。** 因果是读的时候下的判断；`antecedents` 只记「接着谁」。

### 2.4 边界

- `antecedents` 只能指**更早的碎片**：时间只往后，不会成环，也不会指自己。
- 出生时写死；以后发现「还接自第二条」，不能补，只能**新开一条碎片**。
- 同一秒进来多条碎片，快照各存一份——冗余，自包含，可以接受。

## 3. 事件

### 3.1 它是什么

- 事件是**第二层**，是**解释**，不是记录。
- 事件从一段**连续的碎片**里读出来，圈一段、起个名、指回碎片。
- 事件不是碎片的字段；事件在碎片之外，**引用**碎片。
- 名字必须能指回碎片；指不回的不算。
- 允许有些碎片不进任何事件（留缝）；不允许一个事件没有碎片支撑（孤儿）。

### 3.2 事件 = 名字 + 经过 + 证据

- **名字**：一句话，这件事是什么。
- **经过**：一段叙事，写清起因、经过、结果，带上当时的语气、细节、转折。**不规定字数**——有的事长，有的事短，跟着事本身走。
- **证据**：经过里那一两句原话，必须能在碎片里一字不差找到。
- 只写发生过的，不写「这件事说明什么」「我学到了什么」——那是另一种东西，容易编。

经过是碎片里没有的东西：把一堆话读成「一件事」，这才是抽象。

### 3.3 怎么切

- 换**目的**、换**主体**、**告一段落**，才算换事。
- 同一件事里情绪起伏不算换事。
- 宁可少切，不可硬编。
- 切事在夜里做（大模型读完整段再切）。
- 切漏了可以**补切**：追加新的冷事件，旧的一个字不动。

### 3.4 冷库 / 热库

**冷库**（夜里第一刀切出来的事）：

- 只追加、不改。
- 每条指回连续的一段碎片。

**热库**（当前用的那一版）：

- 可以变：合并、拆分、改名、压缩、沉底、复活。
- 每条必须有**来源**；来源直接记**冷库 id 的集合**，不记热库 id（避免链条越接越长）。
- 合并时来源展平到冷库；拆分时来源 = 冷库事件 + 碎片子区间。
- 变一次出**新版**；旧版 `state='retired'` 留档，新版记 `op` 和 `reason`。
- 不复用「变更账」表：版本链本身就是历史——上一版是「变之前」，这一版是「变之后」，`changed_at` 是时间。

### 3.5 温度与额度

- 事件是**温库**：不是每轮都进提示词，被带出来 / 被问起才进。
- 进的时候**名字 + 经过全文**一起进；**另开一个额度**，不占原来的 800 token 预算。
- 额度先不设硬上限，只记 token；以后按实测再收。
- 一轮先按**最多一条**事件。
- 碎片是**冷库**：不进提示词，想深了沿事件翻。

### 3.6 压缩与遗忘

- **压缩** = 合并 / 缩短经过，出热库新版，旧版留档。
- **遗忘** = 热库沉底（`state='sunk'`，不再浮现），冷库和碎片一步不动。
- **复活** = 从冷库重新长一条热事件。
- 压缩和遗忘，动的都是解释层，永远不动碎片。

## 4. 三张表

### 4.1 建表

```sql
-- 1. 碎片：原来的 raw_turns 改名 + 加列
CREATE TABLE fragments (
  id TEXT PRIMARY KEY,
  agent_id TEXT NOT NULL,
  session_id TEXT,
  turn_id TEXT,
  seq INTEGER NOT NULL DEFAULT 0,
  role TEXT NOT NULL,
  form TEXT NOT NULL DEFAULT 'text',
  text TEXT NOT NULL,
  snapshot TEXT,
  antecedents TEXT,
  meta TEXT,
  at TEXT NOT NULL
);
CREATE INDEX idx_frag_agent_at ON fragments(agent_id, at);
CREATE INDEX idx_frag_session_seq ON fragments(session_id, seq);

-- 2. 冷库：夜里第一刀，只追加
CREATE TABLE cold_events (
  id TEXT PRIMARY KEY,
  agent_id TEXT NOT NULL,
  title TEXT NOT NULL,
  narrative TEXT NOT NULL,
  from_fragment TEXT NOT NULL,
  to_fragment TEXT NOT NULL,
  quotes TEXT,            -- JSON 数组，必须能在碎片里逐字找到
  created_at TEXT NOT NULL
);
CREATE INDEX idx_ce_agent_at ON cold_events(agent_id, created_at);

-- 3. 热库：当前版本，可版本化
CREATE TABLE hot_events (
  id TEXT PRIMARY KEY,
  agent_id TEXT NOT NULL,
  title TEXT NOT NULL,
  narrative TEXT NOT NULL,
  sources TEXT NOT NULL,  -- JSON：冷库 id 的数组（拆分时可带碎片区间）
  op TEXT NOT NULL,       -- merge / split / rename / compress / sink / revive
  reason TEXT,
  version INTEGER NOT NULL DEFAULT 1,
  state TEXT NOT NULL DEFAULT 'active',  -- active / retired / sunk
  created_at TEXT NOT NULL,
  changed_at TEXT NOT NULL
);
CREATE INDEX idx_he_agent_state ON hot_events(agent_id, state);
```

## 5. 旧系统怎么处理

**不是推倒，是加一层。**

- 旧库其他表全部不动。
- `raw_turns` 退场，代码里引用它的地方改到 `fragments`（约 110 处，机械替换 + 测试兜底）。
- 旧读路径（深翻、asof、visibility、ops 对账、vault 导出）改完要冒烟。
- 新的事件库先只写不读：夜里切冷库，不接注入。
- 稳定事实、检索、遗忘、日记、纪要，全部先留在旧系统。
