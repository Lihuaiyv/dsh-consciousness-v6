# 改动 · 判边搬进插件进程，用宿主主模型 · 2026-11-17

## 为什么搬

主人定了分工：**切事留本地，判因果交给宿主主模型**（一天一两块）。

卡点：宿主主模型只能在插件进程里拿到。独立脚本（`judge-causal.mjs`）里试了三次：

```
primary.name: chain
chat 输出: "{}"   servedBy: fallback   lastError: chain: no adapter for chat
complete: "{\"overlap\":\"unknown\",...}"   lastError: chain: no adapter for complete
```

`HostLlmAdapter` 在独立进程里没有宿主上下文，`available()` 拿不到东西，chain 就找不到能跑 chat 的适配器。所以“起个脚本子进程判”这条路走不通。

## 改了什么

1. **`event_causal.js` 加 `judgeDay(db, aid, day, { via, limit })`**：把原先脚本里的“取当天事件 → 找候选 → 批量判 → 反事实重排 → 记账”整套搬进模块，只判不写库，返回 `{ calls, pairs, usable, rels, judged }`。
2. **`workers.js` 的判边 tick 不再 spawn 脚本**：直接在插件进程里 `judgeDay(..., { via: 'main' })`；写库仍看 `event.causal.write`，判完写 `event.causal.judged.<day>` 标记。
3. **两道保护**（不然会静默判废）：
   - `completeBy` 走主模型时，如果 `servedBy === 'fallback'`（其实没调到模型，返回的是 `{}`）**直接抛错**，不返回空结果；
   - tick 里 `out.calls === 0 && out.total > 0` 就**不写标记**，下一轮重来——否则那天会被记成“判过了”，实际一条没判。
4. `judge-causal.mjs` 保留，仍可手动/本地跑（`--model main` 在独立脚本里会失败并报错，不再静默）。

## 怎么验

- 两个模块导入 ok，`judgeDay` 存在。
- 门禁 `node test/run-tests.mjs` → **584/584**。
- 真正的验证要看重载后第一次判：`events` 里 `event.causal.judge` 的 payload 应带 `via: "main"`，且 `flags.event.causal.judged.<day>` 只在那天确实判过之后才出现。

## 生效与观察点

- 重载插件后 90 秒第一次 tick；它会挑最近三天里切完但没判的那天。
- 看 `hooks`/probe 里的 `causal-judge(<day>) calls=… pairs=… usable=… wrote=…`。
- 如果看到 `causal-judge-nothing`：说明主模型没调到（或全部失败），标记没写，会重试——这时候要查宿主模型可用性，不是判边逻辑。

## 成本

按 117 件/天、每件 6 个候选算：117 次调用、输入约 30 万 token、输出约 6 万 token，一天一块到一块五。
