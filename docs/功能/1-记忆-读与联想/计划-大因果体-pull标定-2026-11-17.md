# 计划 · 大因果体 `pull` 标定（B 期）· 2026-11-17

> 文档 §14.1 第 3 点：「`pull` 校准：0.9 和 0.6 的差别不能拍脑袋。要有一张 rubric：明确连接词 / 证据 = 0.9，强蕴含 = 0.7，同话题 = 0.5，仅同日 = 0.2；否定词（不对 / 推翻 / 改回 / 算了）= 负。先标 50 对校准，再上线。」
>
> 现在模型是自己瞎给 0~1 的数，所以阈值全是虚的：说 `|pull| ≥ 0.6` 是骨架，但没人知道 0.6 到底对应什么。

## 四档锚点（人给的，不是模型给的）

| 档 | 分数 | 判据（人话） | 例子 |
|---|---|---|---|
| 3 | 0.9 | 话里明说了因果（因为 / 所以 / 导致 / 结果），或者有硬证据（同一份文件、同一条报错） | 「帧写口不通 → 改完就通了」 |
| 2 | 0.7 | A 铺好了路，B 顺着做，但话里没明说因果 | 「先立在场基线 → 再建帧行注入」 |
| 1 | 0.5 | 同一话题的下一步，不是因果 | 「讨论拆文件 → 实际拆文件」 |
| 0 | 0.2 | 只是同一天/同一会话挨着 | 「早上问天气 → 下午改代码」 |
| − | 负 | 否定、推翻、冲突、改回 | 「本来要 A → 算了，改 B」 |

规则：**拿不准就往低档写**。文档 §10 的 `none` 率 ≥50% 就是靠这个守住的。

## 素材从哪来（关键，别再用随机对）

2026-11-17 试过一次随机抽 12 对：6 对是「同一件事说了两遍」，3 对只是同一天，3 对不相干，**没有一对是因果**。拿这个标定等于没标。

正确做法：

1. 先跑影子判（`scripts/judge-causal.mjs --dry`），只挑它判成 `cause/enable/prevent/revise/resolve` 的对；
2. 人工只看这些——它们才是候选锚点；
3. 每个判出的对，人工标「真因果 / 只是接着 / 没关系」三选一；
4. 攒够 50 对再算一致率。

## 一致率怎么算（≥80% 才过）

- 机器给的 `pull` 按四档归档（≥0.85 → 3；≥0.6 → 2；≥0.35 → 1；其余 → 0；负值单独一档）；
- 人工档位和机器档位一致的占比 = 一致率；
- 线：**≥80%**（文档 B 期验收线）。
- 不一致时看方向：机器普遍偏高还是偏低，整体平移一档，不改 rubric 结构。

## 退路

- 标定不通过 → `event.causal.write` 保持 off，读路径也不开；
- 不通过不改代码结构，只调权重或干脆把模型给的数只当排序、分档由规则算（文档 §14.8「不该调模型的：排序 / 预算」）。
