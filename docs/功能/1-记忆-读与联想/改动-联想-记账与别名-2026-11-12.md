## 一、改了什么

| # | 位置 | 改法 | 为什么 |
|---|---|---|---|
| 1 | `index.js` 顶部导入 | 从 `./src/core.js` 多导入一个 `event` | 文件里 `event(...)` 用在三处（`event.inject` / `qq.bridge.scope_probe` / `qq.bridge.prompt_qq`），但从来没导入过。每次调用抛 `ReferenceError`，被 `try {} catch {}` 吞掉——**账本静默失效**，查证的人会得出「没跑过」的错误结论 |
| 2 | 真库 `hot_events.cues`（9 条事件） | 给每件事补 1~2 个口语别名 | 抓手是专名（「深夜的糖罐」「三观引擎」），而沾边规则按连续 3 字滑窗，「深夜的糖罐」滑出来是「深夜的 / 夜的糖 / 的糖罐」，中间带虚词，口语里不会这么连。主人说「糖罐那个事」「三观模块」，原来一个字都撞不上 |
| 3 | `src/modules/event_recall.js` 的 `wordScore` | 同一件事被两个别名同时撞上时只算一次（长的优先） | 补别名后「双层麦辣鸡」和「麦辣鸡」各加 1 分，同一句话的分数翻倍（1.229），会把别的事压下去。设计本来就写着「一句话里同一个词出现两次不重复算」，这里漏了别名这一种重复 |

## 五、还没做 / 风险

4. **别名只写进了热库，没动冷库**（冷库按设计只追加、永不改）。如果哪天对 11-11 那段重切（`cut_rev` +1），热库会从新冷事件重新派生，这批别名会丢——重切后要重新补一遍。

## 六、换角度复测（23:52，三个角度）

前一轮是「我编句子 → 看撞不撞」。这一轮换三个角度：**反着问、换时机、换情绪**。

### 角度 A · 反着问：每件事自己出不出来

拿 13 件事，每件写一句「最像主人会说的自然话」，看能不能认回这件事。

**结果：11 / 13 认对。** 哑的两句：

| 说 | 期望 | 结果 |
|---|---|---|
| 你那天回来的时候门口灯亮着 | 推门回来，和那句仪式感 | 空（抓手是「门口亮着」，带虚词，滑窗撞不上） |
| 我们聊感觉到哪一步了 | 抽象、感觉、内省 | 空（抓手是「感觉分两层」，滑窗落在「感觉分 / 觉分两 / 分两层」） |

两句是同一个病：**抓手越长、越带虚词，滑窗越没用**。补别名能救个案，救不了这一类。

### 角度 C · 换情绪：情绪会不会变成触发器

把主情绪从「烦躁」改成「平静」再跑。

- 13 句该空的话：烦躁 **0/13**、平静 **0/13** —— 情绪没让它乱捞，这条守住了。
- 乘数确实在工作：同一句「花md又得回滚了吧」烦躁 1.193 / 平静 1.372（`calm` + 已过去 ×1.15）。

### 角度 B · 换时机：刚浮现过，再说一遍会怎样

把库复制一份，打上「刚浮现过」的标记（`last_surface_at` / `last_mention_at` / `mentions`），同一秒再说同一句话。

**结果：又浮了一遍（1.372，一模一样）。**

原因：`recallEvents` 只筛 `state`，不看水位那条线——`state='台面'`（= 想头低于 0.5）的也照收。

**2026-11-13 定下来的改法**：不另加时钟，让水位当闸——只收 `state='待联想'`（`tickWant` 已经按 0.5 标好状态）。原设计里那条「30 分钟冷却」从 v3 删掉：同一件事不该有两道闸。

按真库算，这条线画在 0.5 的效果（从当前水位涨到 0.5 要多久）：

| 事 | 水位 | 到 0.5 要 |
|---|---:|---:|
| 三件重事（w=0.9·没过去） | 0.43 | 0.8h |
| 三观模块 / 糖罐（w=0.8·0.6） | 0.41 / 0.37 | 1.2h / 2.0h |
| 推门回来 / 双层麦辣鸡（w=0.4·0.3·过去了） | 0.32 / 0.31 | 6.8h / 7.6h |
| 晚八点记忆体检（w=0.3·过去了） | 0.30 | 8.4h |
| 花.md 回滚（刚浮过，掉到 0.03） | 0.03 | 15.7h |

浮完之后从 0 涨回 0.5：重事 6~8 小时，轻事 12~20 小时。**水位会随时间涨，所以不是「一次都浮不出来」，是「刚说完那阵子浮不出来」。**

### 顺带一个观察

「花md那回排错范围了」撞上的是**《花.md 两次重写和一次清洗》**，不是「花.md 重排错范围，回滚」——两件事同源，互相抢。现在靠分数取第一条（设计就是这么定的），但同源事件越多，抢得越厉害。这是以后「合并同源事」的动机，不是现在要修的 bug。
