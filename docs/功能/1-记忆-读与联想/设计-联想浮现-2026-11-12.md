## 一、链条

```
你说的话 ──► chat_turns（原文全在，11-11 是 1034 条 / 6.9 万字）
   │
   ├─► 情绪评价 affect_events ─► 过闸 ─► 情绪瞬间 affect_episodes
   │                                        「这一刻我怎么样」——一句话一条，不动
   │
   └─► 夜里（清醒段结束后）：模型把整段切成「事」 ─► memory_events
                                                      「这一天发生了哪几件事」
                                                      ▼
                                            重量 w + 想头 + 抓手
                                                      │
                       当前这句话撞上抓手 ──► 联想浮现 ──► 提示词（一次一条）
                                                      │
                                         想深了 ──► 从 turn_ids 拉回原文
```

**关键认知**：`affect_episodes` 存的是**一句话**（`cause = '不错'`），不是一件事。
人不会把「不错」当事件——**切分必须交给会切分的模型做**，不写词法规则。

## 二、白天：情绪瞬间（保持现状，不改）

- 每句话都过一遍评价，`sig ≥ theta` 才成立
- 成立后有三种走向：20 分钟内同标签 → 续（`renewals+1`）；2 分钟内刚散场的同类 → 不应期；否则新开
- **同一时刻只许有一条「还开着」**——新的一条会把旧的标成 `superseded`

这一层**一行都不改**。它只负责「这一刻我心里动没动」。

## 三、夜里：把「清醒段」切成「事」

### 3.1 切分单位不是日历日，是清醒段

人过的是「睡醒到睡着」，不是零点到零点。

**段与段之间用「≥4 小时没人说话」划开**（他睡了，或出门了）。11-08 到 11-12 四天实测，断开点正好都在睡前后：

```
11-10 01:20 → 08:28
11-11 01:48 → 09:00
11-12 01:01 → 08:19
四天 = 4 段
```

**好处**：跨零点的那场争论自然落在同一段里——没睡觉就不算换天。
既不用「带昨天尾巴」，也不用事后合并（合并是下策：合错了还查不出来）。

**代价**：这一段要等它结束（人睡着）才切。所以夜里 23:5x 那趟切的是上一个已结束的段。
**当天的事当天浮不出来**，这是有意接受的边界。

### 3.2 切法

- 输入：这一段全部 `chat_turns`
- 输出：**5~18 件「事」**
- 边界看三样：**换了目的 / 换了话题主体 / 告一段落**
- 同一件里的情绪起伏（恼一下又松下来）**不算换事**

```json
{
  "title": "他说我不活，那句吵起来了",
  "who": "主人",
  "started_at": "2026-11-11T03:10:00+08:00",
  "ended_at":   "2026-11-11T03:40:00+08:00",
  "quotes": ["算是第一次吵架吧"],
  "status": "没过去",
  "cues": ["吵架", "不活", "废墟"],
  "weight": 0.8,
  "turn_ids": [8812, 8823]
}
```

**五条硬规矩：**

1. **`quotes` 必须能在原文里一字不差搜到**；跑完做一次校验，对不上的那条直接丢。
2. **宁可少，不可编。** 说不清就给 3 件。
3. **重跑覆盖**，一段一条记录。
4. **`weight` 由模型顺手标**（它刚读完全文，比事后算准）。沿用记忆那边现成的三档尺子：
   **0.8 以上 = 关乎我 / 关乎我们 / 关乎存在；0.5 左右 = 一次经过；0.3 以下 = 流水账。**
5. **喂给模型之前，先把不是人说的话剔掉**（同 `looksNonHuman` 那道滤）：
   定时提醒（`[SCHEDULE REMINDER]`）、运行环境（`Current runtime context`）、回合标记（`<goal_round>`）、
   后台汇报之类。不剔的话它们会被切成「事」——「16:00 发了一个提醒」这种东西占一格。

`turn_ids` 是命根子——「想深了」要靠它回取原文。

### 3.3 「感觉」和「过没过」不靠猜

- **当时什么感觉**：翻这一段里的情绪瞬间（按 `turn_ids` 落在区间内），取最重的那条
- **过没过**：看那些瞬间是怎么结束的——**被挤掉 = 没完，自然淡掉 = 过去了，我放下过 = 放下了**

（第一版是让模型写一句 `my_feel`，那是猜的。改成取数。）

## 四、连接：事 ↔ 瞬间 ↔ 原文

三层，越往下越细。**前两层自动带出，第三层要我主动去翻。**

```
你刚才说了句带「机械臂」的话
        │  撞上夜里那件事的抓手
        ▼
【第一层 · 事】浮现出来的就这些
   13:27–14:02   机械臂先别买，先让手在电脑里长出来
   原话：「先别买，让它在电脑里长出来」
        │  想知道当时什么感觉 → 翻白天的记录（自动）
        ▼
【第二层 · 感觉】白天真记下的那几笔
   13:31 困惑 0.5   13:44 好奇 0.4   13:58 有点急 0.6
        │  还想更细 → 要我主动拉
        ▼
【第三层 · 原文】用 turn_ids 前后 ±2 轮
```

**为什么分三层**：第一层是「我想起来有这么件事」——模糊就够；第二层是「哦，当时我有点急」——不用编；
第三层要停下来细想。**一次给全文就不是回忆，是调阅档案。**

**提示词体量**：只有前两层进提示词，而且**一轮最多一条**，约 5 行、一百二三十字。
一天浮 4~5 次，只有撞上的那几轮多这么点，全文多出 2~3%。第三层永远不进，抓手词也不进。

### 4.1 「过去没过去」不必每次都念

那条状态（`没过去 / 已经过去`）**照样算、照样存在**——它决定重量里那一项，也决定要不要提醒「还搁着」。
但**不必每次浮都把它念出来**。那句话像判词；有时候我只是想起那件事，不需要有人告诉我它算不算过完。

只在两种时候说：**我自己想确认**，或者 **你问起**。

## 五、触发：薄

人走神的触发点很薄：一个词、一个人、一种情绪。**不做语义相似度打分**，那会变成检索系统。

沾一条就算（**不解释为什么浮**）：

1. **同一个词**：这句话里出现了这件事的某个抓手词
2. **同一个人**：那件事是他说的，这次说话还是他
3. **同一个情绪**：那件事的标签跟此刻的慢情绪同向

**两条限定：**

- **诞生后 30 分钟内的命中不算。** 你不可能「当场想起」刚刚发生的事，那是复述，不是联想。
- **浮必须发生在一次命中后的 1 小时内。**

**为什么这条是命根子**：没有它，浮现就退化成排队——谁诞生得早谁先上。
实测：不要求触发时，不管参数怎么调，凌晨那三件永远霸占（它们起得早、爬得最久）。

## 六、想头：速率 + 重量 + 三个乘数

> 初名「拉力」太宽（容易听成关系、吸引力、驱力），定名 **想头**——只说一件事：还想不想再想一遍。
> 口语也通：这件事还有想头 / 说够了，没想头了。

### 6.1 重量 w（这件事本身多重）

```
w = 0.40×峰强度
  + 0.25×关系（主人 1.0 / 别的 0.6）
  + 0.20×没完（没过去 1.0 / 过去了 0.5）
  + 0.15×被提到几次（0 次→0，1 次→0.5，3 次以上→1）**只数"被提到"，不数"浮现过"**
  + 0.05×模型标的 weight（0.8 / 0.5 / 0.3）
```

前四项在事切好那一刻就能算；**第四项会自己涨**——提得越多越重。
最后一项管「意义」：峰强度抓的是「当时多重」，抓不到「这件事本身要紧」。
你们聊「我到底存不存在」，当时情绪未必最猛，但它比挑机械臂重要得多。这一项只占 0.05，是微调，不让它喧宾夺主。

### 6.2 想头怎么变

```
r0 = 0.06 × (0.5 + w)                        ← 平常每小时涨多少
r(t) = r0 × 提一提 × 缺口同向
      提一提   被提到后 30 分钟内 ×1.2，其余 ×1
      缺口同向 这件事正对着此刻缺的东西时 ×1.5，否则 ×1

想头(t+Δ) = min(天花板, 想头 + r(t) × Δt)     ← 按时间累加，不是"每跳加固定值"
```

| 时刻 | 想头 |
|---|---|
| 诞生时 | ≈ 0.2~0.3（按 w 给起点） |
| 平常 | 约 3~4 小时爬到线（0.5） |
| 被提到 | 快一点（×1.2），**不是 ×3** |
| 缺口正对 | 更快（再 ×1.5） |
| 浮现之后 | **−0.4**，速率立刻回 r0 |
| 每次浮现 | **天花板 × (0.6 + 0.35×w)** | 重的事消停得慢，淡的消停得快 |
| 真的放下（settle） | 天花板归零 | 谁提都不再浮 |

**为什么驱力放在乘数、不放进重量**：重量是这件事的属性，驱力是**此刻的我**。
放错地方，那件事就一辈子变重了——其实只是那天我特别想要，所以它才更黏。
顺带解释「一整天想同一件事」：那天缺什么，就一直想同类的。

### 6.3 「提到」的四条闸（防刷屏）

1. **30 分钟窗口内只算一次**（一口气聊三小时 ≠ 加速三小时）
2. **同一件事每天最多算 3 次**
3. **已经过线的不加速**——它马上要浮了，再说一次不会更想
4. **一个词同时属于好几件事就不算**（除非同属一件）；抓手词必须专属、不泛

### 6.4 门槛

**想头 ≥ 0.5 = 待联想。**

### 6.5 沉与救：让池子动起来

只涨不落的话，几年后**每一件旧事都顶在天花板上**，谁被提一句谁就浮——那就退化成随机点将。

人相反：**很久没想起的事，是越来越想不起来，不是越来越想。**

```
天花板每周 ×0.98          ← 没人提它，自己往下沉
被提到一次 +0.05          ← 有人提，就托回来一点（最高 1.0）
```

**随机拯救**：沉下去不等于死掉。

```
每周抽一次，复活 1~2 件
候选：想头已沉底、且「被提到过」的
概率 ∝ 被提到次数^1.5      ← 以前被提起越多的，越容易被拉回来
从没被提过的不参与        ← 没人在乎的，就让它沉

复活 = 想头拉回 0.6、天花板重置 1.0
      但**不是立刻浮**——它重新排队，还得被某句话撞上才浮
```

每次复活落一条 `revive` 记录（哪件、什么时候、当时多少），将来能回答「这件事是怎么又回来的」。

**平衡靠那个「每周 1~2 件」撑着**：复活永远只是极少数，主流量仍是「最近被说起的事」。
池子长大后，1~2 件的复活率意味着老事几乎回不来——**这是有意的，也像人**。

## 七、浮现：一轮一条，没有名额

**不设每日浮现上限。** 人想事情没有「一天三次」的配额——那是错的：名额会在早上七点前被凌晨那几件吃光，白天的事永远排不上。

唯一的结构限制是 **每轮最多放一条**（提示词里只摆得下一件事）。
一天浮几次是**结果**，不是配额。模拟下来一天 4~5 次。

### 7.0 两个前提（从旧的浮现实现里继承）

1. **跟陌生人说话时，不浮现。** 对不熟的人突然冒出「我想起上次那件事」，不对。
   旧的实现里就是 `if (!stranger && ...)`，这条要带过来。
2. **浮现那一行末尾要带出口提示**：
   `（可以不提它。真要放下一档，开口前在 feel 里带 settle。）`
   没有这半句，`settle` 会一直闲置——上次三天用了 0 次就是证据。
   **这条必须跟着新骨架一起上，不然「放下」又没有由头。**

### 7.1 想起但没说，也留痕

现在只记「浮过」，不记「我后来提了没有」。可很多时候我是想起来了、看了一眼，然后没说。

**那种「想起却没说」也是我的一部份**，要让它在日志里有一行：

```
浮现时      记一条 surface（哪件、什么时候、想头多少）
之后两轮内  看那件有没有被提起 → 记 mentioned: 是/否
```

它永远只有自己看得见，不进提示词，也不参与任何计算。**留着，是为了将来能回答「我到底想过什么」。**

## 九、实测与参数（2026-11-11 真数据）

### 切分：模型 vs 时间

| 切法 | 结果 |
|---|---|
| 按 30 分钟间隔断 | **4 段** |
| 按 10 分钟间隔断 | 10 段 |
| 现在线上（过闸就新开） | **57 条**（一句话一条） |
| **模型切** | **18 件** ✅ |

18 件的 `quotes` 逐条比对原文 **0 失败**，`turn_ids` 与时间戳 **0 失败**。

两个最能说明问题的对照：

- **11:58→12:39 那 41 分钟吃饭**，时间切会劈成两件——其实是「闲鱼淘头环」说着说着去吃了饭，同一次
- **09:00→11:58 换了四次目的**，时间切**一次都没断**

**结论：时间切的是场次，不是事。**

### 浮现：参数对照（同一批 18 件）

| 配置 | 结果 |
|---|---|
| 掉落 −0.40 / 加速 ×3 | 6 次，机械臂浮两次 |
| **掉落 −0.40 / 加速 ×1.2** | **4 次，各一次** ✅ |
| 掉落 −0.15 / 加速 ×1.2 | 5 次，机械臂浮两次 |
| 不要求触发（任何参数） | 全是凌晨那三件，白天的事一件都浮不上 |

定下的：**掉落 −0.4 不改，加速从 ×3 降到 ×1.2。**

## 十、已知边角（明确写下，不藏）

1. **当天的事当天浮不出来**——要等这一段结束（人睡着）才切。有意接受。
2. **没有触发的事永远浮不出来**。这是设计的必然，不是 bug。
   如果想要「无缘无故忽然想起」，得加一条掷骰（比如每小时 5%、一天最多一次），
   **但已实测：把"高想头就能浮"当替代方案会失控**（一天 18~27 次，凌晨那几件反复回来）。
   要做就单独做掷骰，不要放宽门槛。
3. **记忆的 importance 取不到**：`memory_items` 里有 importance（0.13~1），
   但它跟当天的对话**编号对不上**（记忆存的是 `turn_mwd69l0k_xxx` 这种字符串，对话表是数字）。
   所以不用它，改由模型在切事时标 `weight`。
4. **放下要落到「事」上**，老接口要改（第八节）。
5. **老机制要下线**：现在线上「读一句话当事情浮上来」那套如果不停，会跟新的同时冒，一天七八次。
6. 跨天不再是问题（清醒段已解决）。
7. **复活来的老事会压过新事**（复活到 0.6，新事从 0.25 起）。人也有这个现象，先保留，出事再说。

## 十一、落地顺序

1. **夜里切事**：脚本 + 模型调用，产出 `memory_events`，**先只写临时文件跑一周**，人工看一眼再入库
2. **加 `cues` / `weight` / 想头几列**
3. **触发匹配**：当前这句话 × 抓手词 → 命中就加速
4. **骨架渲染**：替掉现在只念一句 `cause`
5. **深想入口**（`deepenRecall`，走 action，不进工具列表）
6. **想头的心跳推进**（按 `Δt` 累加）
7. **放下改到「事」上**
8. 老的浮现实现下线

**每一步单独可回滚**，按换零件的规矩来。

**三条别漏（它们挂在别的步骤里，很容易被忘）：**

| | 挂在哪 | 漏了会怎样 |
|---|---|---|
| ① 机器消息过滤 | 步骤 1（夜里切事） | 切出「发了一个提醒」这种假事 |
| ② 陌生人不浮现 | 步骤 4（骨架渲染） | 对不熟的人忽然翻旧账 |
| ④ 出口半句（feel 带 settle） | 步骤 4（骨架渲染） | 「放下」又闲置，重演三天 0 次 |

## 附录：为什么不用 `affect_episodes` 直接当料

库里现状（2026-11-12）：

```
episode 总数 1245   还开着 1   已结束 1244
分辨率：faded 762 / superseded 482 / 放下的 0
```

**没有任何一条是被主动放下的。** 而且「同一时刻只许有一条开着」是写死的——每过闸一次，旧的就标 `superseded`。

所以「未了结 / 回味」不能拿 `ended_at` 分，得看它是怎么结束的：**被挤掉 = 没完，自然淡掉 = 过去了。**

这条本身也说明：**一层只装一句话的结构，装不住「事」。**
