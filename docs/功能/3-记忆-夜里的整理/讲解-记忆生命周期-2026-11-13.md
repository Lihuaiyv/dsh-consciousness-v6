# 记忆生命周期 · 总讲（怎么存、怎么取、怎么淡、怎么忘）

> 2026-11-13，把整条命从生到死捋一遍。**现状**取自代码与真库（11:1x 快照），**目标**对齐 v2.1 计划。
> 一句话：**原话永远在；事是解释；事实是沉淀；平时用的只是候选；忘只忘「能不能被带出来」，不忘「发生过」。**

---

## 一、怎么存（写入）

### 现状：一次对话，至少写四份

| 时机 | 写什么 | 谁写 |
|---|---|---|
| 你说一句 / 我回一句 | `fragments` 原话（带当时的快照、接自） | archive.appendTurn（唯一写口） |
| 同一轮 | `chat_turns` 通道账（cht_*，无 turn_id） | index.js / features.js / qq_* / wechat |
| 同一轮 | `memory_items` 一条 episode（每轮原话再来一条） | commitTurn / chatReply **两套并行** |
| 每轮 | `scene_archive` + `state_scene` 注入块留底 | confluence.recordScene |
| 夜里 | `episodes` 纪要（每 6 轮 / 每 session·day） | archive.buildEpisode |
| 每晚 | `diaries` 日记 | diary.upsertDiary |
| 抽取 | `memory_items` 的 fact/appraisal/reflection + provenance + timeline + links + claims | extract_queue → 抽取模型 → addMemory |
| 事件 | `cold_events` / `hot_events`（每件：名字/经过/证据/抓手/想头/天花板） | **目前手工切 + 导 JSON，不入库** |

**毛病**：同一段日子五六种写法；两套写链靠「别同时跑」的约定；切事只产 JSON、格式对不上、热库要手开；每轮 episode 和碎片重复。

### 目标：每层一个家、一个写口

```
碎片（只追加）→ 夜里自动切 → 事（冷库→热库）→ 沉淀 → 事实库
                                      └→ 讲述 → 日记 / 纪要（只投影）
```

- 碎片：一轮一条，带快照/接自，永不改。
- 事：定时任务直接写冷库+热库，抓手 2~6 个（至少一个专名），无抓手拒收；同段碎片只一条冷事件。
- 事实：只从「事/碎片」蒸馏；必须能指回证据；带有效期、版本、对账。
- 叙事：只引用，不产生事实。
- 每轮 episode 停写；`chat_turns` 补 `turn_id`，降为通道投影。

## 二、怎么取（检索）

### 现状：每轮拼二十几段，最后砍到 800

1. **召回**（preStep）：最后一句 → contextualQuery → `retrieve`：
   - 路由 S1/S2/S3（每轮 / 回看 / 深查）；
   - 多路取：FTS（bm25）+ 实体 + 向量（**13% 覆盖，已停 12 天**）+ asof（带过去时间）+ 深翻；
   - RRF 融合名次、相对门 0.7、MMR 去重、配额 anchor/fresh/self/pattern；
   - 被想起 = 强化：hits+1、stability 上调、heat 重算（`touch`）。
2. **打包**：`packMemoryBlock` 拿一半预算（默认 400），日记→记忆→passport→fade；最后 `clampInjection` 800 硬收口；情绪行不丢，feelguide 单开，事件再单开 400。
3. **自己想起**（五条通道，各带预算）：
   - 事件联想：一句话撞抓手（每轮≤1，单开 400）；
   - pulse：每 2 小时一条候选，直塞提示词；
   - affect.surface：情绪高的旧事，一天 3 次；
   - quote_echo：引语回响；
   - open_loops：答应过的事。
4. **汇流**：口令/API 手动触发，单开 1600；`recordScene` 每轮写照片，但审计账不写。

**毛病**：五条通道抢一个 800；**两个拼装器**（网页 `consciousnessBlock`、/chat/微信/QQ `buildContextBlock`），事件联想只接了网页；预算 800/400/1600 三道互不感知；向量路死着。

### 目标：一个候选池，三种模式

- **候选池**：检索、事件、自发、情绪、引语、开环、汇流都往里放候选，只出候选，不直接进提示词。
- **排序**：相关度 × 重量 × 新鲜度 × 可提取性 R × 情绪乘数；接近时重事优先，再想头优先；**不丢弃，只排队**。
- **三模式**：被问起（检索）/ 没被问（联想，一轮≤1）/ 站回去（汇流，手动）。
- **预算一张表**：日常 800（含全部候选）/ 事件 400 / 汇流 1600（手动才开）。
- **两个拼装器共用**同一张候选池和预算表。

## 三、怎么变淡（fade）

### 现状：三把尺子，各算各的

| 尺子 | 怎么算 | 效果 |
|---|---|---|
| **热度** | `heat = 0.40·重要度 + 0.22·新鲜度 + 0.18·强化次数 + 0.10·钉住 + 0.10·情绪显著度`；半衰期 `30×(1+2·importance)` 天 | 只影响排序和配额，不决定进不进 |
| **可提取性** | `R = 1/(1+t/(9S))`；被想起时 `S' = S·(1+0.25·(1−R))`（FSRS-lite） | 越费劲想起，下次忘得越慢 |
| **温度** | 90 天没用 → cold（退出每轮 S1）；180 天 → archived（只能显式翻）；30 天内想起 ≥3 次 → hot；降档要连续 2 次（迟滞）；locked/taboo/promise 永不下沉 | 决定「进哪一档」 |
| **内容模糊** | 30 天起分档，只删括号注释 / 数字时间 / 引号原话；带因果/否定/承诺的不删；删到一半就回退；reflection 门槛 0.95、其余 0.7；value/boundary/taboo/promise/identity/conflict 永不模糊 | 字还在，细节少了 |

**毛病**：同一个 90 天，热度可能还高、温度已 cold、内容已删数字——三件事互不通知；「淡」到底按哪把尺，答不出来。

### 目标：只留两把尺

- **多重要**：importance/weight（出生时按类型 + 关键词，之后被想起可微调）。
- **多清楚**：fade/confidence（只影响"说多清"，不影响"说不说"）。
- 温度 = 「进哪一档」的派生（S1 每轮 / S2 回看 / S3 深查），热度 = 排序的派生；**都从"重量 + 时间 + 想起次数"算出来，不再各写一套**。

## 四、怎么忘（forget）

### 现状：八套机制，谁都能让一条记忆消失

| # | 机制 | 干什么 | 现状 |
|---|---|---|---|
| 1 | **HIDE / DELETE**（visibility） | 唯一「说好要忘」：整轮排除；asof/汇流/深翻共用 forgottenTurnIds | 活的；但 **55 条老账没有 turn 链**，只能时间窗近似 |
| 2 | 软删 / 硬清 | soft_deleted → 7 天后真删 | 活的 |
| 3 | 取代链 | superseded_by / invalid_at，旧的失效 | 活的（pair_judge 默认 off，只在 gate 跑） |
| 4 | 冲突卡 | conflicts，a/b 矛盾 | 45 条全 resolved，3 天没新行 |
| 5 | 对账 claims | 还算不算数（pending/done/stale） | `claim.enable` 默认 off |
| 6 | 温度 cold/archived | 退出每轮 / 只能显式翻 | 活的 |
| 7 | 内容模糊 fadeText | 细节变少 | 活的 |
| 8 | 事件沉底 | 90 天沉热库；想头<0.5 不再浮 | 活的 |

**毛病**：八套互不通知；「忘」没有唯一入口；冷库（碎片/事冷库）永不删，热库/条目层各有一套「不再出现」的定义；HIDE 的级联最容易漏。

### 目标：忘只有一个口

- **visibility 说「能不能被带出来」**（唯一说不的地方）；HIDE 必须能一路追到原话轮次（turn 链）。
- 取代 / 对账 / 冲突 / 温度 / 沉底 / 模糊：只标状态、只排序、只改清晰度，**不删内容、不绕过 visibility**。
- 冷库和碎片永不删；照片（scene_archive/state_scene）永不删。
- 「忘」只发生在解释层和读口，不发生在地基层。

## 五、四段的接缝（一张图）

```
存：碎片（永不删） → 事（解释） → 事实（沉淀） → 叙事（讲述）
取：候选池 → 排序（相关 × 重量 × 新鲜 × R × 情绪） → 三模式 → 一张预算表
淡：两把尺（多重要 / 多清楚）；温度与热度都从它们派生
忘：visibility 一个口；其余只标状态；HIDE 必须追得到原话
```

**一句话**：**存得全、取得对、淡得慢、忘得干净**——四件事各有一个家，才不会互相打架。

## 六、现在最该补的五件（对齐 v2.1）

1. **切→导→热**：事件不入库，中心就是空的。
2. **两个拼装器**：读口只覆盖网页，/chat、微信、QQ 收不到事件联想。
3. **两把尺合一**：不然「淡」永远是三套数打架。
4. **忘的口唯一**：八套机制互相不知道，HIDE 老账还会漏。
5. **向量停写**：13% 覆盖、12 天没写，先声明停，别让它假装还在。
