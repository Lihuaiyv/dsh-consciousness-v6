## 一、修正：热度高，不是「5168 次」灌出来的

我原先说「5168 次命中灌满了热度」。看代码，[tiers.js:57](../../../src/modules/tiers.js) 的公式是：

```
heat = 0.40·重要度 + 0.22·新鲜度 + 0.18·强化 + 0.10·钉住 + 0.10·情绪显著度
强化 = min(1, log1p(hits)/log1p(8))     ← hits 到 8 就顶满
新鲜度 = 0.5 ^ (距上次命中 / 半衰期)     ← 锚点是 last_hit_at
```

所以 hits 从 8 涨到 5168，**一分钱都不多加**。那两条 heat=1.0 的真实构成是：
重要度满分（0.40）+ 钉住（0.10）+ 情绪显著度（0.10）= **0.60 的固定底盘**，加上「每轮注入把 last_hit_at 拨到现在 → 新鲜度恒满 0.22」和强化满格 0.18。

**真正的环只在一处**：注入 → `touch` 把 `last_hit_at` 拨到此刻 → 新鲜度永远满格。
**第二处是固定底盘**：`locked` + 重要度 1.0 + salience，这 0.60 跟热度、跟注入都没关系，钉在那儿。

## 二、抄了谁、抄不抄

| 出处 | 他们怎么做 | 我们 | 抄不抄 |
|---|---|---|---|
| Generative Agents（Park 2023） | 检索时现算 recency(0.995^h) + importance + relevance，**不落盘** | 我们落盘（面板要用），公式还更细 | 公式不抄；抄「recency 只在真被用到时重置」 |
| MemoryBank（Zhong 2023） | R = e^(−t/S)，**被回想时 S += 1、t 归零**；检索是向量 top-k | 我们 `touch` 是 FSRS 版：S' = S·(1+0.25·(1−R))，比它细 | **它也是在「被回想」时重置**——所以「重置」本身没错，错在**我们每轮都无条件算一次回想** |
| Access-Weighted Decay（2025） | 强化递减：第 n 次只给 1/(1+0.2n) | 我们的 S' 本来就随 R 递减，`log1p(hits)/log1p(8)` 也封顶 | 已经抄到了，这块不差 |
| Mem0 v3 | 写入时 LLM 决定 ADD/UPDATE/DELETE，靠检索排序 | 我们没有写侧去重 | 想做，但那是**写链**，另排期 |
| Zep / Graphiti | 双时间 valid_from / valid_to | 我们的 `valid_at` 几乎全空（老账） | 另排期 |

**查完的结论比原来更明确**：我们的公式（FSRS + 半衰期 + 封顶）不比别人差，缺的不是公式，是**触发条件**——别人是「这条真的被这条 query 问到、且真的被用上」，我们是「每轮固定名额，塞了就算」。

## 四、这一步做什么、不做什么

**做**：把 `last_hit_at` 的刷新从「塞进去」挪到「说出口」。只动触发条件。
**不做**：不动固定底盘（`locked` / 重要度 / salience）——那是 heat 0.60 的底，跟本环无关，动它是「调人格」不是「修 bug」；不动锚点名额；不动写链；不做递减（已有）。

## 五、验收（v2 换了一个指标）

原来的验收写「24h 内 hits 增量 ≈ used 增量」——**错了**，因为 hits 到 8 就封顶，这个数看不出来。改看两个：

1. **单测**（进 `test/run-tests.mjs`）
   - 注入 5 条 → 5 条的 `last_hit_at`、`hits` 都不变（`on` 档）；
   - 回复命中其中 1 条 → 只有它 `last_hit_at` 变新、`hits+1`；
   - 开关 `off` → 与现在逐字一致（注入即 +1）。
2. **门禁**：改前 570/570，改后全过。
3. **shadow 一天**：`surfaced_items` 新增 X，`used=1` 新增 Y；`memory.heat.shadow` 里「本该加」的条数应 ≈ Y 而不是 X。若 Y/X < 1%，先调判据（现在 `2-gram ≥ 0.3` 偏严），不急着开 `on`。
4. **on 之后（真机 24h）**：
   - 抽那条「潮水」：**24 小时内 `last_hit_at` 被拨了几次**（现在≈每轮一次，一天几百次）→ 应掉到个位数；
   - 全库：`last_hit_at` 落在最近 1 小时内的条数，应从「每条注入过的都算」降到「≈真被说出口的几条」；
   - 兜底：`retrieval_log` 每轮仍能捞出 4~6 条，不能因为不加热什么都捞不出来。
