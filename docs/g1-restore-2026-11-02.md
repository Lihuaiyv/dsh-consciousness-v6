# G1「当时」接入 + 测试清理（2026-11-02）

本文件记录这一轮修了什么、为什么、以及可核对的数字。旧 `重要/12-变更日志.md` 是 GBK 编码，
本轮不动它，避免整文件被重写成 UTF-8。

## 为什么

`docs/memory-asof-plan-g1.md` 的「落地记录（2026-11-01）」写着 G1-0…G1-6 都做完了，
但当前快照里：

- `memory_timeline` 表**根本不存在**（db.js 里没有 DDL），`logEvent` 一直静默失败；
- `gate.js` 的 `applyWrite` **没有 update 分支**，同 `fact_key` 改口只会新增，旧句不留底；
- 硬删只删 `memory_id = ?`，改写留下的 `<id>:hist:<n>` 旧句留在冷库里；
- `asof.js` import 了一个不存在的 `hasLexOverlap`，模块连加载都加载不了；
- `index.js` / `chatReply` 里没有任何 as-of 注入入口；
- `memory.asof / memory.asof.axis / memory.asof.auto` 三个参数没登记，`writeParam` 直接 404。

所以表现就是「从现在往后有数据，之前是空的」——不是画图的问题，是**时间线写入侧整段没接上**。

## 改了什么

**schema**

- `src/db.js`：新增 `memory_timeline` 表（只追加、无正文）+ `idx_tl_mem` / `idx_tl_at`。

**写入侧（每条路径都留事件）**

- `src/modules/memory.js`：`addMemory` 记 `ADD`（带出生照 `text_ref` 和说话时间 `valid_from`）；
  同 key 取代走 `invalidateMemory` 记 `INVALIDATE(supersede)`；批量取代记 `INVALIDATE(consolidate)`；
  高风险冲突记 `INVALIDATE(conflict)` + 双方 `DISPUTE_OPEN`；`softDelete` / `restoreMemory` 记 `HIDE` / `UNHIDE`；
  `resolveConflict` 记 `REACTIVATE` / `INVALIDATE` + `DISPUTE_CLOSE`。
- `src/modules/gate.js`：`decideWrite` 新增 `update`（同 `fact_key` 换了说法）与 `delete`（`op: 'delete'`）两个分支；
  `commitUpdate` 把旧句写进 `fact_archive`（`<id>:hist:<version>`）、改正文、改 FTS，**同一事务**；
  存根写不进就整笔回滚、退回「新增一行」（`fallback: 'update_failed'`），不覆盖旧句。
- `src/features.js`：过去事实记 `INVALIDATE(past_fact)`、否认句记 `INVALIDATE(negation)`。

**清理**

- `src/modules/ops.js`：`purgeExpired` 单条硬删改成 `memory_id = ? OR substr(memory_id,1,n) = '<id>:'`
  （不用 `LIKE`，`_` 是通配符会误伤），同时删 `fact_fts` 与 `memory_timeline`；整实例清除的级联表加了 `memory_timeline`。

**读 / 注入**

- `src/api.js`：新增 `GET /v1/agents/:id/memory/:mid/history` 与 `GET /v1/agents/:id/memory/as-of?q=&at=|from=&to=`。
- `src/modules/retrieval_log.js`：新增 `memoryHealth(db, aid)`（含 `timeline_drift`）。

  `memory_id` / `cause_id` / `text_ref`，重复导入按 `(agent, memory, op, at)` 去重。

**归属（INV10）**

## 追加：认人这件事的两处僵化（2026-11-02）

1. **号是按字面比的**。`isOwner` 原来是 `String(handle).trim() === ownerHandle(db)`，
   桥那头传 `qq:3192248859`、`3192248859@qq` 或带空格的号，主人就被判成陌生人（少学、也不叫主人）。
   现在先剥前缀/后缀再比；空号一律不是主人。
2. **漏了号就当主人**。`canLearn = !speakerHandle || isOwner(...)` —— 通道漏号（桥超时、字段改名）
   等于默认「是主人」，模型失败时兜底回复会对陌生人喊「主人」、说「记下了」。
   现在分开判：外部通道没号 → 陌生人（宁可少学，不可串人）；网页那条路根本没 `speaker` → 主人本人。

`test/speaker-identity.test.mjs`（`npm run test:speaker`）30 条，覆盖「号不对」「没号」「网页无 speaker」三种，
并断言兜底回复里不出现「主人 / 记下了」。顺手把短档的文体补了一句姿态：
「一句就停，不解释；不用道歉，也不用检讨。」——只约束「说多少」的话，模型会自己补上检讨口吻。
