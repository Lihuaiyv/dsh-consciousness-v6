# 记忆时态 · 沉默与确认 · 计划

> 起点：测评结论——「什么时候说的」覆盖率 100%，「现在还算不算数」只有 1.2%。
> 差别不在算法，在**观测通道**：我们只知道聊天里说过什么。
> 所以这一轮不加「更聪明的判断」，只加两个**可观测的新信号**：沉默，和提问。

---

## 0. 一句话

**判不出来就不判。把「之后没再提过」说出来，把「还成不成立」问出来。**

三件事：先量沉默有多大（G），再验一个看起来能白捡的开关（H，结论可能是别开），最后把「不确定」变成一句真的问话（I）。

---

## 1. 全局：这三件事在系统里的位置

```
写入侧（改）                            注入侧（读）
  gate / addMemory                        packMemoryBlock
  supersedeByKey                          passportLine ── 已有：date / 更新 / 陈述
       │                                        └── 本轮新增：silence（沉默）
       ▼                                              │
  memory_items ───────────────────────────────────────┘
       │
       ├── open_loops（已有：待办 / 提醒 / 说了一半）
       │        └── 本轮新增 kind='checkin'（事后确认，不是派活）
       │
       └── raw_turns（已有：全部原话）
                └── 沉默检测：这个话题之后还出现过吗
```

三条约束（这一轮不动）：

- **不猜新旧**。相似度只用来「找人」，不用来「定性」。
- **不删不改**。所有新信号都是加一句标注 / 加一条待确认，不动记忆正文。
- **可关**。每个新东西一个参数，默认偏保守。

## 2. 阶段 G｜沉默检测：先量，别先写

**要回答的问题**：全库有多少条记忆是「提过要做什么，之后 30 天再没出现过」。

如果只有十几条，不值得为它加一条注入规则；如果有上百条，那是一条真的漏。

### G0. 只读量数（不动代码）

新增 `scripts/audit-silence.mjs`（只读，复制库到临时文件也不写）：

1. 取候选：`memory_items` 里 type∈{fact, appraisal} 且正文含「打算 / 要不要 / 准备 / 之后 / 下一步 / 待 / 等」这类**意图或未完成**信号
2. 取主题：`topicOfFactKey` 的段（没有 key 的用正文 bigram 前几名）
3. 查沉默：`raw_turns` 里在这条记忆 `created_at` 之后，还有没有出现过这个主题
4. 输出：
   - 候选总数
   - 沉默 ≥ 7 / 30 / 90 天的分层
   - 抽样 20 条原文（人工看像不像「真的没下文」）
   - 误报估计：抽 20 条里，有多少是「本来就不该再提」（比如一次性的评价）

**验收**：输出一张表 + 20 条样本。**先不改任何行为。**

**决定点**：沉默候选 < 30 条 → 停在这里，把结论写进测评，不做 G1。
≥ 30 条且抽样误报 < 40% → 进 G1。

### G1. 注入时带一句「后来没再提过」

前提：G0 通过。

- `passport.js` 新增 `silenceNote(db, aid, row, opt)`：
  - 条件：条目超过 N 天（默认 30）、正文有意向信号、之后 raw_turns 里主题零命中
  - 文案：`（11-01 说的，之后没再提过）`——**不说「过时了」**，只陈述沉默
  - 位置：串在 `passportLine` 的日期之后，和 statement 同层
- 新参数：
  - `memory.passport.silence`（默认 **off**，先观测一轮）
  - `memory.passport.silence.days`（默认 30）
- 性能：raw_turns 4500 条，按主题 LIKE 查一次 ~几 ms；每轮最多查被召回的那几条，可接受。
  但要加**结果缓存**（同一 memory_id + 同一主题，一天内不重复查）。

### G2. 回放验证

- `replay-stale.mjs` 加一组：silence on / off
- 指标：明确信号覆盖率（现在 1.2%）能提到多少；平均 token 涨多少
- **门槛**：明确率提升 ≥ 10 个百分点、token 涨 ≤ 15，才考虑把默认打开

**风险**
- 「没再提」不等于「不成立」。有些事不提但一直有效（比如「她怕黑」）。
  → 文案只说事实，不下结论；参数默认 off。
- 主题 LIKE 会漏（换个说法就不算提到）→ 宁可漏，不要错报。所以要求「零命中」才算沉默。

## 3. 阶段 H｜弱标默认：验证后大概率**不开**

**原来的想法**：`memory.passport.weak` 打开，「提示」从 5 → 13 条，token 不涨，白捡。

**但这个判断有问题**：那 8 条新增提示说的是「同主题后面还有一条更晚的说法」——
而我们这一轮刚刚证明，「同主题」这个判定**大量是词面撞车**（「oneLine」能撞出五条互不相干的结论）。
给一个已被证伪的判定开显示口子，等于把噪音放进注入。

### H0. 只做验证，不改默认

1. 从回放里把那 8 条取出来，逐条人工判：是「真更新」还是「撞车」
2. 判完再看：
   - 真更新 ≥ 3 条 → 说明 weak 还有救，可以考虑开
   - 全是撞车 → 维持 off，并在 `passport.js` 注释里写清「为什么默认关」

**验收**：一张 8 条的判读表，结论写进测评。

**这一步不改任何代码**（除非结论要改默认值）。

## 4. 阶段 I｜不确定就问：把猜测换成一句问话

**要回答的问题**：系统不知道「那件事还成不成立」，但**人知道**。能不能在合适的时候问一句，而不是自己猜。

**为什么复用 `open_loops` 而不是新建表**：
- 它已经有 `kind / due_at / stale_after / state / fire_count / fired_at / closed_at`
- 已经有节流（6 小时）、去重（最长连续子串 ≥4）、提满 5 次自动收
- 已经有 `closeLoop` 和「用户说做完了」的判定
—— 这些就是「问一句、别烦人、问完就收」的完整机制，重造一遍只会更差。

### I1. 加一种 kind：`checkin`

- `open_loops.kind` 新增值 `'checkin'`，语义：**不是派活，是事后确认**
- 现有的 `pendingLoops` 默认**排除** checkin（保持老行为不变）；新增 `pendingCheckins(db, aid, opt)` 单独取
- 节流更保守：同一件事 **7 天最多问一次**，总共最多问 **2 次**（问两次还没回应，就是不想说）

### I2. 从哪生成

两个来源，都要求「有明确可问的东西」：

1. **沉默记忆**（阶段 G 的产物）：一条「打算做 X」的记忆沉默 30 天 → 挂一条 checkin「你之前说要 X，后来做了吗」
2. **未收尾的开环 + 已过期的 due**：现有 `open_loops` 里 due 过期 7 天还没收的，升级成 checkin（现在它们只是反复提醒，不会问「还要吗」）

**不生成的情况**（重要）：
- 情绪类、评价类（「今天心情不好」不需要确认）
- 已经问过 2 次的
- 最近 7 天刚被提到过的
- 同一主题已有 open 的 checkin

### I3. 什么时候浮现

**不做主动弹窗**，只在两种时机：

1. **对话里自然相关时**：检索到那条旧记忆、且它挂了 checkin → 注入末尾加一句
   `（顺带一问：你之前说要 X，现在还需要吗？）`
2. **夜间整理时**：`nightly` 里挑最多 1 条，放进第二天的「想问你的事」

**为什么不做主动推送**：这一轮的目标是「诚实」，不是「黏人」。主动问会变成打扰，
而打扰的代价比「暂时不知道」大得多。

### I4. 用户怎么回答

- 说「做了 / 不用了 / 还在弄」→ `closeLoop`（已有）
- 说「别问了」→ 关闭并拉黑这个主题（记到 `open_loops.state='closed', closed_by='user_refuse'`）
- 没回应 → 7 天后问第二次，再没回应自动关（`fire_count>=2`）

**这里不新增任何模型调用**，全靠现有的「用户说做完了」判定（`loops.js` 的 DONE_RE + longestRun）。

### I5. 面板

- 「时态」卡片加一行：待确认 N 条（点开看是哪几条、什么时候问过）
- 给一个「不用再问」的手动关闭按钮

**验收**
- `test/checkin.test.mjs`（新）：生成条件、排除条件、节流、两次上限、用户回答后关闭
- `test/loops.test.mjs` 不回归（checkin 不影响原有待办）
- 回放：checkin 命中时注入只多 1 行，token 涨 ≤ 20

## 5. 顺序与依赖

```
G0（量沉默）─── 不是够大 ──→ 停，写结论
    │
   是够大
    ▼
G1（沉默标注）→ G2（回放验证）
                    │
                    ├→ 达标：默认 on
                    └→ 不达标：默认 off，只留观测
H0（验证 weak 8 条）── 独立，随时可做，只出结论
I1（checkin 骨架）── 依赖 G0 的候选（也可以先用手工造的样本）
    └→ I2（生成规则）→ I3（浮现时机）→ I4（回答关闭）→ I5（面板）
```

**建议顺序**：H0（半天，只出结论）→ G0（半天，只出数字）→ 看两个结论再决定 G1 和 I 做不做。

理由：H0 和 G0 都是只读、只出结论，不写代码。它们决定后面两件大活值不值得干。

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 用相似度判「旧了」 | 论文 AUROC 0.59；这一轮已经证明「同主题」大量是撞车 |
| 自动改记忆正文 | 沉默 / 确认只加标注，不动内容 |
| 主动推送确认问句 | 打扰的代价大于「暂时不知道」 |
| 给 T2/T3 也做沉默检测 | 它们本身就是按天存的叙述，沉默没有意义 |
| 新建一张 checkin 表 | `open_loops` 的节流/去重/关闭已经够用，重造只会更差 |
| 追「旧当现在压到 0%」 | 分母只有 5 条，这个 0% 没有意义 |

## 8. 这一轮我还没把握的

1. **沉默的「主题」怎么取**。fact_key 只有 39%，剩下的用 bigram 会撞。G0 的抽样就是来看这个的。
2. **「提过要做」的信号词**准不准。现有的 `detectLoop` 是给待办调的，套到记忆正文上可能太松或太紧。G0 会暴露。
3. **checkin 会不会被答成「嗯」然后永远关不掉**。I4 的「没回应问两次就关」是新规则，没有历史数据支撑。
4. **沉默标注会不会让注入变吵**。G2 的 token 门槛（≤15 涨幅）是拍的，可以再调。
