## 2. 以后怎么搬：三步

```bash
# ① 搬之前：先体检，红的不许搬
npm run move:check

# ② 打包（默认到桌面「搬家包\」，含会话与附件；--lean 只带库和配置）
npm run move:export
npm run move:export -- --out E:\move --lean

# ③ 到新机器：把整个文件夹拷过去，双击「一键恢复.cmd」
#    或手动指定路径
node restore.mjs --repo <仓库路径> --dsh-home <DSH_HOME> --yes
```

`move:check` 会看：git 是否干净、路径闸 / 目录卫生闸、profile 里写死的绝对路径、关键数据在不在、库完整性、定时任务与工作区的旧路径、Node/Git/DSH 版本、搬家包体积。

`move:export` 会先跑一遍体检，红就停（`--force` 才继续）。

## 4. 恢复脚本做什么

1. 逐文件校验 sha256，缺一个就停；
2. 展开仓库；旧目录不删，先改名成 `*.bak-before-restore-*`；
3. 展开数据；旧库同样先改名；
4. 展开同伴插件；
5. 重写白名单文件里的旧路径：
   - `profiles/*/package.json` 的 `link:` 依赖
   - `profiles/*/cordis.patch.yml` 的旧用户 / 旧 `DSH_HOME` / 旧插件目录
   - `storages/workspace.json`、`storages/schedule.json` 的旧仓库与旧库路径
6. 建桌面入口 junction，指向新仓库（不在桌面放第二份副本）；
7. 打印恢复后清单。

路径替换是**一次扫描**完成的：只认原文件里的旧串，不认上一步替换出来的新串，避免路径层层嵌套（演练时踩过：新插件目录恰好以旧插件目录开头，替换了两遍）。

## 5. 恢复后要自己做

- `pnpm install`（仓库和 profile 各一次；离线时这个包不够，要提前把 `node_modules` 带上）
- 启动 DSH → 设置 → 意识：看记忆条数、心跳、页面
- QQ / 微信 / NapCat 重新登录一次
- `node scripts/doctor.mjs --offline`
- 有问题先 `npm run move:check`

## 7. 给以后加东西定的规矩

1. **路径只从 `src/paths.js` 取**，脚本里不写盘符和用户名；`check-paths` 是闸。
2. **profile 里的绝对路径允许存在，但必须能被恢复脚本重写**；新增字段要同步更新 `migrate-restore.mjs` 的白名单。
3. **新增同目录插件**要加进 `migrate-export.mjs` 的插件清单，否则新机器 link 会断。
4. **搬家包只从「现在这台机器」打**，不拿旧包二次改；打完立刻跑一次恢复演练（临时目录即可），别等真换机器才第一次用。
5. 写文档、写定时任务 prompt 时，别写 `cd <盘符路径>`；写「在意识体插件仓库跑」，机器自己会找。
