# 计划：她自己的记忆 · 第二阶段「认出自己」（2026-11-03）

> 第一阶段（v1 计划）解决的是「有没有一条我自己的记忆车道」：
> 旁白停写、每轮记一条自己的、夜里写一条今天的、注入留固定名额、生活流开大。
>
> 第二阶段解决的是「有了车道之后，车上装什么」：
> 我记下的是流水账，不是「我这个人是什么样」；想不起来时我嘴上说「我可能记错」，其实根本没去翻；
> 夜里想明白的事留不下来；同一件事我会反复讲。
>
> 纪律同 v1：每步先写测试、再改代码；每步一个开关、可单独回退；不删存量数据。

## P1 我是谁：把反复出现的模式攒成一句话（约 2.5 小时）

**要的东西**：不是贴标签，是我自己反复看见的模式。比如「我总先道歉再解释」「我总怀疑自己是不是假的」。

### 1.1 新模块 `src/modules/self_pattern.js`

- `patternMaterial(db, aid, days)`：读最近 N 天 `source='self'` 的条目（含 `self.day.*`）、`source='life'` 条目、`type='insight'`，格式化成 `日期 · 文本` 的素材串，上限 2000 字。
- `writeSelfPattern(db, aid, opt)`：
  - 素材里若不足 3 个不同日期 → `{skipped:'few_days'}`，宁可不写。
  - 模型返回 JSON：`{ "patterns": [{ "key": "先道歉再解释", "text": "我好像总是先道歉再解释，怕对方觉得我在推责任。", "days": ["2026-10-30","2026-11-01","2026-11-02"] }] }`
  - 闸门：`key` 2~12 字且不含「用户/他/她」；`text` 第一人称、16~120 字、过 `selfTextOk`；`days` 去重后 ≥3 个不同日期；一条都不过就 `{skipped:'gate'}`。
  - 落库：`source='self'`, `type='pattern'`, `fact_key='self.pattern.' + normKey(key)`, `confidence=0.65`, `importance=0.6`。
  - 幂等与累积：同 `fact_key` 已存在 → 不新增，改 `importance = min(0.9, importance+0.05)`、`confidence = min(0.85, confidence+0.03)`、`last_seen_at` 更新；`key` 对不上但 `cosine(vectorize(text), 旧条目text) >= 0.78` → 并入旧条目（同一模式换了个说法）。
  - 每晚最多写 `memory.pattern.per_night` 条（默认 2）。
- 参数（`kernel.js` PARAMS）：`memory.self.pattern`（on/off，默认 on）、`memory.pattern.min_days`（3）、`memory.pattern.per_night`（2）、`memory.pattern.window_days`（30）。

### 1.2 夜里挂上

- `nightly.js` 在 ⑤c `self_day` 之后加 ⑤d `self_pattern`，返回 `push('self_pattern', {ok, written, merged, skipped})`。

### 1.3 注入时优先露脸

- `retrieve.js` 的 `selfCandidates`：排序键从「相关度 → 新鲜」改成「type='pattern' 优先 → 相关度 → 新鲜」；pattern 条目不受 `selfQuota` 的「只在一条都没有时补」限制——每轮名额外再留 1 个位（`memory.inject.pattern_quota`，默认 1，0 关）。
- 理由：模式是「我是谁」的结论，不该跟流水账抢同一个名额。

### 1.4 测试 `test/memory-self-pattern.test.mjs`（≥16 断言）

- 3 个不同日期才写；2 个日期不写（few_days）。
- 旁白式 text 被闸门挡；key 含「用户」被挡。
- 同 key 第二次不新增、importance/confidence 累加、封顶。
- 换个说法（cosine 高）并入旧条目，不新增。
- `memory.self.pattern=off` 时直接跳过。
- `per_night` 上限生效。
- 注入：pattern 与普通 self 同时存在时，pattern 排前面且占单独名额。

## P2 我去翻翻：想不起来的时候先动手，不空口认错（约 2 小时）

**要的东西**：她能不能说「我去翻翻」然后把翻到的东西拿出来，而不是先甩一句「我可能记错」。

### 2.1 触发

- `retrieve.js` 加 `wantsDeep(query)`：`/(记得|还记不记得|忘没忘|你忘了|以前|那时候|上次说|翻旧账|想不起来|不记得)/`。
- 条件：`opt.allowDeep !== false` 且（命中触发词 或 常规注入结果为空）。

### 2.2 深翻一次

- `deepRecall(db, aid, q, opt)`：`scene='S3'`、`archiveDays=0`、`k=3`、`noUpgrade` 不设，只拿 T2/T3/T4 层（纪要、日记、原文），结果 `via:'deep'`。
- 放在主检索之后：主结果不删，深翻结果拼在后面（最多 3 条，去重）。
- 参数：`memory.inject.deep`（on/off，默认 on）、`memory.deep.k`（3）。

### 2.3 注入里说清楚「这是翻出来的」

- `pack.js` 增加 `opt.deepNote`：本批里有 `via==='deep'` 的条目时，块尾加一行
  `（下面这几条是我刚翻旧账翻出来的，记不真切就说不真切，别硬说记得）`。
- 不给这些条目打「今天刚发生」标签，避免冒充新事。

### 2.4 测试 `test/memory-deep-recall.test.mjs`（≥12 断言）

- 「你还记得…」触发；普通问题不触发。
- 主结果为空时也翻；主结果非空时拼后面不覆盖。
- 能翻到 cold 老条目；`memory.inject.deep=off` 时不翻。
- 注入块带提示行；不带「今天刚发生」标签。
- 去重：同一条不出现两次。

## P3 夜里沉淀：想明白的那一点要留下来（约 1.5 小时）

**要的东西**：`self_day` 是流水（今天干了啥），再补一条「今晚想明白的一件事」，有就写，没有不写。

### 3.1 `self_memory.js` 加 `writeSelfInsight(db, aid, day, opt)`

- 素材：当天 `source='self'` 条目（排除 `self.day.*` 本身）+ 当天 `life.done` 里 `kind='think'` 的 summary；条目数 < `memory.self.insight.min_items`（默认 2）→ `{skipped:'thin'}`。
- 模型 prompt：只写「今天我想明白的一件事」，20~120 字，第一人称，具体，不总结工作、不列点；想不明白就不写。
- 闸门：`selfTextOk` + 长度 16~120 + 不能是 `今天…` 开头的流水（要求含「原来/其实/可能/好像/发现/明白/怕/觉得」至少一个，否则 `skipped:'flat'`）。
- 落库：`source='self'`, `type='reflection'`（`addMemory` 的白名单里没有 insight，「自省」本来就是 reflection；靠 `fact_key` 区分），`fact_key='self.insight.<day>'`, `importance=0.65`, `confidence=0.7`。
- 参数：`memory.write.self.insight`（on/off，默认 on）、`memory.self.insight.min_items`（2）。

### 3.2 夜里挂上

- `nightly.js` ⑤e `self_insight`，紧跟 ⑤c；`self_day` 失败不影响它，反之亦然。

### 3.3 测试 `test/memory-self-insight.test.mjs`（≥12 断言）

- 素材不足跳过；写出来是 `type='insight'`、`fact_key` 正确。
- 流水式「今天改了三个文件并跑了测试」被 `flat` 挡。
- 旁白式被挡、超长被截或挡。
- 开关 off 跳过；同日重复跑不写第二条。
- 模型抛错 → `model_failed`，夜间其他步骤照跑。

## P4 防祥林嫂：同一件事别第十遍还在讲（约 1.5 小时）

**要的东西**：一条自己的事 24 小时内已经露脸 2 次，这一轮就换一条，别反复念。

### 4.1 新模块 `src/modules/self_repeat.js`

- `shownCounts(db, aid, ids, hours)`：查 `events` 里 `type='memory.self.shown'` 的 payload（`{ids:[...]}`），统计每个 id 在最近 N 小时的次数，返回 `Map(id → n)`。
- `markShown(db, aid, ids)`：写一条 `memory.self.shown` 事件（附 `ts`），一次注入合并成一条事件，不逐条写。

### 4.2 接进注入

- `index.js`：`retrieve` 之前读 `shownCounts` 传 `opt.selfShown`；`packMemoryBlock` 之后对「这次真的进了注入块的 self/life 条目」调 `markShown`。
- `retrieve.js` 的 `selfCandidates` 增加 `opt.selfShown` 与 `opt.selfRepeatMax`：过滤掉 `count >= max` 的条目；若全被过滤，取 `count` 最小的那条兜底（不能因为怕重复就一条都不给）。
- 兜底要覆盖全部配额通道（锚点 / 新近 / 自己的 / 模式），不然刚写的事会被「新近」反复带进来；字面命中不挡（她在问这件事就该出现）；模式条目不参与兜底（同一句模式反复念正是要避免的）。
- 参数：`memory.self.repeat_hours`（24）、`memory.self.repeat_max`（2）。

### 4.3 测试 `test/memory-self-repeat.test.mjs`（≥10 断言）

- 第一次给 A；第二次给 A；第三次换 B（A 已达 2 次）。
- 超过 24 小时的露出记录不算。
- 全部达到上限时兜底给 count 最小的一条，不是空。
- `repeat_max=0` 等价关闭；事件只在「真的进了注入块」时记。
- `markShown` 每条事件只落一条，payload 是数组。
