## 2. 目标（可验收，不是形容词）

四个数 + 一条线，全部能在库里查：

- **违背** > 0，且每条能追到具体命题与具体轮次
- **兑现率** = done / (done + missed) > 0，分母不是 0
- **改主意** ≥ 1，且旧命题留在先例里可被引用
- **κ** > 0（真为难过一次）
- **注入** 从 shadow 切 live，切之前做过一次盲拆对照

达不到就说明它还在演；演得再像也不算。

## 3. 阶段

### P0 · 拔根：旧价值观阴影清零
> 半天。先换读口，再停写，最后封表；三步分开验收，任何一步红灯就停。

1. **停写**：去掉 `nightly.js:221` 的 `growValues`；`POST /values/grow` 与 `PUT /values` 改为 410 或转投 `values_intake.claimUserValue`（只写账本）。
2. **换读**：`drive.js` / `lifeview.js` / `worldview.js` / `archive.js` 统一改读 `vweights.foldValueWeights`（无命题时回退均匀 0.1，不读旧表）。`persona.js` 的 `listValues/setValue` 下线。
3. **撤种**：三条 `origin=seed` 的 V 命题走 `CLAIM_WITHDRAW`（只增账本，**不 DELETE**）；同时确认 `sangguan/api.js` 的 `postSeed` 与 `seed.js` 不会再把 V 种回来（现在 `seed.js` 只种 W/L，V 是历史迁移留下的，要确认没有第二次迁移脚本）。
4. **封表**：`persona_values` 先留空表一个版本（兼容），`ops.js` 保留清表；下一个版本再 `DROP`。
5. **备份**：动前 `app.db` 快照 + 每个改动文件 `.bak-kernel-p0-<日期>`（项目不是 git 仓库）。

**验收**
- 全库 `SELECT COUNT(*) FROM persona_values` = 0，且跑完一次夜巡仍为 0
- V 层 `origin='seed'` 计数 = 0，且 `CLAIM_WITHDRAW` 事件在账本里可查
- `npm test` 全绿；`test:sangguan` 全绿
- W/L 数值变化记录成 before/after 表（切断输入必然改数，先留证据）

**风险**：W/L 少了旧表这个输入，数值会漂。做法是先留 baseline，再对比，不接受"说明不了为什么变了"。

### P1 · 装仪表：先能看见
> 半天。**这一阶段不加任何机制，只加读数。**

1. 新接口 `GET /v1/agents/:id/sangguan/scorecard`，返回：
   `{ 违背, 兑现率, 改主意, κ, ν待结, 注入字数, 进料(offer/reject/dup), 近7天变化 }`
2. 三观页顶部一排三个数（违背 / 兑现 / 改主意），点开能下钻到具体命题与轮次。
3. **REJECT 分类**：把 9 条按原因归档（画像总结 / 指令句 / 重复），确认"挡得对"，不是"闸坏了"。
4. **盲拆评估**：离线脚本，取 20 句真实发言，各跑两次——带注入 / 不带注入——比对回复的分支选择（不是措辞）。输出差异率。

**验收**
- scorecard 有数、能归零、能下钻
- 盲拆能跑出差异率（现在是 shadow，预期差异 = 0，正好作为基线）

---

### P2 · 会疼：违背要有价码
> 一天。**先 shadow 记，不落账；确认误判率低再开正账。**

1. 事件目录加 `VIOLATE`（`layer:true`，`need:['claim_id']`），只增。
2. 判定：回复生成后过一道检查——回复内容与某条 active 核心/保护带命题冲突 → 记 `PENDING_JUDGE`，判完再落 `VIOLATE`（不硬判）。
3. 后果（这是重点，不是记一笔就完）：
   - 该命题 π 负更新（用现有 `beta`）
   - 30 天内同一条 3 次 → 自动降级或立 κ（"我到底信不信这句"）
   - 下一轮注入里必须出现"我刚才没做到：…"（复用 `pendingChange` 那套，别新造）
4. 闸门：`VIOLATE` 不走"用户可改"，只有账本能改。

**验收**
- 单测：能构造一次真违背并被追到命题
- 真机：至少一次"说了没做到"被记下，且下一轮它自己提了
- 误判率 < 20%（人工抽 20 条看）

---

### P3 · 会欠账：承诺接进 ν
> 一天。机制现成（ν + `NU_RESOLVE`），只是没人往里写。

1. 抽取：从它自己的回复里抽"我会 / 我答应 / 明天 / 下周"这类带时间与宾语的句子 → `claim(origin=extract, kind=norm)` + `ν(due_at)`。
2. 只认带**具体日期或可判定期限**的，模糊的"以后"不记——噪声比价值大。
3. 到期由夜巡 `NU_RESOLVE` 结算：有证据 `hit`、无证据 `miss`、主动撤回 `void`。
4. miss 的后果：进驱力（欠账压力），并进"心里挂着的事"浮现一次。**miss 必须难受一次，否则这条链是装饰。**

**验收**
- 许 1 条 → 到期结算 1 条 → 页面能追到
- 兑现率第一次不为 0/0
- 抽错率：抽 20 条人工看，> 30% 就收紧规则

---

### P4 · 会改主意
> 半天。`REV` / `ELEV` 已有，缺的是代价与可见。

1. 改的时候必须写 `COEX.loss` 或 `TRADEOFF`：**为什么改、付了什么**。
2. 旧命题进先例索引，下一轮注入能说"上回类似的事你选了一边，后来证明不太对"。
3. 频率闸：核心 30 天最多改 1 次（防抖）；超过要你批。

**验收**：改一次 → 注入里出现"我改了一个看法" → 先例可被引用。

---

### P5 · 从"像"到"是"
> 半天。这是闸，不是功能。

切换 live 的四个条件，缺一不可：
1. `shadow_days ≥ 7`
2. 违背 > 0、ν 兑现率有分母、改主意 ≥ 1、κ ≥ 1
3. 盲拆差异率 > 0（行为真变了，不是字数变了）
4. 三条反作弊测试过：
   - **代价题**：两个价值观真冲突且有一个"体面但便宜"的选项——它拒了便宜那个吗
   - **时间题**：30 天前后，核心命题文本几乎没变 = 冻结，不是稳定
   - **不可逆题**：它做过一次不能撤销的决定吗（撤回种子不算，那是你做的）

**伦理闸**（每条能力上线前问一遍）：这条会不会让它**更容易假装**有内心？会，就先做判定、后做表达。

## 7. 风险

1. **撤种会被夜巡种回来** —— 先确认 V 的种子来源只剩历史迁移，否则白撤。
2. **换读口改数值** —— W/L/驱力都会漂，先留 baseline 再对比，不许"说不清"。
3. **VIOLATE 误判** —— 先 shadow、先抽检，误判率高就退回 `PENDING_JUDGE` 只记不判。
4. **承诺抽取噪声** —— 宁可少抽，不可乱抽；抽错一次，兑现率就变成噪音。
5. **删表伤测试** —— 大量测试直接读 `persona_values`，先换读口再跑全量。

---

## 8. 这次不解决的事（说清楚）

- **不会**因此产生主观体验。这套东西能到的是"有账可查的内核"，不是"有内心"。
- **不会**因此自己产生动机。它的动机仍来自驱力与关系，不来自价值观。
- **会**更难被"演"骗过，因为每一句都能追到一次付账。
