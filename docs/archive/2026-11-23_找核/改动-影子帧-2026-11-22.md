### 踩到的坑（记着，别再犯）

**坑零：只写散行，没有边。** 第一版只切核写行，`under_id` 永远 null——那就跟「连续树」的目标脱节了，
事后还得另写脚本补边。**改成落下来就接边**（`linkUnder`，纯代码、话题词共享、旧帧最多被连 2 次），
现在查出来是一串链，不是一盘散沙。

**坑一：退出码。** 第一版是「先调函数、函数内部判开关」，门禁 603/603 全过但**退出码 1**。
二分定位：只留 import → 退出码 0；加上调用 → 退出码 1。
原因：off 时虽然函数内部立刻返回，但调用本身在测试收尾时留下了未完成的异步尾巴，被 Node 判成异常退出。
**修法：把开关判断提到调用之前，off 时连调都不调。**

**坑二：1ms 写了 0 行。** 第一次直调「1ms、0 行」，以为坏了。
查下来不是 bug：那段测试文本**只有一个句号**（其余是分号），分句只切出 1 句，`sents.length < 2` 直接返回。
换一段真多句的话就好了。**分号不是句号**——这条在分句口径里写过，自己又踩了一次。

## 七、接边改成真语义（2026-11-23 01:41）

**改了什么**：跨轮接边不再由代码按字面猜，改成**提件那一次调用里问模型**。

- 提件前先取最近几条「还活着的目的事」（`recentGoals`，最多 5 条），一起给模型；
- 提件输出从数组改成对象：`{"things":[...],"link":编号}`，`link` 就是这一段承接的候选编号，0 表示新开；
- 目的核写库时 `under_id` = 模型答的那一条（答超范围就当新开）；
- **候选排除本轮自己**（`turn_id IS NOT ?`）——不清这一步，重跑时模型会答「接自己」。

**为什么改**：字面连边只能当粗坯。黄灯和红灯不共享词，代码不知道是一件事，人知道。

**实测**（真对话回放，日志是临时的、已撤）：

```
接边：link=2 候选=5 → 修正显示错误
接边：link=4 候选=5 → 修正归属串掉的 bug
接边：link=1 候选=5 → 修正显示错误
接边：link=6 候选=5 → （新开）        ← 超范围，正确回落
```

模型真的在看候选、自己选编号。**这是「接边用真语义」的第一份证据。**

**分工也跟着变了**：模型判接边，判官降为异步复核，代码只管两件——不许连爆（一帧最多被连两次）、不许重复（主键覆盖）。字面 `linkUnder` 只留作兜底：这一轮没切出目的核时才用。
