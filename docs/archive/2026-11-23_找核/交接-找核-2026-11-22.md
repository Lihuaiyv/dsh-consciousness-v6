# 交接：找帧与找核（2026-11-22 夜）

## 一、这轮在干什么

目标没变：把一段真实对话切成**帧**（一个核 + 一片范围），再让帧连成**连续树**，并且整条链要自动跑，不靠手标。

- **线上**跑的是旧法：每轮一次 `writeAffairs`，要 `events` 加四格（`motive` / `motive_why` / `step` / `step_why`），写进 `affect.v4.affairs|<conv>` 与 `affair_rows`。它给帧一个「在干什么」的说法，但**不找核**。
- **离线**（`scratch/frame-core/`）在试新法：题 → 件 → 主判 → 字面加挂 → 回指合并 → 接续 → 塌，切出核与卫星。**还没接进线上**。

我 11-21 加进线上那套「找事」（`where` / `open` / 格表 / 三行注入）已被主人否掉，现在行为上关掉了：`plusOn` 写死 false、`frame_line.plusTail()` 直接返回空。**残留代码还没清**，这是已知欠账。

## 二、四个判据现在各自站哪儿（想三遍才定下来的）

| 判据 | 干什么 | 权限边界 |
|---|---|---|
| 题（问答一致性多遍取交集） | 说这段在谈什么 | 只用来**切帧**：交集出现两个互不相干的题 → 这段不是一个帧 |
| 件（提事，1～4 个短语） | 说这段有哪几件事 | 唯一出候选的；会漏（「重新配对」被并进「步骤」里提不出来） |
| 主判（这句主要为哪件事说话，三遍取多数） | 分配句子归属 | **全程只有它改句子归属** |
| 字面证据（事件名两字词命中≥2） | 句子里有没有指向那件事 | 只许**加挂**第二件，不许否掉主判 |
| 回指（代词指哪句/哪物） | 两句在说同一个东西 | 只许**合并件**，不改句子归属；必须成对、两边各≥2 句、不传递 |
| 接续（这句接着哪句说） | 顺序与缝 | 只做顺序与缝，不改归属；缝只当候选，不当边界 |
| 塌（= 接续图入度） | 有没有人接它 | 只做**收尾裁核**：外面有句子接它 → 承重核；没人接且不是起点 → 孤立 |
| 加粗 | 我自己的注意力痕迹 | 只对账，16 轮里只对上 1 轮，作废 |

v12/v13 失败的根子就是让几个判据都去动归属；这条边界现在写进文档了。

## 三、塌到底是什么（这轮最重要的一个想通）

塌**不是**「读起来通不通」（删任何一句都通），**不是**「缺了什么内容」（模型只答「缺结论」），**不是**「哪版更完整」（它一律挑更短的那版，诊断脚本原样打出来是 `"B"`）。

塌是**指称悬空**：抽走这件，别处还有句子原本指着它。所以它不用问模型，直接数**接续图入度**。

例外一条：一段话的开口本来没人接它，不能因此判孤岛——只对「含第一句」的件开这个口子（早先把缝也算进去，S19 轮3 四个件全被救成起点核，等于没筛）。

## 九、我这轮是怎么想的（思路留档，按时间顺序）

写这一节是因为结论会留下，弯路不会；而弯路才是下次最容易重踩的。

1. **一开始我把「问答一致性」当成了逐句的尺子。**
   我拿「这句在回答什么问题」去量每一句，卫星答不上来，全被逼成「答案」。
   后来回读文档才看到那句原话：它是入口，不是终点。入口用来圈候选核，逐句那步是「这句服务谁」。
   这个错很典型：一个判据在入口很好用，就顺手把它推到了终点。

2. **「核」被我钉死在句子上，是因为实现顺序错了。**
   我先分句、再从句子里面挑，挑出来的当然只能是一句。而文档说核的形式自由（词/短语/半句/整段逻辑），
   句子只是它落脚的证据。v11 改成先提「一件事」，才第一次能提「分析黄灯原因」这种短语。
   但改得不彻底：藏在「步骤」里的「重新配对」还是提不出来，因为候选阶段仍是「读句子提事」。

3. **「一句挂两件」我试了三种写法，全失败，最后才知道问题在哪。**
   - v12 放开「最多挑两个」→ 模型几乎全挑两个，十二句挂十二次，核吃掉整段；
   - v12b 加「独占句」门槛 → 反过来一个核都立不住；
   - v13 先问「还有别的吗？只答有/没有」→ 它把「有」当默认答，还是滥用。
   三次之后我认了：14B 分不清「同时服务两件」和「顺带提一句」。于是换思路——不让模型判，让**字面**判：
   事件名里的两字词在句中出现 ≥2 个，才算第二件。结果加挂次数只有 0～1 次，
   反过来说明「一句真服务两件」本来就稀少，之前的滥用全是模型顺着指令凑的。

4. **「塌」我问了四次，每次都答得漂亮，每次都没信息。**
   - 「删掉还成段吗？成段/散句」→ 四次全成段（删任何一句话都通）；
   - 「缺什么？主语/结论」→ 一律答缺结论；
   - 「只要说改不成就算承重」→ 全承重；
   - 「A 原文 / B 抽掉后，哪版更完整」→ 七个件全答 B。我不信，单独写诊断脚本打原始回答，结果就是 `"B"`——
     它偏好更短更干净的那版。
   四次之后我想通：这三个问法都在问「读起来怎么样」，而塌根本不是读感问题。
   塌是**指称悬空**：抽走这件，别处还有句子原本指着它。那就不必问模型——数接续图的入度即可。
   换入度之后第一次有了分辨力（S20 轮3：一个件被外面 1 句接、两个件零入边）。
   顺手踩的坑：早先把「缝」也算作起点，S19 轮3 四件全被救成起点核；改成只认含第一句才干净。

5. **接续和回指是两条判据，这点是被主人数出来的。**
   我原来把「回指」实现成数代词（16 轮最多命中 1 次，等于没信号）。
   主人指出：回指是问「它/这个/那个指哪一个」。改成指认之后，5 句带代词、2 句能指到具体句子。
   而接续问的是「这句接着哪句说」，12 句里 8 句接得上。两者数据不同、用途不同：
   接续给顺序与缝，回指给「两句在说同一个东西」——后者只能用来合并件。

6. **判据位置是问自己三遍才定下来的（不是排出来的）。**
   第一遍问「它替我说出什么」，第二遍问「它会怎么坏」，第三遍才排顺序、定谁有权改归属。
   前两遍决定一件事：**只有主判能改归属**，其余（题/证据/回指/接续/塌）各自只做一件事。
   v12/v13 翻车就是因为几个判据都能动归属，谁也说不清谁算数。

7. **线上为什么不马上换。**
   线上那套四格正在给帧供「停在哪一步」，连续树还要用 `step`。
   新链现在只是离线可跑，还没人工核对过；按「一次只动一条链、新路带开关」的规矩，
   先影子跑、比对，再谈替换。`motive` 两格等核稳了可以从核推，`step` 那两格推不出来，得留。

8. **模型调用这三件事是今天才学会的。**
   - `num_ctx` 写死 16384 在 16G 卡上装不下 → 子进程崩 → 每次调用冷启动（40 秒/次）。改 8192 后 0.2 秒/次；
   - 实验脚本直连 11434 会绕过队列、把常驻 14B 挤掉 → 现在一律走 `scripts/lib/exp-call.mjs`；
   - 插件实验口有频控，连续调用会被拒 → 本层串行节流 320ms、频控最多重试两次，第三次就停手查。
