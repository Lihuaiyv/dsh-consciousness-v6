## 四、错在哪（比数字重要）

1. **编号步骤被吸进相邻的解说件。** ⑥⑦⑩ 是「1. 先充电 / 2. 观察 / 3. 充满再试」这条操作链，被整块判给了丁「重新配对」。
   不是随机错：⑧⑨ 恰好是「如果充电没改善，就重新配对」的条件分支，模型把整个编号列表当成同一件事往下顺。
   v14 那次（记录第三节）⑥⑦⑩ 被挂到「电量低表现」——**同一个错，换了个落点**：步骤句总被吸进前面最近的那件。
2. **丙「建议充电测试」零句。** 提件提出来了，主判一句都没给它；然后回指拿「丙→丁」把它并掉。
   回指本来只该合并「两句同指却被提成两件」的情况，这里合并的是「零句的件」，等于替主判收拾残局。
3. **旁支没件可挂。** ⑪⑫⑬ 是「浏览接口没开」这一条，提件阶段没提出来（四件上限已满），于是 ⑪ 判不上、⑫⑬ 被塞进乙。
4. **塌把错误放大了。** 丁明明有 7 句，却因「件内接续不算入度 + 不含第一句」被判「孤立」。
   塌的前提是归属正确；归属一错，它不会变中立，只会把错的那件判死。这条以前没写下来过。

四条结论：

1. **「编号步骤」不是唯一问题。** 它只在 S20 轮3 显形；S15 轮6 的错来自「打比方说明问题」被提成一个件，然后论证句（④⑤⑯⑰）真的判给了它。两种错法，同一个落点：**句归属错了**。
2. **错在提件，不在主判。** 三段的件名都是动词短语——「给帧系统写总纲」「把 anchor 挑出来」「打比方说明问题」「说帧的两个字段」「读完文档」。件名一粗，主判只能往粗里靠；三票取多数在这三段里没有出现「票分裂」，每次都很稳地选了某件，只是**件本身不对**。
3. **所以下一刀切在提件**（件的粒度与形态），不是改主判的投票方式。S20 轮3 那条「先切编号步骤」的候选方向，可能只是提件问题的局部症状。
4. 交接记录里 S20 轮3 的四件判定与这次实跑也不同（那次是 3 件、丙被外面 1 句接着；这次 4 件、丙零句）。14B 有随机性，**数字要按次记**，别把某一次当定论。
