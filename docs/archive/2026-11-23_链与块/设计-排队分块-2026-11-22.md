# 排队分块设计（2026-11-22 主人定）

## 一句话

模型调用按**三块**排队。块内先来后到，块与块之间按块优先——聊天块可以插到实验块前面，实验块可以插到夜间整理块前面。

## 三块

| 块 | 块号 | 里面放什么 | 谁来排 |
|---|---|---|---|
| 聊天 | 1 | 聊天本身、分帧、判定、这一轮的摘要、摘要重试、向量（聊天要用的前置） | 本地 14B 通道 + 语义通道 + 宿主通道 |
| 实验 | 2 | 实验判官、对照、实验性小模型 | 本地 14B 通道（只走 `POST /local/exp`） |
| 夜间整理 | 3 | 切事、日记、整理、批量兜底、预热 | 本地 14B 通道 |

**分帧属于聊天块，切事属于夜间整理块**——分帧是每轮都要的，切事是攒够一段才做的，两回事，别混。

## 规则

1. **块内**：先来后到（FIFO）。同一个块里，谁先来谁先跑，不许按重要性插队。
2. **块之间**：块号小的可以插到块号大的前面。聊天块新来的活，可以插到已经在排队的实验/夜间任务前面。
3. **不走优先级数字**：每个调用只声明「我属于哪一块」，不再自己编 priority 数字。数字是设计的一部分，不许各调用点各写各的。

## 三条通道各自怎么用这套规则

- **本地 14B**：一个槽，并发 1。按块排序，块内 FIFO。
- **语义向量**：一个槽，并发 1。它只服务聊天，所以只归聊天块；跟 14B 互不抢。
- **宿主（DSH 的模型）**：一个槽，并发 1。目前只有聊天块在用（判定、摘要、切事抽取），所以就是 FIFO。

## 归块速查（调用点该写哪个）

| 调用 | 标签 | 块 |
|---|---|---|
| 聊天回复 | `chat` | 聊天 |
| 情绪分帧/判定 | `affect:judge` | 聊天 |
| 这一轮摘要 | `affect:summary` / `affect:summary:retry` | 聊天 |
| 向量 | `embed` | 聊天 |
| 实验判官 | `exp:*` | 实验 |
| 切事 | `split:*` | 夜间整理 |
| 日记/整理 | `nightly:*` | 夜间整理 |
| 批量判边/蒸馏/预热 | `batch:*` | 夜间整理 |

## 怎么验

1. 离线：`node scripts/check-host-queue.mjs`（宿主 FIFO）+ 情绪链端到端。
2. 真实：`hook.log` 里每条 `host label=…` 会标块号；两个会话同时说话时，后到的聊天该插到夜间整理前面，但不该插到同块的人前面。
3. 门禁必须全绿（602 项）。

## 为什么这么定

以前按调用各自的 priority 数字排（1 判定、3 摘要、5 切事、7 批量），散落在十几个调用点里，改一处忘一处，而且出现过「判定插到摘要前面，摘要还没生成，这一轮读到旧摘要」的问题。
现在把规则收成一个块表：新加一个调用，只需要回答「它属于哪一块」，排序逻辑不用碰。
