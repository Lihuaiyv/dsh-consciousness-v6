# 并发会话隔离：worktree 的用法（2026-11-07）

> 为什么要有这页：两个会话在同一个目录里改，谁先提交就把对方没提交的改动一起卷走。
> 11-06 已经发生两次（`bcbe99b`、`f20b6b4` 前后）。worktree 是把两边从物理上分开。

## 现在的两间屋子

| 目录 | 分支 | 谁在用 |
|---|---|---|
| `D:\deepseek\dsh-plugins\dsh-consciousness-v6` | `refactor/brain-box` | 主线（我这边的活） |
| `D:\deepseek\dsh-plugins\dsh-voice-wt` | `voice-split` | 语音那摊 |

两间屋子共用同一个 `.git`，但工作区文件各是各的。在一间屋里新建、修改、删除，另一间屋看不到。
git 也不允许同一条分支在两间屋里同时 checkout，所以「两边改同一条分支」这种最坏情况会被它直接拦住。

## 为什么不用 node_modules

这个仓库的测试只用 node 自带的 `node:sqlite`，没有依赖目录可装；在 worktree 里直接 `node test/xxx.test.mjs` 就能跑，已经验证过（sayonce 12/12、日记 25/25）。将来真要用到依赖，再把 `node_modules` 用目录联接指回主目录，别重装。

## 合并

1. 各自在自己的分支上提交（语音那边 `git -C ..\dsh-voice-wt add ... && commit`）。
2. 主线这边：`git merge voice-split`（或先 `git fetch` 再 rebase）。
3. 冲突按文件小步解，解完跑 `node test/run-tests.mjs` + `node scripts/check-parts.mjs`。

## 收尾（语音那边做完之后）

```
git worktree remove ..\dsh-voice-wt     # 屋子收掉
git branch -d voice-split               # 分支合并完再删
```

`git worktree list` 随时能看到现在有几间屋子。

## 注意

- 未提交的改动不会跟着分支走：换屋子之前先提交，或者把文件复制过去。
- 两间屋子的 `hook.log`、数据库路径都是同一份（`~/.dsh/consciousness/app.db`），跑测试时别同时压线上库。
