# Bug：时光机能把「忘掉的东西」翻出来

> 2026-11-09 中午发现。**这是现有代码里的洞，不是汇流设计的问题。**
> 状态：**未修**。严重度：中高（遗忘权 / 隐私）。影响面：`asof` 的两条取原话路径 + 将来的汇流。
> 相关：[汇流-基石-2026-11-09.md](./汇流-基石-2026-11-09.md) §18.1 / §10.5（I5 遗忘优先）

---

## 1. 一句话

记忆被 HIDE（用户说"忘掉"）之后，`memory_items` 那条确实变 `soft_deleted` 了，**但原文层 `raw_turns` 没有任何过滤**——`asof` 取原话的两条路都还读得到。

**结论能忘，原话忘不掉。**

## 2. 证据

### 2.1 代码

`src/modules/asof.js`：

```js
// ① 按记忆的 source_turn_id 直读原话 —— 不看可见性
function quotesFor(db, aid, row, q, from, to) {
  if (row.source_turn_id) {
    const rs = db.prepare(
      "SELECT text,created_at,role FROM raw_turns WHERE agent_id=? AND turn_id=? AND role='user' ORDER BY seq LIMIT 2"
    ).all(aid, row.source_turn_id)
    ...
```

```js
// ② 按话题在时间窗里搜原文 —— 根本不知道哪句后来被 HIDE
function windowQuotes(db, aid, q, from, to, k = 3) {
  rows = searchRaw(db, aid, q, 40) || []
  return rows.filter((r) => r.role === 'user' && r.created_at >= from && ... )
```

两条路都不查 `memory_timeline`、不查 `memory_items.status`、不查 `deleted_at`。

### 2.2 库

- `memory_timeline` 里 **HIDE 共 55 条，`reason` 全是 `user`**（用户主动要求忘掉的）。
- 被 HIDE 的记忆，`memory_items.status = 'soft_deleted'` ——**这一步是对的**，问题在别处。
- `fact_archive.source_turn_id` 覆盖率 **2786 / 4239 = 66%** ——顺带发现：三分之一的记忆**没有出证能力**，`quotesFor` 对它根本取不到原话。（这不是本 bug，但会让"出证"看起来像在藏东西，见 §5。）

## 3. 复现

```sql
-- 1. 找一条被 HIDE 的记忆
SELECT memory_id, at, reason FROM memory_timeline WHERE op='HIDE' LIMIT 1;

-- 2. 它现在在热库里的状态：应该是不可见的
SELECT id, status, deleted_at FROM memory_items WHERE id = '<memory_id>';

-- 3. 但它的原话还在冷库里，而且 asof 会照读
SELECT r.text FROM raw_turns r
 WHERE r.agent_id='<aid>' AND r.turn_id = (
   SELECT source_turn_id FROM fact_archive WHERE memory_id='<memory_id>'
 );
```

第 3 步能读出原文，就说明洞成立。

## 4. 修法

### 4.1 先做（便宜、纯读取层，不动表）——**已实现（2026-11-09）**

新增 `src/modules/visibility.js`：

```js
forgottenMemoryIds(db, aid)   // HIDE / DELETE 过的记忆
forgottenTurnIds(db, aid)     // 它们指向的原话轮次（整轮）
forgottenInWindow(db, aid, from, to) // 落在时间窗里的「已忘」条数
```

`asof` 的三处取原话点全部改走它：`quotesFor` / `windowQuotes` / `windowQuotes` 的兜底。
返回里新增 `hidden_quotes`（挡掉了几条），**不返回被挡的正文**。

**⚠️ 实测发现的一个硬事实（比原 bug 更麻烦）**：
现库 55 条 HIDE **全部没有 `source_turn_id`**（老账没链），所以「精确到轮」一个都封不住——
`forgottenTurnIds` 返回 0。

补的兜底（保守封）：

> 查询窗里只要落着「已忘」的记忆（`forgottenInWindow > 0`），**这一窗就不按话题去搜原文**。

代价是那一窗的出证变少（实测：11-01 那天的窗里落了 52 条已忘记忆 → 该窗原话全不出）。
但方向对：**宁可少出证，不当遗忘后门**。新账会带 turn 链，以后就能精确到轮。

### 4.1.1 原计划（保留作对照）

```js
// 建议：modules/visibility.js（只读）
export function forgottenTurnIds(db, aid) {
  // HIDE / DELETE 过的 memory → 它的 source_turn_id 集合
  // 用 memory_timeline 反查，不依赖 memory_items 当前状态（老行可能已清理）
}
export function isTurnForgotten(db, aid, turnId) { ... }
```

- `quotesFor`：命中 `forgottenTurnIds` 就返回空，并带 `{ hidden: true }` 让上层知道"不是没有，是被忘了"。
- `windowQuotes`：过滤掉被忘的 turn。
  - **粒度要小心**：一轮对话可能支撑多条记忆，其中一条被忘，不该连坐整轮。折中规则：**被忘记忆的 `source_turn_id` 指向的那一轮，整轮排除**。理由：用户说"忘掉这件事"时，那一轮的原话就是那件事本身；留半句反而是更糟的泄露。
- `deleted_at IS NOT NULL` 的行同样处理。

### 4.2 再做（硬解，可选）

**crypto-shredding**：每行原文配一把独立密钥，遗忘 = 删钥；行还在（append-only 不破），读出来是乱码。这是不可变审计日志对上"被遗忘权"的标准解（[Crypto-Shredding](https://zenodo.org/records/17946987)）。它解决的是"以后想物理上真忘"的需求，不是现在这个读得到的问题。

### 4.3 不做

- **不改 `raw_turns` 结构**，不物理删、不改写（违反 append-only 与可审计）。
- **不在写入侧抹字**：`raw_turns` 是"当时真的说了什么"的底，抹了就再也证明不了任何事。

## 5. 顺带发现（不是同一件事，但一起记）

1. **「降落地」分三层，深度不一样**：
   - `memory_timeline.text_ref → fact_archive` 出生行：**4199 / 4201（99.95%）** —— 这才是时光机真正的降落点，每条记忆都落得到存根。
   - `fact_archive.source_turn_id → raw_turns`：**2786 / 4239（66%）** —— 能落到"那一轮原话"的只有三分之二。`quotesFor` 走的正是这条，所以对三分之一记忆，它不是"忘了"，是"根本没有"。
   - 真忘（软删满 7 天硬删）：存根 + timeline 一起删，**连指针都不留**。
   - 结论：修这个 bug 时别把"取不到"当成"被忘了"——两种原因要分开报（`hidden` vs `no_source`）。
2. **`windowQuotes` 目前只取 `role='user'`**：她说的话（`role='assistant'`）从来不出证。对"我那时是什么口气"这类问题，这是缺的。
3. **两条路径没有共享过滤**：现在 `quotesFor` 和 `windowQuotes` 各写各的；`asofInjectItems` 又再拼一次。加过滤时如果只改一处，另外两处照漏。→ 所以要先抽函数，再改调用点。

## 6. 验收

| 编号 | 做什么 | 必须 |
|---|---|---|
| **E12-a** | HIDE 一条 → `retrieveAsOf` 对它返回的原话为空，且带 `hidden` 标记 | 通过 |
| **E12-b** | HIDE 一条 → `windowQuotes` 在同话题时间窗里搜不到那一轮 | 通过 |
| **E12-c** | 同一轮支撑两条记忆，只 HIDE 其中一条 → 该轮整轮不出（按 4.1 规则） | 通过 |
| **E12-d** | 没被 HIDE 的记忆，出证行为与改前逐字一致（不许误伤） | 通过 |

E12-d 是防回归的：这个改动最容易出的错是"多忘了一些"。

## 7. 影响汇流的地方

汇流（`reconstructScene`）要取原话，**必须复用同一个 `forgottenTurnIds`**，不许自己写一条 SQL。否则修了 asof，汇流又漏一遍——同一个洞开两次。
