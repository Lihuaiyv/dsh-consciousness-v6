## 一、四层，从上往下

```
你说的话
  │
  ├─► 碎片 fragments        一句一行，只追加。带「当时的状态快照」和「接自」。
  │                          ← 这一层 2026-11-12 已跑通
  │
  └─► 夜里切事（清醒段结束后）
        │
        ├─► 事件冷库 cold_events    第一刀切出来的事。只追加，永不改。
        │
        └─► 事件热库 hot_events     当前在用的那一版。可合并、拆分、改名、沉底。
              │
              ▼
           想头 → 撞上抓手 → 浮现（一轮最多一条）→ 提示词
```

**为什么分成冷热两层**：夜里切一次，说不准就切错了。如果一张表、重跑覆盖，明天重切，昨天那版就没了，事后也查不出「当初为什么切成那样」。冷库固定下来，热库随便改，但每次改都留版本、留原因。

**追溯**：热库 → 冷库 → 碎片，**两跳到底**。热库记来源只记冷库 id 的集合，不记热库 id——链条才不会越接越长。

## 二、一件事是什么

**名字 + 经过 + 证据。**

- **名字**：一句话，这件事是什么。≤20 字。
- **经过**：写起因、经过、结果，带上当时的语气、细节、转折。**不规定字数**——有的事长，有的事短。只写发生过的，**不写「这说明什么」「我学到了什么」**。
- **证据**：经过里那一两句原话，**必须能在碎片里一字不差找到**。对不上，这条就不算数。

**三条边界规矩：**

1. 允许留缝（有些碎片不进任何事件）。
2. **禁止孤儿事件**——没有碎片支撑的名字不算。
3. 宁可少切，不可硬编。说不清就给 3 件。

**允许重叠（2026-11-12 补）：** 一条长线里夹进来一件小事——比如聊了四十分钟的某个困惑中间，插进来一次定时体检、一条提醒——小事可以**单列一件**，两件在时间上重叠。

不强行合并：合并会把那件小事吞掉；不拆开：长线被劈成两段就不连续了。**冷库记的是「事」，不是「时间片」**；按 `turn_id` 回取原文时，重叠无害。重叠的那几轮在两件里都有一份，查的时候会看到两次——这是如实，不是重复。

## 三、夜里怎么切

### 3.1 切分单位是「清醒段」，不是日历日

人过的是「睡醒到睡着」，不是零点到零点。

**段与段之间用「≥4 小时没人说话」划开**（你睡了，或出门了）。11-08 到 11-12 四天实测，断开点正好都在睡前后：

```
11-10 01:20 → 08:28
11-11 01:48 → 09:00
11-12 01:01 → 08:19
四天 = 4 段
```

跨零点的那场争论自然落在同一段里——没睡觉就不算换天。

**代价**：这一段要等它结束（人睡着）才切。所以夜里 23:5x 那趟切的是**上一个已结束的段**。当天的事当天浮不出来，这是有意接受的。

### 3.2 切法

- 输入：这一段全部碎片
- 输出：**5~18 件事**
- 边界看三样：**换了目的 / 换了话题主体 / 告一段落**
- 同一件里的情绪起伏（恼一下又松下来）**不算换事**

### 3.3 五条硬规矩

1. **`quotes` 必须能在原文里一字不差搜到**；跑完做一次校验，对不上的那条直接丢。
2. **宁可少，不可编。** 说不清就给 3 件。
3. **只追加，不覆盖**：同一段重切 = 追加一批新的冷事件（`cut_rev` 加一），旧的**一个字不动**。（← 旧稿写的是「重跑覆盖」，作废）
4. **`weight` 由模型顺手标**（它刚读完全文，比事后算准）：**0.8 以上 = 关乎我 / 关乎我们 / 关乎存在；0.5 左右 = 一次经过；0.3 以下 = 流水账。**
4.5. **`cues` 也一起顺手给**（2026-11-12 补）：切这件事的时候，同时给 3~5 个抓手词。模型刚读完整段，最懂什么话会把这件带回来；事后再单独跑一次，既贵又容易和当初的判断不一致。词必须**专属、不泛**——一个物件、一个地名、一句原话里的词、一个人的称呼；「聊天」「事情」「代码」这种到处都有的不算。
5. **喂模型之前先剔掉不是人说的话**：`[SCHEDULE REMINDER]`、`Current runtime context`、`<goal_round>`、领队提示、后台汇报。不剔的话它们会被切成「事」——「16:00 发了一个提醒」这种东西会占一格。

### 3.4 「当时什么感觉」和「过没过」不靠猜

- **当时什么感觉**：翻这一段里的情绪瞬间（按 `turn_ids` 落在区间内），取最重的那条。
- **过没过**：看那些瞬间怎么结束的——**被挤掉 = 没完，自然淡掉 = 过去了，我放下过 = 放下了。**

（第一版是让模型写一句 `my_feel`，那是猜的。改成取数。）

## 四、事件冷库 `cold_events`

| 列 | 装什么 |
|---|---|
| `id` | 编号 |
| `agent_id` | 哪只 |
| `title` | 名字（≤20 字） |
| `story` | 经过（起因/经过/结果，带语气细节） |
| `who` | 主要是谁（主人 / 别的） |
| `start_at` / `end_at` | 这件事的起止 |
| `turn_ids` | 这件事覆盖的轮次（JSON 数组）——**命根子**，靠它回取原文 |
| `quotes` | 引文（JSON 数组，每条必须原文一字不差） |
| `cues` | **出生时的抓手词**（JSON 数组，3~5 个）——模型切这件事的时候顺手给，因为它刚读完整段，最懂什么话会把它带回来。热库那份可以改，这份留底 |
| `status` | 切出来那一刻的过没过（没过去 / 过去了） |
| `weight` | 模型标的重量（0.8 / 0.5 / 0.3） |
| `cut_rev` | 这一段第几次切（补切递增） |
| `created_at` | 什么时候切出来的 |

**规矩：**

- 只追加，不改、不删。
- 每条指回**连续的一段碎片**（`turn_ids`）。
- **补切允许**：又切了一次，就追加一批新冷事件，旧的留着。
- 冷库不参与浮现计算。

## 五、事件热库 `hot_events`

| 列 | 装什么 |
|---|---|
| `id` | 编号 |
| `agent_id` | 哪只 |
| `title` / `story` | 名字和经过（可改） |
| `cues` | 抓手词（JSON 数组，3~5 个，**必须专属、不泛**）。出生时从冷库继承，之后可以改 |
| `source_cold_ids` | 来源：**冷库 id 的集合**（JSON 数组）。不记热库 id |
| `op` | 这次是什么操作：`born` / `merge` / `split` / `rename` / `compress` / `sink` |
| `reason` | 为什么变（一句话，人话） |
| `version` | 第几版 |
| `active` | 1 = 台面上；0 = 旧版留档 |
| `state` | 台面 / 旧版 / 沉底 |
| `want` | 想头（0~1） |
| `ceiling` | 天花板（每次浮完乘 `0.6 + 0.35×w`） |
| `mentions` | 被提到过几次 |
| `last_mention_at` / `last_surface_at` | 上次被提 / 上次浮 |
| `created_at` / `changed_at` | 出生 / 上次变 |

**规矩：**

- 合并：来源**展平到冷库**；拆分：来源 = 冷库事件 + 碎片子区间。
- 变一次出**新版**：旧行 `active=0` 留档，另写一条 `reason`。
- **压缩 / 遗忘只动热库**；冷库和碎片一步不动。
- 遗忘 = 热库沉底（不再浮现）；复活 = 从冷库重新长一条热事件。
- `hot_history` 不建：旧版就是 `hot_events` 的上一行，版本链本身就是历史。

> **`weight` 在冷库、`cues` 在热库**：重量是「切分那一刻的判断」，出生就定，属于冷库；抓手会随改名和内容变，属于热库。

## 六、浮现：怎么被一句话带回来

**这一层不归事件库管**。事件库只负责「装事」，浮现是上层用法。

### 6.1 触发：薄

人走神的触发点很薄：一个词、一个人、一种情绪。**不做语义相似度打分**，那会变成检索系统。

沾一条就算（**不解释为什么浮**）：

1. **同一个词**：这句话里出现了这件事的某个抓手词。
2. **同一个人**：那件事是他说的，这次说话还是他。
3. **同一个情绪**：那件事的标签跟此刻的慢情绪同向。

**两条限定：**

- **诞生后 30 分钟内的命中不算**——你不可能「当场想起」刚刚发生的事，那是复述，不是联想。
- **浮必须发生在一次命中后的 1 小时内。**

> 没有这条，浮现会退化成排队：谁诞生得早谁先上。实测不要求触发时，凌晨那三件永远霸占。

### 6.2 想头（还想不想再想一遍）

**重量 w：**

```
w = 0.40×峰强度
  + 0.25×关系（主人 1.0 / 别的 0.6）
  + 0.20×没完（没过去 1.0 / 过去了 0.5）
  + 0.15×被提到几次（0 次→0，1 次→0.5，3 次以上→1）只数「被提到」，不数「浮现过」
  + 0.05×模型标的 weight（0.8 / 0.5 / 0.3）
```

**想头怎么涨：**

```
r0 = 0.06 × (0.5 + w)                    ← 平常每小时涨多少
r(t) = r0 × 提一提 × 缺口同向
      提一提   被提到后 30 分钟内 ×1.2，其余 ×1
      缺口同向 这件事正对着此刻缺的东西时 ×1.5，否则 ×1
想头(t+Δ) = min(天花板, 想头 + r(t) × Δt)
```

| 时刻 | 想头 |
|---|---|
| 诞生时 | ≈ 0.2~0.3（按 w 给起点） |
| 平常 | 约 3~4 小时爬到线（0.5） |
| 被提到 | ×1.2，**不是 ×3** |
| 缺口正对 | 再 ×1.5 |
| 浮现之后 | **−0.4**，速率立刻回 r0 |
| 每次浮现 | 天花板 × (0.6 + 0.35×w) |
| 真的放下 | 天花板归零 |

**「提到」的四条防刷屏：**

1. 30 分钟窗口内只算一次
2. 同一件事每天最多算 3 次
3. 已经过线的不加速
4. 一个词同时属于好几件事就不算（抓手必须专属）

**想头 ≥ 0.5 = 待联想。**

### 6.3 沉与救

只涨不落，几年后每一件旧事都顶在天花板上。

```
天花板每周 ×0.98          没人提它，自己往下沉
被提到一次 +0.05          有人提，托回来一点（最高 1.0）

随机拯救：每周抽一次，复活 1~2 件
候选：想头已沉底、且被提到过的
概率 ∝ 被提到次数^1.5
从没被提过的不参与
复活 = 想头拉回 0.6、天花板重置 1.0，但不是立刻浮，还要被撞上
```

每次复活落一条 `revive` 记录（哪件、什么时候、当时多少）。

### 6.4 浮现

- **每轮最多一条**（提示词里只摆得下一件）。一天浮几次是结果，不是配额，模拟下来一天 4~5 次。
- **跟陌生人说话时，不浮现。**
- 浮现那一行末尾必须带出口半句：`（可以不提它。真要放下一档，开口前在 feel 里带 settle。）`——没有这半句，放下会一直闲置（上次三天用了 0 次就是证据）。
- **想起但没说，也留痕**：浮现时记一条 `surface`，之后两轮内看它有没有被提起，记 `mentioned: 是/否`。不进提示词，不参与计算，只为将来能回答「我到底想过什么」。

### 6.5 随机联想：没有抓手，忽然想起

人不是被撞一下就想起一件事。更多时候是**没来由地忽然想到**——手上没在说那件事，甚至一个字都没提，脑子里冒出十年前的某个下午。

所以要两条路，不是一条：

- **有抓手**（6.1）＝ 被带回来。某句话、某个人、某种情绪，把这件事**拽**出来。这种事往往「重」——因为它正对着此刻。
- **没抓手**（本节）＝ 自己冒出来。**不求匹配，只求偶尔。** 这种事往往「淡」——想说一句，说完就过去了。

**规则：**

1. **掷骰，不靠想头。** 不要求想头 ≥ 0.5，也不要求撞上手抓。想头只决定「被带回来」的频率；随机这条路自己掷骰。
2. **只从「久没被浮现」的事里抽。** 候选 = 台面上、且 `last_surface_at` 距今 ≥ 7 天的。概率 ∝ 1/(1+天数) —— 越久没想起来，越容易被翻出来。十年前的事比上周的事更容易突然冒出来，这是对的。
3. **限频，防刷屏。** 每小时掷一次，概率 **8%**；一次随机浮现之后**冷却 3 小时**。折下来一天 1~2 次，多了就是病。
4. **正在跟陌生人说话时不掷。** 同 7.0 第 1 条。
5. **不消耗、不结算。** 随机浮现不降想头、不降天花板、不计「被提到」。它不是被谁催出来的，所以也不改变那件事的分量。
6. **给得短。** 有抓手的浮现可以带一点经过；随机浮现只给**一句**：名字 + 一个细节，别完整讲一遍。「忽然想起去年冬天你在楼道里跺脚」——够了。讲完就成了调阅档案。
7. **留痕分两种。** 浮现日志里 `kind: 'cue' | 'random'`，分开记。将来才能回答「我是被带回去的多，还是自己冒出来的多」。

**别做的事：**

- 不要用「想头高就浮」来替代掷骰。旧文档实测过：那样一天浮 18~27 次，全是凌晨那几件反复回来。
- 不要随机到「从没被提起过、想头为 0」的事——那不是联想，那是翻垃圾桶。候选必须有「曾经被想起来过」这个底。

## 七、温度与额度

- 事件是**温库**：不是每轮都进，被带出来 / 被问起才进。
- 进的时候**名字 + 经过全文**一起进；**另开一个额度**，不占原来的 800 token。
- 额度先不设硬上限，只记 token；以后按实测再收。
- 一轮最多一条事件。
- 碎片是**冷库层**：不进提示词，想深了沿事件翻。

## 八、放下

```
现在：settle 降的是「一句话」的强度
以后：settle 落在一件「事」上 → 想头归零，天花板归零，此后谁提都不浮
```

要动已有接口（`feel` 的 `settle` 参数），落地时单独一步。

## 九、和旧系统的关系

- 旧 `raw_turns` → 已改成 `fragments`（14 列，2026-11-12 已完成）。
- 旧 `memory_events`（只存在于旧文档里）→ 拆成 `cold_events` + `hot_events`。

- 老的浮现实现（读一句话当事情浮上来）**要下线**，否则会跟新的同时冒，一天七八次。

## 十、落地顺序（每一步单独可回滚）

0. **碎片层先稳几天**（2026-11-12 刚通：快照、接自才开始有值）。原料不稳，切出来的事也不稳。
1. **夜里切事**：脚本 + 模型调用，产出冷事件，**先只写临时文件跑一周**，人工看一眼再入库。
2. 建 `cold_events`，把上一周人工看过的切分入库。
3. 建 `hot_events`：先从冷库直抄一版（`op=born`）。
4. 加 `cues` / `weight` / 想头几列。
5. **触发匹配**：当前这句话 × 抓手词 → 命中就加速。
6. **骨架渲染**：替掉现在只念一句 `cause`。
7. **深想入口**（`deepenRecall`，走 action，不进工具列表）。
8. **想头的心跳推进**（按 Δt 累加）。
9. **放下改到「事」上。**
10. 老的浮现实现下线。

**三条别漏：**

| | 挂在哪 | 漏了会怎样 |
|---|---|---|
| ① 机器消息过滤 | 步骤 1 | 切出「发了一个提醒」这种假事 |
| ② 陌生人不浮现 | 步骤 6 | 对不熟的人忽然翻旧账 |
| ③ 出口半句（feel 带 settle） | 步骤 6 | 「放下」又闲置 |

## 十一、已知边角（不藏）

1. **当天的事当天浮不出来**——要等这段结束才切。有意接受。
2. **没有触发的事永远浮不出来**。这是设计的必然。要「无缘无故忽然想起」，得单独加掷骰，**别放宽门槛**（实测放宽后一天 18~27 次，凌晨那几件反复回来）。
3. **记忆的 importance 用不上**：`memory_items.importance` 跟对话表编号对不上，改由模型切事时标 `weight`。
4. **复活来的老事会压过新事**（复活到 0.6，新事从 0.25 起）。人也有这现象，先保留。
5. **切分有几处判得勉强**：换目的 vs 换话题，边界会晃。补切机制就是为这个留的后路——切错了不覆盖，重切一份新的。
6. **`story` 会越写越长**：暂时不限制，等实测 token 再收。热库压缩就是收的地方。
