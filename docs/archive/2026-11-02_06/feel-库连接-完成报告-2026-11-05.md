## 一、做了什么

### Phase 0 · 对齐时间（地基）
- `affect_feel` 加 `turn_id`：这条感觉是哪一轮说的。
- `recordFeel` 写库时自己从 `raw_turns` 找当轮（同会话优先，60 分钟窗口，找不到留空）。
- `aroundOfFeel` 改成「有 turn_id 按轮取，没有才退回 5 分钟时间窗」。
- 修了一个回放 bug：`at` 传 ISO 字符串时旧代码会 `Number()` 成 NaN、退回「现在」，回放全挤到同一时刻；现在毫秒 / ISO / Date 都认。

### Phase 1 · 清账
- `purgeExpired` 的整实例清除清单补上 `affect_feel`——不再留孤儿行。
- 门禁判删（`status='deleted'`）和用户隐藏（`soft_deleted`）现在一起清——以前门禁删的那批永远停在原地。

### Phase 2 · 存根带感觉（T4）
- `fact_archive` 加 `feel_id`；`archiveFact` 写入时带上记忆出生时的 feel。
- 原地改写留下的历史存根（`<id>:hist:<n>`）也带。
- `GET /archive/facts` 的每条存根现在带 `feel` 对象。

### Phase 3 · 叙述带感觉（T2/T3 + 开环 + 嘀咕）
- `episodes` 加 `feel_id`：取该时段内离结尾最近的一条。
- `diaries` 加 `feel_ids`：当天写下的所有感觉，按时间串起来（JSON 数组）。
- `open_loops` 加 `feel_id`：挂上时取 30 分钟窗口内最近一条。
- `thoughts` 加 `feel_id`：嘀咕时接最近一条。

### Phase 4 · 关系事件带感觉
- `rel_event` 加 `feel_id`：事件前 30 分钟内最近一条。

### Phase 5 · 反向用起来
- `feelRecall(db, aid, { label, from, to, limit })`：按感觉找东西——每条 feel 带同时段（±30 分钟）的记忆和当天日记。
- `feelEventContrast(db, aid, { days, limit })`：感觉 ↔ 情绪事件对照——这条 feel 写完后 10 分钟内，评价层判了什么、标签一不一致。给校准用。
- 新 API：`GET /agents/:id/feel/search?label=&from=&to=&limit=`、`GET /agents/:id/feel/compare?days=&limit=`。
- 新工具 `feel_search`：模型可以按感觉找记忆（只读）。

## 四、生效方式与注意

1. **必须重启插件进程**：代码在 `D:\deepseek\dsh-plugins\dsh-consciousness-v6`，当前网页进程加载的还是重启前那一版。重启 DSH（或让插件宿主重载）后新代码才生效。
2. 生效后，新写入的 feel 会带 `turn_id`；新记忆、新存根、新纪要、新日记、新开环、新嘀咕、新关系事件都会带 feel 引用。
3. 旧数据不回填。理由：历史 feel 与历史轮次的对应关系只能按时间猜，猜错了会把感觉挂到别的话上——这比空着更糟。`turn_id` 可以回填（`backfillTurnIds`），但旧 feel 的轮次没有可回填的来源，所以保持 NULL。
4. 回滚：每个阶段只加列 / 加引用，不改旧字段语义；把新列留空即可退回「只有记忆挂 feel」的旧行为。
