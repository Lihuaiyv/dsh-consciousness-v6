# 记忆「把过去当现在」修复计划（v2 · 综合版）

> 状态：计划中，未动运行代码。2026-11-04 晚。上一轮临时补丁已整体回退。
> 依据：本地真实库体检 + 外部研究（见 [记忆时态-调研.md](./记忆时态-调研.md)）+ 时光机现状核对。

## 一、要修的是什么

- 注入里的旧结论和新进展平权，我会拿旧结论当现状。
- 真实库：48h 内 812 条新增、124 条作废（84 条是反思合并）；「情绪快照：待完成 / 完成」两条并存；反思压缩把待办、进行中的事压成泛结论。
- 外部研究：过时的竞争陈述比无关证据更有害（Obsolete Facts，100%→44.6%）；压缩会把不确定写成确定，模型只认语气不认来源（Manufactured Confidence）；被动标签会被忽略。

## 二、原则

- 不改表结构；动的是注入拼装、读侧查询、压缩选材。
- 每处带开关，默认值写清楚；关掉即回退。
- 先只读量基线，再改；每步真实库验过再进下一步。
- 标签只作辅助，主修是「让旧版退场 + 用冗余来源」。
- 「当时」查询只读，不 touch、不加热旧记忆。

## 三、阶段

### P1 基线体检（只读，先做）

- P1-1 `scripts/audit-stale-memories.mjs`：列出「仍现行、但同主题有更晚说法」的条（fact_key 主题段 + 关键词两路）；统计被 reflect 压掉且含待办词的条数。
- P1-2 小回放集：从真实库取 20–50 对「旧结论 + 新进展」（用 `retrieveAsOf` 取「某天当时」的版本做对照），测「注入后回答现在怎样」的准确率。
- 产出：修复前基线数字。不改运行代码。

### P2 注入端（核心，先于 P3）

- P2-1 **同主题旧条退出注入**：同一主题只让最新一条进记忆块，旧条降为「深查可见」。
  - 判定先用现有信息：`fact_key` 主题段 + `entity_id`；不动写入。
  - 开关 `memory.stale.eject`，默认 on；先 dry-run 打印「会被挤出的是哪条」。
- P2-2 「最近被取代」行：只认改口和被新说法取代（supersede / conflict），不认反思合并，不认刚写 10 分钟内的；最多 3 条，≤ 60 字。
  - 开关 `memory.recent.inject`，默认 on。
- P2-3 会话续接补今天：跨会话时带今天最近一条纪要（与现在间隔 ≥ 120 分钟才带）。
  - `sessionBridge(..., { allowToday: true })`，默认仍是旧行为。
- P2-4（可选）打开 `memory.asof.auto`：问句带过去时间时自动带「那时」行。现默认 off，先评估开启后的注入长度与误触。
- 验收：单测 + 真实库注入前后对比；「回放集」准确率有提升。

### P3 覆盖端（动写入，dry-run 先行）

- P3-0 现状（2026-11-04 真实库）：`conflicts` 表共 24 条，13 条高风险、11 条低风险，**全部 resolved、open 为 0**；最近 10 条全是「分步实现 vs 分步测试」这类同义重复。
  - 现有冲突检测只能抓「同一时刻、两条字面很像、只有正反/措辞差异」；抓不到「旧说法过时」（跨天、措辞不像、写新条时不会去比旧条）。
  - 低风险冲突故意两条都留，结果就是旧说法和新说法并排躺着。
- P3-1 `fact_key` 主题段归一：同主题已有更晚说法时，优先复用 key 或走 supersede 链，别留「待完成 / 完成」两条并行。
- P3-2 写入时识别「同一件事、状态相反」的对（待完成 ↔ 完成），当场标取代。
- P3-3 **过时检测（新增，补冲突机制的盲区）**：不靠「两条撞上」，靠时间——
  - 写入后 / 夜巡时扫「同主题（fact_key 主题段 / 实体）+ 更晚 active 说法」，把旧条标成被取代。
  - 不需要问你：时间顺序本身就是证据；只把「同主题、状态词相反」的留成待确认。
- P3-4 界面接上：冲突页不只显示「同义重复」，也显示「过时取代」这一类；否则又变成没人看的悬案。
- 用 `memoryHistory` 验取代链是否接上；先 dry-run 统计能接上多少对，再决定改抽取提示词还是合并逻辑。
- 验收：dry-run 在真实库上列出会被取代的条，人工抽查 20 条，错标率 < 10% 再进下一步。
- 开关按实例可关。

### P4 压缩端（reflect 防护）

- P4-1 `reflectFrom` 选材先聚类：只压同话题批次，不跨话题混压。
- P4-2 状态词保护：含「还没 / 待 / 等…之后 / 答应 / 提醒 / 未完成」的条目不压。
- P4-3 压缩稿保留不确定措辞：prompt 明确「原文里的未完成/推测状态必须保留，不许升级成确定事实」。
- 验收：真实库那 40 条样本回放 dryRun，看待办是否还在。

### P5 观测、开关、回滚

- 单测：P2 / P3 / P4 各一组；小回放集纳入回归。
- 指标：带更新标注的注入条数、被挤出的旧条数、反映射吞掉的待办数、跨会话今日纪要带入率。
- 回滚：全部靠参数关闭；数据不删，作废旧条仍可深查。

## 五、顺序与理由

1. P1 先量基线（上一回没量就改，改了个不响的）。
2. P2 先于 P3：注入端不动写入，风险最小，且研究说「旧条退场」是收益最大的一步。
3. P3 并行准备 dry-run，等 P2 验证出效果再动写入。
4. P4 独立于 P2/P3，可并行做 dryRun 评估。
5. P5 贯穿每步，回放集作为总验收。
