# 写入路由 v6 · 提升方案（代码级）

> 2026-11-04 · 小汐
> 对象：`src/modules/gate.js`（写入路由）/ `memory.js`（冲突检测）/ `vector.js`（向量通道）
> 基准：工作区数据副本 `_tmp_memdb_copy.db`（2059 条活跃记忆）+ 本机 bge-m3（1024 维，Ollama 已就绪）

---

## 0. 一句话结论

写入路由现在不是「四级门控」坏了，是**其中三级在这份数据上几乎不触发**：

| 路由 | 设计 | 实测（2059 条活跃记忆） |
|---|---|---|
| merge（同义合并） | 字面 ≥0.92 / 同实体 ≥0.80 | 8522 对同实体句对里，字面 ≥0.92 的只有 **2 对（0.02%）** |
| update（同 key 改写） | 同 `fact_key` 原地改写 | 502 个 key，**501 个只出现 1 次**；「同 key 新件 supersede」实际触发 0 次 |
| conflict（矛盾） | 字面 ≥0.50 + 极性翻转 | 2330 次写入只开了 **14 张**冲突卡，其中还有同义句被误判成矛盾的 |
| new（新增） | 其余 | 占绝对多数 |

所以「同一件事换三种说法认不出」不是感觉，是**字面阈值在这批语料上的召回接近 0**：抽取出来的句子是「用户希望…」「用户此前问过…」这种自由转述，换个说法后字面交集就掉到 0.2–0.4，永远进不了 0.92。

## 1. 代码断点（带行号）

### 1.1 相似度是纯字符集，连二元组都没有

`gate.js:35-47`

```js
function charSet(text) {
  return new Set(String(text || '').match(/[\u4e00-\u9fff]|[a-zA-Z0-9]/g) || [])
}
export function similarity(a, b) { /* 单字 Jaccard */ }
```

- 只比 **单字集合**，语序、词形都不参与；
- `memory.js:40-45` 的 `sim()` 是同一套逻辑的第二个副本（分母写法不同，等价）；
- `contradict.js:28-35` 是第三个副本；
- `sangguan/sim.js:37` 已经有更好的 `lexicalSim = 单字 Jaccard 与二元组 Dice 的平均`，**但写入门控没用它**；
- `fingerprint.js` 的 256 维哈希向量（1-gram + 2-gram、log 频次、L2 归一）也已在检索侧使用，**写入门控同样没接**。

一份数据，四套相似度，写法各不同——这是第一处该收口的地方。

### 1.2 向量通道：表是活的，写入是死的

`vector.js` 注释写「记忆向量在写入后 / 回填时算好」，实际：

- `writeVector` 只在 `backfillVectors` 内部被调用（`vector.js:121`）；
- `backfillVectors` 在全仓库只有一个调用者：**手动脚本** `scripts/backfill-vectors.mjs`；
- `addMemory`（`memory.js:165-293`）里**没有任何 embed 调用**；
- 实测：`memory_vec` 698 条，写入日期全部是 10-30 / 10-31 / 11-01（回填脚本跑的），**11-02 以后新写的约 1300 条记忆，向量为 0**；
- `fix-plan-v1.md:91` 的 P2.3 写着「落库成功后异步 embed + `writeVector`」——**计划有、代码没有**。

后果：`retrieve.js:366` 的 `loadVectors` 只读到 33.9% 的记忆；`vector_index.js:142` 的 `minCoverage = 0.3` 刚好被这 33.9% 骗过，向量通道处在「以为开着、其实只覆盖三分之一」的假性开启状态。

### 1.3 `fact_key` 不是槽位，是句子标签

`memory.js:124-163` 的 supersede 规则依赖「同 key」，但实测 502 个 key 里 501 个是唯一的：

- `用户.表达偏好.人话`
- `记忆系统.旧事实覆盖`
- `用户.方案.取舍`

这是**对这句话的自由描述**，不是「实体 + 属性」的规范槽位。同一个槽位明天换个措辞，key 就变了，supersede 永远不打。所以「同 key 新件默认 supersede」这条规则目前是装饰品。

### 1.4 冲突判定会把同义句判成矛盾

实测一条 `conflicts.evidence`：

```
a: 用户要求开发时按步骤推进，每完成一步先做模拟测试并修复 bug，确认完善后再进入下一步。
b: 用户要求实现功能时按步骤推进，每完成一步先模拟测试、找 bug、修 bug，确认无误后才进入下一步。
similarity: 0.651  via: polarity  risk: low
```

两句是同一件事的不同说法，却因为「字面 ≥0.5 + 一边带否定词」被开了冲突卡（low，两条都留）。11-02 有 10 张 `conflict_superseded` 卡，基本都是这一档。**低相似度不只漏合并，还会制造伪冲突。**

### 1.5 决策不可回放

`applyWrite` 只在 merge / conflict / stale 时写事件；判成 `new` 的原因（top1 是谁、分多少、为什么没过线）**不落盘**。半年后想回答「这条为什么没并进旧条」，只能靠猜。

## 2. 外部参考

### 2.1 MELD（arXiv:2608.16357，2026-08 预印本，未经同行评审）

它的写入裁决正好是五结果，每一条都对得上你的痛点：

- **insert / merge / relate / conflict / reject** —— 比你多一个 `relate`（相关但不同件：只连边、不合并、不新增）。你现在的「相近但不确定」直接 `new` 且不建边，等于把这个信号丢了。
- **三信号**：`claim-key identity` + `embedding similarity` + `NLI verdict`；
- **层级判定而非裸阈值**：key 完全相等 → 直接 merge；key 不同才退到 embedding + θ_merge；再被 context / authority / freshness 门控；
- **矛盾用「相关地板 σ_lo」而不是合并阈值**：词法差得远但语义相关的矛盾（σ ∈ [σ_lo, θ_merge)）要**浮出来**，不能 drop，也不能 merge；
- **阈值离线校准**，在 held-out 句对上选，报敏感性而不是声称最优；实测 false-merge 1.3%、AUC 0.968。

来源：[MELD 摘要](https://arxiv.org/abs/2608.16357)

### 2.2 Mem0 v3：写时从「改写」退到「只增不改」

Mem0 v3 的写入管线是 `EXTRACTION → DEDUPLICATION(MD5 精确去重) → STORAGE`，明确 **ADD-only**，不再在写入时做 UPDATE/DELETE，理由是改写容易误伤；事实变化时两个版本都留，靠时间戳区分。

这对你的方案是个反向约束：**不要一上来就把 update 做成自动改写**。先修「结构信号」和「可回放」，再谈自动 supersede。

来源：[Mem0 Platform Architecture](https://raw.githubusercontent.com/mem0ai/mem0/main/skills/mem0/references/architecture.md)

### 2.3 bge-m3 的阈值不能照搬

中文短句上，bge-m3 的余弦基线偏高：实测同实体随机句对里 71% 落在 0.5–0.7，只有 0.3% 过 0.85。所以「同义改写 0.7-0.85」这种博客口径只能当起点，**必须用你自己的句对校准**——这正好就是你要补的那块。

## 3. 方案 v6

> **与 v5 的职责边界（先划清，不然两份文档会互相打架）**
>
> | | v5（时态/六库） | v6（写入路由） |
> |---|---|---|
> | 回答的问题 | 这条记忆「旧了没有」、注入时怎么把时间说出来 | 这条新记忆「是不是同一件事」，该并、该改、该开冲突还是该新增 |
> | 判新旧 | 槽位 key（确定性）+ 时间 + v5 阶段 B 的收紧规则 | **不判**。v6 只产出「候选对」，新旧仍由 v5 的时间闸裁决 |
> | 用不用相似度 | 不用于挤出（论文 cosine 判新旧 AUROC 0.59，只配做标注） | 用于「是否同一句」的合并/冲突/连边，**不用于「谁过期」** |
> | 共享的落点 | `memory.stale_pair_seen`（v5 阶段 B 补 targetType/score，为回放攒样本） | `memory.write_decision`，**同一套 evidence schema**，回放集复用 v5 的 104 对 |

一句话：**v5 决定「旧的那条该怎么说」，v6 决定「新的这条该不该写」。** 两边都要用 `fact_key`，但 v5 管它的身份，v6 管它的形态。

### L0 · 槽位 key 只做「形态归一」，不扩覆盖（与 v5 阶段 A 对齐）

v5 已经拿数据判过：844 条带 key 的条目里只有约 300 条是真槽位（fact/appraisal），反思/情景的 key 是给摘要句硬编的编号——**「提升 key 覆盖率」这条路要停**（`记忆时态-六库适配计划-v5.md` §0.2 / D2）。

所以 v6 不新造 key，只做两件事：

1. **消费 v5 阶段 A 的 `isSlotKeyRow`**：只有 `slot=true` 的 key（fact/appraisal 且 key 非空）才允许进「同槽位」分支；反思/情景的 key 只进 FTS，不参与任何时态或合并判定；
2. **对已经是 slot 的 key 做形态归一**：把同义 key 并成一个，例如 `开发流程.分步测试` / `开发流程.分步测试偏好` / `开发流程.分步测试修复` → `开发流程.分步测试`。不动 enrich、不动 FTS、不清任何现有 key。

`decideWrite` 里 key 相等只升到「强信号」，**不单独握自动 supersede 权**；自动改写仍要过 v5 阶段 B 的时间闸与收紧规则。这一条和 v5 是接力关系，不是替代关系：v5 先给 key 分身份，v6 才在真槽位上归一形态。

现状是自由文本 key，同一个槽位换个措辞 key 就变，这是「同 key supersede 实测触发 0 次」的直接原因；但解法是**收紧身份 + 归一形态**，不是提高覆盖率。

### L1 · 收口相似度：字面层先融合

新增 `src/modules/sim.js`（或直接复用 `sangguan/sim.js` 的 `lexicalSim`），写入门控只调一个函数：

```js
score = 0.5 * charJaccard + 0.5 * bigramDice   // 与 sangguan/sim.js:37 一致
```

- 顺带修掉 `gate.similarity` 没有大小写归一、没有去标点的问题（`sim.js:6` 的 `norm` 已经做了）；
- 二元组能救「喝咖啡不加糖 / 不加糖喝咖啡」这类语序变化，零延迟、零依赖；
- `contradict.js` 的 `jaccard` 一并换成同一个函数，避免第三套口径。

### L2 · 语义层：写入时同步向量，检索时消费

这是「把接口接上」的最小闭环：

1. `addMemory` 事务提交后，异步调 `embedText(safe)` + `writeVector(db, aid, mid, vec)`，失败静默、不阻塞返回；
2. `backfillVectors` 挂到夜巡（`tick` 里加一步，`limit: 50`），补齐历史缺口；
3. `decideWrite` 的候选集先按 L1 字面分取 top-20，**只对这 20 条**算余弦（它们的向量从 `memory_vec` 读；没有向量的跳过并标记 `vec:null`）；
4. 融合分：`S = max(lexical, 0.7 * cosine + 0.3 * lexical)`，并把 `sameEntity` 的加分从 +0.08 降到 +0.03（实测同实体 ≠ 同一件事：123 条那个大实体里大部分句对余弦只有 0.5–0.7）；
5. 写入路径的 embed 超时给 200–300ms（不是 800ms），超时就只用字面分——**宁可不语义，不能卡写入**。

延迟预算：本机 bge-m3 单句约 30–80ms，候选 20 条可批量一次算完；实测 491 句批量 embed 约 40 秒（≈80ms/句），写入时只 embed 新句 1 条，可接受。

### L3 · 灰区判官：只在 [σ_lo, θ_merge) 里问一次

向量分落在灰区（比如 0.78–0.90）时，调一次**宿主小模型**做三分类：

```
这两句话是不是在说同一件事？
A. 同一件事（合并） B. 同一件事但互相矛盾（冲突） C. 两件事（新增/连边）
```

- 只在灰区调用，实测灰区比例很低（同实体对里 0.85–0.9 只有 1 对）；
- 结果按 `(min(id), max(id))` 缓存，避免同一对反复问；
- 超时 1.5s，失败就退回「新增 + 建边」，不做破坏性合并。

这一步替代不了 L2，但能把「换三种说法」的最后一档（同义不同词）补上——embedding 认得出「像」，NLI 才认得出「是」。

### L4 · 五结果 + 可回放

`decideWrite` 的返回值从 4 种扩到 5 种，并**每次都落一条决策日志**（不是只在 merge/conflict 时）：

```js
// events: memory.write_decision
{ action, score: {lexical, cosine, key, entity}, top1_id, reason, threshold_version }
```

- `relate`：语义在 0.55–τ_rel 且 top1 同实体 → 建 `memory_links`（`related`），不合并、不新增；
- `evidence` 里存完整信号向量，冲突卡和合并都能 replay；
- 阈值改动必须在日志里带 `threshold_version`，方便事后对账（「改完之后误合并多了没有」）；
- **事件 schema 与 v5 阶段 B 共用**：v5 要给 `memory.stale_pair_seen` 补 `targetType` / `score`，v6 的 `write_decision` 用同一组字段，回放集直接复用 v5 阶段 F 的 104 对，不另起一套口径。

## 4. 阈值校准（补上「没有人工标注」）

现在的问题是：0.92 / 0.80 / 0.50 是拍的。做法：

1. **造 200–300 对句对**：从真实库分层抽
   - 正例（同一件事不同说法）：同 key、同实体高余弦、同一主题的相邻条目；
   - 负例：同实体但不同事、随机跨实体；
   - 冲突例：已知 14 张冲突卡 + 人工补 20 对；
   - 每对三个标签：`same / conflict / different`，两人标一次算 Cohen's κ。
2. **画 PR 曲线**，不拍单点：横轴「误合并率 ≤ 0.5%」的预算，纵轴取召回；`θ_merge` 取该预算下召回最高的点。
3. **冲突用两档阈值**：`σ_lo`（相关地板，扫 0.55–0.75）和 `θ_conflict`（矛盾判定），分开校准——MELD 的做法就是「矛盾不必表面接近」。
4. **线上先 shadow**：新路由只记 `write_decision`，不真的改库；跑 3 天，对比新旧决策差异（多少条从 new 变成 merge/update），人工抽 30 条复核，再开写。
5. 校准脚本放 `scripts/calibrate-write-route.mjs`，输出 json（阈值 + 数据集 hash + 指标），进 `docs/`。

指标口径（写入侧最重要的不是准确率，是三类错误）：

| 指标 | 含义 | 目标 |
|---|---|---|
| false-merge | 两件不同的事被并了 | ≤0.5% |
| missed-merge | 同一件事换说法写成两条 | 越低越好，先测基线 |
| conflict-precision | 开的冲突卡里真矛盾的占比 | ≥0.9 |
| conflict-recall | 已知矛盾里被判出来的占比 | 用 34 对样本测 |

## 5. 分期与验收

| 期 | 内容 | 文件 | 验收 |
|---|---|---|---|
| P0（半天） | 写入时同步向量 + 夜巡回填 + 检索侧消费 | `memory.js`、`vector.js`、夜巡 | `memory_vec / active ≥ 0.9`；`vectorStats` 能报覆盖率 |
| P1（半天） | 收口 L1 字面融合 + 实体加分下调 | `gate.js`、`contradict.js` | 同义改写对在 λ=0.92 下召回从 ~0 提到可测 |
| P2（1 天） | 五结果 + 决策日志 + relate | `gate.js` | 事件表能看到每次写入的完整信号 |
| P3（1–2 天，**必须在 v5 阶段 A 之后**） | slot key 形态归一（不扩覆盖、不动反思/情景 key） | `passport.js`、`entities.js`、`gate.js` | 真槽位（fact/appraisal）里同 key 多件的比例 ≥10%；反思/情景的 key 参与率为 0 |
| P4（1–2 天） | gold set + PR 校准 + shadow 上线；**回放集复用 v5 阶段 F 的 104 对** | `scripts/`、`docs/` | 误合并 ≤0.5%，冲突 precision ≥0.9 |

顺序上只有一处硬依赖：**P3 必须在 v5 阶段 A（key 分身份）落地之后**，否则会把反思的假 key 当槽位归一。P0 / P1 / P2 / P4 都与 v5 无依赖，可以先跑。

回滚：L2 全部走开关（`memory.write.vector: off|shadow|on`），L4 日志只增不改，L3 超时即降级——任何一期出问题都能退回纯字面路由。

## 6. 风险

- **向量维度漂移**：`memory_vec` 现在全是 1024 维（bge-m3）；换模型必须整表重算，`vector.js` 里已按 `dim` 过滤，但要加一条「dim 变更 → 全量重 embed」的巡检。
- **写入延迟**：本地 Ollama 冷启动可能 1s+，所以必须异步 + 超时降级，不能把 embed 放进事务。
- **短句**：<8 字不做语义判定（现在 <4 字丢弃，8 字以下也建议只走字面）。
- **同实体先验**：实测同实体 ≠ 同一件事，+0.08 的加分是「用实体当相似度替身」的旧债，要降。
