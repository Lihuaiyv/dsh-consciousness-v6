# 记忆时态整体修复 v4：四种时间与「注入行护照」

> 换角度重查。v3 从「六个库」往里看；v4 从「一条记忆身上的时间」往外看。
> 目标不变：任何一次「现在怎样」的判断，都不能拿旧说法当现状。

## 一、新角度：一条记忆身上有五种时间/来历

1. **发生时间**（occurred_at）：这件事什么时候真的发生。
2. **记录时间**（recorded_at）：我什么时候把它写下来。
3. **生效时间**（valid_from）：它从什么时候开始算数。
4. **失效时间**（invalid_at）：它从什么时候开始不算数。
5. **来源**（derived_from）：它从哪来的（哪句话 / 哪段纪要 / 哪次对话）。

「把过去当现在」的每一次，都是这五个里至少缺一个，或者被某个模块擅自改掉了一个。

## 二、六库 × 五字段对照

| 层 | occurred | recorded | valid_from | invalid_at | derived_from |
|---|---|---|---|---|---|
| T1 事实 | 部分（timeline.valid_from） | 有（created_at） | 有（timeline） | 有 | 有（fact_archive 的 episode/turn） |
| T2 纪要 | 有（start_at/end_at） | 有 | **无** | **无** | 有（session_id） |
| T3 日记 | 有（day） | 有 | **无** | **无** | 部分（refs） |
| T4 原文/存根 | 约等于 created_at | 有 | **无** | **无** | 有（turn_id / payload） |
| 索引 | 有 | 有 | 有 | 有 | 有 |

一句话：**「失效」只活在 T1 和索引里；T2/T3/T4 根本没有失效这个概念，却在注入时和 T1 平权。**

## 三、管道审计：谁在替记忆做时态判断（13 个漏点）

- **写入**：`ingest` 的摘要把「大概/听说」写成确定（features.js）；`gate` 的 UPDATE 只写 REVISE、不写「取代」，注入侧看不到（gate.js）；`flip_policy=conflict` 拍板前新旧并存；`consolidate` 跨话题 top10 压缩、吞待办；`fade` 删细节不删错结论。
- **存储**：T2/T3/T4 没有 `invalid_at`（db.js 表定义）。
- **读取**：S1 只含 T1+T3，T2 要 S2/S3 才进（retrieve.js / memory-layers §11）；`deepRecall`、`pulse.pendingSurface`、`self_repeat` 都不看「是否已过时」。
- **装箱**：`pack.dedupe` 只按文本相似去重，不按「同主题新旧」（pack.js）；配额丢弃只看分区，不看护照。
- **注入**：时间/来源标签是**可关的装饰**（`memory.inject.age` / `provenance`），关掉就回到「一句话裸奔」；`bridge` 只取一条纪要；`selfnote` 只读最近三天、不核后来；`asof` 只查 T1 的当时版本，T2/T3/T4 没有「当时」。

## 四、新方案：注入行护照（不建表）

在注入拼装时，给每一行申领一张临时护照，五个字段都从现有数据算：

- `occurred_at`：T1 取 timeline.valid_from 或 created_at；T2 取 start_at；T3 取 day；T4 取 created_at。
- `recorded_at`：都有。
- `valid_until`：T1 取 invalid_at / 后续取代；T2/T3/T4 取「之后同主题有更晚记录」的日期（用 episode/day/session 外部键查）。
- `derived_from`：T1 用 fact_archive 的 episode_id/turn_id；T2 用 session_id/day；T3 用 day；T4 用 turn_id。

## 五、为什么这版逻辑闭合

- **输入**：每条注入行必须能回答三问——什么时候的、现在还作数吗、从哪来；答不上来就不该当现状用。
- **处理**：失效从「T1 的列」变成「注入行的护照字段」，所以 T2/T3/T4 也能有失效——这是 v3 没做到的。
- **输出**：旧条要么被标失效，要么装不进去；新条带着何时/何来。
- **观测**：护照覆盖率 = 100% 才算过；抽查旧条，看「后来还有更新的」有没有漏。

## 六、落地顺序

1. **V4-0 只读预览**：给现有注入行算护照，dry-run 打印，不写入。
2. **V4-1 T1 接护照**：valid_from / invalid_at 从 timeline 取，先只做「失效标注」。
3. **V4-2 跨库失效**：T2/T3/T4 查「之后有没有更晚的同主题记录」，用外部键；命中标「之后有新记录」。
4. **V4-3 装箱门槛**：pack 拒绝无护照行；失效优先丢。
5. **V4-4 写侧补时间**：gate UPDATE 写「取代」语义；状态词保护；`flip_policy` 与过时分工。
6. **V4-5 整理侧管手**：fade 不碰状态词/否定词；reflect 保留 hedge、先聚类。

验收：任意注入行三问可答；任意「被取代」能回链到 T2/T3/T4 的证据；真实库抽查 20 条旧条，错标 < 10%。

## 七、与 v2 / v3 的关系

- v2 是「分阶段补丁」，v3 是「六库分区 + 仲裁」，v4 是「四时间 + 护照」。
- v4 不否定 v3 的跨库查询，而是给它一个统一的产物：**护照**。v3 的 A1（跨库仲裁）在这里变成「给 T2/T3/T4 的行补 valid_until」。
- 回滚：护照有开关；关掉即回到现状；不新增表、不改 schema、不上图库。

## 八、风险与取舍

- **注入变长**：每行 +12–16 字，只在旧/有更新的行上显示；新条不显示。
- **跨库查询慢**：最多候选条数 × 1 次；用 episode/day/session 索引。
- **误判**：T2/T3 的「更新」要强命中同主题；不确定就不标，宁可少标。
- **不做**：不建新表、不改 schema、不重写 T2/T3/T4、不引图数据库。
