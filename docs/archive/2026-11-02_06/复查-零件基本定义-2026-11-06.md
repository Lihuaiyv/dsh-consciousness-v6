## 一、这次按五条查

1. **可换三样齐**：登记 + 考卷 + 回退点。
2. **考卷能单跑、能打假**：单独跑得起来；塞过坏版本、被拦过。
3. **输入输出说得出，出入口在自己身上**：入口、判决、落库都在登记的文件里，不靠宿主文件替它交。
4. **不粘连**：不 SQL 别人的表、不 import 别人的内部文件、不靠副作用。
5. **表归它、写权单点；界桩真扫到它**：ownership 名单里有它，`check-ownership` / `dep-graph` 看得见它。

## 三、五条真缺口（按该修的先后）

### 1. 写权没收口：主动开口一个人写着三张表

- `src/parts/speak/index.js:89` 直接 `INSERT INTO proactive`，而 `ownership.js` 的 `WRITES.memory` 里写着 `proactive` 归 memory；`src/modules/conflict_ask.js` 也在写同一张表。
- `src/parts/speak/store.js` 写 `proactive_decisions` / `proactive_stats`，这两张表在 `ownership.js` 里只挂在 host 的 tables 下，没有 `WRITES` 声明——**等于没人认领**。
- 结果：`proactive` 有 memory、speak 两个业务写手（外加 host/ops 搬库），写权单点不成立。
- 为什么界桩没报红：`src/parts/speak/*` 八个文件根本不在任何域的 files 里，`check-ownership.mjs:36-39` 只扫登记过的文件，直接跳过了它们。

### 2. 半个零件在 `features.js`：四个零件共用一份 2439 行的宿主文件

- `features.js` 现在 2439 行。主动开口、情绪评价、记忆写入闸、注入四个零件的 `files` 里都列着它。
- 里面确有真逻辑：`clampInjection`（`features.js:2086`）是注入的硬上限判决；`features.js:526` 是写入闸的落库；`features.js:1011`、`1961` 是情绪评价的应用段。
- 后果：换注入要 checkout `features.js`，而主动开口也要 checkout 同一个文件——两个零件不能各自独立换。这跟上次「内容门别单独立零件」是同一类问题，只是这次没人在 `files` 里藏，是明着写上去的。

### 3. 界桩没盖住零件体内（就是计划第一笔账）

- `check-ownership` 只扫 OWNERSHIP 里登记的文件；`src/parts/speak/*`（8）、`src/modules/memory_source.js`、`src/algo/reldyn.js`、`src/algo/desensitize.js`、`src/algo/expression.js`、`src/modules/expression_state.js`、`index.js`、`client.js`——**16 个零件文件在名单外**。
- `dep-graph.mjs:15` 还只 `readdir src/modules` 顶层，`parts/`、`algo/`、子目录都不进图；所以 `parts/speak/trigger.js → modules/loops.js` 这类跨零件依赖没有环检查。
- `check-parts` 只查：文件存在、考卷能跑且分数对、名字/归属/入口非空、可换要有 `rollback.pointer` 字符串、`src/parts/*` 不反向 import `features.js`。**不查**：tag 真存在、入口函数真存在、说明页在不在、文件归不归 ownership、有没有打假。

### 4. 计划里说好的三笔技术账还没落

- 计划第 2 笔：flags 收归 kernel。现在 `judge.js:80/86`、`budget.js:10/15`、`prefs.js:17/22` 各开一把锁，还是三份。
- 计划第 3 笔：开口别直读记忆表。`judge.js:144/148` 仍在直接 `COUNT(*) FROM memory_items`。
- 计划第 4 笔：sangguan 的环。`fast.js:497` 还在调 `inject.js:185` 的 `noteAskSpoken`，环没拆。

### 5. 册子和页面对不上（四处小账）

- `parts.js:30` 主动开口写 `status: '在用'`，但它登记、考卷 21/21、回退点 `speak-before-swap` 三样齐，按定义应是「可换」。
- `零件-开环.md:5` 顶部写「考卷（56/56）」，同一页第 150 行和册子里都是 63/63——一页里两个数。
- 十个零件的 `assert` 全是 `null`：迁移断言一条都没有。现在没换过，不算翻车；但「旧数据能读、能切回」这半句还是空的。
- 打假 16 个用例盖了九个零件，**主动开口没被塞过坏版本**。21 道卷子从没证明「拦得住」。

## 四、不算缺口的三件（免得白改）

1. **没有 `src/parts/<id>/` 目录不算错**。定义是「能单独喂数据测」，不是「必须有目录」；八个零件散在 `modules/`、`algo/` 里，只要文件边界清楚、表归它，就成立。
2. **`swaps` 空不算错**。可换 ≠ 已换；十件里只有主动开口真换过三次，其余没换过就该空着。
3. **域 ≠ 零件不算错**。衰减和分层记忆共用 layers 域、召回和检索骨架构共用 `retrieve.js`，术语表写明了域可以大于零件；只有「同一个文件被两个零件都列进 files」才算粘连。

## 五、建议顺序（一次一个，不抢跑）

1. 先补两行事实（不碰代码）：`parts.js` 主动开口改回「可换」；`零件-开环.md:5` 改 63/63。
2. 再让机器看得见（计划第一笔账）：把 16 个零件文件收进 ownership（纯函数的挂只读域也行）；`dep-graph` 扩到全 `src`。这一步只为「照出来」，不改行为。
3. 写权归口：`proactive_decisions` / `proactive_stats` 收成主动开口自己的表；`proactive` 要么只读、要么走记忆域公开函数。
4. `features.js` 拆半：注入的 `clampInjection`、写入闸的落库车道、情绪评价的应用段——最重，放最后，一次搬一个，每次先跑对应考卷和全量。
5. 给主动开口补一张打假，再谈「认人」。

> 这五步里，1、2、5 是「让事实和检查对齐」，3、4 才是动结构。前三步做完，下一件零件（认人）开起来才不用背着一堆看不见的账。
