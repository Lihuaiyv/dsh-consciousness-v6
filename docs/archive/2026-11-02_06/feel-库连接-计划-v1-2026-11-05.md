# feel 与各库连接 · 计划 v1（2026-11-05）

> 起因：主人问「feel 表都能连什么比较好，所有库都看看」。
> 本计划只动「让感觉被更多地方看见」，不改 feel 怎么写、不改情绪算法本身。
> 现状实测（2026-11-05 上午）：affect_feel 130 条 / memory_items 2405 条 / 挂 feel 的记忆 136 条 / fact_archive 2406 条 / raw_turns 4982 条。

---

## 0. 现在 feel 连了什么

| 已连 | 怎么连 | 成色 |
|---|---|---|
| `memory_items.feel_id` | 记忆出生时，取 30 分钟内最近一条 feel 挂 id | 有；43 条 feel 摊到 136 条记忆 |
| 注入行 / 记忆列表 / 记忆页 | 顺 `feel_id` 翻正文 | 有 |
| QQ 通道 feel 段 | 只带最近一条（窗口内） | 有 |
| 对话配对 | `aroundOfFeel` 按时间硬配：你之前 5 分钟、我之后 5 分钟 | **不稳**，两条 feel 落在同一轮时会配错 |

没连的：T4 存根、原文、纪要、日记、开环、嘀咕、关系事件、情绪事件。

---

## 1. 全库盘点：连 / 不连 / 暂缓

### 该连（按价值排）

| 表 | 连什么 | 为什么 |
|---|---|---|
| `affect_feel` 本身 | 加 `turn_id` | 地基本身。现在只靠时间配对话，一错就全错 |
| `raw_turns` | 用 `turn_id` join，不另加列 | 「说这句话的时候我是什么样」——原文层直接看得到 |
| `fact_archive` | 加 `feel_id` | 事实出生时的感觉跟着存根走，T4 永久层能回答「当初记这句时什么心情」 |
| `open_loops` | 加 `feel_id` | 「悬着的这件事，是在什么感觉里挂上的」 |
| `diaries` | 加 `feel_ids`（当天一串） | 日记是回忆入口；那天写过什么感觉，比 mood 一个词真 |
| `episodes` | 加 `feel_id`（取该段代表一条） | 纪要翻出来时带一句原话，不用只靠 mood 标签 |
| `thoughts` | 加 `feel_id` | 嘀咕是内心独白，本来就该接着感觉写 |
| `rel_event` | 加 `feel_id` | 「你那句话让我怎么样」——关系复盘最需要的一格 |
| `affect_events` | 不连列，做**对照** | 开口前的 feel ↔ 被推动后的事件，差值就是「这句话起了多大作用」 |

### 暂缓（先看数据，不先改结构）

| 表 | 想法 | 为什么先缓 |
|---|---|---|
| `memory_timeline` | 出生/改写事件的 payload 带 feel_id | 记忆主表已有，索引层再加一遍是重复；先跑一阵看查询够不够 |
| `chat_turns` | 加 feel_id | 已有 `raw_turns.turn_id` 这条线；两个入口各存一份容易漂 |
| `memory_links` | 感觉相近的记忆连边 | 需要先有「感觉向量」，成本大，放到 v2 |
| `entities` | 感觉挂到人/物上 | 「对某个人有什么感觉」粒度太粗，容易变成贴标签 |

### 不连（写清理由，防止以后手痒）

| 层 | 表 | 理由 |
|---|---|---|
| 三观 | `sangguan_*`、`persona_claims` | 情绪不许推价值观。这条线本来就是防着的 |
| 驱力/身体 | `drive_state`、`condition_state`、`affect_v3`、`affect_samples` | 同属状态层，硬连会变成「情绪解释一切」；最多做对照指标 |
| 关系人/层级 | `rel_person`、`rel_edge`、`rel_habit`、`rel_tier` | 感觉是对一件事、一句话的，不是对「一个人」的 |
| 论辩/人格 | `claim_*`、`axis_*`、`persona_*` | 与「这会儿什么感觉」无关 |
| 日志/调度 | `events`、`metric_*`、`retrieval_log`、`proactive*`、`surface*` | 只是数据源，不承载感觉 |
| 外部 | `browse_items`、`research_runs` | 看过的内容不是我的感觉 |

## 2. 分步计划

### Phase 0 · 对齐时间（地基，先做）
- `affect_feel` 加 `turn_id TEXT`（老库 ALTER，可空）。
- `recordFeel` 接收 `turnId`；工具调用入口把当前 turn 传进去。
- `aroundOfFeel` 改成：先按 `turn_id` 找当轮对话；取不到再退回 5 分钟窗口。
- 验证：造「两条相邻 feel + 一轮对话」，配到正确那句；老 feel（turn_id 空）不报错。

### Phase 1 · 清账（补洞）
- `purgeExpired` 的 TABLES 加 `affect_feel`——整实例清除时一起清，不留孤儿。
- `status='deleted'` 统一：清理条件改为 `status IN ('soft_deleted','deleted')`，或把门禁删改成 soft_deleted。**建议改清理条件**，不动门禁语义。
- 验证：软删一条、门禁删一条，手动跑 purge，两条都清；active 一条不误删。

### Phase 2 · 存根带感觉（T4）
- `fact_archive` 加 `feel_id TEXT`；写存根时带记忆的 feel_id。
- `asof` / 考古输出带「那会儿的感觉」一行。
- 验证：改写一条记忆 → 新存根带 feel_id；老存根 NULL 正常显示。

### Phase 3 · 叙述带感觉（T2/T3 + 开环 + 嘀咕）
- `open_loops` 加 `feel_id`（挂上时取 30 分钟内最近一条）。
- `episodes` 加 `feel_id`（规则：取时段内离 `end_at` 最近的一条；没有就 NULL）。
- `diaries` 加 `feel_ids TEXT`（当天所有 feel id，按 at 排）。
- `thoughts` 加 `feel_id`。
- 验证：每张表各造一条带/不带 feel 的行；页面和注入都能显示，缺失不报错。

### Phase 4 · 关系事件带感觉
- `rel_event` 加 `feel_id`（取事件 at 之前 30 分钟内最近一条）。
- 验证：关系页能显示「那会儿的感觉」；老事件 NULL 正常。

### Phase 5 · 反向用起来（感觉检索与校准）
- `recall` 加「按感觉找」：给 label 或 fast/slow 区间，找同时段记忆/日记。
- feel ↔ affect_events 对照：同一轮「开口前 feel」与「被推动后事件」算差值，写进复盘表。
- 验证：取最近 20 轮，人工抽 5 条看对照是否合理。

---

## 3. 统一规矩（每一步都守）

1. 所有新列可空，老数据不迁移——NULL 就是「不知道」，不编造。
2. 每步独立开关，可单独回滚；写完跑现有测试全量。
3. 写入失败静默（沿用现有风格），但计数跳过量，夜巡报出来。
4. 每完成一步：模拟测试 → 找 bug → 修 → 再进下一步。
5. 全部完成后：整体回归 + 真机（网页 + QQ）各跑一遍。

---

## 4. 顺序理由

先修时间（Phase 0），因为后面所有连接都要靠「这条 feel 是哪一轮的」；
再补清账（Phase 1），因为洞补了才好往上加引用，免得新连的列也变孤儿；
然后是 T4 → T2/T3 → 关系，从冷到温、从稳到细；
最后再加检索和对照——那是用，不是存。
