# 记忆时态 · 两个小实验的结果

> 时间：2026-11-04 夜
> 目的：验证两条「还没试过」的路——让模型重读、用实体表当锚。
> 结论：**两条都没成，但失败原因指向同一个地方。**

---

## 一、实验 1：让模型重读

**做法**：拿两条候选记忆，问模型「这是同一件事的前后两个阶段吗」。

**结果**：**跑不了。**

```
model.capabilities() = { appraise:false, extract:false, summarize:false,
                         reply:false, complete:false, chat:false, embed:true }
```

插件里只有 `embed` 可用，没有 `complete`。模型能力由 DSH 宿主提供，插件进程里没配凭据。

**这不是方法死了，是环境里没有这个能力。** 要做得在宿主侧接模型通道。

---

## 二、实验 2：用实体表当锚

**做法**：如果两条记忆指向同一个实体，那它们更可能是同一件事，比字面相似可靠。

**结果**：**实体表不是实体表。**

```
entities 条数：811
kind 分布：{"thing": 782}     ← 全是同一个 kind
命中次数前 8：
  用户 221 / 继续 95 / 整体 77 / 测试 48 / 好了 35 / 主人 33 / 你能实现吗 20 / 他的 19
```

这些是**高频词**，不是实体。「继续」「好了」「整体」「你能实现吗」——没有任何一条能当锚。

有 `entity_id` 的记忆确实很多（1812 / 2171 = 83.5%），但锚的是这些词。覆盖率是虚的。

抽样：
```
ent_009bdbcdf1 同时挂着：
  貔貅元素的设定 / 形象画得可爱 / 偏好颜文字 / 文字表达可爱
```
四件不同的事，挂在同一个「实体」上。

**结论：实体锚不能用。** 和 `episodes.topics` 是同一个病。

---

## 三、顺带发现的第三件事：嵌入也不行

`embed` 是唯一可用的能力（1024 维，249ms/次）。顺手试了它能不能替 2-gram 判「同一件事」。

**40 对候选**（全部是现在被判成「同主题后面还有说法」的）：

```
原样余弦   : avg=0.740  std=0.109  min=0.526  max=0.953
剥模板后   : avg=0.712  std=0.092  min=0.521  max=0.896
```

剥模板（去掉「1. **事实**：」「**偏好**：」这些骨架）之后，平均降了 0.029，但**标准差也变小了**（0.109 → 0.092）——区分度不但没变好，反而更差。

致命样本：

| 旧 | 新 | 余弦 |
|---|---|---|
| 用户提到"小小"是自己的朋友 | 用户提到自己有个朋友叫小绿 | **0.867** |
| 用户询问检索算法效果，问有没有更好方案 | 用户关注检索算法表现，主动问有没有更好算法 | 0.953 |
| 两个角色登不进去 | 两个角色无法登录、会被弹回登录页 | 0.854 |

「小小」和「小绿」是两件完全不同的事，余弦 0.867；真正同一件事的两条，0.953。**分不开。**

原因不在模型，在语料：**所有反思摘要都用同一个模板写**（`1. **事实**：… 2. **偏好**：… 3. **边界**：…`）。骨架相同，所以语义差异被句式相似淹掉了。

（`memory_vec` 的覆盖率也只有 698 / 2154 = 32%。）

---

## 四、三个实验指向同一个病

| 基础设施 | 看起来 | 实际 |
|---|---|---|
| `episodes.topics` | 177 条全有主题 | 是正文的 2-gram 切片（「你还」「还挺」） |
| `entities` | 811 个实体，83.5% 记忆挂上了 | 是高频词（「继续」「好了」） |
| 反思摘要 | 结构清晰、信息完整 | 全是同一个模板，语义被淹没 |

**上面任何「判断同一性」的算法，输入都是这些。所以不管换 cosine、换模型、换实体，都算不准。**

这也解释了之前所有失败的真正原因：不是算法选错，是**输入本身是脏的**。

---

## 五、那怎么办：三条路，成本差很多

**路 1：修抽取层（贵，但根治）**

- 反思摘要别再套模板——让它写成自然段，或者干脆不写摘要、只存原话
- 实体提取换成真抽取（现在等于没做）
- `topics` 改成模型生成的主题词，或者直接删掉

三个里**第一个最值得做**：模板化摘要污染了 1127 条反思（占全库一半），是最主要的脏源。

**路 2：绕开文本，只用结构（便宜，但天花板低）**

只用「同一个 fact_key」「同一个 turn_id」「同一个 episode」这类**结构信号**判同一性——它们不依赖抽取质量，是确定性的。

代价：覆盖率就是那 39% 有 key 的 + 有 turn_id 的，剩下的永远判不了。

**路 3：问人（最便宜，最准，但只在有人时可行）**

就是之前说的 checkin。不判，问。

---

## 六、我的建议

**先做路 1 的第一项：让反思摘要脱模板。**

理由：
- 它是三个脏源里唯一「改一处、影响一半数据」的
- 它同时能救嵌入（去掉模板污染后，余弦可能就分得开了）
- 它不新增判断逻辑，只是把生成方式改掉

改完之后，**重跑这个实验**——如果「小小 vs 小绿」的余弦掉到 0.6 以下、真同一件事的还在 0.9，那嵌入这条路就通了，后面的判新旧才有基础。

如果改完还是分不开，那就老实走路 2 + 路 3，别再折腾算法。
