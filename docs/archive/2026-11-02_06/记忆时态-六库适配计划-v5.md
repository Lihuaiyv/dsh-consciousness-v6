# 记忆时态 · 六库适配计划 v5

> 上一版 v4 是「给记忆加双时态 + 护照 + 挤出」。这一版不改那个骨架，
> 改的是**用力方向**：把「判新旧」从主干降成 T1 层内的一个补丁，
> 把「六库粒度不同」当成主干。
>
> 写这一版的原因：动手前按真实库核了一遍，有三条判断被数据推翻（见 §0）。
> 每一条都在下面标了「原判断 → 实测」。

---

## 0. 被推翻的三条（先说坏消息）

### 0.1 「episodes.topics 可以当跨层锚」——错，它是垃圾

原判断：T2 的 177 条纪要全有 `topics` 字段，可以拿它跟 T1 的 fact_key 主题段做结构化对接。

实测抽样：

```
2026-11-04 | 还在不，有啥变化       | ["你还","还挺","哈哈"]
2026-11-04 | 现在看看有了吗         | ["陌生","生人","我是","被陌","人文","文咋"]
2026-11-04 | 咱们的记忆系统是不是… | ["整体","记忆","在的","计划","综合","没有"]
```

`topics` 是**正文的 2-gram 切片**，不是主题标签。拿它做锚 = 拿随机片段做锚，比 LIKE 还差。
**结论：跨层锚不能用 topics。** 详见 §4 阶段 D。

### 0.2 「844 条带 fact_key」——水分大，真槽位约 300 条

实测 type 分布：

| type | active 条数 | 带 key 条数 |
|---|---|---|
| reflection | 1195 | 208 |
| appraisal | 402 | 221 |
| fact | 302 | 275 |
| episode | 255 | 140 |
| **合计** | **2154** | **844** |

真「事实」（type=fact）只占 14%，其中 275 条有 key。剩下 **569 条 key 是打在反思/评价/情景上的**，正文长这样：

```
type=reflection  key=用户.反应.哇塞        text=1. **事实**：用户只说了"哇塞"，没有提供…
type=reflection  key=用户.情绪记录.测试    text=1. **事实**：用户在这段对话中只说了…
type=reflection  key=用户.指标回落.偏好    text=1. **事实**：用户注意到指标从上一句的 0.4…
```

这类 key 不是「主语.关系」的槽位，是给一段摘要句硬编的编号。
**结论：「提升 key 覆盖率」这条路要停。** 详见 §3 D2。

### 0.3 「确定性覆盖能退休 50 条」——实际约 10 组

22 组重复 key 的明细（type 组合）：

| 可退休（双方都是 fact/appraisal） | 不可（含 reflection/episode） |
|---|---|
| 开发流程.分步测试 (4) | 登录.故障 (reflection×3) |
| 渠道.QQ优先 (2) | 密码.偏好 (reflection×3) |
| 消息拆分.偏好 (2) | 解释偏好 / 解释.偏好 / 表达.偏好 |
| 开工.用语 (2) | 沟通.偏好 / 文档修改.确认 |
| 开发流程.整体回归测试 (2) | 协作偏好 / 协作偏好.自主闭环 |
| 开发流程.分步测试偏好 (2) | 偏好.自动生成 / 记忆备份.需求 |
| 开发流程.分步测试修复 (2) | 称呼.宝宝（含 episode） |
| 代码修改.谨慎偏好 (2) | 特效.偏好（含 reflection） |
| 交付.对比数据说明提升 (2) | 情绪记录类全部 |

**严格可退休：约 9–11 组，约 20 条。** 占全部活跃记忆 **不到 1%**。

所以论文那套「同主语同关系的值变了就退休」在我们库里是**一个小补丁，不是主干**。
它已经实现了（`memory.js:supersedeByKey`），而且收得比论文还紧（只 fact/appraisal、一次最多 5 条、不用 enrich 补的 key）——**不用重做，只要修它的入口**。

## 3. 五个诊断（决定计划形状）

### D1 主战场错位
论文治的是「一个事实库里的版本替换」。我们旧话冒充现状，量最大的是**T2/T3 的叙述**和 **T1 里的反思**——这两类没有「值」，只有「当时怎么想」。
**对症的不是退休，是带上日期说话。**

### D2 fact_key 提取器在制造假结构
它把「1. **事实**：用户只说了哇塞」压成 `用户.反应.哇塞`。
这类 key 进 `search_text` 对召回有用（不该删），但**不能用来判谁过期**。
`supersedeByKey` 已经按 type 挡住了一半（只 fact/appraisal），但 `passport.stampRow` 的 LIKE **没有 type 闸**——反思也能被标「有更新的说法」。
**结论：key 要分「检索 key」和「槽位 key」两种身份，现在混着。**

### D3 六库是粒度分层，不是版本链
T1 是提炼、T2 是一段话、T3 是一天、T4 是原话。
**不会因为有了 T1 的总结，就把 T4 的原话退休。** 跨层做取代是范畴错误。
跨层需要的是：**时间标注 + 向下指针**（这条出自哪句原话）。

### D4 挤出的两个来源不对称
`isStale` 认两种：`invalid`（确定性）、`topic`。
而 `topic` 里又混了两样：
- 同 fact_key（确定性，对）
- `isStalePair` 状态词对（"还没做好"→"做好了"，半确定）

论文实测 cosine 判新旧的 AUROC 只有 0.59。状态词对不是 cosine，但它同样是**文本模式猜测**，不该握「挤出」这个不可逆权限。

### D5 挤出之后账本失联
旧条被挤出，模型完全不知道「这儿还有旧版本」。
`asof` 能翻，但它是独立工具旁路，注入时没人提。
论文说「要旧值就翻账本」——我们账本有（T4 + fact_archive + timeline），**但没连到注入**。

### 阶段 A：key 分身份（检索 key ≠ 槽位 key）

**动机**：D2。现在 844 条 key 一视同仁，导致反思被当事实判新旧。

**改法（不动数据，只加判定）**
1. `src/modules/passport.js` 新增：

```js
const SLOT_TYPES = new Set(['fact', 'appraisal'])
export function isSlotKeyRow(row) {
  return !!row && SLOT_TYPES.has(String(row.type || '')) && !!String(row.fact_key || '').trim()
}
```

2. `stampRow` 的返回补 `slot: isSlotKeyRow(row)`。
3. `isStale`（passport.js:90）改成：

```js
export function isStale(db, aid, row) {
  if (!row) return false
  const s = stampRow(db, aid, row)
  if (s.source === 'invalid') return true          // 明确作废：任何类型都挤
  if (s.source !== 'topic') return false           // topic_weak / topic_state：只标不挤
  return s.slot                                    // 只有真槽位才能因「同 key 更新」被挤
}
```

4. `retrieval_log.memoryHealth` 增加 `key.by_type`（fact/appraisal/reflection/episode × 有 key 数）和 `slot_key` 计数。

**不做什么**：不清 fact_key、不改 enrich、不动 FTS。检索召回一点不受影响。

**验收**
- 单测：新增 `test/passport-slot.test.mjs`（≥6 条）
  - reflection 带 key 且后面有同主题新条 → `source=topic` 但 `isStale=false`
  - fact 同 key 新条 → `isStale=true`
  - invalid_at 非空 → `isStale=true`（不论 type）
- 基线对比：挤出条数应下降；护照条数基本不变（标还是标）

**风险**：反思条目在 S1 里可能重新露脸（本来被挤掉的）。
**兜底**：`memory.stale.eject` 可一键回 off；对比前后 S1 注入里反思占比。

### 阶段 B：挤出收紧（只留确定性）

**动机**：D4。状态词对不该握挤出权。

**改法**
1. `passport.js:81` 的 source 拆三档：

```js
const sameKey = row.fact_key && later.fact_key && row.fact_key === later.fact_key
const statePair = isStalePair(row.text, later.text)
out.source = sameKey ? 'topic_key' : (statePair ? 'topic_state' : 'topic_weak')
```

2. `isStale` 认 `invalid` / `topic_key`（已由阶段 A 的 slot 闸兜住），**不认 `topic_state`**。
3. `passportLine`（passport.js:149）的文案分档：
   - `topic_key` → 「（10-03 说的；10-27 起有更新的说法）」（原样）
   - `topic_state` → 「（10-03 说的；后来看到它已经做完了）」← 标出来，告诉模型「这是当时的进度」，但不挤
   - `topic_weak` → 维持现状（默认不进注入）
4. `gate.js` S4（`memory.write.stale_supersede`）**保持 off**，但把 `memory.stale_pair_seen` 事件补上 `targetType` 和 `score`，为阶段 F 的回放积累样本。

**验收**
- `test/stale-pair.test.mjs` 扩到含 source 三档（≥10 条）
- `test/eject.test.mjs` 断言 `topic_state` 不挤
- 基线对比：挤出 = invalid + topic_key 两类之和，且 topic_key 全部 slot

**风险**：明确「做完了」的旧条会重新进注入（只是带一句标注）。
**判断依据**：这正是论文「不删只标」的做法。若注入噪音变大，再考虑给 `topic_state` 单独一个降权系数（`memory.stale.state_cut`，默认 0.85），而不是挤掉。

### 阶段 C：非事实层的「把时间说出来」

**动机**：D1 + D3。T1 反思、T2 纪要、T3 日记都没有「这是几号的」。

**改法**

C1. **T1 非事实条目加「陈述时态」**
`passportLine` 对 `slot=false` 的条目（reflection/episode/appraisal）输出：

```
（10-03 我记下的判断，不是说现在）
```

只在 `validUntil` 存在或条目超过 3 天时贴，避免每条都驮一句。
实现：`stampRow` 已给 `occurred`，直接用；新增参数 `memory.passport.statement`（默认 on）。

C2. **T2/T3 补时间**
1. `retrieve.js:searchEpisodes` 返回值补 `created_at: r.day + 'T00:00:00.000Z'`（day 是 YYYY-MM-DD），让 `memoryTag` 能算年龄。
2. `retrieve.js:searchDiaries` 的 text 前面拼 `r.day + ' · '`（和 T2 一致）。
3. 两处都补 `partitionScope: 'layer'` 标记，让 `packMemoryBlock` 知道这层没有护照（避免以后误加）。

C3. **T2/T3 加「后来有没有更新」**
不做取代，只做**向下指针**：`crossLayerNote` 现在从 T1 往 T2/T3 找。反向不需要。
但 **T2/T3 自身加一句「这是 X 号的事」** 就够了——它们本身就是按时序存的，day 就是真话时间。

**验收**
- `test/cross-layer.test.mjs` 扩：断言 T2 item 带 created_at、T3 text 带 day
- 注入快照对比：`scripts/smoke-injection.mjs` 前后 diff，T2/T3 行必须出现日期

**风险**：每行多几个字，挤占 `memory.inject.budget`（默认 800）。
**兜底**：日期前缀走 `pack.oneLine` 之前拼，若 budget 紧张由现有 `DROP_ORDER` 自然处理；C1 只在超过 3 天时贴，控制增量。

### 阶段 D：跨层指针（用 timeline，不用 topics）

**动机**：D3 + D5。跨层不是取代，是「这条出自哪儿 + 后来在哪儿提过」。

**改法**

D1. **挤出留指针**
`packMemoryBlock`（index.js:472）被挤出的条目，数量 >0 时在注入末尾补一行：

```
（另外还有 3 条旧说法被我收起来了，要翻我就说「翻旧账」）
```

实现：`kept.length < base.length` 时生成；参数 `memory.inject.ejected_note`（默认 on）。
这行不带内容，只告诉模型「有账本，可以翻」，配 `asof` 已有能力。

D2. **跨层锚改用 fact_key 主题段 ↔ T2 正文**（不用 topics）
`crossLayerNote`（passport.js:124）现在是 `LIKE %topic%` 撞 summary/title/topics。改成：
- 优先匹配 `episodes.title`（标题是人写的，比 topics 有信号）
- 不再查 `topics` 列（已证伪）
- 保留 `related()` 2-gram 复核（现有）

D3. **timeline 当指针源**
`stampRow` 的 `derived` 已经能拿 `episode:<id>` / `turn:<id>`。
在 `passportLine` 里，当条目属于 T1 且 `derived` 存在时，可选追加「（出自 10-27 那次聊天）」。
参数 `memory.passport.origin`（默认 off，先观测）。

**验收**
- `test/cross-layer.test.mjs`：断言不再查 topics 列
- 单测：挤出 3 条 → 注入末尾有那一行；挤出 0 条 → 没有
- 人工看 10 条注入样本，确认那行读起来自然

**风险**：多一行可能被模型当成「必须翻账本」。
**兜底**：文案明确「要翻我就说」，不命令。

### 阶段 E：可见性（面板 + 体检）

### 阶段 F：回放验证（开开关前最后一关）

**动机**：所有「该不该挤/该不该取代」的判断，最后都要用数据说话。

**改法**
1. 新增 `scripts/replay-stale.mjs`：
   - 取阶段 0 基线里的候选对（同 key 组 + 状态词对 + 跨层命中）
   - 每组构造两个问句：「现在怎样？」「当时怎样？」
   - 跑当前注入 → 看模型是否把旧条当现状
   - 分别关/开挤出跑，对比
2. 指标：旧当现在率、注入条数、token 占用、误杀（人工抽 20 条）

**验收**
- 旧当现在率：开挤出 vs 关挤出，必须开更低
- 误杀率：人工抽 20 条，误杀 ≤ 2 才允许把 `memory.write.stale_supersede` 打开

**风险**：回放要调模型，慢且耗 token。
**兜底**：先跑 20 组小样本，通过再全量。

## 5. 明确不做

| 不做 | 理由 |
|---|---|
| 给 T2/T3/T4 加 invalid_at | 它们是粒度分层不是版本链（D3）；要管旧事，标日期就够 |

## 8. 执行结果（2026-11-04，阶段 0→F 已完成）

逐阶段改动与前后数字见 **[记忆时态-提升报告-v5.md](记忆时态-提升报告-v5.md)**。

对 §7「没把握」的逐条回答：

1. **`it.stale` 设置点**：确认只有 `retrieve.js:238/287` 两处，按 `invalid_at` 设；S1 主路径根本不召回旧条。
   `pack.js:152` 的「（已更新，旧说法）」在 S1 不走这条分支。
2. **反思类被误标的条数**：阶段 A 的 slot 闸之后，非槽位不再因「同 key」被判「有更新」，实测 **0**。
3. **T2/T3 注入频率**：没有单独量；字段已补（`created_at` + `day` 前缀），单测断言了「带日期」。
   语义级收益（模型是否因此少把旧事当新事）未测，见报告 §6。
4. **回放问句构造**：改成**规则代理**（旧条进注入且无任何时间提示 = 裸暴露），不调模型，可重复跑。
   语义级评测留作下一轮。
5. **budget 压力**：回放平均 token 改动前 291–292，改动后 292，**没有挤压**。

**计划外的一条改动（重要）**

原计划保留 `topic_weak`（只同主题）作为「只标不挤」的一档。执行到阶段 F 回放时发现：
它把「同主题」当成了「旧」，127 条里大量是词面撞车（「oneLine」能撞出五条互不相干的结论）。

最终改为：**只同主题不产生 `validUntil`**，只留 `weakLater` 当弱标候选（默认不进注入）。
这样「旧」的定义收回到「同 key 或状态词对」，与论文「相似度不足以判新旧」的结论一致。

结果：误标 127 → 0，实际挤出 5 → 0，注入带时间提示 75 → 626（靠陈述时态，不是靠乱标）。
