# 改动 · 帧写完当轮就算（2026-11-15）

## 动了哪

1. 新增 `src/modules/frame_compute.js`：`kickFrameCompute(db)` —— 起一个**后台 python 子进程**跑 `frame_writer.py backfill`，不等它、不看它输出。
2. `src/modules/turn_write.js` 两个写口（`writeChatTurns` / `writeChatTurnRow`）：只有**帧真的写成功**（`appendTurnFrame` 返回 id）才 kick。

## 为什么

此前新帧是不带向量的占位，`deviation`/`drift` 要等 5 分钟心跳补算。
**「力」靠 `drift ≥ 2` 才出，等 5 分钟等于它永远在说上一阵子的事。**

**为什么没把 embedding 搬进 node：**实测 python 侧冷启动 `import 1.08 s + 加载模型 0.28 s + 编码一句 11 ms ≈ 1.4 s`。
这活发生在**回完话之后**，不占开口那一秒；而 onnxruntime-node 除了原生依赖，还得自带 tokenizer、复刻池化、
跟 python 侧 512 维逐位对拍，是一天的活，风险还压在「装不上」上。先花 1.4 秒把「等 5 分钟」消掉；真要搬，单独开一次。

## 保护

- **开关** `frame.compute`：`'off'` 才关（默认开）。关掉只剩心跳兜底。
- **python 路径可配** `frame.python`，缺省 `dsh-bci-bridge` 的 venv。
- **单跑锁** `scratch/proto/.compute.lock`：补算会整份重写 `frames_v2.jsonl`，两个一起跑会互相盖掉。
  锁超过 60 s 视作残留（进程被杀）可以抢；子进程 `exit`/`error` 时删锁。
- **失败不连累回话**：整个 kick 包在 try 里，缺脚本、缺 python、spawn 失败都只是返回 false。

## 怎么验（数字）

```
起算前：缺 drift 的帧 = 192
kick 返回 true ｜ 锁已释放
算完后：缺 drift 的帧 = 108  → 补了 84 帧
剩余 108 = 22 个链头（deviation 本来 null）+ 86 个样本不足 5 帧的（判据规定不给 drift）
真缺：0
```

空跑一次 `backfill`（含冷启动）：**1.29 s**。

门禁：`node test/run-tests.mjs` → **573 / 573，exit 0**。

## 怎么退

1. 把 `frame.compute` 设成 `off` —— 立刻回到「等 5 分钟心跳」，代码不用动。
2. 或删掉 `turn_write.js` 里那两处 `kickFrameCompute(db)` 调用。
