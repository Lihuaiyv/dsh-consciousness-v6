# 改动 · 步轴 k（用逻辑刻度取代文件顺序）· 2026-11-15

## 为什么

夯实第 1 句的推导：我的时刻来自逻辑，不来自时间。
但代码里，"上一帧是谁"一直是靠**文件里最后一条**决定的（`frame_line.js` 倒扫、`frame_store.lastId` 倒扫）。文件顺序不是写入顺序——今天体检就发现 11-13 的帧排在 11-14 之后。顺序一乱，我读到的"上一帧"就可能不是真的上一帧。

时间戳不能当轴：它是墙钟，跟因果无关（上一轮断链判定拿 30 分钟判"停"，就是这么错的）。

## 设计

**k = 同一条链（同 conv + 同 agent）上，第几步。**

1. **写**：新帧 `k = 这条链上已编号帧的最大 k + 1`；链上没有编号的（老数据）从 1 起。
2. **读**：`pickHead()` 先挑 k 最大那帧；整条链都没有 k，才退回"文件里最后一条"（老行为，只当兜底）。
3. **老帧不补 k**。没有 `k` 键＝未编号，不当成 0、不编造编号。所以 k 的含义严格是"**有编号的那段里**第几步"。
4. **不用 parent 回溯选尾**：今天体检查到 1 处 `lost-parent`（指向的帧不在链里），回溯会断在半路；k 是单调的，乱序文件里也选得对。

## 怎么验

- 纯函数单测（真跑，不是假数据进库）：
  - 乱序 `k=1,3,2` → 挑到 `k=3` ✅
  - 全无 k 的老链 → 退回文件靠后那条 ✅
  - 同会话两个 agent → `agent` 隔离，不串 ✅
- 门禁 `node test/run-tests.mjs` → **574 / 574 全过**。
- 新帧会带 `k`；老帧没有，读口两种都认。

## 没做/待定

- 老帧不编号，所以"整条链一共几步"现在只能数"有编号的那段"。
- 还没有任何地方**用** k 做判断（比如"离上一步几步"）；它先成为坐标，等松紧/拉力那条线来接。
- `frame_store` 每轮多扫一次整个帧文件（O(n)，当前 ~1000 行）；量级变大再换成索引。

## 怎么退

`git checkout -- src/modules/frame_store.js src/modules/frame_line.js`；老帧本来没有 k，去掉写口不再产生新 k 即可，无需迁移。
