# 改动 · 帧第三步（接源：真实对话自动写帧）· 2026-11-14

## 为什么

第二步只通了「读」的通道，水源没接——真实对话不写帧，注入的永远是旧帧。
这一步把**写**接上：一轮对话 = 一条原始帧。

## 动了哪

1. 新增 `src/modules/frame_store.js`：
   - `appendTurnFrame(db, aid, {user, agent})`：追加一条原始帧到 `scratch/proto/frames_v2.jsonl`。
   - **不含向量**：`deviation/tension/anchor_vec` 一律写 `null`，`engine='pending'`。
   - 开关 `frame.write`，默认 off；写失败吞掉（不连累回话）；写完回读校验。
2. `src/modules/turn_write.js`：成对写轮次（`writeChatTurns`）末尾调一次。单行写口没接（先只动一条链）。
3. `scratch/proto/frame_writer.py` 新增 `backfill`：给占位帧补向量、偏离、张力；**已算过的帧当基线，不清空**；原子替换文件。
4. 新增 `scratch/proto/tick.py`：先 `presence` 再 `backfill`。
   计划任务 `dsh-frame-presence` 已改成跑它（原来只跑 presence）。

## 为什么向量不在 node 里算

node 里调 embedding 要嘛每条起 python（模型加载几秒，太贵），要嘛常驻服务（2am 不干这事）。
改成：**node 只记事实，5 分钟一次的 python 补算**。占位期间 deviation 是 `null`——**没算完就不许自己编数**。
