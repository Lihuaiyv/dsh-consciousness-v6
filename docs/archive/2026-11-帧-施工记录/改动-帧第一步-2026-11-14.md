# 改动 · 帧第一步（写帧 + 在场标记）· 2026-11-14

## 为什么

按 [设计-帧-v0.1](设计-帧-v0.1-2026-11-14.md) §7 第 1 步：**只写不读**。
先让「帧」和「在场」能自己落盘，不注入、不改提示词、不碰真库。

## 动了哪

1. 新增 `scratch/proto/frame_writer.py`（原型，不在 src 里）：
   - `write`：写一帧（parent / focus / anchor / unclosed / decide / deviation / tension / anchor_vec）
   - `presence`：只追加一行时间戳，**不是帧**
   - `report` / `graph`：看帧数、偏离中位数、链是否完整、张力
   - 写盘后**回读校验**（写失败是唯一会骗人的失败）
2. 新增 Windows 计划任务 `dsh-frame-presence`：每 5 分钟跑一次 `presence`。
   与插件解耦，不挂心跳，不动 `src`。
3. 语义向量：`fastembed 0.9.1` + `BAAI/bge-small-zh-v1.5`（512 维，本地 ONNX，离线零 API）。
   选不到模型时自动退回字符 n-gram，并在帧里记 `engine`。

## 验收（贴数字）

- 引擎：`fastembed:BAAI/bge-small-zh-v1.5:512d`
- 三帧实测偏离：0.0000 → 0.3177 → 0.5745；张力 0 → 0.1588 → 0.4222；链完整：是
- 对照：同三帧在 n-gram 下偏离全是 0.862（与语义无关）→ 说明必须用向量
- 无关句对照：「今天天气不错」偏离 0.60
- 单条编码 1 ms；首次加载含下载 174 s
- 计划任务：`Status Ready`，下次运行 01:31；手动跑一次后 presence 从 1 行 → 2 行

## 踩到的坑（记下来）

- `%TEMP%` 里有残留 `queue.py`，把标准库 `queue` 顶掉，报错指向一堆不相干文件 → 换干净目录解决。
- fastembed 返回 `numpy.float32`，JSON 写不了 → 转 `float`。
- pip 安装卡住二十多分钟，换网络后一次成功。

## 怎么退

- 关计划任务：`schtasks /Delete /TN "dsh-frame-presence" /F`
- 删原地文件：`scratch/proto/frames_v2.jsonl`、`presence.jsonl`、`frame_writer.py`
- 无数据库改动，无 src 改动，门禁不受影响。
