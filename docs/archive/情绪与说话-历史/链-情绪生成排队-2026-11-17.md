# 链 · 情绪生成的排队（2026-11-17）

> 按《设计 · 三递质情绪引擎（2026-11-16）》§2.1 写。只讲「情绪生成链怎么排队」，不写事帧字段、不写递质公式、不混别的链。
> 设计文档本文不动；这份是它 §2.1 的排队细化。

## 一、三条通道，各自的位置

| 通道 | 排在哪儿 | 做什么 | 和回复的关系 |
|---|---|---|---|
| **快（同步）** | 用户消息落库后、回复生成前 | 纯规则：用 open 帧槽位 + 这一句的文本信号，算 provisional S/N/D + 一级向量 | 只等毫秒，不卡 |
| **深（异步）** | 回复结束之后，worker 里 | 模型细化事帧槽位、二级标签、他人情绪猜测；回来 merge 覆盖 provisional | 永不阻塞回复 |
| **心跳（轻）** | 30~60 秒一次，挂现有心跳 | 只做衰减和静默判断，不调模型 | 毫秒级 |

一句话：**回复前只跑快通道；模型那一步永远在回复之后。**

## 二、排队的硬规则

1. **一轮一条任务**：每条用户消息只排一个情绪任务；同一轮只允许一条最终结论（`finalShadowRows` 口径）。
2. **不靠内存队列**：深通道任务先落 `affect_jobs` 表，进程重启接着吃；丢任务等于丢情绪。
3. **顺序在表里，不在线程里**：`affect_jobs` 按入表顺序取；同一意识体的任务串行（前一条落定再取下一条），不同意识体可以并行。
4. **provisional 带 `rev`**：深通道回来时，`rev` 没变就覆盖，变了就 merge，并记一条 `affect.refine` 对账。
5. **失败不重排队**：深通道失败保留 provisional（source=rules），下一轮的新任务照常排；不在同一轮里无限重试。
6. **情绪任务优先于后台重活**：切事、判边这类批量任务在开始前问「本地/宿主是否被情绪占用」，占用就让路；情绪链不反过来等它们。
7. **超预算就弃深通道**：模型调用超出本任务预算时放弃细化，保留 provisional；记录超时原因，不把整条链卡住。

## 三、一轮的时序（排队角度）

```
用户消息落库
  └─ 快通道（同步）：provisional 写进 affect_v4_shadow（source=rules，rev=1）
  └─ 回复生成（主模型）
  └─ 回复结束 → 深通道任务入 affect_jobs（异步）
        └─ 队列取任务 → 模型细化 → merge → 写 source=model（rev=2）
下一轮
  └─ 快通道读 open 帧槽位，接上一条的最终结论
```

## 四、和另外两条链的边界

- **情绪链的队列**只管情绪任务；切事链、判边链各自的 worker 有各自的忙闲标记，两边通过「是否被占用」让路，不共用一张队列表。
- **提示词读取**发生在快通道之后：只读已落定的最新结论（provisional 或 model 都行），不现场触发模型。

## 五、已定（2026-11-17 主人定）

- **「事」是什么**：对**最近十轮摘要**的总结，最多 50 字，不设下限——这就是「正在发生什么」。
- **上一轮（回复结束后、异步）**：只做到「事的总结」——把最近十轮的摘要收拢成一句「事」（≤50 字），写进事帧，就停，不判断。
- **这一轮（用户说话后、回复生成前）**：代码把新句拼进事帧（新句 + 上一轮总结的「事」 = 完整事帧；材料 = 这一轮原话 + 近 10 轮摘要；冲谁 = 这句冲谁），然后进判断层（模型），出 S/N/D、8 角、二级词，再给这一轮提示词。
- 所以判断层属于这一轮，回复前会等这一次模型调用（1~2 秒）；这一轮回复用的就是这一句的情绪。
- 设计文档 §2.1 第 50 行「回复前只跑快通道（纯规则）」是旧说法，按这条定稿执行；设计文档本身不动。
