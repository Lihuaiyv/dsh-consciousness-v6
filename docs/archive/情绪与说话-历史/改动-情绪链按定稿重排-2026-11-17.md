## 三之五、最终定稿：料、时序、优先级、词表（2026-11-17 夜 ~ 11-18 凌晨）

按主人当夜逐条纠正后的最终状态（以本节为准，前面三之四的模型部分作废）：

1. **料是每句摘要，不是「事」。** `summarizeAffairs` 读 `presence.last_sentence`（每轮「你说了什么 / 我回了什么」压成的话），按 `conv` 字段隔离会话；不再读 `frame.summary`（那等于总结的总结）。
2. **上一轮摘要做完，才做上十轮总结。** 总结带 `waitTurnId`：等这一轮的压句落库，最多 3 秒；等不到照常跑（缺一条不阻塞）。
3. **总结提示词加「反馈」。** 【事件结构】要素里加「反馈——对方或环境给了什么回应」，并单列一句「反馈不一定是对方说的：环境的变化、结果的成败、世界给出的反应，都算」。初衷：不是只接住对方，是接住世界给的反应。
4. **总结走宿主普通 chat（非 JSON）**，1~2 秒；失败回退本地 `qwen2.5:14b-instruct`（`format:''`、`think:false`）。
5. **回复前不再补总结**：删掉 `appraiseTurnNow` 的 `ensureAffairs` 分支，回复前只留判断这一笔；缺「事」用「（新事）」，下一轮补。
6. **宿主闸门加优先级**：判断 `priority: 1` 不挂同 agent 链、直接抢全局槽；全局等待按 priority 插队。见《8-工程/改动-宿主闸门优先级-2026-11-17》。
7. **二级词表 28 → 55**：按 S/N/D 原型距离 × 门控取 top1。见《5-情绪与说话/改动-二级词表扩充-2026-11-17》。
8. **端到端验收**：`scripts/check-affect-chain-e2e.mjs`（真库副本，17 项：料/隔离/压句先于总结/两行/失败回退/急事先跑），已进门禁；当前 589 / 589。
