## 为什么

原来的 `secondaryDistribution` 是「191 个词全局比距离取前 5」：不看片、不看格，一只脚跨好几片。比如位置落在「烦」那片，结果里会捞出「恶劣」——那是委屈那片的词。

这一版按定稿结构走：

1. 位置先落**片**（按片心三维距离，片内的词才参选）
2. 判断层的「谁做的 × 对谁」落**格**
3. 格里的词按 **典型度 × 浓淡** 排，取前几个

典型度 = 这个词的标注跟这格差几个维度（0 → 1.0，1 → 0.6，2 → 0.3，其余 0.1），**永远 > 0**，所以格子不会空。
浓淡 = 词自带的轻/中/重，跟当下强度（位置偏离中点多少）对齐。

## 怎么开（已默认）

**默认就走网格**，不用传任何开关。旧路已经删干净了：

- 全词表比距离那条路 → 删
- 球面口径（`affect.v4.geo` / `opt.geo`）→ 删，传了也不起作用
- 影子模块里那个 `geo` 参数 → 删

还能调的只有 `typicalWeight`（默认 0.7）：越大越看重「这格像不像」，越小越看重浓淡对不对。

```js
secondaryDistribution(frame, { position, limit: 5 }, judgment)                 // 就这么用
secondaryDistribution(frame, { position, limit: 5, typicalWeight: 0.9 }, j)   // 更看重像不像
```

## 还没做

- **默认没开**。开之前得先看真实聊天里挑出来的词顺不顺，现在只在 5 个手造场景里看过。
- **典型度还只是机械规则**（按标注差几个维度），没按语感修。「我冲外面雀跃」这种读起来别扭的，规则给 0.3，但没有逐条校准。
- **片内挑词的兜底**：如果片挑错了（位置刚好在两片中间），词会整片跑偏。还没做「片内挑不出像样的就退到第二近的片」。
- `lexicon_grid.js` 是生成物，**改了标注 md 要重跑** `node scratch/gen-grid-data.mjs`，不然数据是旧的。
