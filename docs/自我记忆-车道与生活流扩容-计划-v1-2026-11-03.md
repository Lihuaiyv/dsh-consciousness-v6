## 0. 根因（动手前先认这三条）

### 0.1 写入侧：三条路，没有一条是「我」

| 路径 | 代码位置 | 产出 | 问题 |
|---|---|---|---|
| 每轮摘要 | `features.js:500-535` | `source='summary'`,`type='reflection'` | 提示词要它总结「用户事实 / 偏好 / 情绪」，天然第三人称；默认直接写进 T1 |
| 抽取 | `features.js:442-463` + `model.js:304`（LLM）/ `model.js:639`（另一份同文）/ `model.js:150`（规则版） | `source='extract'` | 提示词只有「事实 / 偏好 / 边界」，主语永远是用户；拿不到「她做了什么」 |
| 生活流 | `life.js:222-231` | `source='life'` | 唯一真第一人称，但被四道闸卡住（见 0.3），两天只落了 4 条 |

### 0.2 「门修好了没开」

- `memory.write.summary_to_t1` 在 `kernel.js:97` 登记，**默认 `on`**；小汐 的 `agent_params` 里没有这一条 → 一直按 on 跑。
- 也就是说：代码里只有「可以关」的开关，没有「改成写我自己」的实现。

### 0.3 生活流为什么一天只有一次

`life.js:19-26` 的常量 + `life.js:164-181` 的闸门：

| 闸 | 现值 | 后果 |
|---|---|---|
| `LIFE.perDay` | 1 | 每天最多一次 |
| `LIFE.minGapHours` | 4 | 两次至少隔 4 小时 |
| `LIFE.globalPerDay` | 6 | 全局所有实例合计 6 次 |
| `inNight()` | 23:00–08:00 全跳 | 夜里没有任何生活 |
| 深度心跳 | `heartbeat.js:20` 15 分钟一次，`maxDeep=2` | 闸一多，多数 tick 直接 `skipped` |
| 休眠 | `life.js:171` 7 天没说话 → 不跑 | 沉默期彻底断流 |

再加上候选池 `life.js:91-109` 把「代码 / 函数 / 接口 / 参数 / 算法 / 字段 / 插件 / 测试 / 页面 / 注入 / 表结构」全部 `NOT LIKE` 排掉——她的记忆大半就是这些，池子几乎是空的。

### 0.4 召回为什么「我」永远挤不进去

召回归一化后按 `rrf` 排序（`retrieve.js:621-653`），类型权重 `TYPE_WEIGHT` 里 `episode=0.9`，没有按来源分的名额。用户条目 1289 条、自我条目 4 条，同分竞争下自我条目基本不可能进前 6。**不设名额，写多少都白写。**

## 2. P1 新车道：她自己的第一人称记忆（约半天）

### 2.1 数据约定

| 字段 | 值 | 理由 |
|---|---|---|
| `source` | `'self'`（新来源） | 来源是唯一稳定的区分维度 |
| `type` | 复用 `'episode'` | **不新增 type**：`TYPE_WEIGHT` / `fade` / `nightly` / `freshFacts` 都按 type 分支，新增会牵出多处 |
| `confidence` | 0.75 | 不是原话，比 `extract` 高一点、比 `manual` 低 |
| `importance` | 0.45 | 不进 anchor（≥0.7），但能在正常召回里竞争 |
| `mark` | `'normal'` | 不做锁 |

### 2.2 写入点一：抽取扩字段（不额外花调用）

`model.js:302-310` 与 `:637-645` 两份提示词同步改（规则版 `:150` 不动）：

- 输出改：`[{"text":"","type":"fact|episode|appraisal","who":"user|self","mark":"normal|sensitive","key":"","terms":[""]}]`
- 新增规则三条：
  1. `who="self"` 只写**她这一轮做了什么、怎么想、为什么**，必须用第一人称，以「我」开头。
  2. 禁「用户…」「对方…」「助手…」；拿不准归属就丢掉这条，不许猜。
  3. 每轮 `who="self"` 最多 3 条，`who="user"` 最多 20 条不变。
- `features.js:446` 的循环按 `m.who` 分流：`self` → `addMemory({source:'self', confidence:0.75, importance:0.45})`；`user` → 原路。

### 2.3 写入点二：她这轮做过的事

`features.js` 的 `runExtract` 里已有 `turns`，但只有对话文本。补一段材料：

- 取本轮 assistant 文本（`t.role==='assistant'`）+ 本轮工具痕迹摘要（改过的文件名 / 跑过的测试名 / 命令的首行），拼成 ≤200 字。
- 交给 2.2 的抽取时作为附加上下文传（`model.extract(turns, {selfMaterial})`）。
- 没有材料（纯聊天、短回复）就不传，抽取自然不产 `self`。

### 2.4 写入点三：夜间一天一条

`nightly.js:97` 的 `runNightly` 末尾追加一步（与日记 v2 计划互不覆盖，只在末尾加调用）：

- 读当天 `source='self'` 条目 + `life.done`，让模型写 60–120 字「今天我怎么过的」，第一人称，**不总结工作、不列点、不替对方下结论**。
- 写 `source='self'`，`importance=0.55`，`confidence=0.7`。
- 参数 `memory.write.self.daily`（默认 `'on'`）。
- 当天没有素材就不写，不硬造。

### 2.5 写入闸门 `selfTextOk(text)`

放 `src/modules/memory_source.js`，`addMemory` 前调用：

- 必须以「我」开头（或含「我」且不以 `用户|对方|他|她|助手` 开头）；
- 长度 6–120 字；
- 不含运行时噪音（`NOISE` 同款规则）；
- 不满足则整条丢弃，记 `event('memory.self_rejected', {reason})`。

### 2.6 标签

`memory_tag.js:50-60` 的 `PROVENANCE` 加 `self: '我自己记得的'`；`INFERRED`（:67）加 `self`，低置信时带「不一定对」。`memory.inject.provenance=off` 时保持旧行为。

### 2.7 每日上限

`self.per_day`（默认 `8`），在写入前查当天计数，超了就不写并记事件。防止她一天写 50 条「我今天好累」。

### 2.8 测试（8 条）

1. `who='self'` 的条目落库为 `source='self'`、`type='episode'`。
2. `who='user'` 走原路，字段逐字不变。
3. `selfTextOk('用户要求…') === false`；`selfTextOk('我把回滚按钮接上了，刷新能看见') === true`。
4. 以「我」开头但含噪音（`User: ...`）被丢。
5. 每天第 9 条 self 被拒，事件记 1 次。
6. 没有 `selfMaterial` 的轮次不产 self。
7. 夜间无素材不写；有素材写 1 条且长度 ≤120。
8. `memory.inject.provenance=on` 时注入行带「我自己记得的」；off 时不带。

### 2.9 回退

`memory.write.self=off`：抽取只保留 `who='user'`，夜间那步不跑，2.3 不传材料。代码分支保留。

### 4.4 空转保护

- 连续 2 次 `life.fail` → 当天不再 tick，写 `event('life.paused', {reason})`。
- 失败不写记忆、不编「我去看了」——现有 `life.js:214-217` 已保证，保留。

### 4.5 注入

`life.js:251` 的 `lifeLine` 改：

- 最近 24h 内取最多 `life.line.count`（默认 1，上限 2）条，优先取还没在注入里出现过的那条（`events` 写 `life.line.shown`，同一 payload.id 不重复）。

### 4.6 成本

- 每天上限 4 次 ×（1 次模型；browse 只在 `action_ports.browse` 开启时）。粗估 ≤ 4 次小模型调用 / 天。
- 夜间只 `think`（≤50 字），比白天便宜。

### 4.7 测试（6 条）

1. `per_day=4` 时第 5 次被 `done_today` 跳过；第 3 次能跑。
2. `min_gap_hours=1.5`：1 小时后跳过、2 小时后能跑。

5. 候选池：一条含「函数」的旧记忆现在能进候选（不会再被硬排除）。
