> 一句话：**三列各长各的，共用一个史；草稿靠取舍与归纳长，提示词按情境捞。**

## 0. 要解决的三个问题

| # | 现象 | 根因 |
|---|---|---|
| A | 三观页都是工程记录和日记 | 进料口是「这段对话在聊什么」，不是「它做过什么取舍」 |
| B | 世界观 / 人生观 / 价值观 长成一个样 | 一个抽取器、一个 `layer` 字段、一套「像不像立场」的闸；且把「能排除」当成三观总判据 |
| C | 这一页对它说话没影响 | 注入还是 shadow；且注入取的是每层 3 条链头，最多 9 条，不是按情境捞 |

## 1. 目标结构：三列 × 三层

```
              世界观 W                  人生观 L                  价值观 V
核心      世界内核（≤2）             telos（1）                principle（≤2）
条目      信念 + 期待（带置信度）      自我定位 + 方向 + 时间      取舍 + 代价
事件      观察 / 预期落空 / 被证伪     自传章节 / 投入证据          真实取舍 / 违背
判据      预测力                     解释力 + 投入力             排除力 + 代价
```

三个判据不能混用，这是本次改造的核心。

## 3. 分阶段

每个阶段都要：先写测试 → 再实现 → 跑模拟 → 全绿再下一步。项目不是 git 仓库，改前 `.bak-<步>-<日期>`；开关默认关，关掉行为与现在完全一致。

### P0 对齐与清库（半天）

- 契约写进设计文档；`meta_json` 迁移脚本；`EDGE_TYPES` / `EVIDENCE_KINDS` 扩一项。
- 现有活库 6 条（W 1 / L 3 / V 2）按新判据全不合格，走 `CLAIM_RETIRE`（actor=user），不删行，备份库。
- 验收：`test:sangguan` 1086 项不掉；`run-tests` 全绿；活库清退后 `scorecard` 符合预期。

### P1 先做 W（1–2 天）

为什么先 W：它的验证零件已经现成（每条命题自带 ν，到期结算就是一次打脸）。

- `fast.js` 抽取分派：候选带 `lane`，W 走归纳（同模式 ≥3 个不同对象/场景），不要求「有一刻的取舍」。
- `gates.js` `gateW`：`expectation` 必填；纯工程场景拒；自评/元叙述/指令三条老闸保留。
- 置信度回写：ν 结算 → `confidence ±`，落 `meta_json`；连续两次 miss 进 κ。
- 测试：`test/sangguan-lanes.test.mjs`（正反例各 10、跨场景计数、结算回写）。
- 验收：一周内至少 1 条真 W 命题、至少 1 次结算；页面 W 行不再是工程记录。
- 回滚：`sangguan.lane.W=false` 即回到只读；文件备份还原。

### P2 起草闭环（2–3 天）

- J20 反事实标注、J21 起草；`draft.js` 聚类 + 五闸 + 冲突检查。
- API 两条；页面加「草稿」预览卡（只读，不能自动入库）。
- 验收：能自己出 3 条草稿，人改后至少留 2 条；G1/G2/G5 自动判误判率 <10%。
- 回滚：草稿只落文件与接口，不写账本；关开关即消失。

### P3 召回与注入（2 天）

- `meta_json.scene` 落地；`recall.js` 两拍（向量 + 轻判断）；`inject.js` 改成「核心 ≤3 + 召回 ≤2」。
- `constitution.md` 生成器：只从 committed 条目里取，≤400 token。
- 仍 shadow，记「本来会注入什么」。
- 验收：一周召回命中率 ≥60%、误捞 ≤20%；注入不会超过预算。
- 回滚：切回「每层 3 条链头」的旧取法。

### P4 合并、打架、归约、月审（2 天）

- 相同合并：同「放弃物」归一条，`variants[]` 留多种说法。
- `DERIVES` 边；每条上层必须指得出推出哪些下条，指不出退回。
- 月审：被违反次数 / 边界触发 / 人改了多少字。
- 验收：至少一对冲突被真实情境裁决过；`derives` 无空挂。

### P5 收口（1–2 天）

- 页面改三列 × 三层；三个数搬走；L 不再吃日记；`growth_order` 打开（V 空则 W 不新增）。
- 旧仪表折叠降级；README / 总览更新。
- 验收：三观页不再出现工程句与日记原文；关掉开关后行为与改造前完全一致。

## 6. 风险

| 风险 | 应对 |
|---|---|
| W 的「预测」写得假，永远能圆 | ν 必须有可观测的 observe 字段；miss 就降置信度，不许改口径 |
| 召回误捞，拿不相干原则压人 | 轻判断只许回编号；误捞率 >20% 就退回只按核心 |
| 注入变长拖慢对话 | 硬上限 400 token + 预算是硬闸，超了就丢召回 |
| L 缺投入证据，变成愿望清单 | 没有 `invest` 证据只能进保护带，不进核心 |
| 改表导致老库打不开 | 加列幂等、失败只告警不回滚；先备份 |
| 测试膨胀 | 每个阶段只加一个测试文件，并入 `test:sangguan` |

## 7. 不做

- 不从对话里自动长 L/V 命题。
- 不让草稿自动入库。
- 不做三观分数。
- 不动情绪 / 关系 / 记忆的主流程。
- 不为了页面有内容而放行候选。

## 8. 顺序与理由

P0 先把口径和脏数据定住，否则后面每一步都在错的料上跑。P1 只做 W，因为它是唯一「验证零件现成」的一列，最快能证明三列真的分开了。P2 起草器独立于注入，可以并行观察。P3 才碰提示词，因为它一旦接上就直接影响说话，必须等内容对。P4 的合并与归约要有足够条目才有意义。P5 最后收口，避免一边改页面一边改判据。

粗估 8–11 个工作日，按阶段验收，不按日期推进。
