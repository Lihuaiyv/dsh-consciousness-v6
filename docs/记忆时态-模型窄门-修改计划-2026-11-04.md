## 2. 设计：八条约束（每条都有理由）

### D1 候选对来自结构，不来自相似度

上一轮我指出交接 §6 的自相矛盾：用「相似度 0.5–0.9」圈灰区，但 §3 已证明 cosine 分不开（「小小 vs 小绿」0.867）。**余弦不能决定「该不该问模型」**。

候选生成按优先级：

1. **同 `fact_key` 的完全相等**（不是 `LIKE`）——最强
2. **同 `topicOfFactKey()`**（主题段相等，且 ≥2 字）——中
3. **同 `episode_id`**（`fact_archive.payload`）——「同一段对话里抽出来的两条」
4. **同 `source_turn_id`**——「同一轮说的两条」（通常是同一件事被拆开，优先判 supplement）

以上都按时间排序取「旧→新」对，且只取 `old.created_at < new.created_at`。

**相似度只做两件事**：① 在同一候选池内排序（决定先判谁）；② 设上限（每天不超过 N 对）。它**不判断新旧、不判断相关性**。

### D2 只在灰区调模型

「灰区」定义为：**结构信号成立，但规则给不出确定答案**。具体是：

- `decideWrite` 判出 `new`（相似度 < 0.92 且无同 key）或 `conflict`，且候选池里有结构候选
- `stampRow` 判出 `weakLater`（只同主题、没有一个干净的 topic_key）
- 夜间批量：当天新增记忆中，同主题但 `source !== 'topic_key'` 的对

**确定性命中不调**：同 key 已由 `decideWrite` 判 update、明确否定词、`isStalePair` 直接成立（pending→done）、`invalid_at` 已置位。

### D3 三档，不是两档

判定输出只有四个值：

| verdict | 含义 | 动作 |
|---|---|---|
| `supersede` | 后一条取代前一条（值变了 / 做完了 / 改口了） | 允许 `invalidateMemory(old, cause=new, reason='judge_supersede')` |
| `supplement` | 同一件事的补充，旧条不算错 | 只记缓存与事件，**不改任何记忆** |
| `unrelated` | 只是词撞车 | 记缓存（防止反复问），不产生任何提示 |
| `uncertain` | 拿不准 / 模型不可用 / 返回不合格式 | 不落缓存或落 `uncertain`（保留重判），不改行为 |

**判对「同一件事」≠「该取代」**——这是交接里明确写过的教训，代码里必须体现为两档不同的动作。

### D4 绝不在注入路径上调模型

注入预算是几十毫秒。判定只在两个地方发生：

- **写入门控**（`gate.applyWrite`，后台抽取链上）：同步调一次，超时 3s 直接放弃
- **夜间批量**（`nightly` 新步骤）：一天一次，上限 40 对

`index.js` 的三处注入接线**一行都不改**（除 P6 可选的一句补充标注，默认不做）。

### D5 判过就缓存，同一对只判一次

新表 `memory_pair_judge`，主键是 `pair_key = sha1(agent_id + '\u0001' + old_id + '\u0001' + new_id)`。

- 命中缓存直接返回，**不调模型**
- `unrelated` / `supplement` 永久缓存（除非文本被 revise 过：`version` 进入 key）
- `uncertain` 缓存 7 天，之后可重判
- 模型换了（`model` 字段变化）不自动失效——重判成本低时由夜间手动触发，避免「每次换模型全库重判」

### D6 失败语义：永不阻塞、永不冒充

```js
// 伪代码，写进 pair_judge.js
async function judgePair({ complete, old, newer, cached }) {
  if (cached && fresh(cached)) return cached            // D5
  if (!complete) return uncertain('no-model')          // D6
  let raw
  try { raw = await withTimeout(complete({ system, text }), TIMEOUT) }
  catch (e) { return uncertain('error:' + e.message) } // 超时/抛错
  if (!looksLikeJudgement(raw)) return uncertain('fallback-shape') // 坑 1
  return parseVerdict(raw)                             // 严格三档
}
```

`looksLikeJudgement`：返回必须是纯文本且含三档之一；命中 `{"overlap":"unknown"...}` 这种 JSON 形状直接判 `fallback-shape`。**宁可判不出，不能把规则兜底当成模型判断。**

### D7 规则闸兜住已知错误模式

实验已知：两次明确错误都是「同一个专有名词同时出现在两条里」（同一个库名 / 同一个文件名），模型判成同一件事。

规则闸（在调模型**之前**）：

1. 抽 `propers(text)`：反引号内内容、英文标识符（≥4 字符、含 `_.-/`）、`*.json` / `*.mjs` / 库名模式
2. 若两条共享 ≥1 个专名，但**主语段不同**（`fact_key` 第一段不同，或都没有 key 且首 6 字无共享 2-gram）→ 强制 `unrelated`，不调模型
3. prompt 里加一句：「两条里出现了同一个专有名词，不代表在说同一件事；看它们的主语和动作。」

这个闸还有个副产品：能减少要判的对数（D1 的候选池里专名撞车占相当比例）。

### D8 默认关，开也是 shadow 优先

新增参数（`kernel.js` PARAMS，跟随 `C4` 组）：

| key | 默认 | 说明 |
|---|---|---|
| `memory.judge.enable` | `off` | 总开关。off 时新代码不执行任何判定（缓存也不读） |
| `memory.judge.gate` | `shadow` | `off` / `shadow`（只记事件与缓存，不改记忆）/ `on`（supersede 真的作废旧条） |
| `memory.judge.nightly` | `on` | 夜间批量是否跑（受 enable 总闸） |
| `memory.judge.daily_max` | `40` | 每天最多判多少对（成本闸） |
| `memory.judge.timeout_ms` | `3000` | 写入门控单次超时 |
| `memory.judge.min_interval_ms` | `800` | 两次模型调用之间的最小间隔（防抽取高峰时打满） |

**验收铁律**：`enable=off` 时，跑 `replay-stale.mjs` 的 A 组，逐项数字必须与改造前完全一致。这一条不达标就不许进下一阶段。

## 3. 新模块 `src/modules/pair_judge.js`

只做判定，不碰记忆写入（保持 gate 的「本模块不直接写记忆」约定）。

```js
// 导出（全部纯函数或只读）
export function propers(text)                 // 专名抽取（D7）
export function structureCandidates(db, aid, { newRow, limit })  // D1 候选对
export function pairKey(aid, oldId, newId)    // D5 缓存键
export function readJudgement(db, aid, key)   // 缓存读
export function writeJudgement(db, aid, rec)  // 缓存写（只写新表 + events）
export async function judgePair(opt)          // 核心：D6 语义
export function verdictAction(verdict)        // 'invalidate' | 'note' | 'none'
export const JUDGE_SYS = '...'                // prompt，单独导出便于测试
```

`judgePair(opt)` 的入参：

```js
{
  complete,        // ({system, text}) => Promise<string>；不传 = 没模型
  db, aid,
  oldRow, newerRow, // 必须是完整行（要 text / fact_key / created_at / version）
  timeoutMs,
  skipRules,       // 测试用，跳过 D7 闸
}
```

内部顺序固定：**缓存 → 规则闸（专名）→ 结构确认（同 key / 同主题）→ 模型 → 记缓存**。

prompt 草案（中文、三档、要求一个词）：

```
你在判断两条记忆的关系。只输出四个词之一，不要解释、不要标点：
取代 —— 后一条让前一条不再是现状（值变了、做完了、改口了、否定了）
补充 —— 还是同一个问题，后一条只是加了细节/进展，前一条不算错
无关 —— 只是共用了一些词，说的不是同一个问题
不确定 —— 拿不准

注意：两条里出现同一个专有名词（库名、文件名、型号）不代表在说同一件事，看主语和动作。

旧（<date>）：<text>
新（<date>）：<text>
```

解析：先精确匹配四个词；再容忍「是取代」「属于补充」这类前缀；命中多个 → `uncertain`；空/超长/JSON → `uncertain`。
