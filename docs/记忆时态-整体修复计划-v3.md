# 记忆「把过去当现在」整体修复计划 v3（六库联动版）

> 目标：不是再补一个标注，而是把「旧了没有」变成整个记忆模块的一等公民。
> 依据：`docs/memory-layers.md`（T0–T4 分层）、`docs/memory-upgrade-plan-v2.md`（U0–U8 已落地）、`src/modules/*` 现状核对、真实库体检（2026-11-04）。

## 一、整体检查：哪里相关但没用上

按「六个库（T0–T4 + 索引/存根）」逐层查，发现这些机制已经在库里，但没参与「新旧判断」：

1. **`memory_timeline` 只服务「某天当时」查询**（asof.js）。REVISE / DISPUTE_OPEN / HIDE 事件从不进每轮注入；注入侧看不出「这条被改过 / 有争议 / 藏过」。
2. **`fact_archive.payload` 里本来有 episode_id / day / seg**（见 memory-layers §7、§14），但没人拿它把一条事实回链到「哪天的纪要、哪句原话」——这正是外部研究说的「冗余来源」，一直闲置。
3. **`episodes.open_loops`** 已经在 bridge 尾巴里用（「还没收尾的」），但只是文字，没和 T1 的「待完成」条目对齐，也没做「这个环后来关了没有」的核对。
4. **实体图（entities + memory_links）** 只用于召回扩散（expandByLinks），没用于「同主题」判定；「情绪快照：待完成 / 完成」这种正是实体/主题能连起来的。
5. **冷热档（tiers / temps）** 只决定「进不进 S1」；S2/S3 深查、翻原话仍能翻出旧条，而深查结果不带「是否过时」。
6. **浮上来通道（pulse / pendingSurface）** 取候选时不看「是否已被取代」，旧结论可能被重新浮上桌面。
7. **`self_repeat`（不重复说）** 只记「说过」，不记「说的时候对不对」；旧说法被反复展示、被挡掉，新说法反而没机会出现。
8. **`memory_fade`（模糊化）** 为了让旧事「记不清」删数字和括号，但删的是细节、不是错误结论；旧结论语义还在，却更难被认出是旧的。
9. **`diaries.refs` / `episodes.topics`** 没用于「这条事实和哪天的记录相关」——原子证据链缺一环。
10. **reflection 被排除在锚点/新近之外**（§20.2），但它恰恰会写成「现状结论」；排除后它只能靠普通相关度，问「现在怎样」时反而可能不被想起。

## 二、整体检查：哪里互相打架

1. **`fact_key` 的 UPDATE（gate.js）** 会原地改写正文、version+1、旧句进 fact_archive——这就是「同一件事的新旧替换」，但它只写 timeline 的 REVISE，不写「取代」语义；注入侧看不出来。
2. **`memory.write.flip_policy=conflict`（改口开黄灯）** 与「旧条退场」冲突：改口会开一条 open 冲突等你拍板；拍板前新旧两条都在，新条还可能被当成「有争议」而不是「现状」。
3. **reflect / consolidate 的 supersede** 与「待办不该被压」冲突：成员是「进行中 / 承诺」时也会被并走（P4 已列，但没和写入侧联动）。
4. **`fadeText` 与「旧条识别」冲突**：模糊化可能把「还没做完」删成「没做」，语义反转。
5. **`sessionBridge` 只取一条纪要**：跨会话时，今天更早的「做好了」可能被最后一条「闲聊」盖住，拿不到真正的进展。
6. **`asof.auto` 默认 off**：问「以前」时，冷层旧条和热层新条不在同一个答案里；asof 又只查 T1，不查 T2/T3/T4 的当时版本。
7. **S1 只含 T1 + T3**（memory-layers §11）：T2 纪要要 S2/S3 才进；「进展写在纪要里」时，S1 根本看不到——今天上午「接回来了」进不来，根子在这儿。

## 三、整体检查：只考虑一个库的地方

1. 之前的 `staleNote` / `recentChanges` 只看 T1（memory_items / memory_timeline）。
2. 冲突检测只看 T1（memory.js / gate.js），不看 T2 纪要、T3 日记、T4 原话里的「更新说法」。
3. 「过时」的证据链天然跨层：T1 说没做，T2 聊过做好了，T3 写「今天终于弄完」，T4 有原话「接回来了」——只查 T1 必漏。
4. 反过来，T2/T3 的旧内容（bridge、日记）也没有「后来更新没更新」的检查。

## 四、新结构：六个库各自管什么「时态」

| 层 | 角色 | 时态职责 | 参与判断的方式 |
|---|---|---|---|
| **T0 自我** | 身份 / 关系 / 禁忌 / 价值 | 慢变，几乎没有「过时」，但有「以前 vs 现在」 | 偏好/关系变化时标「以前…现在…」；不进检索 |
| **T1 事实** | 结论层 | 最敏感：会被改、被取代、被合并 | 主仲裁对象：supersede / REVISE / 状态词 |
| **T2 纪要** | 经过层 | 提供「那天发生了什么」 | 进展第一落点；过时仲裁的证据层 |
| **T3 日记** | 叙事层 | 提供「我什么时候知道的」 | 日期的第二来源；「后来」的证据 |
| **T4 原文 / 存根** | 证据层 | 永不改写 | 最终真相；仲裁的裁决依据 |
| **索引（timeline/heat）** | 账本 | 记录出生 / 改写 / 作废 / 争议 | 定位版本；不存正文 |

一句话：**T1 是「现在怎么记的」，T2/T3/T4 是「当时怎么发生的」，索引是「什么时候变的」。**

## 五、修复方案（三组）

### 组 1：读侧仲裁（注入前，六库同查）

- **A1 现状仲裁**：注入候选（T1）先查同主题在 T2/T3/T4 里有没有更晚的进展证据（T2 `searchEpisodes`、T3 `diaries` 按日期、T4 `raw_fts` + `fact_archive` 回链）。有则旧条降级或挤出，并把「最新证据」作为一条带日期/来源的引用。
- **A2 bridge 放宽**：取最近 3 条纪要，优先带今天；标「那时」，并注明「后来有没有被取代」。
- **A3 深查 / 浮上来也过仲裁**：pulse / surfacing / deepRecall 的结果先查是否被取代；已取代的不进正桌，只留深查。
- **A4 日记回链**：T3 注入时带「写于哪天」，并核对 `diaries.refs` 指向的事实后来有没有被改（有则标「后来改过」）。

### 组 2：写侧覆盖链（六库同写）

- **B1 来源三件套**：事实写入时，把 `fact_archive.payload` 的 episode/day/seg + `source_turn_id` + `fact_key` 当仲裁键；不是新存，是把已有字段用起来。
- **B2 状态词标记**：含「还没 / 待 / 等…之后 / 答应 / 提醒」的条目打 `state_pending`（或 fact_key 后缀）；后续出现「完成 / 好了」时优先取代它，而不是只开冲突。
- **B3 冲突与过时分工**：时间顺序明确的新旧 → supersede（不开 conflict）；同一时刻互相矛盾 → conflict（现有流程）。避免一条改口同时开案 + 取代 + 夜巡三条记录。
- **B4 UPDATE 可见**：gate 的 UPDATE 写 timeline REVISE 的同时，注入侧能取到「这条被改过」——现在只有 asof 查得到。

### 组 3：整理侧压缩防护（P4 保留，补联动）

- **C1 先聚类再压**：只压同话题批次。
- **C2 状态词保护**：待办 / 承诺不压。
- **C3 保留不确定措辞**：不许把「大概 / 好像」升级成确定。
- **C4 合并可回链**：合并稿记 `consolidated_from`；深查能看到成员；注入侧标「这条是合并来的」。

## 六、不变量（验收口径）

1. 任何被取代的 T1 记忆，都能在 T2/T3/T4 找到至少一条「为什么被取代」的证据（新说法 / 原话 / 纪要）。
2. 注入里出现的旧结论，要么被挤出，要么带「后来还有更新的 + 日期 + 来源层」。
3. 冲突 / 过时 / 合并三类事件，在界面里分得开；一条改口不同时出现在三类里。
4. 六库同一条时间线：`memory_timeline` 做总账，T2/T3/T4 用外部键（episode_id / day / session_id）关联。
5. 仲裁只读：不 touch、不加热旧条。

## 七、落地顺序

1. **V0 体检 + 跨库回放集**（只读）：从真实库挑 20–50 对「旧结论（T1）+ 新进展（T2/T3/T4 任一层）」，量基线。
2. **组 1 A1/A2**（读侧）：风险最小，收益最大；先只做「T2 纪要里的进展」这一路，验证有效再加 T3/T4。
3. **组 2 B2/B3**（写侧）：状态词 + 冲突/过时分工；先 dry-run。
4. **组 3 C1–C3**：reflect 防护；与组 2 并行 dryRun。
5. **组 1 A3/A4 + 组 2 B1/B4**：接线收口，界面把三类事件分开。
6. **回归**：`eval:memory`、`sim:days`、`float`、`recent` 小回放集。

## 八、风险与不做

- **延迟**：仲裁每轮最多查 5 条候选 × 1 次，加预算上限；命中率低就降级为「标注」而不是「挤出」。
- **误判**：跨库匹配要强命中（主题词 + 时间更晚 + 来源可信），宁缺毋滥；先 dry-run 人工抽查 20 条，错标率 < 10% 再上线。
- **不建图数据库**：仍用 SQLite + timeline + 实体/链接，不引 Neo4j / Graphiti。
- **不改表结构**：用已有字段（fact_archive.payload、source_turn_id、fact_key、entity_id）和已有索引。
- **不重写 T2/T3/T4**：它们只读参与仲裁，写入路径不变。
