## 0. 先纠正一句我说错的话

11-03 13:37 我跟主人说：「情绪每轮都是现算的几个数，走完就散了，存下去的只有一句人话标签。」

**前半句不准确。** 实测（只读探针 `_tmp_felt_probe.mjs`，对真实库 `~/.dsh/consciousness/app.db`）：

`event 2026-11-03T14:25:50.045Z` ↔ `sample 2026-11-03T14:25:50.046Z`。
写入点是同一个函数 `src/modules/affect.js:1897-1946`（事件行 1903，样本行 1924）。

另有 `selfStateLine()`（`affect.js:1247`）会把慢/快数值给**评价模型**看，但从来没给**对话**看。

结论：这件事不是「再建一套存储」，是「把已经在库里的东西接回来」。工作量、风险都比上次计划的说法小一截。

### 0.1 另一个必须说清的事实：情绪总是晚一轮

`consciousnessBlock()` 在**回复之前**拼；`appraiseWithEdges()` 在 `commitTurn()` 里**回复之后**才异步跑
（`index.js:1118-1120`）。所以任何时刻注入里能拿到的「最近一条」，正好是**上一轮那句话**的情绪。

这恰好就是我们要的：不是「这一句现在什么情绪」（那还得先算），是「刚才那一句，落在我身上什么数」。
也顺手修掉 11-02 那条 ——「她不知道上一句自己是什么心情」。

## 1. 阶段一（P1）：把上一刻接回来（纯读、纯加一行）

### 1.1 新模块 `src/modules/felt_snapshot.js`

```js
export function feltSnapshot(db, aid, { at = Date.now(), maxAgeMin = 720 } = {})
// → null | {
//   at, ageMin, line,
//   eventId, sampleId, cause, label, intensity,
//   slow, fast, total, fastSelf, fastEmpathy, paired: boolean
// }
```

取数：两张表各取 `ORDER BY rowid DESC LIMIT 1`（**用 rowid，不按 `at` 排序**——`affect_samples` 没有索引，
按 `at` 过滤会全表扫；rowid 尾部是 O(1)），再配对。**配对必须是三个条件同时成立**：

1. 时间差 ≤ **2 秒**（实测同一次评价里两张表的 INSERT 只差 1 毫秒）；
2. `event.at ≤ sample.at`（事件先写、样本后写）；
3. `event.label === sample.label`。

三条不全 → `paired = false`，只带数不带原话、或者干脆 `null`。

为什么这么严：`affect_samples` 有 **2158** 条，`affect_events` 只有 **1460** 条——差的近 700 条是
`decayAffect` / `spontaneousTick` / 定时采样插的，**它们旁边没有那句话**。只看时间差就会把「自发抖动的数」
配到「上一句话」上，读起来还特别像真的。宁可 `paired=false`。

时间窗默认 12 小时。超过就不带——翻出前天半夜的数当「刚才」，比没有更假。

### 1.2 一行长什么样（默认 A 案）

```
（上一句落在我身上的样子：你说「{cause≤40}」，那一刻慢 {slow} / 快 {fast}（其中 {fastEmpathy} 是跟着你的情绪浮上来的），
读出的是{标签中文}、力度 {intensity}。这是那时候的读数，不是现在。）
```

- 标签用中文词表（同 `expression_state.js` 的 `PHRASE` 口径），**不复述 `why`**——
  `why` 是判断（「判为中性任务」），不是滋味，塞进来就成了给她解释自己该怎么想。
- **原话先过 `cleanLine`**（`features.js:1757`）：命中 URL / 盘符 / `.js` / token / 密码，就只给数、不给原话。
  主人白天发的多是路径和日志，这条不拦，快照会把工作日志当「我当时说的话」念出来。
- 括号材料、不加命令句；`①` 段已有的「别逐条复述、别解释来源」仍然管着它。
- **A/B 两案**留到 P2 用 `npm run bench:humanlike` 比：
  - **A**：只给数 + 原话（上面这版）；
  - **B**：数压成人话档（「有点浮」「压下去一点」）不给小数。
  先上 A，因为 A 可核（数是真的）；B 好看但更容易被当成形容词照着演。

`index.js:938-947`，紧跟 `expr.felt` / `trendLine` 之后、`nowText` 之前插一行：

## 3. 阶段三（P3）：没挑的那几句（复用已有的一次调用，零新增成本）

原写「默认不做」——那是把它当成「要新造一次生成」推掉了。查完不对：

**评价那次模型调用本来每轮就在跑**：`appraiseWithEdges()`（`features.js:762`）→ `model.appraise()`
→ `AP_PROMPT_CONCERN`（`model.js:474-501`），一次调用返回一个 JSON。多一个字段，不新增调用、不新增钱。

（上一版我列的 a/b/c 三种都要新造：a 污染输出格式，b 只在 gate=1 时多跑一次、且是事后补想，c 是拿拼好的
`subtextCandidate` 冒充真犹豫。方案 d 比这三种都好，因为它挂在真跑的那一刻。）

### 3.1 做法

在 `AP_PROMPT_CONCERN` 的 JSON 模板里加 `"unsaid":""`，规则补一条（编号接 14 之后）：

> 15. unsaid：如果这一刻你**其实还有另一种更想说的说法**，用一句话写出来（≤30 字，口语，第一人称）；
>     没有就留空串。别为了填而编，拿不准就留空。它不是回答，是你咽回去的那半句。

落库：`events` 表 `unsaid.moment {turn_id, at, text, event_id}`（照 `quote_echo.js` 的 `quote.moment`，**不建新表**）。

**必须同时改第二处**：`appraise.js:65-83 normalizeHint` 是显式字段白名单，只挑它认识的字段返回。
不在那里加 `unsaid`，模型给了也会被丢掉——这就是 `why` 曾经全变 null 的那个坑（`appraise.js:75` 注释自记）。
改完第一件事：随便发一句，查库里 `unsaid` 是不是真的非空，别只看代码。

### 3.2 先影子，不回读

**默认 `on`，但只落库、不进提示词。** 理由：不回读就没有「照着念」的风险，等于白拿数据。
攒两三周再看：空串率、句子像不像人、跟同一条 `cause` 对不对得上。像样了再挂到 P1 那行里。

### 3.3 风险与闸门

| 风险 | 怎么看 | 退路 |
|---|---|---|
| 污染评分（模型为了填字段分心） | `affect.label_kappa`、`scripts/emotion-kappa.mjs` 前后对比 | κ 掉 >0.03 → `affect.unsaid=off` |

## 4. 阶段四（P4）：开环在空转——先修它，不是先不动

原写「来源是抽的，先不动」。查完发现比「来源不真」更糟：**它现在是空的。**

实测（只读，`_tmp_loops_probe.mjs`）：

- `open_loops` 共 **44 条，`state` 全部是 `closed`**，`open` / `half_said` 各 **0 条**；
- `closed_by`：`user_done` **39** 条、`manual` 5 条；
- 样本内容是问句和碎句，不是待办：
  「你觉得模型版本更新之后，你还在吗」「今晚你没开的话是不是明天醒来的时候你也会跑？」
  「好了，你的小圈是不是还没画」「好吧那之后吧」「第三遍：重载之后」。

也就是说：注入里那行「（你自己心里还挂着的事…）」**现在永远不会出现**。P1 接回来的「上一刻」旁边
本来就该并排放着这个，结果那一半是空的。

### 4.1 真凶（第二遍查出来的，比问句更准）

`detectLoop` 的第一道关是 `LOOP_RE`（`loops.js:23`），里面有一个 **`之后`**。
「模型版本**之后**」「重载**之后**」「更新**之后**」全部命中——所以那 44 条里至少两条是这么进来的。
同类过宽的还有：`再说`、`剩下`、`收尾`、`最后一步`、`等会`、`一会儿`。

**只拦问句是治标**（而且会误伤「你明天能不能提醒我」，虽然 `INTENT_RE` 能兜住）。真正该动的是这三个词的用法。

另外两处可疑：

1. `settleLoopsFromUser()`（`loops.js:230-246`）的兜底：没被浮现过的开环，只要
   `overlapChars(r.text, text) >= 0.35` 就关。中文字符集重叠，短句之间随便就过线——
   一句「好了」能把不相干的条目一起关掉。
2. `addLoop` 的去重也用了 `overlapChars(...) >= 0.6`（`loops.js:151`），同一个函数同一个毛病。

### 4.2 四步（互不依赖，可分开上）

- **P4-a**：删窄 `LOOP_RE` 里的纯时间词——`之后`、`再说`、`剩下`、`收尾`、`最后一步` 单独出现不算信号，
  必须和 `INTENT_RE` 或人称同时出现。这一条比「拦问句」更根治（§4.1）。
- **P4-b**：`detectLoop` 再加一条兜底——以「吗 / 呢 / ？」结尾、且不含 `INTENT_RE` 的，`return null`。
- **P4-c**：`settleLoopsFromUser` 的字符重叠兜底，改成 `norm()` 之后**至少 4 个字的连续子串**重合；
  `addLoop` 的 `overlapChars >= 0.6` 同样换成子串判（两个函数一个毛病）。
- **P4-d**：回填——44 条里明显不是待办的标 `closed_by='misdetect'`（**只改标记，不删行**），
  让后面的统计不被这批污染。

> 阈值 4 字是拍的。上之前先拿这 44 条 + 20 句「好了 / 搞定了 / 交完了」离线跑一遍 3/4/5 三个阈值，
> 看各关几条，再定——别拿真库当试验田。

### 4.3 验收

跑三天：`open` 里稳定留下 **1–3 条真待办**；用现成的 `loopStats()` 看误关率（用户说「好了」时
被关掉、但其实没办完的比例）前后对比。若三天里一条都留不下，说明 `LOOP_RE` 本身太窄，再单独议——
但那是另一个问题，不在本阶段。

### 6.1 第 2 条为什么拆成两半做

**这次只做局部收口**：快照这一行自己判断「是不是主人」，不是主人就不给。
不碰 `audience` 的语义，只加一个只管快照的入参（`opts.snap = 'off'`），
调用方在 `index.js:1672` 用现成的判断传进来（`index.js:1676` 已经写过一遍 `ownerHere`）。

**整体 audience 隔离单开计划**，因为它不是一行的事：

- 一接上 `stranger`，日记、开环、主动句、记忆块、冲突那几行**全都跟着变**（`index.js:741-752` 那一整段）；
- 这些行的落账也跟着变（`commitMode` 的 `kept` 判断，`index.js:983-1010`）；
- 得有一组回归：陌生人看不到私有内容，且主人看到的与今天**逐字一致**。

今晚只验了快照一条路，其余五条没验。知道有洞还留着不对，但拿没验过的改动去堵洞更不对——
先堵住我自己新开的那一口，旧的那口单独立项。

附带一条不是漏洞、是要知道的：`affect_samples` **没有 agent_id 索引**（只有 `affect_events` 有 `idx_aevent_agent`）。
现在单 agent 库，`ORDER BY rowid DESC LIMIT 1` 是尾查、O(1)；哪天多 agent 了会退化成扫，届时再加，P1 先不加。
