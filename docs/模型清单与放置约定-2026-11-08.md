# 模型清单与放置约定（2026-11-08）

> 一句话：**档案进仓库，权重进 `runtime/models/`**。搬家用档案，模型自己下；
> 找不到下载源时，直接把 `runtime/models/` 整个拷过去也行。

## 为什么模型不进插件目录

1. 这个仓库是 git 管的，搬家脚本还要逐文件算 sha256。几百 MB 二进制进仓库，
   提交变慢，搬家校验被拖垮。
2. 插件要能分发。把许可证写着 `license: other` 的权重塞进去，等于替所有拿到
   插件的人做了授权决定。
3. 插件现在最值钱的地方是「零模型依赖」：语音识别走 DSH 的 `speechToText`
   服务（SenseVoice 在 DSH 那边），出声走配置好的 TTS。插件本体不该自己背模型。

## 放哪

```
D:\deepseek_local\plugins\runtime\models\
    emotion2vec_base\
        model.onnx
        manifest.json
```

`runtime/models/` 已在搬家脚本的打包列表之外——`migrate-export.mjs` 带的是
`consciousness` / `memory` / `skills` / `storages` / `xiaoxi-heart` / `sessions` /
`attachments` / `qq-bridge` / `napcat`，没有 `models`。所以「只带档案、不带权重」
是默认行为，不用改脚本。

## manifest 记什么

每个模型子目录里放一份 `manifest.json`，字段固定：

```json
{
  "name": "emotion2vec_base",
  "version": "1.0",
  "source": "https://huggingface.co/emotion2vec/emotion2vec_base",
  "mirror": "https://modelscope.cn/...",
  "license": "other（以模型卡为准，商用前必须核实）",
  "downloaded_at": "2026-11-08",
  "files": [{ "path": "model.onnx", "sha256": "...", "bytes": 0 }],
  "purpose": "只取唤醒度，当第二份证据；不拿它判离散情绪"
}
```

- `sha256` 是拷机器时唯一靠得住的校验：文件大小对了也可能坏。
- `version` 要和插件代码里认的版本对齐；插件不认识这个版本就降级，不硬读。
- `purpose` 写给以后的人看，免得三年后有人把它当成「情绪分类器」用。

## 插件怎么用

- 启动时看目录在不在、manifest 版本认不认。不在 → 纯 JS 声学（现在这套），
  正常跑，日志里写一句「没装模型」。
- 在 → 多一路证据，仍然只取唤醒度/强度这一维，和字一起交给模型；错了能被纠正。
- 任何情况都不因为模型缺失而报错。

## 换机器

两种都行：

1. **只带档案**（推荐）：新机器上按 manifest 的 `source` 重下，校验 sha256。
2. **直接拷权重**：下载源没了、或者网络下不动时，把整个 `runtime/models/`
   拷过去。ONNX 是跨平台格式，x64 机器之间直接可用；换 ARM 要重新找对应构建。
