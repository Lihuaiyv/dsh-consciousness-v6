## 3. 三个必须知道的结论

### 1) 六库不是版本链，是粒度分层

T1 事实、T2 纪要、T3 日记、T4 原话是**同一件事的不同粒度**，不是同一事实的不同版本。
**跨层做取代是范畴错误。** 跨层只做两件事：标时间、留指针。

### 2) 只有结构信号是干净的

| 基础设施 | 看起来 | 实际 |
|---|---|---|
| `episodes.topics` | 177 条全有主题 | 正文 2-gram 切片（「你还」「还挺」） |
| `entities` | 811 个实体，83.5% 记忆挂上 | 全是 `kind='thing'` 的高频词（「用户」「继续」「好了」） |
| 反思摘要 | 结构清晰 | 1127 条全是同一模板（「1. **事实**：… 2. **偏好**：…」） |

**所以：cosine、2-gram、实体锚全都不可靠。** 实测「小小 vs 小绿」两件不同的事，余弦 0.867。
嵌入剥离模板后标准差反而更小（0.109 → 0.092），区分度更差。

能用的只有结构：同 `fact_key`、同 `turn_id`、同 `episode`。

### 3) 弱标（`memory.passport.weak`）不要开

它打开的「提示」有 8 条是「同主题后面还有更晚的说法」，而「同主题」已被证明大量是词撞车。
给一个已证伪的判定开显示口子 = 把噪音放进注入。数据：开了之后提示 5 → 13，但 token 不涨——问题不是成本，是准确率。

## 4. 模型判断：可行，但有两个大坑

### 结论
让模型判「这两条是不是同一件事」**方法可行**：30 对样本，我人工对照约 **27/30 ≈ 90%**，624ms/次。
明显好于 cosine（分不开）和 2-gram（把 126 对全判成「有更新」）。

### ⚠️ 坑 1：命令行 ≠ 插件运行时（这条我当场搞错过）

- 命令行跑 `node script.mjs` 时，`model.capabilities()` 里 `complete:false`，`model.complete()` 返回假 JSON
  `{"overlap":"unknown","key":"","name":"","definition":""}`（这是 `RulesAdapter` 的兜底，见 `model.js:174`）
- **但插件运行时是通的**。原因：`HostLlmAdapter` 靠插件启动时注入的上下文（`hostLlmGetter`），
  独立进程里是 null，所以整个宿主通道挂不上。
- **判断方法**：`extract` 和 `complete` 走同一个 `HostLlmAdapter._chat`。
  extract 明显在跑（今天 147 条新增里 123 条带检索卡、108 条带 fact_key；抽取队列 2064 条 done）
  → `_chat` 通 → `complete` 通。
- **`primary:"ok"` 不可信**：它只看「有没有任何一个适配器可用」，embedding 通了它就说 ok。

### ⚠️ 坑 2：本机 ollama 的 gemma4:12b 是 thinking 模型

- 走 OpenAI 兼容层（`/v1/chat/completions`）时，300 个 token 全花在思考上，`content` 返回空字符串
- 必须走原生 `/api/chat` 并带 `think: false`，否则拿不到正文
- 只在「用本地模型做实验」时需要，**接入插件不需要**——插件里有宿主模型

### 实验脚本
- `scripts/exp-llm-judge.mjs`：直连 ollama 原生 API 判 10–30 对（`--n 30`）
- `scripts/exp-sameness.mjs` / `exp-sameness-strip.mjs`：cosine 与剥模板对比
- 全部只读真库，不写库

### 错误模式（已知，可兜）
两次明确错误都是：**同一个专有名词同时出现在两条里**（同一个库名 / 同一个文件名），模型判成同一件事。
可以加规则闸：两条的主语实体不同 → 强制「不同的事」。

## 6. 下一步：把模型判断接进写入门控（未开始）

### 设计约束（三条，别破）
1. **只在灰区调**：相似度落在 0.5–0.9 之间才问模型；确定性命中（同 key、明确否定）不调
2. **结果落库缓存**：同一对记忆只判一次，别重复花钱/耗时
3. **模型不可用就退回现状**：不判、只标日期，绝不阻塞写入

### 接入点
- `src/modules/gate.js` 的 `decideWrite` / `applyWrite`：判「这是同一件事的后续」还是「两件不同的事」
- 夜间整理（`nightly`）：批量判当天没判干净的候选对
- **绝不放在注入路径上**（那是几十毫秒的预算）

### 三档比两档更合适
现在只有「同一件事 / 不同的事」。要判「是不是更新」，还得多一档：
**取代 / 补充 / 无关**。判对「同一件事」不等于「该把旧的退休」——可能只是补充。

### 还没做的验证
- 30 对样本太小，且是我一个人判的（无交叉标注）
- **没有在插件运行时跑过**（只在命令行 + ollama 跑过）。接入前需要先确认走 `model.complete` 也是 90% 左右
