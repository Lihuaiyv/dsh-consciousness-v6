# 零件 · 发信（send）

> 这页给主人看：一句话是怎么从某条通道发出去的。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；工程件：`src/modules/actions/channels.js`，考卷 `test/exam-send.test.mjs`。

## 1. 一句话 + 一个比喻

它管「这句话交给哪条路、按哪个格式送」：企业微信群机器人、QQ 的 OneBot、个人微信窗口。它不管「该不该说」（主动开口），也不管「说什么」。

像门口的三个邮筒：一个通群里，一个通 QQ，一个通微信窗口；信的内容不归它写，它只负责贴对邮票、投对筒、回来说一声「投进去了」或「这个筒坏了」。

真的对应到哪：一个 `{ ok, channel, target, status, detail }` 的回执。

## 2. 它什么时候醒（触发）

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 主动开口 / 工具 | 要发时 | 读配置、选通道、发出去 |
| 设置页的「试一下」 | 手动 | 用同一套口发一条测试 |

没有自己的定时器。

## 3. 醒来之后走哪几步

1. 读配置（`action_config`），没配的用默认值。
2. 选通道：显式指定就用指定的（说微信就是微信，不改道）；`auto` 按顺位 `send.order` 挨个试——默认 **QQ → 企业微信 → 微信**，缺配置的那条跳过，真发失败也换下一条。**微信默认封存**（`wechat.sealed: true`）：它不参加 `auto`，显式点名照样发。
3. 企业微信：拼 `{msgtype:'text', text:{content}}`，超长按 1800 字切片，逐片发，errcode 非 0 就算失败。
4. QQ：私聊打 `/send_private_msg`（`user_id`），群聊打 `/send_group_msg`（`group_id`）；有 token 就带 Bearer。
5. 个人微信：交给本机窗口自动化那条路（4.x 自绘界面要装 Python 后端 wechatauto-replica，光靠 UIA 读不到控件），拿回执。
6. 回执原样交回去，顺带算一个 `conversationId`；发成功的那句话由调用方（工具发信）写进自己的账本。
7. 失败抛错，不吞。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 缺了会怎样 |
|---|---|---|
| 正文 | 调用方给 | 空文本直接拒 |
| 通道 | 调用方给（wechat / wecom / qq / auto） | 不认识的拒 |
| 收件人 | 调用方给，或配置里的默认收件人 | 没有就报缺收件人 |
| 配置 | `action_config`（webhook / token / base_url / 默认值） | 没配的走默认值 |
| 开关 | `action_ports` 只读 | 关着的端口发不出去 |

它不看什么：不判断内容该不该发、不排队、不重试。

## 5. 它怎么判断（判据）

它其实只问三个问题：内容空不空？这条路认不认？对方收了没有？

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 内容空不空 | 去掉空白后非空 | 直接拒 |
| 这条路认不认 | 通道名在四个里；QQ 号是 4–20 位数字 | 拒，给出具体原因 |
| 对方收了没有 | 企业微信 errcode=0 / OneBot retcode=0 | 抛错，带原始返回 |
| 还有没有下一条 | `auto` 时按顺位继续，全都不通才报错 | 报错里写清顺位和每条的原因 |
| 配不配一张图、配哪一组 | 有这组标签就随机挑一张（同一条不连发同一张）；没有就只发文字 | 不报错，退回纯文字 |

表情那部分不单开一页：它没有自己的表、自己的开关、自己的节律，判据也薄（挑组 → 随机），
所以并在这里，只把「配不配图」这条判据单独列出来。等它能自己认表情、自己打标签、自己记账，
再拆成独立一页。

反例：明明配了 webhook，`auto` 却还是先试 QQ——2026-11-07 起主力回到 QQ（微信走窗口自动化，一条要一两分钟，默认封存）；想让它先走企业微信，把 `wechat.mode` 设成 `wecom`，或改 `send.order`；想解封微信就把 `wechat.sealed` 设成 `false`。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 回执 | `{ ok, channel, target, status, detail, conversationId }` | 主动开口 / 工具 / 设置页 |
| QQ 额外 | `message_id` | 调用方 |
| 试过哪几条 | `tried: [{ channel, reason }]`（只在 `auto` 换过道时给） | 工具 / 日志 |
| 失败 | 抛错，带原因（超时 / HTTP / 返回码） | 调用方决定要不要说「没发出去」 |

不发的情况：正文空；通道名不对；没有收件人；对端返回失败。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 微信发不出去，`probe` 读到 0 个控件 | 微信 4.x 聊天界面是自绘的，冷启动 UIA 只给 Qt 空壳 | 装 Python 后端 wechatauto-replica（`pip install wechatauto-replica`），`wechat.backend=auto` 时自动走它 |
| 微信自动化脚本直接退出（exit=1） | 脚本是 UTF-8 无 BOM，Windows PowerShell 5.1 按 GBK 读，中文把引号吃掉；另一处把 `[uint32]` 传给 UIA 的 ProcessIdProperty | 2026-11-07 已修：脚本存成 UTF-8 BOM，进程号按 `[int]` 传 |
| 企业微信发一半失败 | 分片逐条发，中途一条失败就停 | 抛错，调用方知道没发完 |
| OneBot 连不上 | NapCat 没开 / 端口不对 | 错误里写了地址和排查方向 |
| 长文丢后半段 | 个人微信那条路有长度限制 | 已知，企业微信这条会切片 |
| 改一次设置，webhook / token 被抹了 | 设置页回传的是打码值或空串 | 2026-11-07 已修：空串=这次没改，要清空传 null |
| 「演练」一下却真发出去了 | Python 后端 `scripts/wechat-send.py` 没读 `dry_run`，直接调了 `quick_send`（PowerShell 那条是认的，只有 Python 这条漏了） | 2026-11-07 已修：`dry_run` 在 `ensure_gui` / `quick_send` 之前就返回，窗口一次都不碰 |
| QQ 里的图一张都发不出去 | 桥的 cwd 在 `C:\Users\ygys1\.dsh\qq-bridge`，而外发路径的安全策略把 `.dsh` 下任何文件都当凭据拦掉 | 2026-11-07 已修：图放 `C:\Users\ygys1\Pictures\dsh-stickers`，配置里加 `fileSendDirs` |
| 发表情绕过了「污点窗口」 | `qq_face_send` 直连 `sendSegments`，没走 `#sendImageTo` 那道 taint 检查 | 2026-11-07 已修：发之前先问一次，窗口内只回文字 |
| 别人发来的表情收进来却永远发不出去 | 自动收藏时没打标签、名字是 `表情a1b2`，按标签挑不到 | 2026-11-07 先挂 `收藏` 组；按情绪细分还得靠识别 |

## 8. 怎么知道它活着（观察点）

- `action_config` 里最近改过的键。
- 回执的 `status`（sent / dry-run）和 `detail`。
- 失败时的错误文本（通道、地址、返回码都在里面）。

现在就能看：设置页的「试一下」，或看 `action_config`。

## 9. 换它要付什么（代价）

- **能动**：分片大小、超时、默认收件人、顺位（`send.order`）、封存（`wechat.sealed`）。
- **不能动**：说什么（主动开口 / 表达）、发不发（主动开口）。
- **考卷**：`test/exam-send.test.mjs`，42 道，现在 42/42。
- **回退点**：`send-before-part`。
- **换完记在哪**：`parts.js` 的 `swaps`，外加一份 `docs/活论证-发信-<日期>.md`。
