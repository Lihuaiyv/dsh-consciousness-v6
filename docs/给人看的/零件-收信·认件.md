# 零件 · 收信·认件（inbox）

> 这页给主人看：平台递进来的消息，是怎么认成「谁、说了什么」的。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；工程件：`src/host/events.js`，考卷 `test/exam-inbox.test.mjs`。

## 1. 一句话 + 一个比喻

它管「平台递进来的事件，认成谁、说了什么」；不管消息怎么收到（那是平台的事），也不管收到之后怎么处理（那是别的零件的事）。

像门缝里塞进来的信：它只拆开看信封上写的是谁、信里是哪句话，然后把这两样交出去。信怎么送到门口的，不归它管。

真的对应到哪：一个 `{ kind: 'user' | 'assistant' | 'other', text }`。

## 2. 它什么时候醒（触发）

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 平台（`session/event`） | 每条消息 | 认成 user / assistant / other |
| 宿主适配层 | 转出给业务 | 保持老的 import 不变 |

它没有自己的定时器。

## 3. 醒来之后走哪几步

1. 看事件名：`user/message` → 用户；`assistant/message` → 助手；别的 → other。
2. 取消息体：用户消息的 `data` 就是消息本身；助手消息在 `data.message` 里。
3. 取文本：`content` 是字符串就直接用；是块数组就只拼 `type='text'` 的块，别的块跳过。
4. 去掉首尾空白；空的就交空文本，不编。
5. 交回 `{ kind, text }`。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 缺了会怎样 |
|---|---|---|
| 事件名 | 平台给的 `type` | 不认识的当 other |
| 消息体 | 平台的 `data` | 缺了就是空文本 |
| 消息正文 | `content`（字符串或块数组） | 不是这两种形状就当空 |

它不看什么：不碰库、不调模型、不认人、不判断这句话要不要回。

## 5. 它怎么判断（判据）

它其实只问两个问题：这是谁的事件？正文长什么样？

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 谁的事件 | 事件名是 user / assistant | 别的一律 other |
| 正文形状 | 字符串，或块数组里的 text 块 | 非文本块跳过；坏形状给空 |

反例：平台明明发了消息，为什么认出来是空的——事件名变了，或者正文不是它认识的形状。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 一条认好的消息 | `{ kind, text }` | 宿主接线 / 后续的记账与回复 |
| 不认识的 | `{ kind:'other', text:'' }` | 调用方自己跳过 |

不交的情况：没有事件、事件名不是字符串、正文形状不认识——都交空，不猜。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 平台升级后「收不到话」 | 事件名或 `data` 形状变了 | 它会红（考卷喂的是形状），该改的是这一页和代码 |
| 图片、工具块被丢掉 | 只认 `text` 块 | 本来就不该进文本，跳过是对的 |
| 助手消息认成空 | `data.message` 不在 | 交空，不编 |

## 8. 怎么知道它活着（观察点）

- 平台每来一条消息，`readEvent` 就返回一次；index.js 那边拿它记账、回话。
- 考卷 12 道，喂的全是事件形状，不碰平台内部。

现在就能看：`test/exam-inbox.test.mjs`，或者看 index.js 里 `readEvent` 的调用。

## 9. 换它要付什么（代价）

- **能动**：事件名映射、块数组的取法、空值兜底。
- **不能动**：平台怎么收（那是平台的事）、收到之后怎么处理（别的零件）。
- **考卷**：`test/exam-inbox.test.mjs`，12 道，现在 12/12。
- **回退点**：`inbox-before-part`。
- **换完记在哪**：`parts.js` 的 `swaps`，外加一份 `docs/活论证-收信·认件-<日期>.md`。
