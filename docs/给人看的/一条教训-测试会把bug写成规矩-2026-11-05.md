# 一条教训：测试也会把 bug 写成规矩

2026-11-05

## 发生了什么

主动开口（她主动说一句）从 11-03 04:40 起，一次都没通过「注入」这条路送到过。
库里记得很清楚：主动句被预算丢掉 **3387 次**，真进注入 **0 次**。队列里的消息只能等七天过期。

可两天没人发现。因为测试里明写着一条：

> 紧预算先丢主动句

也就是说：测试把「它永远第一个被丢掉」这件事，钉成了「正确」。

## 为什么

- 丢弃顺序里，主动句排**第一**；而注入本身就常年贴着 800 token 的上限。
- 后来加了「只有真进了注入才算说过」（先拼装、后落账）。两条叠在一起：一个永远轮不到，一个永远不认账。
- 测试只测了「顺序对不对」，没测「这条策略在真实预算下会有什么后果」。

## 教训

1. 测试保护的是「现在的做法」，不是「对的做法」。改策略时，先把旧断言反过来，看它原来拦的是哪句话。
2. 凡是「先拼装、后落账」的东西，不能排在第一批被丢——它要靠活下来才能记账，就得给它保底。
3. 界桩要真跑。以前 `check-parts` 只查考卷文件在不在；现在它自己跑，跑挂就红。

## 以后先问三句

- 这条断言，写的时候是想防什么？现在还在防那个吗？
- 把这条断言反过来，谁会疼？疼的地方，就是它一直在遮的地方。
- 这条测试有没有可能永远绿？能永远绿的测试，等于没测。

## 出处

- 修复：`2bcbdd5`（主动句挪到记忆之后才丢；测试反过来钉住）。
- 界桩：`60571b2`（`check-parts` 真跑考卷）。
