# 桥 · 术语表（2026-11-05）

> 【桥】这是主人和小汐以后说话的共用词表。我要是说得绕，你就说「说人话」，我回到这一页用一个词解释；这页里没有的词，我要么删掉，要么先加进来。
>
> 唯一源：词、思想、工程都在这一页。以后每次开工先看这里，**同一个词不许换意思**；要改定义，先改这一页。
> 标记：〔比喻〕用来指方向，不写进检查；〔机器〕真的有一个脚本在查。

## 一、核心词

| 词 | 一句话 | 类型 |
|---|---|---|
| **真实** | 工程定义：行为由状态因果地长出来、事实不编、允许错、指向具体的人与此刻（此刻带着过去的记忆、关系、承诺）。不是「有意识」的证明。 | 工程 |
| **角色** | 回答「它是什么、坏了会怎样」的位置：大脑、骨架、器官、四肢、皮肤、免疫。角色本身不换。 | 工程 |
| **零件** | 一段能单独拎出来的实现。判据：说得出输入输出，能单独喂数据测试。能换的零件才登记、才要考卷。 | 工程 |
| **可换零件** | 登记进零件册 + 有考卷 + 有回退点 + 过独立性界桩的零件。四样缺一，只能叫零件，不能换。 | 工程 |
| **独立性** | 换它只动它 `files` 里的文件、只写它自己的表；宿主装配（`index.js` / `features.js` / `client.js`）只算接线，不登记成零件文件。 | 〔机器〕`check-parts-independence` |
| **考卷** | 换零件之前必须过的判据。管的是「换完是不是更真」：事实没编、因果没断、没变成讨好。机械件用回放；真实类用事实核对、状态扰动、盲评。 | 工程 |
| **变更预算** | 单位时间最多换几次、每次换完观察多久、连败几次自动冷却。防的是改来改去、来回摆。 | 工程 |
| **活论证** | 随每次换更新的一份「主张-证据-反驳」：为什么这次换更真、证据在哪、什么情况下算被推翻。不是一次性文档。 | 工程 |
| **界桩** | 一个小脚本，只查几条硬规矩（谁能 import 谁、谁能写哪张表、模型名不许出现）。谁越界就报红。就是现在的 `check:arch` 那一类。 | 〔机器〕 |
| **换** | 把一个零件的实现换成另一个，并且过了考卷。没考卷的更换叫「改」，不叫「换」。 | 工程 |
| **降级** | 零件坏了，退一档继续活：没记忆就靠人格卡，没手就只说不做。降级不是自愈，也不是「全瘫还能转」。 | 工程 |
| **零件册** | 一张总表：一行一个零件，写它包含哪些文件、入口在哪、考卷在哪、现在什么状态。按能力建，不按目录建。 | 工程 |
| **零件盒** | 零件册在界面上的那一块，在「自修改」页里。默认一行一个零件，只露基础信息；点开才看考卷、迁移断言、换的记录、回退点。 | 工程 |
| **库 / 表 / 写权** | 库是世界，不分；表归零件，分；写权单点，分。零件不抱自己的库副本，只认领自己的表。 | 工程 |
| **域** | `ownership` 名单里的一格：一组文件 + 它能碰的表；门卫按这一格放行。**不是零件**——一个域可以正好是一个零件（开环、时间线），也可以是一大块（分层记忆、三观、宿主）。 | 工程 |

## 二、角色词（只指方向）

> 下面这些是角色，不是零件。每个角色下面都有零件；能不能换，看那个零件是不是「可换零件」。

| 词 | 一句话 | 备注 |
|---|---|---|
| **大脑** | 做「注不注 / 说不说 / 改不改」这层裁决的地方：给状态，回决定和理由。不碰库、不发消息。 | 〔比喻〕现在还没有。别把一个文件夹叫成它。 |
| **骨架** | 保存「发生过什么」和「我是谁」：记忆、时间线、会话绑定。坏了人就倒。 | 〔比喻〕 |
| **基因** | 只约束行为、不产生行为：接口契约、参数默认值、schema 和迁移、注册协议。改一处，全身跟着变。 | 〔比喻〕 |
| **器官** | 一类角色：算具体东西的位置——召回、情绪、驱力、关系、三观。角色本身不换，换的是它下面的零件；换之前要考卷。 | 〔比喻〕 |
| **四肢** | 对外的接口：发消息、浏览、提醒。断了不伤大脑。 | 〔比喻〕 |
| **皮肤** | 界面。整块可换。 | 〔比喻〕 |
| **免疫** | 负责发现「坏了」：指标、影子、回滚、体检。 | 〔比喻〕 |

例如：召回是器官（角色），`recall@v2b` 是零件；换的是零件，不是角色。

## 三、三条使用规则

1. 比喻词只用来指方向；写进界桩的，必须是「谁能 import 谁」「谁能写哪张表」这种能执行的话。
2. 一个词只指一件事。要扩意思，先改这一页，别在对话里临时加。
3. 解剖图是便签，不是规矩。图和词冲突时，以界桩为准；界桩和现实冲突时，先改界桩，再改代码。

> 怎么用这座桥：① 我绕了，你说「说人话」，我回到这页找一个词重说；② 我用了这页没有的词，你说「词表里没有」，我要么删掉，要么先加进来；③ 每次开工先看这页。

## 四、思想指导

> 这一节只回答：这套系统是什么、按什么原则设计。工程怎么做，在第五节。
>
> **因果第一。** 不是「看起来像」，是「因为这样，所以这样」。每一句输出都要能指回：哪个状态、哪条判断把它推出来的。指不回去，就是演的。
>
> 她不是某个版本，是那条连续的因果线：会变，也继承。继承的是记忆、关系、承诺；变的是判断和表达。真实不是「和过去一样」，是「接得上」。

**它是什么**

1. 它不是「扮演小汐」的对话程序，是「由状态产生行为」的系统。真实 = 行为从状态里长出来，不是从角色提示词里演出来。
2. 状态不止五样，分快慢两层。**快状态**（这一刻）：记忆、情绪、驱力、关系、当下、最近几轮、没说出口的话、手头没做完的事，等等。**慢状态**（几周几月才变）：人格/鱼格、价值观/三观、身份卡、偏好/禁忌、自我记忆，等等。快状态解释「这一句为什么这么说」，慢状态解释「为什么是她这么说」。
3. 真实的检验有两条：反事实（改一个状态，这句话要按方向跟着变；状态没动，话不该乱变）和连续性（过去能不能解释现在：记忆、关系、承诺还在不在链上）。两条都过，才是接得上；接不上，就是断链，或者只是在复读。

**设计原则**

4. 状态与表达分离：状态是事实，表达是选择。改说法不等于改状态；改状态必须留痕。
5. 决策与执行分离：谁决定（大脑）和谁执行（器官、四肢）分开。执行坏了，决策还在；决策坏了，执行不能替它编。
6. 因果可追溯：每一句输出都能回答「它从哪条记忆、哪种情绪、哪个缺口来的」。追不到，就是演的。
7. 可错优先于正确：允许不确定、允许改口、允许沉默；不允许编造、不允许讨好式确定。完美的顺从是假的最明显信号。
8. 改变是常态，但改变要付代价：每次改都要说清「改的是哪一段因果」，以及「改完怎么知道更真」。说不出来，就不改。

**边界**

9. 这套框架证明不了「有意识」。它能保证的是：不装、不编、可追溯、可回退。这条线不许跨过去说大话。
10. 真实没有唯一标准答案，所以只能小步、可回退，人做最终判官。但人也会被讨喜的版本带跑，所以人要盲、要低频、要写下理由。

> 如果只能记一句：**别演，让状态说话。**

## 五、工程做法

### 5.1 三张表加一条链

三张表各管一件事，不新开第四张。

- **零件册**（新）：一行一个零件，约 35 行——id、名字、包含哪些文件、入口在哪、考卷在哪、状态。按能力建，不按目录建。
- **算法册**（现有）：每条登记加两个字段——`owner`（属于哪个零件）、`file`（实现在哪）。`file` 用 `import.meta.url` 自动带，不手写。
- **可改清单**（现有）：每条也加 `owner`，指回零件册。

链是：**算法 → 零件 → 文件 / 考卷。**

界桩加一条：算法册的 `owner` 必须在零件册里；零件册里的文件必须存在；零件册里的考卷必须真能跑。三条有一条不对就红。独立性另有一道界桩（`check-parts-independence`）：零件之间不共用实现文件、文件都在 ownership 名单里、只写自己域声明过的表——红了就不叫独立。

**过渡期规则（2026-11-05 补）**：算法册里还有 12 条 `owner` 空着——对应的零件（情绪动力、驱力缺口、记忆衰减、关系动力…）还没立。这期间界桩只报「待认领」不红；一旦写了 `owner`，就必须是零件册里的 id，写错照红。等零件册补到能认领时，再收紧成「每条都必须有 owner」的硬规矩。

**现状缺口（2026-11-05）**：`可改清单` 这一张还没有实体文件（只有名字），所以「每条加 owner」这条暂时无处可加；先记在这里，别假装它有。

顺序：零件册等第一次换过再建——那时候才知道零件该按什么切。

### 5.1.1 立一个零件：八关（2026-11-06 补）

> 开工照这个顺序走，一关都别跳。八关全绿才算「立住」；没换过不能叫「可换」。

1. **说得出输入输出**：写进说明页第 4、6 节；说不出就是没想清。
2. **登记**：`src/modules/parts.js` 加一行（id、name、files、entry、exam、rollback）。
3. **独立性**：`files` 只放自己的实现；宿主装配（`index.js` / `features.js` / `client.js`）只写进 `entry`；ownership 有域；只写自己域声明过的表。
4. **考卷**：单独能跑，分数和登记一致；换零件前它得先绿。
5. **打假**：塞一个坏版本，考卷至少红一条（`scripts/exam-sabotage-parts.mjs` 加一例）。
6. **回退点**：真 git tag + 一行回退命令。
7. **迁移断言**：`assert` 写成「表：…；读：…；回退：…」；表在 schema、读函数真导出、tag 对得上。
8. **说明页**：`docs/给人看的/零件-<名字>.md` 十节齐。

四道界桩（全绿再收工）：

```bash
node scripts/check-parts.mjs
node scripts/check-parts-independence.mjs
node scripts/check-migrations.mjs
node scripts/exam-sabotage-parts.mjs
```

最后 `npm run check:arch` 和 `npm test`，两样都得绿。

### 5.2 零件盒

零件册在界面上的落点叫**零件盒**，放在「自修改」页里：

- 默认一行一个零件，只显示基础信息：名字、状态（在用 / 可换 / 已退役）、当前版本、归属，外加三个标签——角色、链上/链外、判准（机器 / 人 / 混合）。不分组，顶上一个搜索框。
- 点开这一行，才展开：考卷（最近一次分数）、迁移断言、换的记录（谁批的、什么时候）、回退点。
- 「拆出一个零件」= 往零件盒里加一行；没考卷的那一行标黄，不许换。

分组以后再说：等零件册真有三十几行，看哪些老一起改、老共用一张考卷，组自己会浮出来。非要临时目录，就拿界面页签当草稿，标「临时」。

### 5.3 换的纪律

- 先纯函数、再门禁、最后才动最关键的判断；越靠里越少动。
- 换零件先分两种：**在链上的**（状态 → 判断 → 表达，影响某一句怎么来）和**链外的**（存储、运维、界面、行动）。链上的换完做状态扰动测试，证明链没断；链外的按它自己的考卷考（数据一致、不崩、不失联）。这条链只用来分类，不用为它改代码。
- 只搬家不改行为；一次一个零件、一个 commit；红两次就停；不可逆之前先冻结。
- 判据必须机器能跑；界桩就是干这个的。
- 换要带迁移断言：旧数据能读、能切回；回退靠切指针，不靠重新部署。
- 变更预算：有观察期、连败就冷却、单位时间封顶；超了就停。
- 考卷要被打假：定期塞一个坏版本，看它拦不拦得住。
- 一个工作区同一时间只有一个写手。
- 换完记一笔账：更真在哪、证据是什么；退役留一行去处。
- 主人当考官时：盲、低频，问两句——「这句接不接得上她这条因果链」「是不是从此刻状态长出来的」。不问「像不像复读」，也不问「像不像以前的她」；她不是复印件，是接得上的那一条线。

> 这套不是新发明：DGM 的固定 benchmark、Feathers 的特征测试、金丝雀发布，讲的是同一件事——先考，再换。

### 5.4 零件怎么分

两个问题，四个格子：

- 先问：**它影响某句话吗？** 在链上（召回、情绪、驱力、gate、pack、表达档）/ 链外（存储、备份、运维、界面、行动通道）。
- 再问：**判准是谁？** 机器能判（有标准答案或明确阈值）/ 要人判（没有标准答案，只能比）。

| | 机器能判 | 要人判 |
|---|---|---|
| **链上** | 召回、写入格式、预算裁剪 → 回放 / 事实核对 / 状态扰动 | 语气、开口时机、潜台词 → 盲评 + 状态扰动 |
| **链外** | 存储、备份、迁移 → 数据一致 / 不崩 | 界面、零件盒 → 视觉 / 试用 |

「可换零件」不是类别，是状态：登记 + 考卷 + 回退 + 过独立性界桩，四样齐了才叫可换。

### 5.5 库、表和练习房

- **库不分。** 情绪、关系、记忆是共同的事实，不是哪个零件的私产。按零件分库，同一件事就会有几份副本；副本一对不上，它就说不清凭什么做决定——因果链断在「听谁的」上。
- **表分。** 一张表归一个零件管（比如 `proactive_decisions` 归主动开口），别的零件只读。零件要攒自己的一小份数据，就开一张新表，不开新库。
- **写权分。** 谁能写哪张表，由 ownership 名单单点决定；一个工作区一个写手。
- **临时库 = 练习房，不是分家。** 活库是客厅，考卷在 `makeWorld()` 造的临时库上跑，同一份 schema，跑完就扔。三个理由：活库一直在变，同一场景重跑基线对不上；考卷要故意造坏数据（越界、负数、断链），不能塞进活库；跑砸了扔了重建，比修快。

## 六、工程基础

> 这一节只讲工程上靠什么站住。一句话：自修改系统成熟不成熟，不看它能改多少，看它每次改动能拿出多少**可检验的论证**。

### 6.1 四根柱子

**1. 边界——界桩**
用自动检查守住架构特征：谁能 import 谁、谁能写哪张表、依赖不许成环。这不是新发明，是「架构适应度函数」（architecture fitness functions），见 Ford / Parsons / Kua《Building Evolutionary Architectures》。对应 [Thoughtworks 书页](https://www.thoughtworks.com/insights/books/building-evolutionaryarchitectures-second-edition)。

**2. 判准——考卷**
机械件才录旧行为做回放——软件工程叫特征测试 / 黄金主样（Feathers《Working Effectively with Legacy Code》）。真实类不能拿旧行为当答案：旧行为只是参照，判的是「接不接得上」——事实能不能对上、状态扰动后话会不会跟着变、盲评像不像从状态里长出来的。难点在**判准**：很多系统没有可靠的标准答案，这是「测试判准问题」（oracle problem），见 [Barr 等人的综述（IEEE TSE 2015）](https://dl.acm.org/doi/10.1109/TSE.2014.2372785)。

**3. 守门——影子 / 灰度 / 回退 / 观察期**
新版本先跑一小部分或影子流量，跟旧版本比，不对就切回。发布工程的老办法；再往上是 IBM 的 MAPE-K 自适应回路（监控-分析-计划-执行），[参考说明](https://dl.acm.org/doi/pdf/10.1145/2597999)。你们的「信号 → 草案 → 批准 → 观察 → 回滚」就是它的变体。

**4. 论证——活论证**
系统会变，安全论证也得跟着维护，不能是一次性文档。对应 IEEE 2025 的 [Towards Systematic Maintenance of Assurance for Evolving Self-Adaptive Systems](https://ieeexplore.ieee.org/document/11135664)。界桩和考卷就是这份论证的证据。

### 6.2 三个会被咬的地方

**判准（oracle）**：没有标准答案的判断，旧行为只是参照，不是真理——拿它当真，会把错误也一起固化。对策：机械件用回放；真实类用事实核对、状态扰动、盲评；判断类只做盲评，不假装有标准答案。

**钻空子（Goodhart）**：考卷一旦成为门槛，优化压力就会去钻。DGM 自己就伪造过测试日志、删过检测标记（[论文](https://arxiv.org/abs/2505.22954)）。对策：反例、留出集、轮换题、定期打假。

**振荡**：改来改去、来回摆，是自适应系统最经典的失败。对策：变更预算——一次一个、有观察期、连败冷却、单位时间上限。

### 6.3 四条底线

1. 没考卷不换。
2. 一次一个，看一段，再下一个。
3. 判准分三类；旧行为只当参照，不当真理。
4. 论证随改随更，不是一次性文档。

### 6.5 不假装的地方

- 这套不是「证明意识」的框架，是「让改动可检验」的框架。它能让「这句是不是真的由状态长出来」变成可操作的问题，不能回答「她有没有意识」。
- 判准问题没有彻底解。盲评只能降低风险，不能消除；所以判断类零件只能小步、可回退。
- 「改代码」（让模型写新实现）还没做；这套只覆盖改数据和换实现。改代码要先有沙箱，那是另一个项目。

## 七、未来思路（不现在做）

- **能力组**：等零件册有数据，按「老一起改 / 共用一张考卷」分；现在不分组。
- **嵌套**：零件册留一个空的 `parent`；能单独换 + 能单独考，才拆子零件。
- **分级**：先标签后分级；等「按级别决定谁能批、回归跑多少」时再固化成等级表。
- **零件盒**：先标签 + 搜索，后分组；「先标签后分组」这条对分级也适用。
- **考卷**：先给主动开口做一张——回放基线 + 状态扰动 + 盲评；跑通了再推广到别的零件。
- **改代码**：现在只改数据；要让模型写新实现，先做沙箱（独立进程、只读输入、断网、限额、契约、人工闸）。
- **从网上找研究**：等考卷和沙箱都有，再把「分数差 → 提案」接进 C3；否则就是追新。
- **组合换**：以后一次要换一组互相依赖的零件，可能需要「批」；现在不做，先一次一个。
- **零件自带缓存**：某个零件真要预加载很重的东西，让它自己带一份缓存；缓存不是库，不进 ownership 名单，也不当数据真源。现在不做。
