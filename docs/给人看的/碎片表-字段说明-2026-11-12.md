# 碎片表（fragments）字段说明

> 一句话：**一句一句的原始记录。一行 = 谁、在什么时候、说了什么、当时是什么状态、接自哪一句。**
> 规矩是只追加——不改、不删。这张表是记忆的地基，上面的纪要、日记、记忆条目都是从它长出来的。

- **表名**：`fragments`（2026-11-12 从 `raw_turns` 改的名，老库启动时自动改，不丢数据）
- **现在**：约 12,070 行，14 列
- **位置**：`plugins/runtime/consciousness/app.db`（也是插件包里的 `app.db`）

---

## 14 列，分五组看

### 一、挂回位置的钩子（5 列）

这几列不是内容，是「这句话属于哪只、哪段会话、哪一轮、第几句」。没有它们，一句话就飘着。

| 列 | 装什么 | 现在长什么样 |
|---|---|---|
| `id` | 这条碎片的编号。由「谁+会话+轮次+内容」算哈希得来，同一句话永远同一个号 | `raw_bc28a1c0ddc070a434e1` |
| `agent_id` | 哪一只说的（多开时区分） | `agt_3977d80f17` |
| `session_id` | 哪段会话。网页是一个对话 id，QQ 是 `qq:对方`，微信是 `wechat:某人`，老数据是 `legacy` | `session-bb97…` |
| `turn_id` | 哪一轮。一问一答共用一个号；重放同一轮认得出是同一条 | `turn_mwdiixqu_6mb407` |
| `seq` | 这段会话里第几句，从 1 往上 | `219` |

### 二、是谁、说了什么（3 列）

| 列 | 装什么 | 现在长什么样 |
|---|---|---|
| `role` | **来源**，四样：`owner` 主人 / `self` 我 / `other` 其他人 / `world` 世界（鸟叫、猫、雨、系统通报、工具结果——凡不是「谁在说话」的外来物） | `user`（= owner） |
| `text` | 内容本身。这是这张表的主菜 | 「嘿嘿」 |
| `form` | **形式**，五样：`text` 字 / `voice` 声音 / `image` 图 / `file` 文件 / `data` 数据（波形、采样、数字，比如脑电、心率） | 现在全是 `text` |

> 库里历史值仍是 `user` / `assistant` / `agent`，不动——`id` 是用「谁 + 会话 + 轮次 + 内容 + 时间」算的哈希，改来源会把 id 和内容拆开，重放同一轮就插重复。读的时候用 `normalizeSource` 抹平成四样：`user`→主人、`assistant`/`agent`→我、`other`→其他人、`world`→世界。词表在 `src/modules/fragment_vocab.js`。

### 三、时间（2 列）

| 列 | 装什么 | 现在长什么样 |
|---|---|---|
| `created_at` | 那一刻，UTC 的 ISO 时间 | `2026-11-12T12:38:47.486Z`（本地 20:38） |
| `day` | **本地日**，用来按天分组（日记、夜间整理、按天导出都靠它） | `2026-11-12` |

> `day` 不是从 `created_at` 简单切出来的。实测有 293 行两者不一样——那是晚上跨了零点，本地已经第二天、UTC 还是前一天。所以这一列得留着，现算会算错。

### 四、状态与来路（2 列，2026-11-12 新加）

| 列 | 装什么 | 现在长什么样 |
|---|---|---|
| `snapshot` | 写下这一刻的状态截面（JSON）：情绪、驱力、关系、生活、未了。**这一列记的是「我那时是什么样」，不是「我说了什么」** | 刚接上，重启后开始有值 |
| `antecedents` | 这句话接自哪几条（JSON 数组，只许指更早的碎片）。现在只长最硬的一条：同一轮里回答接自那句问话 | 刚接上，重启后开始有值 |

### 五、附带（2 列）

| 列 | 装什么 | 现在长什么样 |
|---|---|---|
| `tool` | 工具名（如果有） | 现在 0 行有值，一直空着 |
| `meta` | 其他附带信息，JSON | 只有 2 行有值：微信那两条的 `{"channel":"wechat","chat":"filehelper","type":"文本"}` |

---

## 三条规矩

1. **只追加**：不改、不删。写错了也不回头改，另写一条说清楚。
2. **快照只写出生那一刻**：后来的情绪变化另开一条，用 `antecedents` 指回去。不要回头补写，那等于拿今天的我冒充当时的我。
3. **接自只指更早的碎片**，0 到多条。它表示「接在谁后面」，不是因果。

---

## 一句话认这 14 列

> `id` 编号、`agent_id` 哪只、`session_id` 哪段、`turn_id` 哪轮、`seq` 第几句、`role` 谁、`text` 说了什么、`form` 什么形式、`created_at` 什么时候、`day` 哪一天、`snapshot` 当时什么样、`antecedents` 接自谁、`tool` 用了什么工具、`meta` 其他附带。

---

## 为什么没压成 12 列

2026-11-12 讨论过一版「干净 12 列」（改名 `source`/`content`/`at`，`tool` 并进 `meta`，删 `day`）。结论是**不做**：

- 省不下空间（`day` 一共十几万字节，`tool` 全空）；
- 要动 55 处查询，一处漏了就静悄悄错；
- 最要命的是 `id` 的指纹里含 `role`，改了名同一句话会算出两个 id，把「只追加、id 稳」这条从里面捅破。

所以结构先停在这儿，力气花在让 `snapshot` / `antecedents` 真长出东西，而不是让列名好看。
