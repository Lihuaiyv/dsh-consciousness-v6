# 零件 · 记忆存储（memory）

> 这页给主人看：一条记忆是怎么写进抽屉的。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；工程件：`src/modules/memory.js`，考卷 `test/exam-memorystore.test.mjs`。

## 1. 一句话 + 一个比喻

它管「一条记忆怎么写进 T1 抽屉」：写标签、盖出生章、同一把钥匙的旧说法换下来、两条对不上的先别撕。它不管「该不该记」（那是记忆写入闸）、不管「以后怎么变淡」（记忆衰减与分层）、不管「怎么被翻出来」（召回）。

像抽屉口的登记台：新纸条先看是不是已经有一张一样的，再看有没有同名的旧纸条，再听两句是不是在吵架——然后才放进抽屉，顺手在档案柜里留一张出生照。

真的对应到哪：`memory_items` 一行 + `memory_fts` 检索卡 + `fact_archive` 出生照 + 事件。

## 2. 它什么时候醒（触发）

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 抽取 / 手记 / 夜里 | 有东西要记时 | `addMemory` 写一条 |
| 人 / 界面 | 手动 | 软删、恢复、改标记、挂实体 |

它没有自己的定时器。

## 3. 醒来之后走哪几步

1. 校验：正文 1–4000 字、类型只能是 fact / episode / appraisal / reflection / conflict。
2. 去重：完全一样 → 不新建，返回原来那条。
3. 同键：同一个 `fact_key` 的旧说法当场退场（`invalid_at` + `superseded_by`），不删。
4. 冲突：同一属性取值不同、或一正一负两条很像 → 高风险开案、旧条退场、发告警、排一句「要不要我改过来」；低风险两条都留。
5. 落库：正文、重要度 / 显著度 / 置信、检索文本、热度与层、实体连边。
6. 出生照：把这句当时的样子抄进 `fact_archive`，之后衰减、合并、推翻都不动它。
7. 事件：`memory.written`（写进去了）、`memory.conflict`（吵起来了）、`memory.archive_failed`（出生照没拍成）。
8. 软删 / 恢复：只改 `deleted_at`，不真删。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 缺了会怎样 |
|---|---|---|
| 正文 | 抽取 / 手记 / 自述 | 没有就拒 |
| 类型 / 来源 | 调用方给 | 默认 fact / manual |
| 重要度 / 显著度 / 置信 | 调用方给 | 默认 0.5 / 0 / 0.8 |
| 键（fact_key） | 抽取 / 手写 | 没有就不做同键取代 |
| 实体 | 抽取 | 没有就不连边 |
| feel 的 id | 装配层注入的取数口 | 没有就不挂 |
| 冷层标记 | 写入闸给的 `cold` | 没有就按热度算 |

它不看什么：不直接读情绪表（feel 由外部注入）、不判断这句话值不值得记、不做衰减、不做召回。

## 5. 它怎么判断（判据）

它其实只问三个问题：已经有了吗？有没有同名的旧说法？这两条是不是对不上？

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 已经有了吗 | 文本相似度到重复线 | 返回旧条，不新建 |
| 同名旧说法 | 同一个 fact_key | 旧的退场，新的接着用 |
| 对不上吗 | 同属性取值不同，或一正一负且相似 | 高风险开案；低风险两条都留 |

反例：明明该记一条新的，为什么只回了旧 id——它判成完全重复了。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 抽屉 | `memory_items` 一行（active） | 召回、衰减、日记 |
| 检索卡 | `memory_fts` 一行（检索文本，不是原文） | 召回 |
| 出生照 | `fact_archive` 一行 | 深查、回溯 |
| 冲突 | `conflicts` 一行（open / resolved） | 界面、主动开口 |
| 告警 | `alerts` 一行 | 界面 |
| 事件 | `memory.written` / `memory.conflict` | 翻账 |
| 软删 | `deleted_at` 非空 | 恢复时清掉 |

不写的情况：正文空或超长；类型不对；完全重复；被写入闸拦在门外（那是上一个零件的事）。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 同一句话存了两遍 | 相似度没到重复线 | 记下 duplicate 的判断线，可调 |
| 旧说法还挡在新说法前面 | 没给 fact_key | 同键才自动退场；没键靠冲突或人工 |
| 冲突误判 | 两条话题像、其实不矛盾 | 低风险只留记录；高风险要人拍 |
| 出生照没拍成 | 归档那边写失败 | 记 `memory.archive_failed`，正文照样进抽屉 |

## 8. 怎么知道它活着（观察点）

- `memory_items` 里 `status='active' AND invalid_at IS NULL` 的条数在涨。
- `fact_archive` 的条数跟抽屉大致对得上（出生照）。
- `conflicts` 里 open 的条数；`alerts` 里 `kind='data'`。
- `events` 里 `memory.written` 的时间。

现在就能看：查 `memory_items` 最近几条，或看 `conflicts` 有没有 open。

## 9. 换它要付什么（代价）

- **能动**：去重线、冲突判定、同键取代、冷层标记、软删策略。
- **不能动**：衰减与分层（冷暖）、召回（召回）、值不值得记（门卫）。
- **考卷**：`test/exam-memorystore.test.mjs`，36 道，现在 36/36。
- **回退点**：`memorystore-before-part`。
- **换完记在哪**：`parts.js` 的 `swaps`，外加一份 `docs/活论证-记忆存储-<日期>.md`。
