# 零件 · 听见（ear）

> 这页给主人看：它是什么、什么时候醒、看什么、怎么判、交出什么、哪里会错。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；词以 [术语表](术语表-2026-11-05.md) 为准。
> 状态：**已立（11-07）**。登记在 `src/modules/parts.js`，考卷 `test/exam-ear.test.mjs`，回退点 `ear-before-part`。
> 工程件：`src/parts/ear/`——`index.js` 是入口，`probe.js` 管体检和修头，`engine.js` 管 ffmpeg 和识别服务。

## 1. 一句话 + 一个比喻

它管「一段声音变成字」，不管这段字要不要信、要不要回、要不要记——那些分别是认人、主动开口、说话分寸、记忆写入闸的事。

像耳朵边坐着一个速记员：你说什么他记什么；他不问你为什么说，也不替你回答。

真的对应到哪：一次转写调用——进去是一段音频字节，出来是一行字，或者一句人话的失败原因。

## 2. 它什么时候醒（触发）

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 她自己（`act_hear` 工具） | 需要时 | 给一个本地音频路径，取来、转规格、交给识别、把字回给她 |
| 别的零件 / 以后的通道 | 需要时 | 调 `transcribeVoice` 就行，入口只有一个 |
| 宿主服务（还没做） | — | 计划里的 `voiceIn`，给外面的 QQ 插件用 |

没有这些，它不会自己动。它没有心跳，也不会自己去翻「有没有新语音」——**现在本仓里唯一的入口就是那个工具**。

## 3. 醒来之后走哪几步

1. 先问通道要素材：能直接给 mp3 最好，给不了再按链接下载。
2. 体检：是不是一段完整音频，头有没有多出奇怪的东西。
3. 转规格：不管原来是 silk、amr，还是别的采样率，一律先转成同一种。
4. 交给识别服务（本地那个），拿回文字。
5. 空文本不当成功：太短、没人说话，都算「没听出字」，报原因。
6. 把字递回去，顺手报两笔账：这段几秒、识别花了多久。

一次走查（按代码路径推的，不是真机记录）：私聊来一条四秒多的语音 → 先要 mp3 → 落一个临时文件 → 转成十六千赫兹单声道 → 识别出一行字 → 这行字带上「[语音消息]」前缀，才进后面的判断。要是那段只是一个「嗯」，它不编字，直接说「可能是录音太短或没人说话」。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 新鲜多久 | 缺了会怎样 |
|---|---|---|---|
| 音频字节 | 通道（QQ 语音、本地文件） | 当次 | 没有就什么都不做 |
| 扩展名 | 通道顺带给的 | 当次 | 猜一个；最终靠内容嗅探，不靠名字 |
| 语言 | 配置，默认「自动」 | 长期 | 用自动；中英混说也照判 |
| 识别服务 | DSH 宿主递进来 | 每次调用 | 没装就说「没启用」，并告诉主人装哪个 bundle |

它不看什么：不看谁发的、不看群还是私聊、不看要不要回、不看这段该不该进记忆；**也不存音频**——转完就丢，只把字交出去。

## 5. 它怎么判断（判据）

它其实只问三个问题：这是不是一段能用的音频？规格对不对？有没有真听出字？

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 能不能用 | 有声音数据、不是空的、不是纯噪声头 | 报「音频太短 / 不是完整录音」 |
| 规格对不对 | 转完是十六千赫兹、单声道、十六位、头干净 | 先自己修一遍；修不好报「转出来的音频不符合要求」 |
| 有没有字 | 识别结果不是空 | 报「可能是录音太短或没人说话」，**不编** |

反例：主人明明说了一句「我在」，转出来是空——它不会猜成「我在」，只报没听出字。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 文字 | 一行转写 | 宿主接线，拼进那一轮 |
| 附带的账 | 音频几秒、识别花了多久 | 日志 / 追踪 |
| 失败原因 | 一句人话，比如「首次使用要下载本地语音模型」 | 主人能看到 |
| 事件 | 转写那一步的成功 / 失败 | 追踪 |

你能直接看到的，只有聊天里那句转写，或者那句失败原因。

听不出字的几种情况：音频太短、没人说话、文件坏了、识别服务没装、模型还没下载——五种都不会给一个假的字。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 文件名写着 amr，其实是 silk | QQ 的语音不是 amr，头是 `#!SILK_V3` | 走通道转 mp3，不硬解 silk；真要解，得用编码器现造一段真 silk 来考，不能拿 wav 糊过去 |
| 文件头前面多一个字节 | QQ 存文件时会多 `0x02` / `0x03` | 这一层没做；现在靠通道转码绕开 |
| 转完平台报「Invalid speech WAV」 | ffmpeg 会写 LIST 元数据，`data` 就不在第三十六字节 | 已经自己重建头部，只留 fmt 和 data（10-04 真机事故） |
| 名字老听岔 | 本地识别没有词表接口，塞不进专有名词 | 纠错表还没做，只能事后改 |
| 云端识别要密钥 | 默认走本地，云端要另配 | 没配就明说，不静默失败 |

这块我不假装绿：纠错表没有，真 silk 也没有实测过。写在这里，比假装过了强。

## 8. 怎么知道它活着（观察点）

- 追踪里「语音转文字」那一步：成功带耗时，失败带原因。
- 日志里出现「首次使用要下载本地语音模型」，说明模型没就绪。
- 一条最笨的检查：给机器人发一条语音，看回的是字，还是一句失败原因。

正常是字出来、耗时不离谱。异常是连续空文本，或者每条都报格式问题。

## 9. 换它要付什么（代价）

- **能动**：格式探测、转码参数、识别提供方（本地 / 云端）、纠错表、超时。
- **不能动**：不写记忆、不发消息、不决定回不回、不存音频。
- **考卷**：`test/exam-ear.test.mjs`，27 道，现在 27/27。另有两个坏版本打假：采样率不查、空文本当成功，卷子都拦得住。
- **回退点**：`ear-before-part`。它打在搬家前那个 commit 上，新文件不在里面，所以回退是「删目录 + 删登记行」，不是一 checkout 就回来。
- **换完记在哪**：`parts.js` 那一行的 `swaps`，外加一份 `docs/活论证-听见-<日期>.md`。
