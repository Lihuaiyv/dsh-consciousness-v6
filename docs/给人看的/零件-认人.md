# 零件 · 认人（who）

> 这页给主人看：它是什么、什么时候醒、看什么、怎么判、交出什么、哪里会错。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；工程件：`src/modules/who.js`、考卷 `test/exam-who.test.mjs`。

## 1. 一句话 + 一个比喻

它管「**这条消息是谁说的**」，不管「关系怎么变」。

像门口的收发室：每封信进来，先看信封上写的是谁寄的；信封上没写，才当成家里人递进来的。

真的对应到哪：信封 = 通道（`ui` / `qq` / `wecom`），寄信人地址 = 句柄（`local` / QQ 号 / 群名），家里人 = 主人。

## 2. 它什么时候醒

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 编排层做关系偏置 | 每轮对话 | 拿「当前说话人」的亲近 / 信任 |
| 开口判断算主动意愿 | 每次判断要不要开口 | 拿 TA 的层级 / 亲近 / 信任 |
| 关系入账 | 每句话进来 | 这一条暂时还走关系动力自己的老路（下一步收口） |

没有这些调用，它不会自己动——它不挂定时，也不写库。

## 3. 醒来之后走哪几步

1. 拿通道 + 句柄，去通道登记里**精确**找。
2. 找到 → 就是那个人（来源记 `channel`）。
3. 没找到 → 退到主人（来源记 `owner`）。
4. 连主人都没有 → 返回空，调用方自己降级。

真实走查：QQ 上绑过「文钊」，句柄 `123` 的消息进来 → 认成文钊；同一个群里没绑过的句柄 → 认成主人（这是已知坑，见第 7 节）。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 缺了会怎样 |
|---|---|---|
| 通道 | 调用方传（`ui` / `qq` / `wecom`） | 默认 `ui` |
| 句柄 | 调用方传（`local` / QQ 号 / 群名） | 默认 `local` |
| 人物行 | 关系账本里的人物卡 | 没有就返回空 |

**它不看什么**：不看语气、不看内容、不猜「这大概是主人吧」。猜，就不叫认人。

## 5. 它怎么判断

其实只问一句：**这个通道 + 这个句柄，登记过谁？**

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 通道登记里有这一条吗 | 通道和句柄都完全一样 | 退到主人 |
| 有主人吗 | 账本里有一张 owner 卡 | 返回空 |

反例：你换了 QQ 号、没重新登记——它会把你认成主人。不是它猜错，是登记里没有新号。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 认出来的人 | 人物行（id / 名字 / 层级 / 亲近 / 信任） | 编排层、开口判断 |
| 来源 | `channel`（通道认的）/ `owner`（兜底） | 查问题时用 |
| 认不出 | 空 | 调用方自己降级 |

你能感知到的只有后果：这句话里的「亲近 / 信任」是按谁算的；这个函数本身没界面。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 群里每个人都算成主人 | 群消息的句柄没按人区分 | 群聊场景要单独登记句柄 |
| 换了号被认成主人 | 新句柄没登记 | 重新登记通道 |
| 两个人绑同一个句柄 | 查询只取一行，先绑的赢 | 绑之前查一下 |
| 认不出时关系偏置变中性 | 返回空，调用方兜底 | 降级是设计好的，不是坏了 |

还有一个没接过来的口子：关系动力内部的 `bumpRelation` 仍是「主人优先」，没调到这里（反向 import 会成环）。这是下一步收口点，写在这里不藏。

## 8. 怎么知道它活着（观察点）

- 看 `rel_channel` 表：通道 / 句柄 / 对应的人。
- 看返回值里的 `source`：`channel` 才是真认出来，`owner` 是兜底。
- 异常长相：明明是文钊的号，却返回主人——先去通道登记里找那一行。

## 9. 换它要付什么（代价）

- **能动**：认人的顺序与兜底（通道优先、主人兜底、没有就空）。
- **不能动**：`rel_channel` 的写权归关系动力；这里只读。
- **考卷**：`test/exam-who.test.mjs`，11 道，现在 11/11。
- **回退点**：`who-before-part`。
- 换完记在零件册的 `swaps` + 一份活论证。
