# 零件说明怎么写（给人类看的那一页）

> 这一页是模板，也是规矩。以后每多一个零件，就照这个骨架写一页 `零件-<名字>.md`；写之前先读这一页。
> 参考三样东西：[Diátaxis 的「解释」](https://diataxis.fr/explanation/)（讲 why，不是操作步骤）、[「参考 vs 解释」](https://diataxis.fr/reference-explanation/)（表格留给查阅，正文用来理解）、简明语言原则 ISO 24495-1（读者优先、一句一个意思）。
> 一句话规矩：**让不看代码的人，读完能自己判断「它靠不靠谱、哪里可能坏」。**

## 一、先想清楚三件事

1. **谁读**：主人。不读代码，但要决定「这个零件值不值得留 / 要不要换 / 坏了怎么办」。
2. **读完能答什么**：六个问题——它是什么、什么时候醒、看什么、怎么判、交出什么、什么时候会错。答不出，就是没写清。
3. **边界**：只讲这个零件。怎么改它 → 计划 / 交接；完整函数签名 → 附录；以后可能怎样 → 计划。

## 二、骨架（十节，顺序别换）

### 0 页头

三行：这页是什么 / 谁看 / 工程件在哪。不写「本文旨在阐述」。

### 1 一句话 + 一个比喻

- 一句话用「它管……，不管……」；「不管」必须写，防止把它当万能。
- 一个生活比喻，一句话，正文里反复用同一个，别换。
- 比喻后面要跟一句「真的对应到哪」，比喻只帮理解，不替代事实。

### 2 它什么时候醒（触发）

一张表，三种叫醒方式：它自己（心跳）/ 你叫它 / 别的零件调它。每行：谁叫、多久、醒来做什么。
最后一句：没有这些，它不会自己动。

强调：**「每 15 分钟醒一次」不等于「每 15 分钟说一句」**——醒是查看，说是另一回事。

### 3 醒来之后走哪几步（流程）

编号步骤，一步一句；分叉写「如果……就……，否则……」。
可以给一个 10 行以内的流程图。
最好给一次真实走查：某天几点、看到什么、判成什么、最后发生了什么。走查比任何描述都好懂。

### 4 素材从哪来（输入）

两张表：别人递的 / 它自己翻的。每行：人话名、从哪来、多久算新鲜、缺了会怎样。
单独一段「它不看什么」——这比「看什么」更能说明它的边界。

### 5 它怎么判断（判据）

先用一句话说清它其实在问几个问题（比如「想要吗」「合适吗」）。
每个判断点一行：它在问什么 / 什么算过 / 没过会怎样。
数字不进正文：正文说「大约」「通常」，精确值放附录。
给一个「反例」：明明你觉得该说，它为什么没说。

### 6 它交出什么（输出）

分层写：判断结果 → 句子 → 排队 → 真正送达。每层：长什么样、落在哪、谁接。
最后一句：你能感知到的只有哪一层。
必须列「不说的几种情况」——人最想知道「为什么没动静」。

### 7 它什么时候会错（已知坑）

表：现象 / 原因 / 现在怎么办。三到五条，写真实发生过的，不写假想。

### 8 怎么知道它活着（观察点）

看哪里（面板 / 表 / 日志）、正常长什么样、异常长什么样。给一条「现在就能看」的路径或命令。

### 9 换它要付什么（代价）

能动的、不能动的、考卷、回退点、换完记在哪。

### 10 附：这页造的词

这页内部用的词 ↔ 代码里的名字 / 表名。只列这页出现的，别抄术语表。

## 三、语言规矩（七条）

1. **先人话，后代码名**：正文写「由头」，括号里写「（代码里叫 `trigger`）」。代码名是脚注，不是主语。
2. **一句一个意思**：超过 30 字断句；一段不超过 5 行。
3. **不用黑话**：「链路」「闭环」「赋能」「对齐」一律换成「第几步」「回到哪」「谁交给谁」。
4. **数字放附录**：正文说「大概」「通常」，附录给 0.68 / 21/21 / 120 条。
5. **代词有主人**：它 = 意识体；这个零件 = 主动开口；这页 = 文档。不混。
6. **一个比喻用到底**：开头选一个，后面别换；换了读者要重新建图。
7. **不确定就写不确定**：「现在还不确定」「这块没测过」，不糊过去，也不编。

## 四、自检（交给主人前念一遍）

- [ ] 不看代码的人，能说出它什么时候醒吗？
- [ ] 能说出它看什么、**不看什么**吗？
- [ ] 能说出它怎么判、为什么这么判吗？
- [ ] 能说出它交出什么、谁会看到吗？
- [ ] 有没有拿「代码就是这样」当理由？有就补一句为什么。
- [ ] 数字是不是都挤在正文里？
- [ ] 比喻有没有中途换掉？
- [ ] 「不说的几种情况」写了吗？
- [ ] 有没有一段其实是写给工程师看的？有就移到附录。

## 五、一个反例（别这么写）

> 「`decideSpeak` 返回 `will / reason / gates`，由 `queueProactive` 消费。」

问题：主语是代码；读者不知道谁在什么时候调它；「消费」是黑话；没说失败会怎样。

改成：

> 「它每次醒来只做一件事：决定这次说不说。说，就交给下一步去写句子；不说，就记一条『为什么没说』。你之后能从这条记录里看到原因。」

## 六、和术语表的关系

- 词的定义以术语表为准；这页可以造「零件内部的小词」（比如「由头」「劲头」），但必须在第 10 节登记，且只在这页用。
- 一个词只指一件事；这页造的词不许跟术语表打架。
- 这页跟代码冲突时，以代码为准；改完代码，回来改这页。
