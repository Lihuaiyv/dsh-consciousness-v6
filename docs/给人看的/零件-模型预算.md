# 零件 · 模型预算（budget）

> 这页给主人看：她夜里提炼、写日记、蒸馏，今天还能不能再叫一次模型。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；工程件：`src/modules/llm_budget.js`，考卷 `test/exam-budget.test.mjs`。

## 1. 一句话 + 一个比喻

它管「今天这几种模型调用还剩几次」，不管那一次调用写进哪条记忆，也不管三观自己的那本账。

像电话卡上的日流量：打之前看还剩多少，打完划一笔。卡是不限额的时候，它只记账，不拦。

真的对应到哪：一笔 `{ day, cap, used, left, detail }`，外加「这次许不许」「今天的抽取要不要推迟」。

## 2. 它什么时候醒（触发）

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 提炼 / 蒸馏 / 日记 / 抽取 | 每次真的叫了模型 | 往当天的桶里记一笔 |
| 抽取要开工之前 | 同一天 | 问还该不该跑，不该就推迟 |

它没有自己的定时器。没人叫，它不动。

## 3. 醒来之后走哪几步

1. 读日顶。写成 0，或没拧过，就是不限额。
2. 读今天已经用了多少，以及五种桶各多少：提炼、聚类、日记、蒸馏、抽取。
3. 有人问「还能不能再来一次」：不限额就许；有顶就看剩下的够不够这一次。
4. 有人说「这次成了」：总数加，对应的桶也加。不认识的种类算抽取。
5. 有人问「抽取要不要让一让」：顶见底，就说让；蒸馏还开着并且蒸馏桶满了，也说让。否则说不用让。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 缺了会怎样 |
|---|---|---|
| 日顶 | 参数 `memory.llm.daily_cap` | 默认 0，不限额 |
| 蒸馏开不开 | 参数 `memory.episode.distill` | 默认开 |
| 蒸馏自己的顶 | 参数 `memory.episode.distill.daily_cap` | 默认 6 |
| 今天用了多少 | 共享便签 `flags`，键带日期 | 没有就是 0 |

它不看什么：不看记忆正文，不看三观那本账，不决定这句话好不好。

## 5. 它怎么判断（判据）

它其实只问两句：今天还够不够，以及抽取该不该让路。

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 还够这一次吗 | 不限额，或用掉的加这次仍不超过日顶 | 不许，调用方不该再打 |
| 抽取要让吗 | 顶还有剩，并且蒸馏没满（或蒸馏关着） | 推迟。顶见底优先于蒸馏满 |

反例：明明记了很多次，它还说许——日顶仍是 0。不限额时它只记账。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 许不许 | `{ ok, used, left, detail }` | 要打模型的那一方 |
| 记完一笔 | 同一形状，used 已加上 | 调用方自己留着看 |
| 要不要推迟 | `{ defer, reason }` | 抽取。`daily_cap` 或 `distill_cap` |

不挡的情况：日顶是 0。这时 left 是无限，`ok` 一直是真。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 记了很多仍不拦 | 日顶默认 0 | 把 `memory.llm.daily_cap` 拧成正数才挡；最大记到 64 |
| 三观的调用没进这本账 | 三观自己有预算，故意不挤这一本 | 别改种类名单去收它 |
| 文件里有一句「把抽取推迟到明天」 | 写了，没有别的文件在叫它 | 现在真正生效的是「该不该推迟」那个判断，不是那句改队列的话 |

## 8. 怎么知道它活着（观察点）

- 便签键：`llm.budget.used:<谁>:<日期>`，旁边有一笔分桶明细。
- 考卷 16 道，喂的是假的一天，不打模型。

现在就能看：`node test/exam-budget.test.mjs`。

## 9. 换它要付什么（代价）

- **能动**：日顶默认、五种桶的名字、蒸馏满了让不让。
- **不能动**：三观自己的预算；记忆正文怎么写。
- **考卷**：`test/exam-budget.test.mjs`，16 道，现在 16/16。
- **回退点**：`budget-before-part`。
- **换完记在哪**：`parts.js` 的 `swaps`。
