# 零件：召回

> 这页是什么：一个零件的说明书——它管什么、什么时候醒、怎么判、交什么、哪里会坏。
> 谁看：主人。不读代码，但要判断「它靠不靠谱、要不要换」。
> 工程件：`src/modules/retrieve.js`（主入口 `retrieve`），考卷 `test/exam-recall.test.mjs`（76 道）。

## 1. 一句话 + 一个比喻

它管「这一轮该想起哪几条」，不管「想起来之后怎么放进提示词」，也不管「想起来了要不要说」。

比喻：**图书馆管理员**。你问一句，他从几个架子上抽出几张卡片，每张卡片上写着「我是从哪条线索找到的」。卡片递给下一个零件；怎么把卡片摆到桌上、摆几张，不是他的事。

对应到真的：管理员 = `retrieve`；架子 = 分区（T1 事实、T2 纪要、T3 日记、T4 原文）；卡片 = `items`，每张带证据分 `e` 和「凭什么进来」的 `via`。

## 2. 它什么时候醒

| 谁叫 | 多久 | 醒来做什么 |
|---|---|---|
| 每轮用户消息（宿主 `agent/pre-step`） | 每句话一次 | 拿这句话去翻，回来的结果进这一轮的提示词 |
| 模型主动查（检索工具） | 她说「我去翻翻」时 | 用同一个入口，但门槛压到很低，把相关的那层都交回去 |
| 接口调试（`GET …/retrieve?q=`） | 你点按钮时 | 同样翻一次，把场景、证据分、名次一起给你看 |

它自己没有心跳。没人叫它，它就安静。

## 3. 醒来之后走哪几步

1. 认场景：这句话是随便聊聊（S1）、在回看（S2），还是在问「记不记得」（S3）。
2. 洗查询：把「上次 / 那个 / 说的」这类场景词洗掉，剩下的才是真在问的东西。
3. 按场景翻架子：S1 翻事实 + 日记；S2 翻纪要和原文；S3 四个架子都翻。
4. 算证据分：每条候选和这句话到底对得上多少。
5. 过门：低于这一场景的准入线就不要；S1 一条都过不了，就自动升级成 S3 再翻一遍。
6. 融合：只按名次混，不混各架子的原始分。
7. 忘掉该忘的：可提取性低于阈值的，不再想起。
8. 重排 + 去重：热度高的略前；六条里不要三条说同一件事。
9. 补名额：重要度锚点、今天新近、她自己的事、「我好像就是这样」各留位置。
10. 截到 k 条，交出去。

走查（真实数据里的一天）：你问「咖啡」，管理员翻事实架子，捞到「用户喜欢喝美式咖啡」，证据分满分；猫那条对不上，不要；锚点那条「答应过把图重画」再补一个名额。这一轮交回两条：咖啡 + 承诺，各带「为什么被捞上来」。

## 4. 素材从哪来

别人递的：

| 人话名 | 从哪来 | 多久算新鲜 | 缺了会怎样 |
|---|---|---|---|
| 这一句话 | 用户消息 | 就是现在 | 没有查询，只能空翻——空翻时只出配额位 |
| 上一句用户话 | 会话上下文 | 上一轮 | 指代词接不上（「那个库」找不到「库」） |
| 心情 | 情绪零件 | 此刻 | 少了「心情一致」的加成，不影响字面召回 |

它自己翻的：事实 / 纪要 / 日记 / 对话原文；还有检索卡上的同义词、实体别名、记忆之间的连线。

它不看什么：不读参数表（参数由调用方传进来）；不写库（召回只读，热度回写是调用方的事）；不看界面。

## 5. 它怎么判断

其实只问四个问题：

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 这句在问哪一类？ | 关键词认出来，认不出就当随便聊 | 场景猜错，会去翻错架子 |
| 这条够不够格？ | 证据分 ≥ 场景准入线 | 丢掉；一条都不剩就升级再翻 |
| 进来之后谁先？ | 名次融合，再看热度 / 可提取性 | 分低的排后面 |
| 要不要补名额？ | 锚点 / 新近 / 自己 / 模式各留一席 | 不补；重要的事这一轮就不出现 |

反例：你觉得「团子那只猫」该被想起，它没想起——因为「这只」把查询稀释了、三字也对不上，证据分刚好没过门。

## 6. 它交出什么

| 层 | 长什么样 | 落在哪 | 谁接 |
|---|---|---|---|
| 判断 | 场景 + 为什么这么判 | `retrieve()` 返回的 `scene / why` | 注入零件、调试接口 |
| 候选 | 每条带证据分、名次、来路 | `items` | 注入零件挑行 |
| 调试 | 每层进来几条、过门几条 | `debug` | 面板、`retrieval_log` |

不出来的几种情况：没过证据门；被遗忘阈值拦住；被升级后反而没命中；被注入预算挤掉（最后这一条不归它管）。

你能感知到的只有最后一层：这一轮提示词里多了哪几行记忆。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 明明记得却想不起来 | 说法差别大、三字对不上，证据分打折 | 靠扩词、检索卡、实体路补；都不行就深翻 |
| 想起来的不是要的那条 | 同主题太多，先被锚点/新近占了名额 | 锚点有轮转；重复的话题会被热度压下去 |
| 「那个库」接不上 | 上一句不是同一件事，拼接反而带偏 | 只在有明显指代词时拼；拿不准就只按这一句 |
| 旧说法又冒出来 | 回看/深查会带被取代的旧说法 | 旧说法打七折且标「已更新」；S1 不带 |
| 第三人称旁白混进记忆 | 历史摘要与她的记忆同库 | S1 默认不注入；开关打开才带 |

## 8. 怎么知道它活着

- 面板：设置 → 意识 → 检索/记忆那页，能看到最近一次的场景、命中条数。
- 表：`retrieval_log` 里每轮一条，带场景、条数、花了多少 token。
- 命令：`GET /v1/agents/<id>/retrieve?q=咖啡`，看 `scene / items / debug.kept`。

正常：有查询就有场景，命中条数 0～6；异常：永远是 0（多半是查询被洗空或门调太高），或者永远满 6（门太低）。

## 9. 换它要付什么

- **能动的**：证据分、门、融合、配额规则，都可以换实现。
- **不能动的**：输入输出形状（`items` / `debug` / `scene`）；它不写库、不读参数。
- **考卷**：`test/exam-recall.test.mjs`，76 道；界桩真跑。
- **算法册**：`recall@v2 / v2b / v3` 的 `owner` 都指向这个零件；`check-algos` 会查 owner 是否真在零件册里。
- **回退点**：`recall-before-part`（2026-11-05 立零件之前）。
- **换完记在哪**：零件册那一行的 `swaps` + 一份活论证。
