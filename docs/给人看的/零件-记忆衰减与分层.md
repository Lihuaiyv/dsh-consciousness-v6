# 零件：记忆衰减与分层

> 这页是什么：一个零件的说明书——它管什么、什么时候醒、怎么判、哪里会坏。
> 谁看：主人。不读代码，但要判断「它靠不靠谱、要不要换」。
> 工程件：`src/modules/tiers.js`（热度 / 档位 / 可提取性 / 强化）、`src/algo/decay.js`（`decay@v1 / v1b`）、`src/modules/temps.js`（冷热温度状态机），考卷 `test/exam-tiers.test.mjs`。

## 1. 一句话 + 一个比喻

它管「一条记忆现在有多清晰、该沉到哪一层、还值不值得每轮被想起」，不管「这句话该不该被召回」（那是召回零件），也不管「旧事的话要不要说糊一点」（那是注入）。

比喻：**晒被子**。被子晒过就蓬松（热度回升），一直叠在柜子里就潮下去（热度衰减）；什么时候算该收进柜子（冷）、什么时候算该打包搬走（归档），它按天数判。

对应到真的：晒被子 = 被想起一次（`touch`）；蓬松程度 = 热度（`heat`）；潮下去 = 可提取性/温度（`retrievability` / `temp_state`）。

## 2. 它什么时候醒

| 谁叫 | 多久 | 醒来做什么 |
|---|---|---|
| 召回之后（`touch`） | 每条被想起来的记忆一次 | 记一次「想起来过」，把可提取性拨回清晰 |
| 夜间巡检（`refreshHeat` / `tickTemps`） | 一天一次 | 重算全部热度、档位；推进冷热温度，每次只走一格 |
| 面板读接口（`nowRow`） | 你打开页面时 | 按这一刻现算一份给你看，不写库 |

它没有自己的心跳。

## 3. 醒来之后走哪几步

1. 算热度：重要度、新鲜度（半衰期）、被想起的次数、钉住、当时多激动——五项加权。
2. 分档：短期 / 中期 / 长期，只影响排序和配额，不影响「准不准进来」。
3. 判温度：多久没被碰过——90 天冷、180 天归档；30 天内被想起三次以上回热。
4. 降档要等两次（迟滞），升档立刻生效。
5. 被想起时强化：把稳定性往上抬一点，越费劲想起来（越模糊）抬得越多。

走查：一条「答应周末画图」的记忆，钉住了 → 档位永远短期、温度永远热；一条 100 天没碰的普通事实 → 档位长期、温度冷；一条昨天刚说过三遍的偏好 → 热。

## 4. 素材从哪来

| 人话名 | 从哪来 | 缺了会怎样 |
|---|---|---|
| 重要度 | 写入时定（`seedScores` 或显式给） | 缺省 0.5；半衰期按 30 天起 |
| 稳定性 | 写入 1.0，被想起时往上长 | 缺省按 1 天算 |
| 上次被想起 | `last_hit_at` / `last_decay_at` | 没有就拿创建时间 |
| 钉住 | `mark='locked'` | 不钉就按热度判 |

它不看什么：不看文本内容、不看情绪、不读参数表；也不删记忆——冷和归档都只是「不再占每轮的位置」。

## 5. 它怎么判断

其实只问三个问题：

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 有多清晰？ | 越久越模糊，稳定性越高越慢 | 模糊到阈值以下，召回时不再被想起 |
| 该排哪一档？ | 热度够高或两天内 → 短期 | 落到中期 / 长期，排序靠后 |
| 该进哪个温度？ | 90 天内碰过 → 温；否则冷 | 冷了退出每轮注入，回看/深查还能翻到 |

反例：一条很重要的旧承诺，如果没钉住、也没被想起，理论上会被判冷；所以承诺类要钉住，这不是它「偏心」，是钉子本来就在。

## 6. 它交出什么

| 层 | 长什么样 | 落在哪 | 谁接 |
|---|---|---|---|
| 数 | 热度 0–1、档位、可提取性 R | 库里的 `heat/band/last_decay_at/stability` | 召回、面板 |
| 状态 | 温度 hot / warm / cold / archived | `memory_items.temp_state` | 召回（S1 只捞热的） |
| 观测 | 各档条数、最热十条 | `tierStats` | 面板、验收 |

不出来的几种情况：不知道年龄、老库没有温度列——按缺省走，不报错。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 页面上的热度一天不动 | 库里存的是昨晚巡检的快照 | 读接口用 `nowRow` 现算，不读存档 |
| 同一条记忆在热/温之间来回跳 | 每天多聊两句就够阈值 | 迟滞：降档要连续两次 |
| 明明记得清楚，却被判模糊 | 稳定性没长起来（从没被强化） | 想起一次就长一点；重要的事钉住 |
| 老库升级后所有记忆同一天变冷 | 没有 `last_hit_at`，全拿创建时间当锚点 | 启动补一遍（`ensureHeatBootstrapped`） |
| 写入闸落的冷，过一夜又变回温 | 旧规则只看年龄，年轻的冷一律当「该是温」 | 2026-11-05 修：冷且一次没被想起 → 保持冷；被想起来才回温 |

## 8. 怎么知道它活着

- 面板：记忆页能看到每条的热度、档位、温度（现算的）。
- 命令：`tierStats(db, aid)` 返回各档条数、最热十条、温度分布。
- 表：`memory.temp_changed` 事件只在真的迁移时写，一天最多一批。

正常：短/中/长都有，冷的不多；异常：全是长期（热度没算对）或全是短期（阈值失效）。

## 9. 换它要付什么

- **能动的**：五项权重、半衰期、档位阈值、冷/归档天数、迟滞次数、强化公式。
- **不能动的**：不删记忆；不读参数表以外的库；`temp_state` 的四个取值。
- **考卷**：`test/exam-tiers.test.mjs`；界桩真跑；打假塞坏版本（半衰期改短 / 冷热不迟滞）。
- **算法册**：`decay@v1 / v1b` 的 owner 指向这个零件。
- **回退点**：`tiers-before-part`。
