# 零件 · 出声（mouth）

> 这页给主人看：它是什么、什么时候醒、看什么、怎么判、交出什么、哪里会错。
> 骨架照 [零件说明-写法.md](零件说明-写法.md)；词以 [术语表](术语表-2026-11-05.md) 为准。
> 状态：**已立（11-07）**。登记在 `src/modules/parts.js`，考卷 `test/exam-mouth.test.mjs`，回退点 `mouth-before-part`。
> 工程件：`src/parts/mouth/`——`index.js` 是入口，`providers.js` 是三条嗓子，`format.js` 看回来的字节是不是音频。

## 1. 一句话 + 一个比喻

它管「一段字变成声音」，不管该不该说、说什么、发给谁——那三件分别是主动开口、说话分寸、发信的事。

像嗓子：字已经在嘴里了，它只管把字念出来，念得好不好听是另一件事，念给谁听也不是它定的。

真的对应到哪：一次合成调用——进去一句话和一份配置，出来一段音频字节加一个格式，或者一句人话的失败原因。

## 2. 它什么时候醒（触发）

| 谁叫它 | 多久 | 醒来做什么 |
|---|---|---|
| 她自己（`act_say` 工具） | 需要时 | 合成一段，写到临时文件，默认直接在本机播出来 |
| 别的零件 / 以后的通道 | 需要时 | 调 `synthesizeVoice`，入口只有一个 |
| 宿主服务（还没做） | — | 计划里的 `voiceOut`，给外面的 QQ 插件用 |

没有这些，它不会自己动。它没有心跳，也不会没事念两句——**现在本仓里唯一的入口就是那个工具**。

## 3. 醒来之后走哪几步

1. 先看有没有字：空的就不合成，直接说「要念的内容是空的」。
2. 再看配置齐不齐：缺密钥、缺参考音频、嗓子名字不认识，都在这时候说人话，不等请求发出去才报 401。
3. 挑一条嗓子发请求：微软发 SSML，兼容接口发 JSON，本机 GPT-SoVITS 发它自己的 /tts。
4. 回来看字节：是不是真的音频。回来的是一段 HTML 错误页，就不交出去。
5. 交出去：音频字节 + 格式。

一次走查（按代码路径推的，不是真机记录）：配的是微软那条嗓子 → 发一句「晚安」→ 回来一段 mp3 → 看头是 ID3，认得出 → 交出去。要是那天服务挂了、回一段 502 页面，它就在第四步停住，报「嗓子回的不是音频」。

## 4. 素材从哪来（输入）

| 人话名 | 从哪来 | 新鲜多久 | 缺了会怎样 |
|---|---|---|---|
| 要念的字 | 调用方给 | 当次 | 空的就不合成 |
| 嗓子配置 | 设置里填的 | 长期 | 缺什么说什么，不硬试 |
| 参考音频（本机嗓子） | 主人自己录的 | 长期 | 没有就克隆不出声音，先报缺 |
| 网络 / 本机服务 | 外面 | 每次 | 挂了就报原因，不假装成功 |

它不看什么：不看这句话该不该说、不看语气该不该软、不看发到哪个群；**也不存音频**——合完就交出去，不落盘。

## 5. 它怎么判断（判据）

它其实只问三个问题：有没有字？配置齐不齐？回来的到底是不是音频？

| 它在问什么 | 什么算过 | 没过会怎样 |
|---|---|---|
| 有没有字 | 去掉首尾空白还有内容 | 报「要念的内容是空的」 |
| 配置齐不齐 | 嗓子认识、密钥或参考音频在 | 缺什么说什么，一个请求都不发 |
| 是不是音频 | 头几个字节像 wav 或 mp3 | 报「回的不是音频」，不交出去 |

反例：主人明明点了「念一下」，为什么没声音——因为那天密钥过期，请求 401，它在第二步就报了原因，没有合成，也没有发一条空语音。

格式这条还有一句：以字节为准。配置写着 mp3 而回来的是 wav，就按 wav 说，不跟着配置撒谎。

## 6. 它交出什么（输出）

| 层 | 长什么样 | 谁接 |
|---|---|---|
| 音频 | 一段字节 + 一个格式 | 通道（宿主接线） |
| 失败原因 | 一句人话，比如「本机嗓子缺参考音频」 | 主人能看到 |
| 账 | 这次用了哪条嗓子、多大一包 | 日志 / 追踪 |

你能感知到的只有「听到了一段 / 没听到」。

它交出去之后就不管了：发不发、发哪里、要不要转成 QQ 要的格式，都是通道的事。

## 7. 它什么时候会错（已知坑）

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 听着是静音，日志写成功 | 服务挂了会回一段 HTML，被当成音频 | 已经加「看字节」：认不出就不交出去 |
| 配置说 mp3，回来是 wav | 有的兼容服务不守约定 | 按字节说，让通道按真的处理 |
| 微软 400 | SSML 里少转义一个 `&` 或 `<` | 转义做全了；考卷里有一条专考这个 |
| 本机没声音 | 没配参考音频，克隆不出来 | 先报缺，不硬发 |
| iOS 那头听不见 | 码率太高，苹果那边解不了（网上的做法是压到很低） | 这条**没验过**：我们靠通道转码，参数能不能带还不知道 |
| 等太久 | 云端 60 秒、本机 120 秒就断 | 已知，先这么定 |

## 8. 怎么知道它活着（观察点）

- 追踪里每次合成：哪条嗓子、多大一包、多久。
- 失败原因是不是人话：缺密钥 / 缺参考音频 / 401 / 不是音频，四种一眼能分开。
- 一条最笨的检查：让它念一句，戴上耳机听；听到的是人声，不是静音。

正常是「有字节、有格式、能播」。异常是每次都在第四步停住（说明服务回的都不是音频）。

## 9. 换它要付什么（代价）

- **能动**：三条嗓子的取舍、音色与风格、超时、看字节的判据。
- **不能动**：不决定说不说、不改语气、不碰 record 段、不存音频。
- **考卷**：`test/exam-mouth.test.mjs`，27 道，现在 27/27。打假塞两个坏版本：不看字节就交、缺配置也硬发，卷子都拦得住。
- **回退点**：`mouth-before-part`。它打在搬家前那个 commit 上，新文件不在里面，回退是「删目录 + 删登记行」。
- **换完记在哪**：`parts.js` 那一行的 `swaps`，外加一份 `docs/活论证-出声-<日期>.md`。
