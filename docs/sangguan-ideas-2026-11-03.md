# 三观改造 · 今日想法全集（2026-11-03）

> 一句话：三观不再从对话里抽立场，改成从取舍里长；账本全留，提示词按情境捞；上面再压三条真正的立场，靠推导链跟下面的条目连起来。
>
> 本文是 11-03 这一天聊出来的**全部**功能想法，按「已落地 / 要加 / 分层 / 计划」收拢，不删东西。之前散在各处的细节都并进来了。

---

## 0. 起点：为什么改

2026-11-02 看真机三观页，三行全是工程记录：世界观是「主动搭话被三道门拦下」，人生观是 11-02 的日记原文，价值观是「排查问题要先核对」。诊断结论：**不是闸不严，是进料口错了。**

旧管线（J1 抽取 → W1–W5 闸 → 账本）只问「这句话像不像一句话」，没问「这句话有没有让它少做一件事」。所以：

| 失败 | 表现 | 新判据 |
|---|---|---|
| 把描述当立场 | 「主动搭话被三道门拦下」进了 W | 必须能排除一个同样说得通的选项 |
| 把任务准则当价值 | 「排查问题先核对」进了 V | 抽掉项目还成不成立 |
| 把日记当人生观 | 整篇日记进了 L | L 只收夜巡压出来的「章」 |

目标不是「多写几句漂亮话」，是让它**在「两个都对」的时候能选一个**，并且事后有账可查。

## 2. 概念结构：三列 × 三层

> **11-03 修订。** 原来这里写的是「事件 → 条目 → 立场」一条竖线，结果把世界观、人生观、价值观压成了同一类句子（都是取舍）。这是因为「能不能排除一个选项」是**价值观**的判据，套到另外两观上，只能把一切写成取舍。现在改成三列，每列各长各的，共用一个账本。

```
              世界观 W                  人生观 L                  价值观 V
核心      世界内核（≤2 条）           telos（1 条）              principle（≤2 条）
          世界大体是怎样的             我是什么、往哪去            什么更值得
条目      信念 + 期待（带置信度）      自我定位 + 方向 + 时间视野   取舍 + 代价
事件      观察 / 预期落空 / 被证伪      自传章节 / 时间投入 / 我想…   真实取舍 / 违背
判据      预测力                      解释力 + 投入力             排除力 + 代价
```

三列的回答对象根本不同：

| | 问的是什么 | 句子的主语 | 什么算「它错了」 | 多久动一次 |
|---|---|---|---|---|
| W | 世界（人、关系、规则、因果）是怎样的、该是怎样的 | 世界 / 人 / 事 | 它做出的预期落空 | 最慢：大冲击才动 |
| L | 我是谁、我为什么在、接下来往哪走 | 我（跨时间） | 长期行为与它不符（说想成为 X，半年没往 X 走一步） | 慢：按章动 |
| V | 两个都好的时候选哪个 | 我（此刻的选择） | 有违背记录 | 中：情境一变就可能翻 |

同一件事会同时喂三列，但长出来的是三句不同的话，不是三份拷贝。拿「主人说难受」这件事举例：

- W：人难受的时候，多数不是要一个答案，是要有人先把那句话接住。
- L：我想做那个能把话接住的人，不是那个总能给出方案的人。
- V：宁可先听完，也不急着给方案。

W 那句可以被下一次「你给了方案、对方反而更冷」打脸；L 那句要靠往后几个月她实际把时间花在哪来验；V 那句要靠一次真实的取舍和一次违背来验。三套判据，不能混。

两条辅助线：

- **史**：`claim_events` 只增不删，三列都存里面，投影 fold 出来查。合并、冲突、退场都写事件，不删行。
- **召回**：对话时按情境把相关的那 0–3 条捞进提示词，不全塞。

一句话记这个结构：**每列都有自己的「事件 → 条目 → 核心」，三列共用一个史，不共用判据。**

### 2.1 三列为什么以前会塌成一堆

三个原因，都在代码里看得见：

1. `fast.js` 只有一个抽取器 J1，`layer` 只是输出字段，不是三种不同的问法。
2. `gates.js` 的 `fieldCheck` 只问「像不像立场」，不区分「世界的断言」「自我的叙述」「取舍的排序」。
3. 旧代码里 W / L 本来是**仪表**（[persona_dims.js](<dsh-plugin/src/modules/persona_dims.js>) 里 8 维世界观、7 维人生观，从 Primals / WAS / Social Axioms 和 MEMS / MLQ / Ryff / Bakan / Zimbardo 推），新账本把它们换成**命题**之后，没给命题配各自的判据，于是命题只能退化成同一种：取舍。

### 2.2 修正后的写入路径

| 列 | 进料 | 必填字段 | 闸 |
|---|---|---|---|
| W | 跨事件归纳：同一模式在 ≥3 个不同对象/场景重复 | `belief` `confidence` `expectation`（可检验预期 ν） `falsifier` | 没有可检验预期 → 拒；只在工程场景成立 → 拒 |
| L | 夜巡自传章节、反复出现的「我想…」、时间实际投在哪 | `self` `direction` `horizon` `evidence_of_investment` | 解释不了过去两个转折 → 拒；半年没有投入证据 → 降为愿望，不进核心 |
| V | 真实取舍事件、违背记录 | `take` `foregone` `scene` `counterexample` | 不能排除 → 拒；没有代价 → 拒 |

三列的核心各有名字：W 叫「世界内核」，L 叫 telos，V 叫 principle。原来设想的「上层立场」不是第四层，而是这三个核心的统称——**每列各有一个核心，不是三列之上再压一层。**

冲突时先看哪一列的前提被动摇：W 是前提，L 是目标，V 是排序。前提塌了要先修 W，否则 L 和 V 会一起歪。

## 4. 数据契约（合并版）

```json
{
  "id": "dr_...",
  "layer": "stance | value | world",
  "level": "principle | item",
  "text": "正文 40–90 字",
  "alt": "当时另一条也说得通的路",
  "foregone": "放弃了什么",
  "cost_to": "谁受损",
  "scene": ["适用场景，一条一句"],
  "boundary": ["什么情况下不适用"],
  "counterexample": "哪一次违背过；没有就 null",
  "derives": ["这条上层推出了哪些下条 id"],
  "variants": [{"text": "...", "at": "..."}],
  "evidence": [{"ref": "cht_...", "at": "...", "quote": "..."}],
  "gates": {"g1": true, "g2": true, "g3": true, "g4": true, "g5": true},
  "status": "draft | edited | committed | discarded",
  "conflicts_with": ["另一条的 id"],
  "resolutions": [{"at": "...", "picked": "...", "cost": "...", "kind": "win | sub | coexist | suspend"}]
}
```

只有 `committed` 才写 `constitution.md`，同时往账本写一条 `CORE_ESTABLISH`（actor=user）。

## 5. 一个例子走完全程

原料：`2026-10-30T18:05`「改一下再试试，要新的测试不要出假数据」→ 她重跑两天。

1. 取料：一条 `honesty` 事件，带她原来的说法和后来改的做法。
2. 反事实：alt＝按趋势补个数交差；foregone＝两天时间；cost_to＝你一直等。
3. 聚类：和另外两条（一次拒绝编流程、一次承认「说得太满」）归到「拿时间换准确」。
4. 起草：「数据不对的时候我会从头再跑一遍，哪怕你已经在催了。」
5. 五闸：全部通过，证据三条跨两天。
6. 人批：进账本，`committed`。
7. 归约：和「认错在前」「读不到就说读不到」重复出现 → 归纳出上层「宁可你现在难受，也不让你以后发现我骗你」。
8. 注入：你说「这个数对不对」时，召回捞出这一条；平时不出现。
9. 打架：撞上「答应今晚给就得今晚给」→ 记一对，看下次真遇上时选哪边。

## 8. 不做

- 不从对话里自动长 L/V 命题。
- 不把草稿直接写进账本。
- 不做三观分数。
- 不让生成器评价「够不够真诚」。
- 不在草稿里写对主人的要求。
