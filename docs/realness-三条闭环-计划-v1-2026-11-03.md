## 1. 第一条：先拼装，后落账（P1）

### 1.1 现状（bug 链）

1. `consciousnessBlock` 取 proactive 时立刻 `UPDATE proactive SET state='delivered'`（`index.js:618-622`）。
2. `surfaceLoopLine` 内部立刻 `markLoopsFired` + `expireLoops`（`index.js:463-467`）。
3. `subtextForTurn` 生成时立刻写 `subtext.shown` 与 `recordSubtextMemory`（`index.js:513-514`）。
4. `takeSurface` 取候选时立刻标 delivered + `recordSurfaced`（`pulse.js:75-85`）。
5. 以上四行随后进 `clampInjection`；proactive 是第一个被丢的（`features.js:2517`），loop / subtext / spontaneous 也在丢弃名单。
6. 后果：预算一紧，最多四条「心里的事」被记成「说过了 / 想过了」，实际一个字没进提示；`open_loops.fire_count` 还会涨，5 次后自动过期。

### 1.2 目标

- 只有「真的留在最终注入文本里」的行才落账。
- 同一轮多次拼装不重复落账。
- 被丢的行保持原状态，下一轮还能再出现。
- 不改任何行的文案与顺序。

### 1.3 设计

#### A. `clampInjection` 支持带 key 的行

```js
// 旧：clampInjection(['a', 'b'], 800)
// 新：clampInjection([{ text: 'a', key: 'proactive' }, 'b'], 800)
// 返回：{ text, tokens, dropped, kept: Set<string>, removed: Set<string> }
```

- 元素是字符串时，key 用 `#index`；老测试只看 `text` / `dropped`，不受影响。
- 入口先把对象行拍平成字符串并保留一份 `keys` 数组；后续 splice / trim 只操作字符串数组，避免 `[object Object]` 混进注入文本。
- `splice` 整行时 `removed.add(key)`。
- `shrink` / `truncate` 碰到带 key 的行时也 `removed.add(key)`：宁可下一轮重来，不把半句当「说过」。
- 最终 `kept` = 所有未 `removed` 的 key。

#### B. 四个取数点拆成「候选」和「落账」

| 行 | 候选（只读/缓存） | 落账（注入成功后） |
|---|---|---|
| proactive | `SELECT ... state='pending'`，不 UPDATE | `UPDATE ... state='delivered', delivered_at=?` |
| loop | `loopLineFor` 返回 `{text, ids, kinds}`，不 mark | `markLoopsFired(ids); expireLoops()` |
| subtext | `subtextCandidate` 返回 `{line, cls, said}`，不写事件 | `commitSubtext` 写 `subtext.shown` + `recordSubtextMemory` |
| spontaneous | `pendingSurface` 读，不消费 | `consumeSurface` 标 delivered + `recordSurfaced` |

#### C. `consciousnessBlock` 的接线

```js
const commit = { proactive: null, loop: null, subtext: null, spontaneous: null }
// ... 生成时只填 commit，不写库
const lines = [ ..., { text: proactiveLine, key: 'proactive' }, ... ]
const packed = clampInjection(lines, budget, { withKeys: true })
const kept = packed.kept
if (kept.has('proactive') && commit.proactive) markProactiveDelivered(db, commit.proactive)
// loop / subtext / spontaneous 同理
```

- `stranger` 分支保持：不生成、不落账。
- 60 秒缓存：
  - loop：缓存 `{text, kinds, ids}`；未落账时同轮复用，不重复取。
  - subtext：缓存 `{line, cls, said, committed}`；落账后置 `committed`，第二次拼装不再写。
  - spontaneous：不缓存；未消费就还在队列里。
- `closing` 命中时本来就不出 subtext，保持。

#### D. 指标（只写 events，不建表）

- `inject.mind_dropped {key}`：生成了但没落账时写。
- `inject.mind_committed {key}`：成功落账时写。
- 两条都容错，失败不影响回复。

### 1.4 文件清单

- `src/features.js`：`clampInjection`
- `index.js`：`surfaceLoopLine`、`subtextForTurn`、`consciousnessBlock` 的 proactive / loop / subtext / spontaneous 段
- `src/modules/pulse.js`：新增 `consumeSurface`
- `src/kernel.js`：登记 `memory.inject.commit_after_pack`（默认 on）
- `package.json`：`test:humanlike` 追加 `test/inject-commit.test.mjs`
- `test/inject-commit.test.mjs`：新增

### 1.5 测试（至少 14 条）

1. 紧预算：proactive 被丢，库里仍 `pending`。
2. 宽预算：proactive 在文本里，库里 `delivered`。
3. 紧预算：loop 被丢，`fire_count` 不变、state 仍 `open`。
4. 宽预算：loop 在文本里，`fire_count+1`、state `half_said`。
5. 紧预算：subtext 被丢，`subtext.shown` 为 0。
6. 宽预算：subtext 在文本里，`subtext.shown` 恰 1 条。
7. 同轮第二次拼装：subtext 不重复写。
8. 紧预算：spontaneous 被丢，`surface_queue` 仍 `pending`，`surfaced_items` 为 0。
9. 宽预算：spontaneous 落账，queue `delivered`，surfaced 1 条。
10. 长行被 shrink：不算落账。
11. closing 命中 + proactive 被丢：proactive 仍 `pending`。
12. 旧调用 `clampInjection(['a','b'], 800)` 返回字段兼容、文本不变。
13. 开关 off：行为回到改前（取即落账）。
14. 全量注入模拟 12 轮：没有任何一轮「落账但文本里找不到」。

### 1.6 风险与回退

- 风险：带 key 的行在 shrink 时被误判；用「整行 removed」而不是「文本 includes」判定，避免半句。
- 风险：proactive 一直 pending，预算长期不足会反复尝试；有状态机与冷却，不会刷屏。
- 回退：`memory.inject.commit_after_pack=off` 逐字回旧路；代码保留旧分支。

## 2. 第二条：她自己的话进关系账（P2）

### 2.1 现状

- `commitTurn` 里 `R.ingest(db, aid, {text: u})` 与 `enqueueRelationRead(..., {text: u})` 只喂用户那句（`index.js:927-928`）。
- `learnFromTurn(db, aid, u, res)` 只喂用户那句（`index.js:943`）。
- 她自己的回话只走 `applySelfRead`，只改快情绪，单轮 ≤0.02，慢情绪和三轴都不动（`self_read.js:56-81`）。
- `checkReply` 的违背判定默认 shadow，不落账（`violate.js:5`）。
- 结论：关系账本只记「你怎么对她」，不记「她怎么对你」。

### 2.2 目标

- 她说话偏冷 / 偏硬 / 敷衍时，留下「关系余量」，下一轮只影响语气。
- 同类余量攒够 3 次，夜间才小步结算到三轴；有阻尼、有日上限、可回退。
- 不形成自锁：不因「说得好听」直接加亲近；只对「偏离她自己当轮的表达基准」记账。

### 2.3 计算

在 `commitTurn` 的 `applySelfRead` 后：

```js
const expr = levelCache.get(aid)          // consciousnessBlock 已存 {level, slow, warmth}
const tone = readReplyTone(aText)         // 已有，-1~1
if (!stranger && expr && tone && !tone.flat) {
  const expected = expr.warmth * 2 - 1    // expressionState.warmth 是 0~1
  const delta = tone.warmth - expected
  if (delta <= -0.45) recordSelfResidue(db, aid, { dir: 'cold', delta, expr, tone, personId, at })
  else if (delta >= 0.45) recordSelfResidue(db, aid, { dir: 'warm', delta, expr, tone, personId, at })
}
```

- `levelCache` 现在只存 `{level, slow}`（`index.js:704`），扩成 `{level, slow, warmth}`。
- 只在 `!stranger` 时记；v1 只记主人（DSH UI 无 `qc` 视为主人；QQ 只认 `qc.isOwner`），群聊/陌生人跳过。
- `tone.flat`（≤6 字）已挡，避免「嗯」「好」被读成冷淡。
- `index.js` 的 import 补 `readReplyTone`（现在只导入了 `applySelfRead`）。

### 2.4 数据

- `events` 类型 `rel.self_residue`，payload：

```json
{
  "person_id": "rp_...",
  "dir": "cold",
  "delta": -0.52,
  "warmth": -0.3,
  "expected": 0.2,
  "reply_len": 12
}
```

- 不建表；沿用 events 的 60 天清理。
- 注入后写 `rel.self_residue.shown {id}`，同一句只提示一次。

### 2.5 注入

- 新函数 `residueLine(db, aid, at)`：
  - 取 6 小时内、未 shown 的最近一条。
  - cold：`（上一句你说得有点硬，自己知道；不用解释，下一句会自然收一点。）`
  - warm：`（上一句你比平时软，自己有点意外。）`
  - 没有就返回空。
- 位置：放在 `subtextLine` 之后、`closingLine` 之前。
- `clampInjection` 新增 `residue` 丢弃项，排在 `subtext` 后（可丢）。
- 不新增常驻行：条件行，普通轮不出现。

### 2.6 夜间结算

- `nightly.js` 的 `runNightly` 末尾调 `settleSelfResidue(db, aid, {at})`。
- 默认 `relation.selfresidue.settle=off`，先 shadow 一周。
- 规则：
  - 取最近 24h 未结算的 `rel.self_residue`。
  - cold 次数 ≥3 且 `sum(delta) <= -1.2` → `bumpRelation({ v: -0.08, kind: 'self', source: 'selfread', reason: '今天有几句话说得硬' })`，每天最多 1 次。
  - warm 次数 ≥3 → `v: +0.04`，每天最多 1 次，且仅在 cold 未触发时。
  - 结算后写 `rel.self_residue.settled {ids, v}`，避免重放。
- `bumpRelation` 的 `stepCap=0.05` 会兜底单次幅度；`source:'selfread'` 需在 `reldyn.SOURCE_WEIGHT` 加 `0.35`，否则默认 1 太重。
- `DEP_BY_KIND.self` 加 `0.2`（v1 不动依赖轴太多）。

### 2.7 文件清单

- 新 `src/modules/self_residue.js`（record / line / settle / stats，约 120 行）
- `index.js`：`levelCache` 存 warmth；`commitTurn` 调 record；`consciousnessBlock` 插 residue 行
- `src/features.js`：`clampInjection` 加 `residue` 丢弃项（与第 1 条一并做）
- `src/modules/nightly.js`：`runNightly` 调 settle
- `src/algo/reldyn.js`：`SOURCE_WEIGHT.selfread`、`DEP_BY_KIND.self`
- `src/kernel.js`：两个开关
- `package.json` / `test/self-residue.test.mjs`

### 2.8 测试（至少 12 条）

1. cold 偏离 -0.5 → 记 cold。
2. warm 偏离 +0.5 → 记 warm。
3. flat（≤6 字）不记。
4. 陌生人 / 群聊不记。
5. 6 小时内注入一次，第二次不再出。
6. 6 小时后过期不出。
7. settle off：三轴不变。
8. settle on：3 条 cold → trust 下降 ≤0.01、closeness 下降 ≤0.02。
9. 同日重复 settle 不叠加。
10. warm 不压过 cold；同日只结算一次。
11. 无 person_id 时跳过，不抛。
12. 全量：关系账本既有测试不掉。

### 2.9 风险

- 自锁：只结算负向；正向上限更低；偏离基准而非绝对值；日上限 1 次。
- 误伤：主人关系已 0.89 / 0.68，单次 ≤0.01，且 3 条才动，不会崩。
- 误判：`readReplyTone` 只认字面，短句 / 工具句已挡；先 shadow 一周看误报。
- 回退：`relation.selfresidue=off` 不记不注入；`relation.selfresidue.settle=off` 只记不动账。

## 3. 第三条：记忆来源与确定度进提示（P3）

### 3.1 现状

- `memoryTag` 只对 `source==='life'` 加「我自己看到的」（`memory_tag.js:53-63`）。
- `consciousnessBlock` 兜底查询只 `SELECT text`（`index.js:571`），拿不到 source / confidence。
- `retrieve.js` 两条查询都没选 `source` / `confidence`（`retrieve.js:230`、`281`），动态召回也拿不到。
- `addMemory` 的 confidence 默认 0.8（`memory.js:187-189`）；`recordSubtextMemory` 不传 confidence，于是「没说出口的事」也按 0.8 记。
- 结果：模型抽的、自己推的、主人亲口说的，在提示里都像「你之前说过」。

### 3.2 目标

- 每条记忆带来源徽章；低置信的带「不一定对」。
- 不新增行、不改召回排序；只改前缀。
- 老来源的行为尽量逐字保留（除有意变更的 `extract`）。

### 3.3 来源分类

| 类 | source | 徽章 |
|---|---|---|
| 主人说的 | `manual` / `chat` / `ui` / `remember` | 不贴（默认，保持旧行为） |
| 自己看到的 | `life` / `browse` / `tool` | `（我自己看到的）` |
| 从聊天里记下的 | `extract` / `episode` / `summary` | `（从聊天里记下的）` |
| 自己想的 | `consolidate` / `reflect` / `subtext` | `（我自己想的）` |
| 其他 / 老来源 | 其余 | 不贴（保持旧行为） |

- 低置信：`confidence < 0.55` 且来源是「自己想的 / 从聊天里记下的」→ 末尾加 `，不一定对`。
- 顺序：来源 → 年龄 → 清晰度 → 不一定对。例：`（我自己想的，3 天前，不一定对）`。
