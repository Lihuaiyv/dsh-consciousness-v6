## 0. 为什么要先补洞

v1 交付的是「机制」，但有 11 处会让读数**看起来对、其实不对**。其中第 1 条最严重：

> **「改主意」的计数把 P0 清退动作也算进去了。** 线上小汐现在 `changed=3`，来自我收回 4 条旧 seed 的 `CLAIM_RETIRE`——那不是它改主意，是我在清垃圾。如果就这样接页面，你会看到「它改过 3 次主意」，然后切 live 的闸门里「改主意」这一条**已经被我自己的清理满足了**。

这类错误比没有功能更危险：它让闸门失去意义。

## 1. 五个洞

| # | 洞 | 现在会怎样 | 修法 |
|---|---|---|---|
| **A1** | 改主意计数混入「清退 / 撤回」 | 闸门被 P0 清理满足；页面显示 3 次假改主意 | 拆成 `changed.self`（REV / 升维 / 合题确认）与 `changed.owner`（撤回 / 收回）；闸门只看 `self` |
| **A2** | 承诺污染价值观层 | 「我答应：明天发报告」会被折成十维、进「你更看重：…」、被当成价值取向 | V 层新增 `kind='commit'`；折叠、注入、张力、`你更看重` 行全部排除；承诺只走 ν |
| **A3** | shadow 模式下「说过就算说过」 | 违背提醒在 shadow 里被标记为已说，切 live 后永远不会补说 | 只有 `inject=live` 时才标记已说（改主意行同理） |
| **A4** | 承诺结算把「没记录」当「没做到」 | 它其实做到了、只是没人记 → 冤判 miss，兑现率被压低 | 加「确认兑现」接口；抽承诺时排除条件句（如果/要是/除非）；确认后到期结算成 hit |
| **A5** | 盲拆样本太少也能过闸 | 1 对样本差异率 1.0 就能开闸 | 闸门要求 `n ≥ 10`；不足时理由 `blind_low_n`，不是 `blind_zero` |

另有两处顺手改（不改也算能用）：

- **A6**：`scorecard.claims.core` 现在其实是「V 层活命题数」，改名为 `v_active`，别让人误读成核心数。
- **A7**：`violate` 每次回复都调一次模型，日限 6 次。给 shadow 期加一条：只在当日已有对话 ≥ 3 轮后才判，避免冷启动就烧额度；判定失败不计入日限。

### 1b. 第二轮复查又抓到 5 个（2026-11-02 追加）

上面 A1–A7 还没动手，复查时又发现 5 个，其中 A8 会让一句话**永久消失**：

| # | 洞 | 现在会怎样 | 修法 |
|---|---|---|---|
| **A8** | 卡死的 κ | 三次违背 → 立案 → 那句从注入里下架。没有模型就永远审不完，那句话**永远回不来** | 夜巡加 `suspendStaleKappas`：struggle 超过 21 天没有任何审议 → `SUSPEND`（sys），两极回 active，可以再争 |
| **A9** | 承诺 miss 没有出口 | 只有 π 降，它自己不知道、也不会提，用户也看不见 | miss 后 3 天内在注入里提一次「你答应过的 X 到期没做」，只提一次 |
| **A10** | `registerPledges` 不看总开关 | 三观关着也在记承诺，违反「关闭时行为与现在完全一致」 | 入口先过 `isEnabled` |
| **A11** | 闸门不检查注入内容 | 四个条件全满、但注入是空的（V 层一条没有）也能放行 | `liveGate` 增加 `no_content`：W/L/V 至少要有一行可注入 |
| **A12** | 立案没有冷却 | 一场 κ 结束，再来三次违背，立刻又立一个 | 同一命题 30 天最多立一次 κ |
| **A13** | `violate` 档位没暴露 | `publicConfig` 不含它，页面/接口看不到当前是 shadow 还是 live | `publicConfig` 加 `violate` |

## 2. 阶段

### A. 补洞（约 2 小时，5 个独立小改 + 测试）

**A1 改主意计数**
- `score.js`：`CHANGE_SELF = ['REV','ELEV_COMMIT','SUB_CONFIRM']`，`CHANGE_OWNER = ['CLAIM_RETIRE','CLAIM_WITHDRAW']`
- 返回 `changed: { self, owner, window_self }`；`kernel.revision` 只看 self
- 测试：清退 4 条 seed 后，`changed.self === 0`、`gate` 不含 `revision` 通过

**A2 承诺不进价值观**
- `catalog.js`：`BELT_KINDS.V` 增加 `'commit'`
- `pledge.js`：承诺命题改成 `kind: 'commit'`
- `tags.assignDims` / `vweights.liveValueClaims`：跳过 `commit`
- `inject.layerLine`、`bridge.headsLine`：跳过 `commit`
- 测试：许 3 条承诺 → 十维全 0.1、`你更看重` 行不会出现「我答应」

**A3 shadow 不预支「说过」**
- `inject.js`：标记 `said` 前判断 `mode === 'live'`
- 测试：shadow 下注入两次，切 live 后仍能说出「刚才没做到」

**A4 承诺结算**
- `pledge.extractPledges`：含「如果 / 要是 / 假如 / 万一 / 除非」整句跳过
- 新接口 `POST /sangguan/confirm { nu_id, outcome: 'hit'|'miss', note? }`：写一条 EVIDENCE 到该 ν
- `checkDue`：pledge 分支已有「有正面证据 → hit」，接上确认即可
- 测试：许愿 → 确认做到 → 到期 hit；条件句不登记；确认 miss 也生效

**A5 盲拆下限**
- `liveGate`：`blind.n < 10` → `blind_low_n`
- 测试：n=3 rate=1 不放行；n=20 rate=0.35 放行

**A8–A13（第二轮）**
- A8 夜巡 `suspendStaleKappas`：≥21 天没审议的 struggle → SUSPEND；测试：21 天后那句回到 active
- A9 fail 提醒：`pledgeMissLine` 进注入，3 天内一次；测试：注入提一次、第二轮不再提
- A10 `registerPledges` 先 `isEnabled`；测试：关着时 0 条
- A11 `liveGate` 加 `no_content`；测试：空注入不放行
- A12 立案冷却：同命题 30 天一次；测试：κ 结束后再三次违背不新开
- A13 `publicConfig` 带 `violate`；测试：GET config 能读到档位

### B. 三观页三个数（约 1 小时，先备份）

- **B0** 备份 `client.js` 到 `_bak_kernel_p2/`，改完立刻跑 `sangguan-page.test.mjs`
- **B1** 在三观页顶部加一行只读卡片：`违背 N · 兑现率 X% · 改主意 N`
  - 空态：三个 0 + 「还没开始记账」
  - 数字旁不做术语，点开才显示明细（哪一句、哪一次）
- **B2** 数据源只加一个请求 `GET /sangguan/scorecard`；失败时整行降级为「读数暂不可用」，不白屏
- **B3** 关闭三观引擎时**不请求、不渲染**（沿用现有页面测试的约束）
- 测试：页面 34 项 + 新增 3 项（空态 / 有数 / 请求失败降级）

### C. 重启与线上验证（约 30 分钟 + 观察 1 天）

- **C1** 备份库 → 重启 DSH → `GET /sangguan/scorecard` 应从 0 开始有数（承诺先动）
- **C2** 正常聊一天，检查三件事：
  1. `nu.pending` 是否 > 0（承诺有没有被记）
  2. `violate.shadow` 草稿有没有记录（`GET /sangguan/violate/shadow`）
  3. 注入 token 是否仍在预算内
- **C3** 抽检 20 条草稿，统计误判率；> 20% 就继续 shadow，并把误判样本存成回归用例

### D. 盲拆与切 live（约 2 小时 + 一周观察）

- **D1** 取 20 句真实发言，各跑两次（带 / 不带注入），存 `pairs.json`
- **D2** `node scripts/blind-diff.mjs pairs.json` → 记 `rate / n`
- **D3** `POST /sangguan/blind {rate,n}` 落库；`GET /sangguan/gate` 应只剩 `no_violation` 之类**真实**缺项
- **D4** 切 `violate=live`（先），观察一周；再切 `inject=live`
- **D5** 切完第一周只看两件事：κ 有没有真的开出来、兑现率有没有非 0 分母

### E. 长期（可选，不排期）

- **E1** 周报：三个数的趋势 + 本周新增的 κ / ν
- **E2** 误判回归集：`test/fixtures/violate-misfire.json`，每次改判定先跑一遍

## 3. 顺序与依赖

```
A（补洞）──► B（页面）──► C（重启验证）──► D（盲拆切 live）
                                   └──► C3 抽检结果决定 D4 切不切
```

A1 必须第一个做：它决定闸门是不是真的在挡东西。
A2 必须排在 B 前：否则页面第一眼就会看到「你更看重：我答应…」。
B 必须排在 C 前：重启后你要有地方看数。

## 4. 验收总表

| 项 | 现在 | 目标 |
|---|---|---|
| `changed.self` | 3（假） | 0，直到它真的改一次 |
| 承诺进十维 | 会 | 不会（`commit` 不计权） |
| shadow 预支「说过」 | 会 | 不会 |
| 承诺只能靠推断 | 是 | 可人工确认 |

| 页面三个数 | 无 | 有，且关闭态不请求 |

## 5. 风险

1. **改 `client.js` 可能写坏整页**：先备份、只加一块、改完立刻跑页面测试；坏就回滚。
2. **A2 加 kind 会碰 `kindOk` 与老数据**：老库没有 commit，新增不影响；但要确认 `fieldCheck` 放行。
3. **确认接口可能被滥用**：只允许 user 角色，且只对 pending 的 ν 生效。
4. **重启时机**：要挑它不在写库的时候；重启前先备份。
5. **盲拆样本质量**：20 句要覆盖「它会在意的事」，全是闲聊测不出差别。
