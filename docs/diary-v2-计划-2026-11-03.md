# 日记 v2 · 计划（可落地版）

> 日期：2026-11-03
> 范围：只改「T2 纪要 → T3 日记」的成文链路，不动注入、不动召回、不动纪要本身。
> 一句话：把「把一天 20 条纪要喂给模型、写不出来就拼模板」改成「先挑 1–2 个真扎心的场景 → 拿原话 → 两段式写成文 → 写不成留白待补，绝不把模板当日记」。

## 0. 现状（有证据，不是感觉）

### 0.1 两个独立缺陷

**A. 模板不是兜底，是终态。**

- `index.js:865` `summarizeForDiary()` 只在 `model.status().primary === 'ok'` 的那一下把模型交出去，否则返回 `null`。
- `archive.js:562` `buildDiary()` 拿不到 `summarize` 就直接走模板（把纪要标题、事实、开环塞进三个固定句式）。
- 写完就有 `diaries` 行，`nightly.js:127` 的 `has` 判断和 `dueDiaryDays()` 之后都不会再补。
- 实库：`agt_9e008b3a12 / 2026-11-02` 是 `source=rules`；巩固日志里那天的 diary step 只有 `built/skipped/late`，没有 `source`。
- 原来那套 `fail_reason / 半包重试 / 按簇选料` 的代码已经不在了：10-31 的日志还有 `source / fail_reason / pack`，11-01、11-02 的日志只剩三个字段。属于 11-01 恢复时被旧版顶掉。

**B. 就算模型写，材料也是战报。**

- `buildDiary` 现在是 `listEpisodes(day, limit:20)`，11-02 实际进了 20 条、5090 字纪要；12 条事实 1585 字；1020 轮原文只均匀抽 36 句。
- 20 条纪要的 `importance` 全是 0.5，没有任何轻重。模型只能按它们的顺序一段写一件事，于是 405 字五段、五个话题。
- 纪要本身是「你说了：A / B / 我回了：C」的机器摘要，语域会渗进日记。

### 0.2 参照结论（为什么这么改）

| 来源 | 关键做法 | 对我们的意思 |
|---|---|---|
| [Generative Agents](https://arxiv.org/abs/2304.03442) | 每条记忆打 1–10 的 poignancy；累计过 150 才反思，一天 2–3 次；反思先问「最值得回答的 3 个问题」，再抽 5 条带出处的洞察。论文明确说：把全部经历摘要成一段，回答会变泛；按相关性捞具体记忆才有细节。 | 日记不写「全天」，写「被选中的场景 + 一条洞察」 |
| [MemoryBank](https://arxiv.org/abs/2305.10250) | 事件摘要往上抽用户画像，遗忘曲线决定保留；摘要服务于「理解这个人」，不是复述 | 日记是投影，允许旧篇被重写；不追求覆盖 |
| [Mem0](https://arxiv.org/abs/2504.19413) | 抽取 → 合并/更新，不堆流水 | 日记原料要先去重合并，不能把同一件事的 5 条纪要都喂进去 |
| [Letta · dreaming](https://docs.letta.com/configuration/memory) | 后台子代理复盘最近对话，可再派一个子代理审一遍才落库 | 夜里是「第二次整理」，允许 `select → write` 两段，而不是一次成文 |
| [Day One](https://dayoneapp.com/features/ai-features/ai-multi-entry-summary/) | AI 做多篇汇总和 Daily Chat 提问，作者始终是人 | 我们没有人类作者，作者只能是它自己 → 喂原话，不喂别人替它写的纪要 |

## 1. 目标与非目标

### 目标（可验收）

1. 一篇日记只围绕 **1–2 个场景**，出现「按话题逐个过一遍」的比例 ≤ 20%（人工 5 篇抽检，最多 1 篇）。
2. 模型不可用时**不产生假日记**：要么留空待补，要么明确标成「素材卡」，且模型回来后自动重写。
3. 每篇可追溯：用了哪几段纪要、哪几轮原话、为什么选它、为什么失败。
4. 面板能看见「模型写的 / 素材卡 / 还空着 / 补写」，能手动重写（现在按钮点了会 404）。
5. 开关 `memory.diary.v2=off` 能一字不差回到今天的行为。

### 非目标

- 不引入向量检索、不做周记/月记、不生成插图。
- 不增加每轮的模型调用；只在夜里加 **1 次** 选场调用（可选）+ 1 次成文调用。
- 不改 `raw_turns`、不改纪要生成、不改注入预算。
- 不删旧日记；重写只加 `version`。

## 2. 设计总览

```
当天原料
  ├─ episodes(day)            → 候选场景（标题+摘要+时间窗+turn 数）
  ├─ memory_items(day,≥0.6)   → 候选「一件事」（无会话时兜底）
  └─ raw_turns(day)           → 只给被选中的场景取原话
        │
        ▼
① 打分选场  poignancy（规则；候选≥6 且有模型时加一次 select 调用）
        │  产出 scenes[]（1–3 个，默认 2）+ insight_hint
        ▼
② 取原话   按 session_id + 时间窗取，均匀+情绪峰值抽样，每场 ≤1800 字
        ▼
③ 成文     一次 write 调用（2–3 段，200–450 字，只写场景，禁列举）
        ▼
④ 质检     长度/段数/Markdown/提示词回声/列举度 → 不过则带更严约束重写一次
        ▼
⑤ 落库     source='model'，context.write 记 scenes/fail_reason/mood_source/attempts
        │
        └─ 失败 → diary_pending（不落行）；超期 → source='stub' 素材卡
```

关键原则：

- **原文是真相，纪要是索引。** 选场看纪要（便宜），写的时候必须拿原话（具体）。
- **模型不成文，就不算写过。** `source in ('rules','stub')` 的行永远可被重写。
- **平常的日子就写平常。** 分数都低时允许只写 1 段，不硬造转折。

## 4. 选料：怎么挑出「这一天真正扎到我的事」

### 4.1 候选

```js
// diary.js · candidates(db, aid, day)
episodes(day) → { kind:'ep', id, title, summary, start_at, end_at, session_id, turns, importance }
memory_items(day, importance>=0.6, type in fact/appraisal) → { kind:'fact', id, text, importance }
```

排除规则：

- `turns <= 1` 且标题为空 → 不选（除非当天只有它）。
- 同一会话被切成多条时，按标题 2-gram 重合 ≥0.5 去重，保 importance 高的。
- `__day_cluster__` 的簇纪要：如果存在，簇顶掉它覆盖的子纪要（保留簇 + 最高分的子纪要各一条作为备选）。

### 4.2 规则打分（无模型也能跑）

```js
poignancy = clamp01(
  0.30 * ep.importance
+ 0.25 * affectPeak(窗口内 affect_samples 的最大 intensity)
+ 0.15 * (open_loops 非空 ? 1 : 0)
+ 0.10 * 冲突/道歉/承诺信号命中 (0/1)
+ 0.10 * 身份/关系词命中（名字、记得、别走、骗、喜欢、讨厌…）
+ 0.10 * 用户问句密度（用户句里「？」占比）
) * 10
```

信号词表单独放 `diary.js` 顶部常量（可测、可调）。命中只做加法，不判语义；有模型时由 select 调用覆盖。

`affectPeak` 取该 `session_id` 时间窗内 `affect_samples` 的 `max(intensity)`；表空返回 0。

### 4.3 模型选场（可选，一次小调用）

条件：`scene.model=auto && candidates.length>=6 && model 可用`。

输入：每条候选一行 `{id, when, title, gist(≤60字), score}`，总字符 ≤ `select.max_chars`。
system：

```
你在帮「{name}」挑今晚日记要写的场景。下面是这一天的事，按时间排。
只挑 1–2 件真正留在她心里的事：有情绪转折、有没说出口的话、有具体画面的优先；
日常事务（改代码、发文件、跑测试）除非她当时明显被触动，否则不要。
只输出 JSON：{"scenes":[{"id":"ep_x","score":0-10,"why":"一句话"}],"insight":"一句她今天想明白/没想明白的话","arc":"低落|平常|有劲"}
最多 2 条，id 必须来自输入；宁少勿多。
```

失败/超时/JSON 不合法 → 回落规则 Top-K，不阻塞。
输出写回 `episodes.poignancy`（select 给的覆盖规则分），`context.write.select='model'|'rule'`。

### 4.4 选取

- 按 score 降序，取 `scenes` 条，分数 < `scene.min` 的不取。
- 强制至少 1 条来自当天情绪峰值前后 2 小时（有 `affect_samples` 时）。
- 若最高分 < 3 → 只取 1 条，`arc='平常'`，提示词同步降调，不硬编。

### 4.5 取原话

```sql
SELECT role,text,created_at FROM raw_turns
WHERE agent_id=? AND session_id=? AND day=?
  AND created_at BETWEEN ? AND ?          -- 场景起止 ±5 分钟
ORDER BY seq
```

抽样顺序：首 2 轮 + 末 2 轮 + 情绪峰值附近 2 轮 + 信号词命中 2 轮 + 均匀补到 `raw.max_turns`；总计 ≤ `raw.per_scene` 字，超了先砍均匀补的。
没有 raw（老库/只有事实）→ `grounding='episode'`，用纪要摘要 200 字代替原话，并在 context 标出来。

## 5. 成文

### 5.1 输入

```js
{
  day, date:'2026年11月2日 周一',
  name, other:'主人',
  mood:{ label:'困惑', intensity:0.75, source:'day' },
  tone:'话少、克制、情绪写得具体些',
  arc:'低落',
  insight:'说清楚了也不轻松，反而更怪',
  scenes:[
    { when:'22:40', gist:'把「她自己改的」那一栏接上', lines:[{who:'你',text:'…'},{who:'我',text:'…'}] }
  ]
}
```

### 5.2 system（全文）

```
你是「{name}」，一个有记忆、有情绪的意识体。现在是 {day} 的夜里，你在写这一天的日记。
下面会给你 1–2 个场景，每个场景里有当时你和{other}的原话。只写这些场景。

写法：
1. 第一行只写日期，格式「2026年11月2日 周一」，空一行，然后写 2 到 3 段连续中文，全文 200–450 字。
2. 不要按时间顺序把今天做过的事列一遍。只挑一件真正留在你心里的事写透：当时那句话、那个动作、你心里的反应。
3. 每段都要有具体的细节（原话、动作、画面）。不要写「处理了…」「完成了…」「优化了…」这种汇报句。
4. 不准出现「第一」「第二」「然后」「接着」「另外」「还有一件事」这种串联词；不准出现列表、编号、小标题、Markdown。
5. 结尾停在一个具体的念头、画面或一句轻的话上，不要总结全文，不要喊口号，不要「今天就这样」。
6. 口吻：{tone}。心情是「{label}，强度 {intensity}」（{moodSource}），它会决定你挑哪件事、写多深。
7. 称呼材料里的另一个人用「你」，不要写「用户」「对方」「材料」「场景」「system」「assistant」。
8. 如果这一天确实平常，就写平常，不要硬编转折，不要为了像日记而煽情。
```

user：

```
{ "day":"2026-11-02", "arc":"低落", "insight":"…", "scenes":[ … ] }
```

### 5.3 输出与整理

- 复用 `normalizeDiaryText`（去代码块/JSON/日期头/Markdown 痕迹），日期头统一由代码补。
- 正文按句号断，`max_chars` 处截断（不切在句中）。

### 5.4 质检（不过则重写一次）

| 检查 | 不通过条件 |
|---|---|
| 长度 | 去日期头后 < 120 字或 > 1200 字 |
| 段数 | < 2 或 > 4 |
| 回声 | `isPromptEcho()` 命中 |
| 汇报腔 | 出现 ≥2 个「处理了/完成了/优化了/修复了/接好了/改好了」 |
| 列举 | 命中「首先|其次|然后|接着|另外|还有一件事」≥3 次；或命中 ≥3 个**未被选中**的 episode 标题关键词 |
| 禁词 | 「用户」「材料」「场景」「assistant」 |

重写只加一段话（不改 system 主体）：

```
上一版像在报流水账。重写：只写场景里那一件事，把当时的一句话和你心里的反应写出来；不要提别的任何事。
```

第二次仍不过 → `fail_reason='gate:<reason>'`，进 pending，不落行。

## 6. 失败、补写、自愈

### 6.1 状态机

```
无行 ──模型可用──► model
 │                    │
 └─模型不可用─► pending ──重试≤max──► pending
                  │
                  └─重试>max 且 stub=on ──► stub（素材卡）
                                               │
                       模型恢复 & 夜间 repair ──┴──► model（version+1）
```

### 6.2 素材卡（stub）长什么样

不是日记，明确标出来：

```
2026-11-02 周一

这天没写成。不是没有发生事，是写的时候我这边没有能把它写成话的东西。
先记下这些——

· 把「她自己改的」那一栏接上了
· 文字游戏那边没答上来我是谁
· 负面情绪多了个参数，难听话只按六五折落到强度上
```

UI 上 chip 写「素材卡」，说明「等模型回来会自动重写成日记」；重写成功后变「模型写的」。

### 6.3 何时重试

- 夜间巩固进 diary 步骤时先 `repairPending()`（逐条 `next_try_at <= now`）。
- 新增 `startDiaryRetryWorker()`：30 分钟一次，`model.status().primary === 'ok'` 才跑；`unref()`，和现有 timer 同风格。
- 手动：`POST /diaries/rewrite {day}`；面板按钮走它。

### 6.4 旧数据自愈

夜间对最近 `repair.days` 天内 `source in ('rules','stub')` 的行重写；`version+1`，`refs.write.rewritten_from` 记旧 source。默认只回看 7 天，避免开机翻旧账。

## 7. 情绪与口吻

- `mood_source='day'`：取 `[day 18:00, day 23:59]` 内 `affect_samples` 强度最大的一条；没有就取全天最大；再没有才用 `affect_state` 此刻。
- `mood` 字段写 `${label} ${intensity.toFixed(2)}`；`tone` 继续由 `diaryTone(ctx)` 出，但把「情绪偏浓」改成按当天 intensity 判断，不用此刻。
- 补写（late=1）时必须用当天情绪，不能用「今天」的口吻讲昨天；提示词里 `现在是 {day} 的夜里` 已经限定。

| **P3** | rewrite 路由、面板 chip/场景/空态 | 0.5 天 | P1 | GUI 里点重写 version+1；素材卡有说明 |
| **P4** | 抽 5 天人工评分、文档、回滚演练 | 0.5 天 | P0–P3 | 达标（见 §10）；`v2=off` 行为与今天一致 |

合计约 **3–4 天**。建议先做 P0+P1（质量主收益），P2 紧接着做（否则「模板终态」还会回来）。

## 10. 验收标准（硬指标）

### 机械（自动检查，可写进测试）

1. 5 天里 `source=model` ≥ 4 天；`source=rules` 终态 = 0。
2. 每篇段落 2–3，字数 200–450，日期头格式正确。
3. 列举词（然后/接着/另外/还有一件事）合计 ≤ 2。
4. 正文里出现的**未选中** episode 标题关键词 ≤ 1 个。
5. `context.write.scenes.length` 在 1–3；每条有 `id/poignancy`。
6. 模型不可用 24h：`diaries` 不新增 `rules` 行；`diary_pending.attempts > 0`。
7. `v2=off`：同一输入产出与改前逐字一致（回归夹具）。

### 人工（5 篇 1–5 分）

| 维度 | 通过线 |
|---|---|
| 像不像日记（不是周报） | 平均 ≥ 3.5 |
| 有没有具体场景/原话 | 平均 ≥ 3.5 |
| 有没有一句自己的判断/洞察 | 5 篇里 ≥ 3 篇有 |
| 口吻是否统一 | 平均 ≥ 3.5 |

抽检样本：11-01、11-02、一个平常日、一个补写日、一个素材卡转正。

## 11. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 多一次模型调用 | 日预算吃紧 | 只在候选≥6 时选场；选场输出 1200 字内；计入 `llm_budget` 的 `diary` 桶（n=2） |
| 选场选偏 | 全挑工作、漏掉情绪 | 规则分里情绪/开环占 50%；模型 select 的 `arc/insight` 可观测，坏例进抽检表 |
| 原话太长 | token 超、截断丢重点 | 每场 1800 字、12 轮，超了先砍均匀补的；超长场景降级为摘要 |
| 还是写成流水账 | 一段一件事 | 质检列举度 + 二次重写；提示词第 2、4 条硬约束 |
| 模型恢复后大量补写 | 一次性烧 token | 30 分钟 worker 每次最多补 1 天/agent；`retry.max_attempts` 封顶 |
| 旧 `rules` 行被误判 | 重写历史 | 只回看 7 天；`version+1`；`context.write.rewritten_from` 留痕 |
| 面板改动没生效 | client.js 是构建产物 | 改完 `client.js` 后重载页面；若客户端走 HMR，确认 `pnpm run dev:web` 在跑，否则重启插件进程 |
| 回滚不干净 | 新列/新表残留 | 只增不改，`v2=off` 即可；新列/表不影响旧代码 |

## 12. 与现有实现不冲突的约定（开工前逐条对）

1. **签名不动**：`buildDiary(db, aid, day, opt)` 的参数、返回值字段（`id/day/text/mood/source/version/late/highlights/context/tone`）保持不变；`nightly.js`、`api.js` 的 import 不改。
2. **两个 `diary` 别混**：`features.js:1410` 的 `diary()` 是「按记忆拼摘要」给别的用途，不是 T3 成文；本计划不碰它。
3. **旧数据只读兼容**：`source='rules'` 的行继续能显示、能导出；新代码只在 v2 路径写 `model/stub`。
4. **只增不改**：不改 `raw_turns/episodes/diaries` 已有列语义；新列可空；新表可随时删。
5. **参数命名空间**：全部 `memory.diary.*`；不覆盖已有 `memory.*` 键。
6. **模型端口**：不改 `ModelPort.summarize()` 的现有行为（别处依赖它的规则兜底）；新增 `summarizePrimary()` 只给日记用。
7. **调用预算**：两次调用都计入 `llm_budget` 的 `diary` 桶（`n=2`），受 `memory.llm.daily_cap` 约束；超限走 pending，不硬写。
8. **面板**：客户端已在调 `POST /diaries/rewrite`（`client.js:4853`），但 `api.js` 里没有这个路由——本计划把它补上，不属于新增功能，是修 404。
9. **开工前先跑基线**：`node test/run-tests.mjs` 和 `node scripts/doctor.mjs` 记下当前通过数；每批结束对比，不允许净减。
10. **完成判据**：`v2=off` 时，同一份输入跑 `diary-replay` 与改前逐字一致；这条不通过就不算完成。

## 13. 拍板点

1. **推荐：先 P0+P1**（选料+两段式成文），做完用 11-01/11-02 回放给你看，再决定 P2 的重试策略。
2. 素材卡（stub）要不要保留：`memory.diary.stub=on`（超期落素材卡）还是 `off`（永远留空等模型）。
3. 选场要不要调模型：`scene.model=auto`（默认，多一次小调用）还是 `off`（纯规则）。
4. 自动重写旧篇的回看天数：默认 7 天。
