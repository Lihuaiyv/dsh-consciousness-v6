# 实验 B：关键节点局部模型判断——跑通了

> 时间：2026-11-04 夜
> 问题：能不能在关键节点让模型判一次，而不是全靠规则/相似度？
> 结论：**能。本机就能跑，624ms 一次，免费，我人工对照约 90% 准。**

---

## 1. 先说结论

| 项 | 结果 |
|---|---|
| 能不能跑 | **能**，用本机 ollama 的 `gemma4:12b` |
| 单次耗时 | **624ms**（30 对的平均） |
| 成本 | 0（本地） |
| 准确率 | 我人工对照 30 对：约 **27 / 30 ≈ 90%** |
| 对比 baseline | cosine 分不开（0.73 和 0.95 无清晰界线）；2-gram 把这 126 对**全判成「有更新」** |

---

## 2. 三个坑（都踩过了）

### 坑 1：插件里的 `model.complete` 是 false

```
model.capabilities() = { ..., complete:false, embed:true }
```

`~/.dsh/consciousness/model.json` 里**只有 `embedding` 一节，没有 chat 模型的 url/key**。
所以插件里没有聊天能力——这不是代码问题，是配置缺一项。

补上（环境变量或 model.json）：

```json
{ "url": "http://127.0.0.1:11434/v1", "model": "gemma4:12b", "timeout": 120000 }
```

### 坑 2：走 OpenAI 兼容层拿不到输出

补了配置之后 `capabilities()` 全 true，但每次调用返回的是规则兜底：

```
servedBy: fallback
lastError: This operation was aborted
```

原因不是超时——直接测 ollama：

```
/v1/chat/completions  → 29.7s, finish=length, completion_tokens=300, content=""
/api/chat (think:false) → 9.7s, content="蓝色"
```

**`gemma4:12b` 是 thinking 模型。** 走 OpenAI 兼容层时，token 全花在思考上，
`content` 返回空字符串。插件把它当失败，3 次后熔断 30 秒，后面全走规则。

必须走**原生 `/api/chat` 并带 `think: false`**。

### 坑 3：超时默认 15 秒

第一次加载模型要 20-30 秒。`model.json` 里要配 `"timeout": 120000`，否则一定 abort。

---

## 3. 实验做法

`scripts/exp-llm-judge.mjs`：

1. 取和 cosine 实验同一批候选（`stampRow` 判出 weakLater 的 126 对）
2. 按余弦降序，**等距抽样 30 对**（固定规则，不手挑）
3. 每对问模型：

```
system: 你在判断两条记忆之间是什么关系。
        只输出三个词之一，不要解释，不要 JSON，不要标点：
        同一件事 —— 后一条是前一条的进展、补充或改口（说的是同一个问题）
        不同的事 —— 两条只是共用了一些词，实际在说不同的事
        不确定 —— 拿不准
user:   旧：<正文>
        新：<正文>
```

4. 直连 `http://127.0.0.1:11434/api/chat`，`think:false`，`temperature:0`

---

## 4. 结果

```
判断分布：{"同一件事": 19, "不同的事": 11}
平均耗时：624ms
```

我逐条人工对照，明确错的 2 条、存疑 1 条。

### 判对的典型

| 旧 | 新 | 模型 | 我判 |
|---|---|---|---|
| 检索算法效果，有没有更好的方案 | 关注检索算法表现，问能否升级 | 同一件事 | ✅ |
| 正式环境登录不进去，带 error | 两个角色无法登录、被弹回登录页 | 同一件事 | ✅ |
| 图表完全画错，横轴纵轴都不对 | 图中五条长度不一致，追问有没有深意 | 不同的事 | ✅ |
| chatReply 按 conversation_id 取上下文 | 保存设置会清掉 qq.token | 不同的事 | ✅ |
| `oneLine` 会在句号处截断 | `oneLine` 吃掉句号导致判定拿不到全文 | 同一件事 | ✅ |
| 说晚安会用「晚安但不晚安」 | 好的晚安但是不晚安 | 同一件事 | ✅ |

**「小小 / 小绿」那类 cosine 分不开的，模型不会靠词撞。** 它靠的是「说的是不是同一个问题」。

### 判错的典型

| 旧 | 新 | 模型 | 我判 |
|---|---|---|---|
| 考试正式环境数据库为 `204/knowledge_inner` | 要求删除今天在正式环境创建的考试 | 同一件事 | ❌ 不同的事 |
| 用户项目 package.json 原为空文件 | 保存设置会清掉 qq.token | 不同的事 | ✅ |

**错误模式很集中：一个专有名词同时出现在两条里（同一个库名 / 同一个文件名），模型会判成同一件事。**
两次明确错误都是这一类。

这是可控的：可以在 prompt 里加一句「两条的主语或动作不同，就算不同的事」，
或者事后加一条规则闸（主语实体不同 → 强制「不同的事」）。

---

## 5. 这意味着什么

**「关键节点局部模型判断」是可行的，而且成本几乎为零。**

按真实写入量估：

- 每天新增记忆 147 条（最近一天的数据）
- 其中需要判的候选对：现在全库 126 对，按比例每天约 **5–15 对**
- 每对 0.6 秒 → **每天 3–9 秒的算力**

这个量级完全可以：

1. **写入门控**：新记忆和候选旧条判一次，决定「这是同一件事的后续」还是「两件不同的事」
2. **夜间整理**：把当天没判干净的候选对批量判一次（不占对话时延）
3. **绝不放在注入路径上**（那是几十毫秒的预算）

---

## 6. 还没解决的问题

1. **准确率是我一个人判的**，没有第二个人交叉。90% 这个数有主观成分。
2. **30 对样本太小**。要下结论得上百对。
3. **「同一件事」判对了，不等于「这是更新」**。同一件事可能是「补充」而不是「取代」——
   这一步模型还得再判一次（或者说，得给它两档：「取代 / 补充 / 无关」）。
4. **错误集中在一个模式**（同名不同事），可以用规则闸兜住，但还没写。
5. 接入插件要改 `OpenAIAdapter`：要么加 `think:false` 透传，要么加一个 ollama 原生分支。
   现在是实验脚本直连，主链路还没接。

---

## 7. 建议的接入顺序

1. **先扩样本**：30 → 100 对，我判 + 模型判，把 90% 这个数做实
2. **加规则闸**：两条的主语实体不同 → 强制「不同的事」，兜住已知错误模式
3. **给模型三档**：取代 / 补充 / 无关（现在只有两档，判「同一件事」还不够用）
4. **改适配器**：`OpenAIAdapter` 支持 `think:false`，或加 ollama 原生分支 + `timeout` 配置
5. **接写入门控**：只在「相似度落在 0.5–0.9 的灰区」时调模型，确定性命中不调
6. **缓存**：同一对记忆只判一次，结果落库（`events` 或新表），避免重复花钱/耗时
